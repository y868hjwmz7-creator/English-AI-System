# 発音評価の実装方針 — 3案の比較

いまの発音スコアは**仮の数値**です(`src/lib/pronunciation.js`)。
本物にするには方式を選ぶ必要があり、それによって費用・精度・プライバシーの扱いが変わります。

このページは、その判断のための材料です。
**結論から言うと、案1で始めて、物足りなければ案2に移るのをおすすめします。**
理由は最後に書きました。

---

## ⚠️ 最初に、前提のひとつを訂正します

仕様書では「音声は端末の外に出さない」方針を立てていました。
調べたところ、**案1(ブラウザの音声認識)でも音声はブラウザメーカーのサーバーに送られます。**

ブラウザの音声認識機能は、音声を端末内で処理しているのではなく、
Chrome なら Google のサーバー、Safari なら Apple のサーバーに音声を送って
文字に変換した結果を受け取る作りになっています。

つまり **「無料の案1なら音声が外に出ない」というのは誤りです。**
3案とも、程度の差はあれ音声はどこかに送られます。

| | 音声の送り先 |
|---|---|
| 案1 ブラウザの音声認識 | Google または Apple のサーバー |
| 案2 発音評価サービス | そのサービス提供者のサーバー |
| 案3 端末内で解析 | どこにも送らない(唯一これだけ) |

**「サーバーに音声を保存しない」という方針は3案とも維持できます**
(採点結果だけを保存すればよいため)。
ただし**「音声を外部に送らない」は案3以外では成立しません。**

学習者に未成年が含まれる可能性があるなら、
利用規約・プライバシーポリシーに「発音採点のために音声を外部サービスに送信すること」を
明記する必要があります。これはどの案を選んでも同じです。

---

## 案1: ブラウザの音声認識を使う

読み上げた英文をブラウザに文字起こしさせ、**お手本の英文とどれだけ一致したか**で採点します。

### できること・できないこと

| | |
|---|---|
| ✅ | 「単語を言えているか」は判定できる |
| ✅ | 言い間違い・言い落としが分かる |
| ❌ | **「どの音が悪いか」は分からない**(L と R の区別など) |
| ❌ | 抑揚・リズムの評価はできない |

「`right` と言ったつもりが `light` と認識された」なら L/R の問題だと**推測**はできますが、
「th の音が弱い」といった音素単位の指摘はできません。

### 費用

**無料。**

### 実装の手間

小さいです。1〜2日程度。すでにある録音の仕組みをそのまま使えます。

### 端末ごとの動作 — ⚠️ ここが最大の懸念

| 端末 | 状況 |
|---|---|
| Mac の Chrome | 問題なく動く |
| 会社PC の Chrome / Edge | 問題なく動く |
| **iPhone の Safari** | **動くが、不安定という報告が多い** |

iPhone の Safari は 14.5 以降で対応していますが、
「イベントが正しく発火しない」「マイク許可を求めずにエラーになる」といった
不具合の報告が見られます。またホーム画面に追加した状態では動かないという報告もあります。

**移動中に iPhone で発音練習をしたい**という使い方をされるなら、
ここは実機で確かめてからでないと採用を決められません。

---

## 案2: 発音評価に特化したサービスを使う

音声を専門のサービスに送り、採点結果を受け取ります。

### できること

| | |
|---|---|
| ✅ | **音素単位の評価**(どの音が弱いか) |
| ✅ | 流暢さ・抑揚・リズムの評価 |
| ✅ | 単語ごとの点数表示 |
| ✅ | 端末による差が出ない(サーバー側で処理するため) |

いまの画面に出している「正確さ / 流暢さ / 抑揚」の3項目は、
まさにこの種のサービスが返す値を想定して作ってあります。

### 主な選択肢

**Microsoft Azure AI Speech(発音評価機能)**

- 音声1時間あたり **およそ $1〜1.7**(2026年8月時点、料金体系は変更されます)
- 無料枠あり
- 日本語のドキュメントが充実しており、情報が探しやすい

**Speechace**

- 英語学習に特化したサービス
- 15秒単位での課金。**具体的な単価は公開されておらず、問い合わせが必要**

### 費用の概算(Azure の場合)

前提を置いて計算します。**あくまで桁を掴むための概算です。**

- 1回の練習 = 5秒の音声
- 1人が1日10回練習
- 単価を $1.6 / 時間、$1 = 150円として計算

| | 音声の長さ | 概算費用 |
|---|---|---|
| 1回の練習 | 5秒 | 約 0.3円 |
| 1人・1日 | 50秒 | 約 3円 |
| 1人・1か月 | 25分 | **約 100円** |
| 30人・1か月 | 12.5時間 | **約 3,000円** |

Supabase の $25(約3,700円)と合わせると、
学習者30人規模で**月7,000円弱**というのが、有料構成でのおおよその姿です。

> 課金の最小単位や対象SKUによって変わるため、
> 実際に契約する前に Azure の料金ページで確認してください。

### 実装の手間

中くらい。3〜5日程度。
音声をサービスに送る処理と、返ってきた採点結果を画面に反映する処理が必要です。

APIキーをブラウザに埋め込むと誰でも使えてしまうため、
**キーを隠す中継サーバーが別途必要**になります(Supabase Edge Functions で作れます)。

---

## 案3: 端末の中だけで解析する

音声をどこにも送らず、ブラウザの中で解析します。

### 評価

| | |
|---|---|
| ✅ | **音声が一切外に出ない**。プライバシー面では最も強い |
| ✅ | 通信費・API費用がかからない |
| ❌ | **精度が読めない**。作ってみないと使い物になるか分からない |
| ❌ | 実装の手間が大きい(2週間以上) |
| ❌ | iPhone では処理が重く、電池を消耗する |

発音評価は音響モデルを必要とする分野で、ブラウザ内で動く既製の仕組みは
選択肢が限られます。**試作段階で選ぶ道ではありません。**

なお、ブラウザの音声認識を「端末内で処理する」ようにする仕様も策定が進んでいますが、
対応状況がまだ揃っていないため、いま採用の判断はできません。

## 3案の比較

| | 案1 ブラウザ認識 | 案2 専用サービス | 案3 端末内解析 |
|---|---|---|---|
| 費用 | **無料** | 月3,000円程度(30人) | 無料 |
| 音素単位の評価 | ✕ | **◎** | △(精度不明) |
| 抑揚の評価 | ✕ | **◎** | ✕ |
| 端末による差 | **大きい(iPhone懸念)** | なし | 大きい |
| 音声の外部送信 | あり | あり | **なし** |
| 実装の手間 | **小(1〜2日)** | 中(3〜5日) | 大(2週間〜) |
| 中継サーバー | 不要 | 必要 | 不要 |

## おすすめ

### まず案1で作り、物足りなければ案2に移る

理由は3つあります。

**1. 無料で、すぐ形になる**
いまの仮のスコアが本物になるまで1〜2日です。
「単語を言えているか」だけでも、仮の数値よりははるかに意味があります。

**2. 本当に音素単位の評価が要るのか、使ってみないと分からない**
「th の音が弱い」と指摘されて、学習者がそれを直せるかは別の問題です。
案1をしばらく使ってから、案2の費用を払う価値があるか判断できます。

**3. 乗り換えの費用が小さい設計にしてある**
差し替えるのは `src/lib/pronunciation.js` の1ファイルだけです。
画面のコードは変わりません。

### ただし、先に確かめるべきことが1つ

**iPhone の Safari で音声認識が動くかどうか**です。
ここが動かないなら、移動中の発音練習という使い方が成立しないため、
案1を飛ばして案2を選ぶ判断もあり得ます。

**確認用の小さなテストページを作れます。**
iPhone で開いて、実際に喋って、認識されるかどうかを見るだけのものです。
30分ほどで用意できるので、判断はそれからでも遅くありません。

### 案3は、いまは選ばない

プライバシー面は魅力的ですが、精度が読めないものに2週間かけるのは、
試作段階のいまやることではありません。
将来「音声を外に出せない」制約が出てきたときに、改めて検討する対象です。
