# お手本音声を用意する手順

練習用の英文の音声をあらかじめ作り、全端末で同じ品質にするための手順です。

> **なぜ必要か**
> 端末に入っている音声は品質がばらばらです。特に iPhone では、
> 利用者が高品質な音声をダウンロードしても、Apple の制限により
> ブラウザからは使えません(仕様書 3.3.4)。
> あらかじめ音声を作って配信する以外に、品質を揃える方法がありません。

---

## 用意する話者(4人)

| 表示名 | アクセント | 性別 |
|---|---|---|
| Emma | アメリカ英語 | 女性 |
| Ryan | アメリカ英語 | 男性 |
| Sophie | イギリス英語 | 女性 |
| Oliver | イギリス英語 | 男性 |

地域訛り(スコットランド英語など)は後回しにしています(仕様書 7.1)。

## 費用

**無料枠に収まります。**

Azure の音声合成は1文字あたりで課金され、**毎月50万文字までは無料**です。

| | 文字数 | 費用 |
|---|---|---|
| いまの例文8件 × 4人 | 約1,600文字 | **$0** |
| 例文500件 × 4人 | 約12万文字 | **$0** |
| 例文2,000件 × 4人 | 約48万文字 | **$0** |

**一度作れば作り直す必要はありません。** 英文を足したときだけ、
足した分の音声が作られます。

## 手順

### 1. Azure のアカウントを作る

1. `https://azure.microsoft.com/ja-jp/free/` を開く
2. 無料アカウントを作る(クレジットカードの登録を求められますが、
   無料枠の範囲では請求されません)

### 2. 音声サービスを作る

1. Azure ポータルで「リソースの作成」→「Speech」を検索
2. 次のように設定する

| 項目 | 値 |
|---|---|
| リージョン | **Japan East**(日本から使うため) |
| 価格レベル | **Free F0**(無料枠) |

### 3. 鍵とリージョンを控える

作成したリソースの「キーとエンドポイント」を開き、次の2つを控えます。

- **キー1**(長い文字列)
- **場所/地域**(例: `japaneast`)

### 4. `.env` に書く

リポジトリの `.env`(無ければ `.env.example` をコピーして作る)に
次の2行を書きます。

```
AZURE_SPEECH_KEY=控えたキー1
AZURE_SPEECH_REGION=japaneast
```

> **`.env` は Git に入りません。** 鍵が公開リポジトリに載ることはありません。
> 逆に、鍵をこのファイル以外の場所に書かないでください。

### 5. 音声を作る

```
npm run audio
```

`public/audio/` の下に、話者ごとのフォルダと音声ファイルができます。
あわせて `manifest.json`(目録)が作られます。

### 6. 反映する

できた音声ファイルをコミットしてプッシュすれば、公開ページに反映されます。

```
git add public/audio
git commit -m "お手本音声を追加する"
git push
```

---

## 音声ができると何が変わるか

- お手本の枠に「**全端末で同じ品質**」と表示されます
- 話者が Emma / Ryan / Sophie / Oliver の4人になります
- iPhone でも Android でも、同じ音声が再生されます

音声が用意されていない英文については、**端末内蔵の読み上げに切り替わります**。
アプリが止まることはありません。

## 英文を追加したとき

### 自動でやる方法(おすすめ)

GitHub に鍵を登録しておけば、**英文を足してプッシュするだけ**で
足りない音声が自動で作られます。コマンドを実行する必要はありません。

**登録は1回だけです。**

1. リポジトリ画面 → **Settings** → **Secrets and variables** → **Actions**
2. **New repository secret** で次の2つを登録

| 名前 | 値 |
|---|---|
| `AZURE_SPEECH_KEY` | Azure のキー |
| `AZURE_SPEECH_REGION` | `japaneast` |

登録すると、`src/data/practicePhrases.js` を変更してプッシュするたびに
`.github/workflows/generate-audio.yml` が動き、足りない音声を作って
リポジトリに追加します。

> 鍵は GitHub が暗号化して保管し、ログにも表示されません。
> 登録するまでは、このワークフローは何もせずに終わります。

### 手元でやる方法

```
npm run audio
```

どちらの場合も**足した分だけ**が作られます。すでにある音声は
作り直さないため、課金も増えません。

---

## どこまで増やせるか

| 例文の数 | ファイル数 | 文字数 | 費用 | 音声の容量 |
|---|---|---|---|---|
| 8件(現在) | 32 | 約1,600 | $0 | 約0.8MB |
| 100件 | 400 | 約2万 | $0 | 約10MB |
| 500件 | 2,000 | 約10万 | $0 | 約48MB |
| 2,000件 | 8,000 | 約40万 | $0 | 約190MB |

**費用は2,000件でも無料枠(月50万文字)に収まります。**

ただし容量には注意が必要です。**500件あたりまでは
リポジトリに音声を置いたままで問題ありません。**
それを超えると、音声の保管場所を別に用意する
(Supabase のストレージなど)ほうが健全です。

`要確認`: 例文を最終的に何件まで増やす想定か。
500件を大きく超えるなら、英文の一覧も JavaScript のファイルではなく
データベースに置き、音声もストレージに移すべきである。
