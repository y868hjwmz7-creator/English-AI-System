### 成功と失敗が、同じ見た目で終わってはいけない

生成が終わってもボタンが元に戻るだけで、**失敗したときと見分けが
つかなかった**(2026-08)。時間のかかる処理は、終わったときに
**何ができたのかを、押した場所のすぐ下に出す。**
問数だけでなく中身の一部(最初の1問)も出す。数字だけでは
本当に中身があるか分からない。ボタンの文言も「作り直す」に変える。

### 守らせたい形は、頼むのではなく道具の形で強制する

`generate-material` は `emit_section` という道具に JSON を書かせている。
**形は演習の種類ごとに作り、必要な欄を `required` にする**
(`SECTION_FIELDS`)。`strict: true` なので API が形を保証する。

以前は全種類で1つの形を使い、必須は `answer` だけだった。会話では
`answer` は空文字でよいため、**「話す人の名前だけの項目が2つ」**という
本文の無いものが通ってしまった(2026-08 実機)。音声もシャドーイングも
できない教材になる。「1項目 = 1つの発言」と**指示文には書いてあった。**

**演習の種類を足したら `SECTION_FIELDS` にも足すこと。**
使わない欄を出さないので、余計な出力に課金されない利点もある。

### 略語のピリオドで、文を切らない(`splitSentences`)

2026-09 利用者の指定。

> Ph. D / Dr. Hara など、ピリオドが含まれるが、文の終わりを示すわけでは
> ない語句のリストを作り、これらのピリオドを文の終わりとして
> 捉えないよう改善してください。

**以前は「辞書は持たない」と決めていた**(抜けが新しい不具合になるため)。
けれども `Dr. Hara` が2つの文に割れると、**読み上げの色も、1文ずつの
◀ ▶ も、名前の途中で切れる。** 見落とし(長い1文になる)より害が大きい。

- **一覧は `ABBREVIATIONS`(`src/lib/wordTiming.js`)1か所。**
  ここは**文の切り方を持っている唯一の場所**なので、読み上げ・
  スラッシュリーディング・Quick Response・集中モードの割り方まで、
  **1つ直せば全部に効く**
- **ほかの品詞にならない語だけを入れる**(`chunker.js` の `SURE_PREPS` と
  まったく同じ考え方)。`no.`(No. 5)・`apt.`・`etc.`・`sun.` `sat.` は
  **ふつうの語として文末に立つ**ので入れない ——
  入れると `The answer is no.` が次の文とつながる。
  **見落としは長い1文になるだけだが、取り違えは文をつなげてしまう**
- **`U.S.` `a.m.` `Ph.D.` は一覧に並べない。** 形で見分けられるうえ、
  **最後のドットは本当に文を終えることがある**
  (`She holds a Ph.D. Everyone applauded.`)。一覧に入れると、
  そこで**永久に切れなくなる**

見るのは4つ(`abbrevAt`)。**上から順に見て、当てはまった時点で決める。**

| | 何を見るか | 例 |
|---|---|---|
| ⓪ | すぐ次が**数字** | `3.5 percent` |
| ① | 次のことばが**小文字で始まる** | `a Ph.D. in physics` |
| ② | つないだ形の**途中**のドット(次が「1文字 + ドット」) | `U.S.` `a.m.` |
| ③ | 一覧にある語 | `Dr.` `Ph.` `Mr.` |

**①がいちばん効く。** 英語の文は小文字では始まらないので、
**一覧に無い略語(`etc. and …`)もこれで拾える。**
逆に**1文字だけ(`A.`)は略語にしない** —— `Choose option A. Then …` で
切れなくなる。**`!` `?` は見ない**(略語に使われない)。

`npm run test:play` が、切る側と切らない側の**両方**を見張る
(`Dr. Hara` で切らない / `Ph.D. Everyone` では切る / 一覧に危ない語が
混じっていないか)。実際に `no` を一覧へ入れて、赤くなることを確かめてある。

### 集中モードで割ったかけらは、そこでは「段落」である

2026-09 利用者の指定。

> 長い段落を集中モードの一塊として区切った場合、集中モード内ではそれらを
> 段落として扱い、繰り返し再生できるようにしてください。現状では文ごとの
> リピートは効きますが、段落は元々の段落を参照してしまい、
> 次のページに進んでしまいます

くり返し「段落」が**元の段落**を回すので、画面は次のかけらへ進んでいた。
**画面が1枚ずつ出しているのに、音は元の段落のまま**だった。

#### **鳴らす英文は割らない。** 割ると、そのぶん課金される

いちばん素直な直し方は「かけらを `parts` として渡す」だが、**採れない。**
読み上げの置き場所は**英文の指紋**で決まるので
(`<版>/<段>/<声の id>/<指紋>.mp3`)、**かけらごとに別の MP3 が作られ、
同じ本文の音声代を二度払う。** 1本にまとめた音声も「声と英文の並び」で
指紋を取るので、やはり作り直しになる。**見えない費用は管理できない。**

だから渡すのは**これまでどおり段落まるごと**で、
**くり返す範囲だけ**を、いま出しているかけらに狭める。

- 画面は **`partRangeOf(段落の番号)`** で
  「その段落の英文の**何文字目から何文字目まで**」を返す。
  **秒で言わない** —— 鳴らす側と画面で数え方を2通り持つことになる
- 狭める算段は **`spanForRange()`(`wholeAudio.js`)1か所。**
  **文の切れ目でしか割っていない**(`focusChunks`)ので、
  かけらの端は必ずどれかの文の端と重なる
- **1本にまとめた音声でも、段落ごとの MP3 でも同じように効く**
  (どちらの `onTime` も同じ関数を通す)
- **狭められなければ `null`。** これまでどおり段落まるごとが回る
  (**行き止まりを作らない**)
- **最後のかけらは、戻す前に鳴り終わることがある。** そのときは
  周回のほうが鳴らし直すので、**かけらの頭から**始める(`replayAt`)
- **割っていない段落では範囲を渡さない**(いまと1ミリも変わらない)
- **紙(`LessonView`)は1文字も変えていない**(あちらは割らない)

`npm run test:mp3` が**道が1本も切れていないこと**を、
`npm run test:play` が**狭め方そのもの**を見張る
(実際に `partRangeOf` を外して、両方が赤くなることを確かめてある)。

### 本文は「問」で数えない

記事は**段落**、会話は**発言**。`countUnit()` / `countLabel()`
(`src/data/exerciseTypes.js`)を使う。「会話(14 問)」と書くと
14個の設問があるように読める。

### 中身が0件のまま「成功」を返さない。転んだ段階の名前を言う

記事・会話は「本文 → 内容の理解 → 語句」と3回に分けて作る。
①の本文が空のまま②へ進み、②の入口の検査で
**「本文が空です。先に記事か会話を作ってください」**と出ていた。
押したのは「会話を作る」なので、利用者には何が起きたのか分からない
(2026-08)。

- **`items` が0件なら「成功」を返さない。** 終了理由を添えて失敗にする
- Claude の応答は `stop_reason` を必ず見る。`max_tokens` で切られると
  **JSON が途中までになり、`items` が丸ごと欠けた「空の成功」**になる
- 何段階かに分けて作るものは、**転んだ段階の名前を付けて**知らせる

### 失敗の知らせは、その操作をした場所に出す

生成に失敗したとき、知らせを画面のいちばん下に出していたためスマホでは
見えず、「何も起きずにボタンが戻る」ようにしか見えなかった(2026-08)。
**押したボタンのすぐ下に出し、そこまで画面を送る。**
時間のかかる処理は**経過秒数**も出す。動いていることが分からないと
固まったと思われる。

### レベルは14段階ぶん、別々に書く。束ねない

2026-09 利用者の指摘。

> 現状、中級から下のレベルは実際より難しく感じ、
> 中級より上は実際より簡単に感じる傾向があります。

原因は、窓口の「レベルの目安」が**14段階を6行に束ねていた**こと。
`Pre-Basic / Basic` が同じ1行、`C1 / C1+ / C2 / Proficiency` も同じ1行では、
**段を分けた意味がない。** しかも「中学1〜2年程度」のような学年のたとえは
測れないので、真ん中(A2〜B1あたり)へ寄る。

- **14段すべてに、別々の行を書く**(`generate-material` の「レベル(14段階)」)
- **測れる目安にする。** 1文の語数・使ってよい文法・語彙の範囲・1項目の長さ
- **Pre-Basic は「He is happy.」「I am eating lunch.」**(2026-09 利用者の指定)。
  これより長い言い方を思いついたら、それは Pre-Basic ではない
- **両側に逆向きの力がかかる**ので、打ち消す指示を書く。
  下では「もう一段やさしく」、上では「教科書的な平易さに戻らない」
- **作り終えたら語数を数えさせる。** 目安を書くだけでは守られない
- 依頼のたびに「**その段の行だけを見る**」と念を押す。表はキャッシュに
  載っているので、念押しは数十トークンで済む

土台は **CEFR-J**(日本の学習者向けに CEFR を細かく分けたもの)と
**English Grammar Profile / English Vocabulary Profile**(どの文法・語が
どの段で出るか)。**表そのものは窓口に置く。** 画面(`cefr.js`)は
名前だけを持つ。判断を2か所に置かない。

### レベルの選択肢には GSE の数字を出す

`cefrOption()`(`src/data/cefr.js`・2026-09 利用者の指定)。

> 各レベルの選択肢としての表記をよりシンプルで適切なものにしてください。
> 例：A1 (GSE 20-30)など

    A1 (GSE 22-25)      ← プルダウンの選択肢(`cefrOption`)
    A1(入門)            ← 札・見出し(`cefrLabel`。**変えていない**)

**選ぶときと、見るときでは要る情報が違う。**
選ぶときは VERSANT のスコアと突き合わせたいので数字が要る。
**VERSANT は Pearson の試験で、点数(10〜90)は GSE そのもの**なので、
「45点だから B1」と迷わず決められる。見るときは「中級」のほうが早い。

- **数字の出どころは Pearson の公表値**(de Jong & Benigno, 2017)。
  A1 = 22〜29 / A2 = 30〜42 / B1 = 43〜58 / B2 = 59〜75 /
  C1 = 76〜84 / C2 = 85〜90 / A1 未満 = 10〜21
- **「+」の4つは Pearson 自身の区切りと一致する**
  (A2+ = 36〜42 / B1+ = 51〜58 / B2+ = 67〜75)。
  残りは公表された帯を**こちらで半分に割ったもの。取り違えない**
- **札(14個並ぶ)には数字を入れない。** 触れたときの説明(`title`)に置く。
  札に入れると狭い画面で折り返して読めなくなる
- 窓口の「レベル(14段階)」の表にも同じ数字を入れてある。
  **画面と窓口で違う数字を持たない**

### 生成の費用は、ほぼ全額が「出力」側

**いま使っているのは Claude Sonnet 5**(入力 $2 / 出力 $10。100万トークン)。
利用者が実物で確かめて「十分」と判断済み(2026-08)。
**費用や品質を理由に勝手にモデルを変えない。**
`generate-material/index.ts` の `MODEL` 1行で切り替わる。
**変えたら画面側の単価(`PRICE_PER_MTOK`)も必ず一緒に変える。**
片方だけだと、表示される金額が実際と食い違う。
参考: Opus 5 は 入力 $5 / 出力 $25。**入力と出力で桁が1つ違う。**
しかも**考えている時間も出力として課金される。**
入力はキャッシュに載るのでほぼ無料(システム指示は約1,650トークン、
Opus 5 の最小長512を超えているので載る)。

**費用を増やす作りを持ち込まないこと。**
- 同じ内容を2つの欄に書かせない(`audio_text` を `prompt_en` と同じに
  させていて、英文を2回書かせていた)
- 弱点ごとに呼び分けない。1回にまとめる(弱点3つで3倍かかっていた)
- `output_config.effort` は `medium`

費用は画面に出す(`estimateCost`)。**見えない費用は管理できない。**
