取り組みを裏で数える(0022)・集計(0023)・スピーチ練習・データの置き場

### 取り組みは、こちらが裏で数える(0022)

**ゲストに「何分やった」を入力させない。** 入力そのものが手間で、
しかも入れ忘れる(2026-08 の設計変更。「学習の記録」の画面は外した)。

- 数えるのは `usePracticeLog(kind)` **1つ**。画面で1回だけ呼ぶ
- **見えている時間だけ**数える。裏に回した端末の時間は数えない
- **1分ごとに送る。** 1回ごとでは通信も行も増えすぎる
- **ゲストのぶんだけ**(`viewerRoleOf() === 'learner'`)
- 1人 × 1日 × 1種類 で1行(`practice_days`)。`vocab_days` と同じ考え方
- 数え方は DB(`learner_practice()`)に置く。**画面に持たない**

**リマインドは、トレーナーが押したときだけ飛ぶ**(利用者の指定)。
自動では送らない。だからゲストの画面に「トレーナーから」と出しても
**嘘にならない。** ゲストが変えられるのは `seen_at` だけ(列単位の grant)。

### 集計(管理者)は「教材の種類と内容」で数える。学習時間で数えない

`AdminDashboard.jsx` + `src/lib/schoolStats.js` + **0023**。
前は `study_logs`(ゲストが手で入力した学習時間)を並べていたが、
その入力欄は 0022 で無くなっている。**入らなくなった数字のグラフを
置き続けると、いつまでも 0 が並ぶ。**

- 数えるのは **種類**(`materials.kind`)・**内容**(弱点タグ / CEFR)・
  **届き方**(`assignments`)・**取り組み**(`practice_days`)
- **数え方は DB に置く。** 合計も割合も画面で足し直さない
- **いちばん見せたいのは「ライブラリの穴」。** 教材が0件の弱点も、
  ゲストがいるのに教材が0本のレベルも**必ず行として出す。**
  隠すと、次に何を作ればよいかが分からない
- 5つの関数はどれも `security definer`。**`is_owner()` の判定を外さない。**
  外すと全校のデータが誰にでも見える(`rls_test.sql` が見張っている)
- `learner_practice()`(0022)は**担当ゲストだけ**のトレーナー用。
  `school_practice()`(0023)は**全校**の管理者用。**取り違えない**
- **Supabase が無いときに見本の数字を出さない。** 実際と食い違ったまま
  判断されてしまう

### スピーチ練習は独立した機能。ただし**点数は付けない**

**呼び名は 2026-09 に「発音練習」から変えた**(利用者の指定)。
**id(`pronunciation`)・ファイル名・`practice_days.kind` は変えていない**
(変えると過去の記録が別物になる)。
**教材の種類「Speech練習」(`kind = 'speech'`)とは別物。取り違えない。**

`pronunciation.js` の点数は**録音を解析していない仮の数値**である。
これを独立した機能の看板にすると、**測れていないものを測れているように
見せる**ことになる。いまは「聴いて、まねて、言う」までにしてあり、
画面にもそう書いてある。採点を足すのは、やり方が決まってから。
**録音を外に送るのは方針の転換**にあたる(仕様書 3.2)。

### データの置き場

| 何を | どこに | なぜ |
|---|---|---|
| 学習記録・教材・配信・スコア | Supabase | 端末をまたいで共有する必要がある |
| **録音した音声そのもの** | **端末内(IndexedDB)** | 生体情報に近い。サーバーに上げない(`docs/PROJECT_SPEC.md` 3.2) |
| お手本音声(MP3) | Supabase Storage | 年 0.3〜1.4GB。Git リポジトリには置けない |
| 設定・アプリ状態 | localStorage | `nav.js` / `theme.js` / `palette.js` / `sfx.js` / `progress.js` など、それぞれの場所 |

**録音音声をサーバーに送る変更は、方針の転換にあたる。** 勝手に行わず必ず確認する。
