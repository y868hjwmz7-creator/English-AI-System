### 取り組みは、こちらが裏で数える(0022)

**ゲストに「何分やった」を入力させない。** 入力そのものが手間で、
しかも入れ忘れる(2026-08 の設計変更。「学習の記録」の画面は外した)。

- 数えるのは `usePracticeLog(kind)` **1つ**。画面で1回だけ呼ぶ
- **見えている時間だけ**数える。裏に回した端末の時間は数えない
- **1分ごとに送る。** 1回ごとでは通信も行も増えすぎる
- **ゲストのぶんだけ**(`viewerRoleOf() === 'learner'`)
- 1人 × 1日 × 1種類 で1行(`practice_days`)。`vocab_days` と同じ考え方
- 数え方は DB(`learner_practice()`)に置く。**画面に持たない**

**リマインドは、トレーナーが押したときだけ飛ぶ**(利用者の指定)。
自動では送らない。だからゲストの画面に「トレーナーから」と出しても
**嘘にならない。** ゲストが変えられるのは `seen_at` だけ(列単位の grant)。

### 集計(管理者)は「教材の種類と内容」で数える。学習時間で数えない

`AdminDashboard.jsx` + `src/lib/schoolStats.js` + **0023**。
前は `study_logs`(ゲストが手で入力した学習時間)を並べていたが、
その入力欄は 0022 で無くなっている。**入らなくなった数字のグラフを
置き続けると、いつまでも 0 が並ぶ。**

- 数えるのは **種類**(`materials.kind`)・**内容**(弱点タグ / CEFR)・
  **届き方**(`assignments`)・**取り組み**(`practice_days`)
- **数え方は DB に置く。** 合計も割合も画面で足し直さない
- **いちばん見せたいのは「ライブラリの穴」。** 教材が0件の弱点も、
  ゲストがいるのに教材が0本のレベルも**必ず行として出す。**
  隠すと、次に何を作ればよいかが分からない
- 5つの関数はどれも `security definer`。**`is_owner()` の判定を外さない。**
  外すと全校のデータが誰にでも見える(`rls_test.sql` が見張っている)
- `learner_practice()`(0022)は**担当ゲストだけ**のトレーナー用。
  `school_practice()`(0023)は**全校**の管理者用。**取り違えない**
- **Supabase が無いときに見本の数字を出さない。** 実際と食い違ったまま
  判断されてしまう

### スピーチ練習は独立した機能。ただし**点数は付けない**

**呼び名は 2026-09 に「発音練習」から変えた**(利用者の指定)。
**id(`pronunciation`)・ファイル名・`practice_days.kind` は変えていない**
(変えると過去の記録が別物になる)。
**教材の種類「Speech練習」(`kind = 'speech'`)とは別物。取り違えない。**

`pronunciation.js` の点数は**録音を解析していない仮の数値**である。
これを独立した機能の看板にすると、**測れていないものを測れているように
見せる**ことになる。いまは「聴いて、まねて、言う」までにしてあり、
画面にもそう書いてある。採点を足すのは、やり方が決まってから。
**録音を外に送るのは方針の転換**にあたる(仕様書 3.2)。

### データの置き場

| 何を | どこに | なぜ |
|---|---|---|
| 学習記録・教材・配信・スコア | Supabase | 端末をまたいで共有する必要がある |
| **録音した音声そのもの** | **端末内(IndexedDB)** | 生体情報に近い。サーバーに上げない(`docs/PROJECT_SPEC.md` 3.2) |
| お手本音声(MP3) | Supabase Storage | 年 0.3〜1.4GB。Git リポジトリには置けない |
| 設定・アプリ状態 | localStorage | `nav.js` / `theme.js` / `palette.js` / `sfx.js` / `progress.js` など、それぞれの場所 |

**録音音声をサーバーに送る変更は、方針の転換にあたる。** 勝手に行わず必ず確認する。


### 誰の記録になるかは、**画面に出す**(第5.178節)

2026-09 利用者の指摘。

> ゲストページ内の…教材内で単語やフレーズを単語帳に登録しているはずなのに、
> 明らかに他のゲストが登録した単語などが入っていることがあります。

**データベースの側では混ざらない。** `review_words()` は
`where r.learner_id = p_learner`、`mark_word()` は `teaches()` を確かめてから、
`word_reviews` の RLS は「自分の行か、担当しているゲストの行」。
**ゲストAの単語帳にゲストBの語が入ることはありえない。**

混ざっていたのは**トレーナー自身の単語帳**である。

| レッスン表示の入り口 | 語の行き先 |
|---|---|
| ゲストのページ → 宿題 → セッションで使う | そのゲスト |
| **教材の画面 → セッションで使う** | **トレーナー自身** |

#### **決め方ではなく、使われ方が違っていた**

あとのほうは 2026-08 に「トレーナー自身の記録でよいですか → はい」で
決めたものである。ところが `LessonView` のメモの節に、こちらで既に
書いてあった ——「**利用者はふだん『教材』の画面から開く**」。
つまり**セッションのほとんどがこの入り口を通っていた。**

**同じ見落としを、メモで一度している**(「書けない理由であって、
ボタンを消す理由ではなかった」)。2度目である。

- **「この画面は◯◯のためのもの」と決めたら、そのとおりに使われているかを
  一度は確かめる。** 決めた日の想定は、使い方が変わっても勝手には直らない
- **黙って既定に落ちる作りは、間違いが見えない。**
  `setWordStatus()` は `learnerId` を渡さなければ黙って `auth.uid()` に書く。
  **props を1つ書き忘れただけで、別の人の単語帳に入る**
- だから**いま誰の記録になるかを、画面に出す**(`SessionOwner`)。
  **見えない持ち主は管理できない** —— AI を呼ぶ前に回数と金額を出すのと
  まったく同じ考え方である

#### 見る側と書く側は、同じ1つを使う

教材の画面が `useWordStatuses(sessionFor)` と
`<LessonView learnerId={sessionFor}>` の**両方**に同じ値を渡す。
分けると「**色は自分・記録はゲスト**」という食い違いが起きる
(CLAUDE.md「数え方を2通り持たない」)。

レッスン表示の中も `owner` 1つで、子(Quick Response・書く欄・
集中モード・6Steps・セッションの記録)はぜんぶそれを見る。

#### 帯の中には置けなかった(320px で 26px に潰れた)

|帯の中身(320px)|幅|
|---|---|
|閉じる|31px|
|ページ送り|103px|
|絵3つ|38px × 3|
|すき間(`gap` 10px × 5)|50px|
|**合計**|**324px / 入れ物 304px**|

**読めない名札は、無いのと同じである。** 帯のすぐ下に1行まるごと使った
(第5.176節「押すところと読むところを分ける」と同じ)。
**行ごと `SessionOwner` が持つ** —— 前後の文を呼ぶ側に書くと、
骨組みと本物が食い違う。

### セッションの記録を、ゲストも書けるようにする(第5.267節・0070)

2026-09-26 利用者の指定。

> ゲストログインしたさいの「セッションの記録」を、ゲストも入力、
> 編集できるようにしたいです。
> また、セッション中にセッションの記録をトレーナーが画面共有している
> ときに、これを画面いっぱい、または半分などに大きくして使用できる
> ようにしてほしいです。

#### **同じ1枚を2人で書くと、あとから書いたほうで上書きされる**

記録は「1日に1枚」で、**書き終えて 1.2 秒だまると自動で保存する。**
ゲストにも書かせると、離れた場所で同時に書いたときに片方が消える。

訊いたところ、答えは「**同時に書いても大丈夫なようにしてください**」だった。

#### 欄を2つに分けた(`body` / `learner_body`)

| 欄 | 書ける人 | 読める人 |
|---|---|---|
| トレーナーの記録(`body`) | トレーナー・管理者 | 両方 |
| **ゲストの記録**(`learner_body`) | **ゲスト本人** | 両方 |

**お互いの欄は見えるが、書けるのは自分の欄だけ。**
だから同時に書いても、どちらも消えない。

**リアルタイムの仕組みは入れていない。** この環境からは Supabase に
届かないので、**正しさが「同時に書けるかどうか」に依る作りは確かめられない。**
欄を分ける形は、動かさなくても正しさが決まる。

#### なぜ RLS ではなく関数なのか

要るのは「**ゲストは `learner_body` の欄だけ書ける**」という**列の制限**で、
RLS は行しか絞れない(CLAUDE.md)。
列ごとの権限はロール(`authenticated`)単位でしか付けられず、
**トレーナーとゲストを分けられない。**

だから `set_learner_note()`(security definer)1つにした。
**`auth.uid()` の行の `learner_body` だけ**を書き換える ——
ほかの欄にも、ほかの人の行にも触れようがない。

#### **トレーナーが自分の欄を空にしても、ゲストのぶんは消えない**

0032 の `saveNote()` は、空にしたとき**行ごと消して**いた
(白紙の日をカレンダーに残さないため)。そのままだと、
**トレーナーが自分の欄を消しただけで、ゲストの書いたものまで消える。**

いまは**読んでから決める** —— ゲストの欄が残っていれば、
トレーナーの欄だけを空にする。**判断は `lessonNotes.js` 1か所**で、
画面に「空なら消す」を書かせない。

#### 大きく表示(全画面 + 幅を選べる)

骨組みは `FocusFrame`(`plain`)—— 教材の「セッションで使う(大きく表示)」と
**まったく同じもの**である。

幅の一覧は `src/data/sheetWidths.js` 1か所に出した。

    SHEET_WIDTHS … 100% / 110% / … / 150% / 画面いっぱい(教材・これまでどおり)
    NOTE_WIDTHS  … **半分** + 上の全部(セッションの記録)

**「半分」は記録の側にだけ足してある。** 言われたのは記録の話なので、
教材の幅は1つも変えていない(**言われた場所だけを直す**)。
`LessonView` は `SHEET_WIDTHS` を取り込むだけで、**出る中身は1つも変わらない。**

### 第5.301節 … 添削が済んだら、原稿の欄は畳む(2026-09-28 利用者の指定)

> 一度添削が済んだらこのグレーの部分はもう必要ないですよね。
> **本文として一本化したきれいな表示**を用意し、
> **閉じたり開いたりできる**ようにすべきです

#### 何を出すか

添削が済んだ(`isReviewed`)ときだけ、原稿の欄のところが2つの畳みに変わる。

| 札 | 中身 | 既定 |
|---|---|---|
| **直した本文**(◯◯ 文字) | `speechText()` を1つの段落で | **畳む** |
| **原稿を直す**(◯◯ / 3000 文字) | もとの `textarea` そのまま | **畳む** |

**まだ添削していないときは、これまでどおり**(原稿の欄がそのまま出る)——
**言われた場所だけを直す**(共通ルール)。

#### 原稿は消さない

「もう一度 添削してもらう」は**原稿から作る**ので、
消すと**やり直せなくなる**(行き止まりを作らない・CLAUDE.md)。
畳んで、開けば直せる形にした。

#### 一本化した文章は `speechText()` 1か所

スピーチ練習の「文章をコピー」(第5.300節)が渡すものと**同じ**である。
**数え方を2通り持つと、画面に出ている文とコピーされる文が食い違う。**

#### ここで転んだ … **畳みの中に入ると、CSS が当たらなくなる**

原稿の背丈は

    .speech-edit > .field > textarea { min-height: 12rem }

で決まっていた。**`<details>` の中に入れたとたん、直接の子でなくなり、
背が縮んだ。** ソースを読んでも分からない ——
**描いて測って初めて出た**(CLAUDE.md「推測でいじらない。まず測る」)。
`.speech-edit textarea` に緩めた(この箱の中に `textarea` はこれ1つだけ)。

#### 描いて測った

`SpeechBoard` は**自分で読み込む部品**なので、骨組み(`__screens.jsx`)には
描けない —— **描けないものは測れない**(CLAUDE.md)。
そこで**読み込みだけを偽物に差し替えた使い捨ての物差し**で、
**本物の部品と本物の CSS のまま**測った。

| | 1280px | 390px |
|---|---|---|
| 畳んだときの背 | **46px**(札だけ) | 46px |
| 2つのあいだのすき間 | **14px** | 14px |
| 開いたときの原稿の背 | 270px | 306px |
| 横のはみ出し | **0** | 0 |

**`<details>` そのものに `display` を書いていない** ——
書くと畳んでも中身が場所を取り続ける(共通ルール)。
畳んだ背が 46px であることが、その証拠である。
