### 4択の並びは、1問のあいだ変えない

`makeChoices()` は**呼ぶたびに混ぜる。** ところがレンダーのたびに呼んでいたので、
**答えた瞬間の描き直しで並びが変わり**、正解が別の場所へ動いてから
緑になっていた(2026-09 実機)。

> 正解の時に、元々の正解の選択肢のあった場所から対角線上に移動してから
> 緑になったり、ランダムに移動して緑に光るから変な感じがして落ち着きません

`useMemo` で、**語(と出題の形)が変わったときだけ**作り直す。
**`rows` は見ない。** 答えると `rows` から1語外れるので、
見ていると同じことが起きる(出題を組み直さないのと同じ理由)。

**「混ぜるもの」を、描くたびに呼ばない。** 同じことが起きる場所は
ほかにもある(`buildSession` は `deal` のときだけ呼んでいる)。

### 単語帳の復習も、集中モードで出す

2026-09 利用者の指定「単語帳モード、集中モードにしよう」。

> この集中モード、単語帳にも採用したい。最高ですね。
> そもそも集中モードというものをおかずに集中モードのように
> 表示されるのが理想です。スマホの画面にいかに全てを詰め込むのかが

単語帳は上に**札・プルダウン・絞り込み**が積み重なっていて、スマホでは
**カードが画面の下のほうから始まっていた。** 出題を画面ぴったりの1枚にすれば
送るものが無くなり、**1語だけに向き合える。**

- **骨組みは `.focus` をそのまま使う**(`FocusReader` と同じもの)。
  `.wbfocus` で足すのは、上の帯が進み具合の帯を持つという1点だけ。
  **同じ見た目を2か所に書き写さない**
- **入口をもう1つ挟まない**(利用者の言葉「集中モードというものをおかずに」)。
  復習の札を押した人は、もう答える気で来ている。**開いた瞬間から出す**
- **戻る道は上の帯の左端**(「✕ とじる」)。出したあとは
  一覧に「今日の復習をつづける」を出す。**行き止まりを作らない**
- **`margin-bottom: 28vh` は外す。** あれは「ページを送ってカードを
  まん中へ持ってくるための送りしろ」で、**送るものが無いこの画面**では
  ただの空白になり、カードが下へずれて見える
- **出題の枠の高さ(`.wordcard-q`)は決め打ちのまま。**
  語や文の長さで枠が伸びると、そのぶん答えのボタンが動く
- **画面を送る `scrollIntoView` は、集中モードでは呼ばない**
  (送るものが無いので、呼ぶと何も起きないか、かえって狂う)
- うしろの画面は `document.body.style.overflow = 'hidden'` で止める

### 復習のカードは、画面のまん中に固定する

2026-09 利用者の指定。

> 単語は、「覚える」や「まだ」「覚えかけ」などを押し出したら画面に固定になり、
> 単語や解答の長さに関わらず、しっかり中央に居座るようにしてください。
> (特にスマホで)そして、4択の回答は中央に表示してください。
> 下に表示されて切れてしまっている時が多いです。

- **出題の枠は高さそのものを決める**(`.wordcard-q` の `height`)。
  `min-height` だけだと長い語・長い文で伸び、**そのぶん答えが下へ動く**
  (実測 112px → 224px で4択が画面の外へ出た)。
  はみ出したぶんは**枠の中だけ**で送る
- **1語ごとに、カードを画面のまん中へ寄せる**(`scrollIntoView`。
  `block: 'center'`・動きは付けない)。単語帳は上に札・プルダウン・
  絞り込みが積まれているので、スマホではカードが下から始まる

  ページの終わりに余白が無いと、それ以上送れず**まん中まで来ない。**
  **`.wb-run` に付けない。** あれは進み具合の帯だけの入れ物で、
  カードはその外にある(付けたら帯とカードのあいだが 200px 空いた)
- **出題の形(おまかせ)は、進み具合の行の右に置く**(2026-09 利用者の指定)。
  画面のはるか上にあったので、訊き方を変えるたびに上まで送り戻していた。
  **変えたくなる場所のとなりに置く**
- **「◯ / ◯ 語」のカウンターは出さない**(2026-09 利用者の指定)。
  すぐ下の**進み具合の点**(`.wb-run-bar`・1問=1目盛り)が同じことを
  言っているので、**同じことを2つ見せない**。
  消したのは**その1つだけ**で、点の帯・出題の形・とじるは残してある
  (`.wb-run-head > .wb-formpick` が `margin-left: auto` なので、
  カウンターが無くなっても出題の形は右端のまま)。
  - **`npm run test:bar` が、この文字を別の目的で読んでいた** ——
    「その教材の語だけに絞れているか」を `.wb-run-count` の
    「/ 3 語」で数えていた。消すと**巻き添えで赤くなる**ので、
    **点の数(`.wb-run-bar > span`)で数えるように付け替えた。**
    見ているものは同じ(1問=1目盛り)。
    実際に絞り込みを壊して、赤くなることを確かめてある
- **その見た目は、読むものの邪魔をしない。** 灰色の塗りつぶしの丸だったので、
  この行でいちばん大事だった「6 / 10 語」より目立っていた
  (**その数字はいま出していない。**上記)。
  1回選んだらしばらく触らないものなので、**ふだんは文字と小さな矢印だけ。**
  触れたときにだけ、うすい面を出す。
  **矢印は自分で描く**(端末ごとに形も大きさも違う)
- **10語やり終えた結果も、同じ場所に置く**(利用者の指定)。
  最後の1語に答えた時点で、画面はその語のカードに合わせて送ってある。
  ところが結果の箱は**それより短い**ので、そのままでは
  画面のずっと下に出たり、上に空きができたりする。
  **語のカードと同じ決まりで置き直す**(狭い画面は上、広い画面はまん中)
- **狭い画面では、進み具合の行を画面の上にそろえる**(利用者の指定)。
  まん中に寄せると上に空きができるぶん、4択の下が画面の外へ出やすい。
  上にそろえれば**進み具合・出題の形・カードが1画面に収まる。**

  広い画面は空きが多いので、これまでどおりまん中

  教材名は長く、狭い画面ではこれだけで1行を食っていた。

### 集中モードでは、カードで**画面を使い切る**(2026-09 実機・利用者の指定)

> もっと大きく画面を使ってください。出会った英文を押した際にいちいち
> スクロールしなければいけない回数が減るからです

**出題の枠の高さを決め打ちにしていた**(`.wordcard-q`)。
答えのボタンを動かさないための決まりだが、そのぶんカードは
iPhone(390×844)で **311px**(画面の1/3強)しか使っておらず、
枠は **144px** だった。だから「出会った文」を開くと、
**その狭い枠の中で送る**ことになっていた。

**集中モードには送るものが無い**(画面ぴったりの1枚)。だから
**枠を伸ばしてもボタンは動かない。**

- **カードが残りいっぱいを取り、枠が余りを吸い、答えの行はカードの
  いちばん下に貼り付く。** Quick Response を紙に載せたときと同じ形である
- **残りの高さを計算しない。** flex に任せる
  (`flex: 1 1 auto` + 途中の箱に `min-height: 0`)
- **下限は残す**(0 まで縮むと問題が真っ白になる)
- **上限は 44rem。** パソコンの縦長の画面でカードが伸びきると、
  語と答えのボタンが数百 px 離れて目が行き来する。
  iPhone(844px)で残る高さとほぼ同じなので、
  **スマホとパッドでは実質いっぱいまで広がる**
- **一覧(集中モードでない側)は1ドットも変えていない**

#### **4択とつづりも、余っている縦は出題の枠に渡す**(2026-09 実機)

**「4択とつづりは、もともと空いていない」と書いたのは言い過ぎだった。**
利用者が2枚の写真で示した。

> 1枚目の写真が、スマホのホーム画面にURLを貼り付けたときの表示、つまり
> 画面下部にブラウザのUIがありません。その分画面上部のバーと単語の部分の
> 余白が大きくなってしまっています。ピッタリ当てはめて欲しいです。
> そうすれば「出会った文」の下が切れてしまうこともありません。
> …2枚目の写真はChromeで開いているときの表示です。割と綺麗に単語の枠が
> 収まっていますが、もう少しだけ上の余白を詰めて、単語のスペースを
> 広くできそうです

**実測すると、どちらの画面でも大きく空いていた**(390px 幅・4択)。

| | 上の空き | 下の空き | 出題の枠 | 「出会った文」 |
|---|---|---|---|---|
| **ホーム画面(844px)** | **176px** | 176px | 144px | **84px 切れる** |
| Chrome(734px) | 123px | 124px | 139px | **89px 切れる** |

出どころは1つ。出題の枠が `clamp(5.5rem, 19vh, 9rem)` で
**9rem(144px)で頭打ち**になっていたことである。だから

- 画面が縦に伸びても枠は広がらず、**余りはカードの上下にただの空白として溜まる**
- そのあいだ「出会った文」は、その狭い枠の中で**切れたまま**

**ブラウザの帯が無いぶん縦が長いホーム画面(PWA)で、いちばんひどくなる。**
利用者が「アプリを実装したときの表示」と言っているのは、この形である。

**直したのは「上限を、画面の余りから決める」の一点だけ。**

- **枠の高さは、これまでどおり中身によらない。**
  「単語や解答の長さに関わらずボタンが動かない」は破っていない
- **上限(24rem)は置く。** 際限なく伸ばすと、「出会った文」を閉じている
  ときに**語と選択肢が数百 px 離れる**(上に書いた心配は、上限が無いときの
  話としては正しい)
- **足りないときは、枠だけが縮む**(`flex: 0 1 auto` + `min-height`)。
  選択肢と入力欄は縮ませない(`flex: 0 0 auto`)ので、
  **狭い画面でも答えが画面の外へ出ない**
- **`--recall` と `--result` には効かせない。** あちらはすでに
  画面いっぱいまで伸ばす決まりで、上限を掛けると**縮んでしまう**

### 「覚えた」はやめた。**続けて押した回数**で卒業を決める(0038)

2026-09 利用者の指定。

> あと、「覚えた」はなくしましょう。
> 20-30回くらい連続で覚えかけを押すとしばらくは出てこない仕様にしましょう

**自分で「覚えた」と申告する道は、当てにならない。** 1回思い出せただけで
押してしまうし、押した瞬間に箱が上がって**30日先へ飛ぶ。** そして忘れる。

いま押せるのは **「まだ」/「覚えかけ」の2つだけ。**

| 押したもの | 数え | 箱 | 次に出す |
|---|---|---|---|
| まだ | **0 に戻す** | 0 | 翌日 |
| 覚えかけ(24回目まで) | +1 | +1(上限 3) | 1 / 2 / 4 日 |
| 覚えかけ(**25回目から**) | +1 | 6 | **30日**(しばらく出てこない) |

- **回数は `word_reviews.learn_streak`**(0038)。**箱では代われない。**
  覚えかけの箱は 3 で頭打ちなので(0027)、「25回続いた」を数えられない
- **卒業までおよそ3か月**(最長4日おき × 25回)。途中で1度でも「まだ」を
  押せば 0 に戻る。**早くしたいときは、0038 の `c_graduate` 1か所を変える**
- **卒業しても `status` は `learning` のまま。** `known` にすると復習から
  **永久に**消えるので、利用者の言う「**しばらく**は出てこない」にならない
- **`known`(覚えた)そのものは残してある。** 本文の中で語に触れて押す
  「知っていた」がこの状態を使っており、すでに付いている語も1件も変わらない。
  **消すのと、見せるのは別のことである**
- **4択・つづりで当たったときも `learning` にする。** ここだけ `known` を
  書いていると、**機械が採点した語だけが卒業の数えから外れる**
- **`vocab_days.correct` は「思い出せたか」で数える**(0038)。
  `known` だけを正解に数えていたので、そのままだと**いつも 0** になる
- **一覧(見返す用)の「覚えた」は、積んだ語にだけ出す**(0039・
  2026-09 利用者の指定「ある程度の回数『覚えかけ』を押さないと
  『覚えた』は出ない仕様にしましょう」)。

  はじめは一覧のボタンをそのまま残していた(言われたのは復習のカード
  だったため)。ところが**そこから1回で卒業できる**ので、
  カードから外した意味がなくなっていた。
  かといって丸ごと外すこともできない — 本文の中で押す「知っていた」が
  同じ状態を使っており、**すでに `known` の語もある。**

  - 判断は **`canMarkKnown()`(`vocab.js`)1か所。**
    目安の回数は **`KNOWN_AFTER`(10)**。25回で自動的に卒業するので、
    その手前の目安である。**変えるならこの1行**
  - **0039 が要る。** `review_words()` が `learn_streak` を返していな
    かったので、画面からは何回積んだのか分からなかった
  - **0039 を貼る前は、これまでどおり出す**(回数が返ってこないため)。
    **貼る前でも動く道を残す**(CLAUDE.md)
  - **足りない語には「覚えかけ 3 / 10 回」と出す。**
    ボタンが消えるだけだと「消えた」のか「まだ」なのか分からない
- **0027 を貼っていない Supabase では「覚えかけ」が使えない**ので、
  そのときだけ「覚えた」を出す(`learningSupported()`)。
  外すと「まだ」しか押せず、**行き止まりになる**

> 出題範囲の時系列での絞りかた(例:１週間以内・２週間以内・３週間以内・
> １か月以内・３か月以内・半年以内 etc...)、その時に復習したい単語やフレーズ、
> 文章の個数だ。これを直感的に選択できる仕組みを作り上げたい。

#### まず読んだ。**指摘は3つの穴を指していた**

| | 単語帳の復習 | Quick Response の復習 |
|---|---|---|
| 時系列の絞り | **カレンダーで1日だけ** | 同じ |
| 1回の個数 | **10語で固定** | **区切りが無い。溜まっている数だけ続く** |
| 範囲の選び方 | カレンダー | 「今日出すぶん / 全部」のプルダウン |
| おさらい | **0件になるまで出てこない** | 同じ |

- **Quick Response には「1回ぶん」が存在しなかった。** 87問溜まっていれば
  「はじめる(87 問)」と出て、87問続く。単語帳には**「終わりの見えない
  作業は続かない。だから10語で区切る」**と書いてあるのに
  (`wordQuiz.js` の `SESSION_SIZE`)、**こちらで破っていた**
- **「1週間以内」を選ぶ道が、どこにも無かった**(カレンダーは1日を指すもの)
- **同じことをする2つの画面が、別の形になっていた**

#### 「直感的」の核心は、**数を札の中に出すこと**

「1週間以内」を選べるようにするだけでは足りない。
**その範囲に何問あるのかが見えないと、範囲を選べない。**

    いつのぶん
    ┏━━━━━┓┌────┐┌────┐┌─────┐┌────┐┌────┐
    ┃今日出す┃│1週間│ │2週間│ │1か月 │ │3か月│ │ぜんぶ│  …
    ┃  12  ┃│ 23 │ │ 41 │ │ 68  │ │ 81 │ │ 87 │
    ┗━━━━━┛└────┘└────┘└─────┘└────┘└────┘

    何問ずつ  [5] [10] [20] [30] [ぜんぶ]

    [ ▶ 23 問から 10 問を出す ]
    1週間以内に出会った問から出します。

- **算段は `src/lib/reviewScope.js` 1か所。** 画面(`Wordbook` / `QrReview`)は
  Supabase を引き連れていて**素の node で一度も走らせられない**ので、
  何にも依存しない形に出してある(`playMark.js` と同じ考え方)
- **見た目は `ReviewScope.jsx` 1つ。** 単語帳と Quick Response で
  **まったく同じものを使う**(ちがうのは数える単位だけ)。
  **書き写すと必ず片方だけ古くなる**
- **札は `.chip` + `.chip-count` を使い回す。** ここで新しい配色を作らない
- **0件の札は押せない**(効かない操作を見せない)。**ただし消さない** ——
  「1か月以内には無い」ことも、それ自体が知らせである
- **選んでいた札が0件になったら、押せる札へ移す**
  (`pickScene` と同じ作法。黙って空のまま置かない)
- **覚える**(`eas.review.word.*` / `eas.review.qr.*`)。
  **単語帳と Quick Response で別に覚える** —— 溜まっているものが違う

#### 「〜以内」は**出会った日**で数える(利用者が選んだ)

**単語帳・復習に入った日**(`added_at`)から数える。
「先週のレッスンで出会ったものをさらう」という使い方になる。
**いまのカレンダーの絞り込みと同じ日付**なので、考え方が2つに割れない。

- 日付は `toDateKey()` を通す(端末の日付)。`.slice(0, 10)` だと
  世界標準時になり、**夜に入れた語が前日**になる
- **出会った日が分からない古い行**(0024 を貼る前のもの)は、
  時系列の札に**入らない。** 当てずっぽうで入れない(「ぜんぶ」には入る)
- **「今日出す」は、範囲ではなく期限で選ぶ。** 間隔をあけて出す仕組み(箱)が
  このアプリの背骨なので、**そこは壊さない。** 範囲は
  「そこに足す」のではなく**「そこから広げる」**選択肢である

#### **遅く出す方へは動かさない**(`shouldRecord()` 1か所)

範囲を選べるようにすると、**まだ期限が来ていないものまで出せる。**
そこで「言える」を押すたびに箱が上がると、同じ範囲を1日に3回まわしただけで
箱が3つ上がり、**明日・明後日の復習が空になる。**

| 押したもの | 記録するか |
|---|---|
| **まだ** | **いつでも記録する**(早く出す方へ動かすだけ) |
| 言える(期限が来ている) | 記録する。ふつうどおり進む |
| 言える(**先取り**) | **記録しない** |
| 言える(この回でもう進めた) | **記録しない** |

- **これで「おさらい」の特別扱い(`extra`)が要らなくなった。**
  1周目は期限が来ているものが進み、2周目にはそれが明日以降へ移っているので、
  もう進まない。**守りはそのままで、規則が1つ減る**
- しかも**おさらいのほうが良くなった** —— 以前は期限が来ているものまで
  記録しなかったので、「おさらいで解いたぶんが1つも進まない」状態だった
- **先取りが何件あるかを、押す前に出す。** 黙って動かさないと、
  進めたつもりで進んでいない

#### 「おさらい」のボタンは、**札の「ぜんぶ」に吸収した**

あれは「期限を見ずに、溜まっているものぜんぶからランダム」で、
**`scope = 'all'` とまったく同じもの**である。ボタンを別に置くと
**同じことをするものが2つ**になる。

**機能は消えていない。** これまでは**0件になるまで見えなかった**ので、
むしろ届きやすくなった(行き止まりも作らない)。

#### **開いた瞬間に始めるのは、やめた**(方針の変更)

**2026-09 の「入口をもう1つ挟まない」を、この回で上書きした。**
あれは「集中モードというものをおかずに」という指定から来ており、
**選ぶものが1つも無かったころの決まり**である。

- **押すのは「◯語を出す」1回だけ。**「集中モードを開く」という段は
  **いまも1つも挟んでいない**(そこは変えていない)
- 覚えているので、**2回目からは選び直さずに1回押すだけ**である
- 戻すなら `Wordbook.jsx` の `running` の初めの値を `true` にする

#### 1回ぶんが終わっても、**読み直さずに次へ進める**

Quick Response は**残りを捨てない**(`pending`)。切り落とすと、
「教材の順」を選んだ人は**いつまでも先頭の10問しか出てこない。**
単語帳は読み直してから組み直す(箱が動いたぶんも映る)。

|---|---|---|
| 1280px | 1行 | 217px |
| 390 / 375 / 360px | **2行** | 259px |
| 320px | 3行 | 301px |

- **狭い画面(560px 以下)では札を詰める。** 詰める前は 390px でも
  **3行・301px** になり、そのぶん「始める」が画面の下へ押し出されていた。
  字を1段(13 → 12px)落として左右の余白を詰めると2行に収まる。
  **押せる大きさ(36px)は割らない** —— 削るのは横だけである
- **名前は切らない**(「今日出す」を「今日」にしない)
- 横のはみ出しは、どの幅にも無い

#### 検証は2つ。**役目が違う**

| 検証 | 何を見るか |
|---|---|
| `npm run test:play` | **算段**(範囲の数え方・個数・`shouldRecord` の4とおり・説明の文) |
| `npm run test:bar` | **描いて測る**(何行になるか・押せる大きさ・0件の札が押せないか) |

**ソースを読むだけでは足りない。** 8つの札が狭い画面で何行になるかは、
描かないと分からない。逆に**描くだけでも足りない** ——
`shouldRecord()` の4とおりは、画面からは1つずつ試せない。

実際に ①札の数を消す ②0件でも押せるようにする ③狭い画面の詰めをやめる
④画面から `ReviewScope` を外す、の4つで赤くなることを確かめてある。

### 設定は1か所。**スマホでは下から出るシート**(`SettingsSheet.jsx`)

2026-09 実機・利用者の指定。**前の回の吹き出しを、一段進めたもの。**

> 単語帳とQuick Response帳は以前よりは良くなりましたが選択肢が多すぎて、
> どちらかというと設定の吹き出しなどを作ってそこで設定できるとよさそうです

> 自分で単語帳に書き込みをしようとすると、戻るボタンがないのが困ります。
> また、上下の説明が不要です。これはquick response、単語帳に共通です。
> そして日付絞り込みのアイコンの位置が悪いです。
> 全体的にもっとプロっぽいデザインにできませんか？

#### まず読んで数えた。**設定が3か所に散っていた**

Quick Response(復習)を上から数えると**7つの区画**があり、
そのうち**設定が3か所**に分かれていた。

| | 何 | |
|---|---|---|
| 1 | 見出し | |
| 2 | 説明3行 | **不要**(利用者) |
| 3 | [6 今日出す][6 溜まっている] | 文言が分からない(下記) |
| 4 | 絞り込み4つ | **日付の位置が悪い**(利用者) |
| 5 | 並べ方1つ | ← **設定なのに別の場所** |
| 6 | [6問を出す][⚙出しかた] | ← **設定なのにまた別の場所** |
| 7 | 「今日出すぶんから出します。」 | **不要**(利用者) |

**「プロっぽくない」の正体は、幅のばらつきだった。**
写真から測ると(390pt 換算)、

    日付 84 / 分野 152 / 場面・話題 178 / 教材 233 / 並べ方 161px

**中身なりの幅の錠剤が、ぎざぎざに4行へ折り返していた。**

#### 直したこと

| 何 | どうしたか |
|---|---|
| 設定が3か所 | **ぜんぶ「出しかた」の中へ。** 押すものは「出す」と「出しかた」の2つだけ |
| 幅のばらつき | **名前を左の柱、欄は残りいっぱい。** どの欄も同じ幅になる |
| 日付のアイコンの位置 | **「1行のうちの1つ」に収まる**ので、置き場所という問題が消えた |
| 上下の説明 | 消した。**空のときの案内は残す**(行き止まりを作らない) |
| スマホで吹き出しが狭い | **下から出るシート**(`SettingsSheet`)。広い画面は吹き出し |

- **`SettingsSheet.jsx` は入れ物だけ。** 何を選ばせるかは知らないので、
  単語帳と Quick Response で**同じものを使い回せる**
- **判断は幅だけ**(`useWide(NAV_PUSH_AT)` = 768px)。
  UA も `pointer` も見ない —— 横向きにすれば吹き出しになるのも素直である
- **閉じ方は3つとも**(✕ / 外側 / Esc)。広い画面は `Popover` が
  外側と Esc を持っているので、**同じ判定を書き写さない**
- **うしろは `lockScroll()` で止める。** 自分で `body` を触らない
- **絞っていることは、畳んでいても分かる**(「出しかた」に札の数)。
  黙って絞ると「なぜ1件しか出ないのか」が分からない

#### **「やめる」は、入れるボタンのとなりに置く**

語句を手で入れる欄には**閉じるボタンがあった**(上の「手で入れるのをやめる」)。
ところが**入力欄まで送ると、そこは画面の外**である。
「読み上げ音声を作り直す」で**まったく同じ指摘**を受けている
(「今はないので戻れません」)。**押した場所のすぐ下に置く。**

#### 数の文言は「まだ / 覚えかけ / 覚えた」にそろえた

> 「今日出す」「溜まっている」の意味が私にも分からないので、
> そもそも文言を変えたいですね。何が良いか考えて提案してください。

**世の中のアプリを調べてから決めた。**

| アプリ | 出している数 |
|---|---|
| Anki(日本語) | 新規 / 学習中 / 復習 —— **どれも今日やる数** |
| WaniKani | Lessons / Reviews —— 同上 |
| mikan | 今日の目標 / **覚えた単語数**(= 進み具合) |
| reminDO・忘却曲線系 | 今日の復習 だけ |

**「帳面ぜんぶの数」を大きく出しているアプリは、ほとんど1つも無かった。**
出しているのは「今日やる数」か「覚えた数」(進み具合)である。

しかも**この単語帳には、すでに「まだ / 覚えかけ / 覚えた」があった。**
Quick Response だけが別の数え方をしていた。利用者がそろえることを選んだ。

- 数え方は **`qrTally()`(`reviewScope.js`)1か所。**
  **`qrReviews.js` に置かない** —— あちらは Supabase を引き連れていて
  **素の node で一度も走らせられない**(`playMark.js` と同じ考え方)
- **SQL は1行も要らない。** `qr_items` は箱(`box`)を返している。
  箱 0 = まだ / 1〜5 = 言えかけ / 6 = 言える(卒業)
- **箱の番号そのものは画面に出さない**(仕組みの内側の数字)。
  出すのは束ねた3つだけである
- **「今日いくつやるか」はここでは言わない。** すぐ下の
  「6 問を出す」が同じことを言っている(同じものを2か所に出さない)

|---|---|---|---|
| 1280px | 72px | **吹き出し** 320×453 | **218px でそろう** |

**この回で実際に踏んだ。** 幅がそろっているかを測る検証を書いたのに、
**幅をそろえるのをやめても緑のまま**だった —— 検証の選択肢が
「すべて」「混ぜる」と**短い文字ばかり**で、中身なりの幅でも
たまたま同じ 82px になっていたためである。

**利用者の画面では「すべて」と長い教材名が混ざる。** だから
`__screens.jsx` の選択肢を**わざとばらばらの長さ**にしてある
(「すべて」/「打ち合わせ前の雑談」/「2026-09-07 / 仕入れ先との交渉 / B1」)。
**「無ければ素通り」する形の検証を書かない**の、長さの版である。

③「やめる」を外す ④数え方を古い文言に戻す、の4つで
赤くなることを確かめてある。

### 段の札は、**押せば、その段だけを復習できる**(`ReviewStats.jsx`)

2026-09 利用者の指定。

> 学習者の心理としては、覚えた、を押すのは少し勇気がいるものです。
> なので、それぞれ数を示すだけではなく、
> タッチすればそれらを復習できるようにしたいです。
> そして中に入ってからも絞り込みができるように

**「覚えた」を押すのに勇気が要るのは、押したらもう出てこないと思うから**である。
いつでも呼び出して確かめられるなら、押すのは怖くない。
数だけ出して押せない札は、**そこに何があるかを見せておいて、触らせない**
という形になっていた。

#### 単語帳と Quick Response で、**段の決め方が違う。そろえない**

| | 何で分けるか | なぜ |
|---|---|---|
| 単語帳 | **`status`**(unknown / learning / known) | 表がその3つで持っている |
| Quick Response | **箱の番号**(0 / 1〜5 / 6) | あちらは卒業しても status が `learning` のまま(0038) |

**どちらかに寄せると、いま画面に出ている数が変わる。**
変えたのは「押せるかどうか」だけである。
一覧は **`WORD_GROUPS` / `QR_GROUPS`(`reviewScope.js`)**、
見た目は **`ReviewStats.jsx` 1つ**(書き写さない)。

- **単語帳の段の id は `word_reviews.status` そのもの。**
  対応表を持たないので、押したら読み込む段がそのまま決まる
  (`VIEWS` の id とも同じ)
- **押したら、範囲を「ぜんぶ」に移す。**「覚えた」語は次に出る日が先なので、
  範囲が「今日出す」のままだと**押した瞬間に0件**になる。
  押せたのに何も出ないのが、いちばん分かりにくい。外したら覚えている範囲へ戻す
- **覚えない。** 範囲と個数は覚えるが、段は「今日はこれをさらう」という
  その場の選択である。覚えていると、次に開いたとき
  **覚えた語ばかりが出てきて**、なぜそうなったのか分からない
- **0件の段は押せない。ただし消さない** —— 「まだ1つも無い」ことも知らせである
- **押した印は、色だけに頼らない**(うすい地色 + 同じ色の文字 + 枠線 + 太字
  + `aria-pressed`)。押したら**戻り方まで**1行で言う(`groupLead`)

#### 「見るものの切り替え」のプルダウンは、**この札に吸収した**

単語帳には「復習 / 覚えかけ / 覚えた」のプルダウンがあり、
**下の2つは札とまったく同じもの**だった(同じものを2か所に出さない)。
札を押すことが、そのまま切り替えになる。

- **一覧(見返す用)は消していない。** 段を押したときだけ、その段の語が下に並ぶ。
  「復習」(押していない状態)では出さない —— そこは出題の場所である
- **一覧の側の絞り込みも外した。** すぐ上の「出しかた」の中に同じものがある

#### 中に入ってからも、**同じ「出しかた」を開く**

`ReviewScope` に **`compact`** を足しただけ。
**中身は書き写さない** —— 札も絞り込みも、始める前とまったく同じものが出る。
ちがうのは「◯語を出す」のボタンを出さない点だけで、あれは**入るためのボタン**
なので、もう入っている場所には要らない。

- 置き場所は、単語帳が**進み具合の行**、Quick Response が**上の帯の右端**
- **変えたら、その場で組み直す。** 判断は **`runKeyOf()`(`reviewScope.js`)1か所** ——
  `setFilter` のすぐあとでは古い値しか読めないので、
  **値そのものを見張って、変わったら組み直す**
- **鍵を書き写さない。** 絞り込みの一覧は `FILTER_KEYS`(`WordbookFilter.jsx`)で、
  「いくつ絞っているか」も「ぜんぶ外す」もそこから作る ——
  レベルを足したときに**片方だけ数え漏らす**形になっていた

#### レベル(CEFR)でも絞り込める(0048)

> また、レベルの絞り込みも欲しいですね

**表も列も増えない。** `materials.level`(0005 で CEFR の文字列)に
もともと入っていて、**返していなかっただけ**である。
0048 で `review_words()` と `qr_items()` の返す列に1つずつ足す。

- **返す列を変える関数は、先に `drop function if exists` を置く**(CLAUDE.md)
- 並びは**やさしい順**(`cefrIndex`)、名前は `cefrLabel`。
  **対応表を `WordbookFilter` に書き写さない**
- **0048 を貼るまでは、レベルの行そのものが出ない**(`levelOf()` が null)。
  絞り込みが1つ増えないだけで、復習はこれまでどおり動く

#### 検証は2つ。**役目が違う**

| 検証 | 何を見るか |
|---|---|
| `npm run test:play` | **算段**(段の一覧・取り出し方・押したら範囲を移すか・`runKeyOf`) |
| `npm run test:bar` | **描いて測る**(札が `<button>` か・40px を割らないか・押した印・レベルの行) |

**ソースを読むだけでは足りない** —— `<span>` に戻しても**見た目は1ドットも
変わらない。** 逆に**描くだけでも足りない** —— `runKeyOf` の食い違いは
画面からは1つずつ試せない。

実際に ①札を `<span>` に戻す ②レベルの行を消す ③復習中の「出しかた」を外す
④押しても範囲を移さない、の4つで赤くなることを確かめてある。

##### 出どころは1行 ——「描くたびに控えへ写す」

| 何 | どうしたか |
|---|---|
| 進める | **`move(i)` 1か所**(`atRef.current = i; setAt(i)`) |
| 読む語 | `const i = atRef.current` を**1周のあいだ動かさない** |
| 「次へ」 | 同じ `move()` を通す。**いま鳴っているものはその場で止める** |
| 割り込み | `atRef.current !== i` なら、その語はもう読まない・進めない |

- **進めるのが先、間を置くのがあと。** 逆にすると、回数は正しくても
  **音が出た時点で画面がまだ1つ前**になる(実測して見つけた)。
  先に進めておけば、語と語のあいだの 0.9 秒で必ず追いつく

| 検証 | 何を見るか |
|---|---|
| `npm run test:play` | 比の数字(既定で 0.5 秒くらいか・**くり返しは今のままか**)・画面が `prepareRead()` を呼んでいるか |
| `npm run test:bar` | **本当に鳴らして、間そのものを測る**(同じ語と別の語で分ける) |

**回数を数えるだけでは足りない。** 上の「長さを変えたら速さが変わるか」は、
**語のあいだだけが 1 秒に戻っていても緑のまま**になる
(実際、そこが 965ms だったことに何か月も気づけなかった)。
**両方を見る** —— 「別の語」だけを見ると、
「今のままでOK」と言われた**同じ語のあいだまで縮めても**緑になる。

実際に ①`WORD_GAP_MS` を 900 に戻す ②`REPEAT_GAP_MS` まで縮める
③先読みをやめる ④画面から `prefetchClip` を直に呼ぶ、の4つで
赤くなることを確かめてある。

##### **もう一段詰めた**(500 → 250・2026-09 実機・利用者の指定)

> また、単語と Quick Response の聞き流しの間ですが、
> **違う単語同士の間をもっと詰めれませんか？もっとサクサク
> 読み上げてほしいです。**

前の回で 900 → 500 にしたが、**それでもまだ長かった。**
実測(既定 1.5 秒・端末の声の入口を差し替えて数えた)。

| | 別の語へ移るとき | 同じ語の2回のあいだ |
|---|---|---|
| はじめ | 965ms | 537ms |
| 900 → 500 | **536ms** | 536ms |
| **500 → 250** | **268ms** | **536ms**(触っていない) |

- **今度も動かしたのは `WORD_GAP_MS` の比1つだけ。**
  `REPEAT_GAP_MS` は「今のままでOKです」と言われたきり**取り消されて
  いない**(言われた場所だけを直す)
- **その結果、語と語(268ms)のほうが、同じ語の2回(536ms)より短くなった。**
  拍としては裏返っているが、**同じ語が2回続くこと自体が、いちばん強い
  区切りの手がかり**なので聞き分けは崩れない。
  気になるようなら `REPEAT_GAP_MS` を同じだけ縮める(1行)
- **単語帳と Quick Response の両方に、この1か所で効く**
  (どちらも `radioGapsOf()` を通る。`WordRadio` は部品1つ)
- **しきい値も一緒に下げる。** `test:play` は 400〜700ms、
  `test:bar` は 800ms 以下で通していたので、**下げないと 500 に戻しても
  緑のまま**になる(「無ければ素通り」する検証を書かない)。
  あわせて **`語と語 < くり返し`** も数える ——
  「縮めたのは語と語だけ」を、比そのもので見る

#### 記録は1ミリも動かさない

聞き流しは**答える練習ではない**ので、箱も次に出す日も動かさない。
「遅く出す方へは動かさない」よりさらに手前の話である。
`npm run test:play` が、`setWordStatus` / `shouldRecord` を
呼んでいないことを見張る。

#### どこで流すかは、`BGM_PLACES` 1か所

**いちばん上が「流さない」。** レッスン中は画面を共有するので、
**切る場所を必ず用意する。**

| id | どこで鳴るか |
|---|---|
| `off` | どこでも鳴らない |
| `radio` | **聞き流しのときだけ**(既定) |
| `review` | 復習中も |
| `always` | ずっと |

- **判断は `bgmPlaysIn()` 1か所** —— 画面ごとに書くと、
  切ったつもりで鳴り続ける
- **知らない id は既定に落とす**(行き止まりを作らない)
- **声が鳴っているあいだは小さくする**(`duckBgm`)。
  大きさは `bgmVolume()`(0.42 → 0.12)が決める

#### 置き場所は、メニューの「音楽」1つ。**下の帯には足さない**

トレーナーと管理者だけに出す。**`TAB_IDS` は4つのまま** ——
利用者が「教材、単語帳、Quick Response、スピーチ この四つに」と決めている。

#### 検証は2つ。**役目が違う**

| 検証 | 何を見るか |
|---|---|
| `npm run test:play` | **算段**(読み方2つ・並び・流す場所・通り道・画面が呼んでいるか) |
| `npm run test:bar` | **描いて測る**(語と訳が出るか・押せる大きさ・**送るものが無いか**) |

**1語だけに向き合う画面なので、送るものが出た瞬間に意味が消える。**
どの幅で送るようになるかは、ソースを読んでも分からない。

実際に ①3つめのモードを足す ②Web Audio を通す ③メニューから外す、の
3つで赤くなることを確かめてある。

### 英語の音声と音楽は、**それぞれ別に決める**(`mixVolume.js`・2026-09)

利用者の指定。

> アプリに好きな音楽を追加し、英語の音声と音楽を独立してそれぞれ音量を
> 調整出来るようにしたいです。英語音声が再生される時に自動で音楽の音量を
> 下げる機能は必要ありません

**曲を入れる仕組み(0049)はそのまま。** 足したのは**つまみ2本**で、
**自動で下げる仕組み(`duckBgm`)は道具ごと消した。**

#### 大きさは `src/lib/mixVolume.js` 1か所

- `voiceLevel()` / `bgmLevel()` は**覚えた値を返すだけ**なので、
  `fade()` が 10ms ごとに呼んでも安い。おかげで
  **鳴っている最中につまみを動かしても、その場で追う**(押し直させない)
- **既定は `DEFAULT_VOICE = 1` / `DEFAULT_BGM = 0.4`。**
  何も触らなければ、いままでとほぼ同じ音量で鳴る
  (0049 の `BGM_VOLUME` は 0.42 だったが、**つまみの 5% 刻みの上に置く** ——
  0.42 のままだと画面に「40%」と出ているのに中身は 42% という食い違いが残る。
  差は −0.4dB で耳では分からない)
- **Supabase も `import.meta.env` も持たない**(`playMark.js` と同じ考え方)。
  `bgm.js` も `audioClips.js` もどちらも引き連れているので、算段だけを出してある

#### **音量を変えるために、音の通り道を変えない**(この決まりを破らない)

`GainNode` に通せば iPhone でも効く。**それをやって全部の声で
バリバリ雑音が乗った**のが、2026-09 にいちばん高くついた失敗である
(`loudness.js` の③)。**ここでも同じ判断をする** ——
そろわないことより、雑音が入ることのほうが悪い。

#### だから、**効かない端末がある**(`volumeWorks()`)

**iOS は `<audio>` の `volume` を無視する。** つまり iPhone / iPad では
**2本ともまったく効かない**(自動で下げる仕組みも、もともと効いていなかった)。

- **端末の名前(UA)では決めない。** `new Audio()` に 0.5 を入れて
  読み返すだけで、その場で分かる。**鳴らさない・`src` も付けない**ので、
  iPhone の解錠には一切関わらない
- **受け付けない端末では、つまみを出さずに理由を1行で言う**
  (「効かない操作を見せない」+「黙って消さない」)
- **いつか受け付けるようになった日には、ひとりでにつまみが出る**

#### 効かせる先は3つ。**1つでも切れると、そこだけ効かない**

| どこ | 何を |
|---|---|
| 英語の音声(MP3) | `audioClips.js` が `fadeGain(base * voiceLevel(), …)` |
| 端末の声(受け皿) | `speech.js` の `utterance.volume = voiceLevel()`(**2か所とも**) |
| 音楽 | `bgm.js` が `bgmLevel()` を読み、`setBgmVolume()` で当てる |

- **`gainFor()` の側には混ぜない。** あちらは**声どうしをそろえる**ための
  もので、`npm run test:audio` が「倍率がすべて 1 以下か」を見張っている。
  **役目を混ぜない**
- **覚えるのと当てるのを、画面に2回呼ばせない。** 音楽は
  **`setBgmVolume()` 1つ**を呼ぶ(片方を呼び忘れると
  「動かしたのに音が変わらない」になる)
- **しかも音は鳴る**ので、道が切れていても気づけない
  (`elevenSettings` が届いていなかったのと、まったく同じ形の穴)

#### 置き場所は**メニューの下1か所**。音楽の画面には置かない

端末ごとに覚える「一度決める設定」で、しかも**聴く人が決める**ものである。
音楽の画面はトレーナーだけなので、そこに置くと
**ゲストが自分の耳の音量を決められない。**
**同じ設定を2か所に置かない**(CLAUDE.md)。

- 部品は **`VolumeRow.jsx` 1つ**(2本並ぶので書き写さない)。
  **自分では覚えない** —— 受け取って描くだけなので、
  `npm run test:bar` が Supabase 無しでそのまま描いて測れる
- **札(◀ 70% ▶)にしなかった。** `Stepper` は場所の無い帯のための形で、
  音量は**動かしながら耳で決める**ものである(しかもここは幅に余裕がある)
- **いまの大きさを数で出す。** つまみの位置だけでは、
  もう一方と同じ大きさなのかどうかが読み取れない
- **音楽の画面の古い説明も直した** ——
  「声が鳴っているあいだは自動で小さくします」は**もう嘘**である
  (**古い注意書きは、消し忘れると嘘になる**)

#### 検証は2つ。**役目が違う**

| 検証 | 何を見るか |
|---|---|
| `npm run test:play` | **算段**(既定・丸め・別々に覚えるか・**`duckBgm` が1つも残っていないか**・効かせる先3つ・画面が本当に呼んでいるか) |
| `npm run test:bar` | **描いて測る**(2本そろうか・数が出るか・**片方を動かして、もう片方が動かないか**・掴める高さ・はみ出し) |

**「2本ある」だけを見ない** —— 同じつまみを2つ並べただけでも、それは満たされる。
**独立していること**が、この指定そのものである。

実際に ①`duckBgm` を戻す ②英語の音声に掛けるのをやめる
③端末の声を片方だけ戻す ④鳴っている最中に追わない
⑤効かない端末でもつまみを出す ⑥部品が自分で覚える
⑦`gainFor()` に混ぜる、の7つで **test:play が7件とも別々に**赤くなり、
⑧骨組みで2本を同じ値にすると **test:bar が「音楽まで動いた」**で赤くなる
ことを確かめてある。

#### **ほかのアプリの音楽とは重ねられない**(こちらでは決められない)

利用者の問い「このアプリの音声を聞きながら自分の好きな音楽を
**他のアプリで**バックグラウンドに流すことは可能ですか？」への答え。

**ページからは決められない。** 混ぜてよいかを決めるのは OS で、
パソコンでは両方鳴るが、**iPhone ではこのアプリが鳴り出した時点で
音楽アプリのほうが止まる。** だから**アプリの中に曲を入れる道**(0049)を

### 一巡したら「おさらい」。**行き止まりを作らない**(2026-09 利用者の指定)

> 単語帳やクイックレスポンスを練習すると、一巡しただけで
> 「今日はもう出すものがありません」となってしまいます。
> 反復してランダムに出題するよう変更してください。

**今日の復習は「その日に出す語」だけ**で組む(間隔をあけて出すため)。
だから一巡すると空になり、そこで**行き止まり**になっていた。

- **おさらいは、単語帳ぜんぶから10語をランダムに出す。** 期限を見ない。
  Quick Response の復習も同じ(溜まっている文ぜんぶから)
- **入口は、断りの文のすぐ下に置く**(`.wb-again`)。
  やり切ったことは伝えたうえで、続けたい人の道をその場に出す

#### **おさらいでは、遅く出す方へ動かさない**

**ここがこの機能のかなめである。** おさらいで「覚えかけ / 言える」を
押すたびに箱が上がると、**同じ日に何度も押すだけで 30 日先へ飛ぶ。**
すると**明日の復習が空になり、反復したい人がいちばん困る形**になる。

| 押したもの | おさらいでは |
|---|---|
| **まだ** | **記録する**(箱 0・翌日へ) |
| 覚えかけ / 言える | **記録しない**(箱も次に出す日も動かさない) |

**早く出す方へは、いつ動かしてもよい。遅く出す方へは動かさない。**
思い出せなかったことは確かな手がかりなので、いつ押しても正しい。

- **間隔の決まり(`mark_word` / `mark_qr`)は1行も変えていない。**
  呼ぶか呼ばないかだけで分けている。**SQL は要らない**
- **画面にそう書く**(「『覚えかけ』を押しても、次に出す日は動きません」)。
  黙って記録しないのは、成功と失敗を同じ見た目で終わらせるのと同じである

#### **おさらいは、まるごと混ぜる**(`buildSession` の `shuffleAll`)

ふだんは**「まだ」を先に出す**(いちばん苦手な語が10語の枠から
外れないようにするため・0027)。ところが**おさらいは何度も回すもの**
なので、その並びのままだと**毎回おなじ「まだ」の語ばかり**が出て、
ほかが一度も出てこない。おさらいのときだけ、順ではなくまるごと混ぜる。

**検証は「出てきた語の種類を数える」だけでは足りない**(2026-09)。
ふだんの並びでも残りの枠は混ざるので、何回か回せば全部が顔を出す。
**実際にそれで、仕組みを外しても赤くならなかった。**
いまは**先頭が「まだ」に固定されていないか**を見る
(30語中3語なら、20回すべて先頭が「まだ」になるのは混ぜていない証拠)。
`npm run test:play` が見張っている。

### 復習のカードは、種類 → 語 → 見る・聴く → 答え の順(2026-09 利用者の指定)

> 言い回し、名詞というのは上に持ってこう。そしてもっとデザイン性を持たせて。
> そして、英語をみる、英語を聴くの２つを日本語の問題の下に。
> そして英語を見るにすると日本語と入れ替えで同じ場所に表示してください。
> その際も聴くボタンをすぐ下に。

```
言い回し ・ 名詞          ← 種類と品詞。**語の上**(眉として読める)
屋上会場・屋上で…         ← 問題。押すと英語と**入れ替わる**
────────────────
[英語を見る] [英語を聴く]  ← 答えではない操作。問題のすぐ下に2つ
[まだ]       [覚えかけ]    ← 答え(2つ)
```

- **答えは「足す」のではなく「入れ替える」**(集中モードの訳と同じ考え方)。
  下に足すとカードが伸び、**いま押そうとしているボタンがずれる**
- **入れ替えるのは4択以外の3つとも**(2026-09 利用者の指定

  > この意味を元々の日本語の下、または日本語も含めた意味に入れ替えて
  > 同じ場所に表示してください。下に出るのはみづらいです

  **目は出題(いちばん上の太字)にある。** そこから離れた場所に出しても
  見ない。**同じものは同じ動きにする**(4択だけは、選択肢そのものが

- **答えを、ボタンの下に出さない。** 残りの「うしろ側」(くわしく・文の訳)も、

  ✗ と綴りを並べただけだと**その綴りがまちがいのように読める**ので、
  4択と同じく「正解は」を添える

  **意味を見たとたんに Listen が消える。**

  **鳴っているあいだ `Stop` に変わるのは、ほかと同じ**
- 読み上げのボタンの文言は **`Listen` のまま**(どの画面でも同じ・利用者の指定)。
  鳴っているあいだ `Stop` に変わる

### 出題の形は「箱」で決める。判断は `formForBox()` 1か所

同じ語でも、覚えの深さで訊き方を変える(`src/lib/wordQuiz.js`、2026-08)。
箱(0〜6)は**その語をどれだけ覚えているか**そのものなので、これを使う。

| 箱 | 形 | 何の力がつくか |
|---|---|---|
| 0〜1 | 4択 | まず触れる回数を稼ぐ |
| 2 | 思い出す | 意味を引き出す |
| **3** | **穴埋め**(0047) | **文の中で使えるようにする** |
| 4〜5 | 日本語 → 英語 | 話すときに出てくる |
| 6 | つづりを書く | メールで書ける |

**答えを出しておいて、答えさせない。** つづりの形で英語をそのまま
見せていたので、写すだけで正解できた(2026-08)。
**出すのは意味だけ**にする。日本語 → 英語も同じ。

**4択のまちがいは、自分の単語帳のほかの語から作る。**
AI に作らせると1問ごとに課金される。自分がつまずいた語どうしなので、
適当な語を並べるより難しい。3語そろわなければ**4択を作らず「思い出す」に落とす**
(選択肢2つでは、まぐれで当たる)。

**1回は10語**(`SESSION_SIZE`)。「今日出す」が48語あると始める気にならない。

#### 穴埋めは、**出会った文をそのまま伏せる**(0047)

2026-09 利用者の指定。

> 単語のトレーニング、これだけでは全くトレーニングとして成り立って
> いません。。。２つ目のトレーニングに穴埋めがあったり、
> ３つ目が日→英になっていたり、そういう仕組みで単語が覚えられるような
> 仕組みにしたいです。

段が「見て分かる(4択)→ 意味を言う(思い出す)→ 言える(日→英)」と
飛んでいた。そのあいだに**文の中で使う**段が要る。

- **材料を新しく作らない。** 伏せるのは `word_reviews.seen_in`(0018)、
  つまり**その語に初めて出会った文**である。
  **AI を1回も呼ばない = 費用は1円もかからない。**
  例文を作らせると、覚えた文脈とは別の文になってしまう

### 単語 / フレーズは1つの種類。**共有したら単語帳に入る**(0047)

2026-09 利用者の指定。

> …これは、フレーズのトレーニングとドッキングして一緒にするのも

**単語の教材は「20問を1回解いて終わり」だった。** ところが同じアプリの
**単語帳には、間隔をあけた復習(0015〜0039)と、箱に応じた出題の形**が

#### ① 種類は `vocab` 1つにまとめる(単語10 + フレーズ10)

- **`kind === 'word'` と書かない。** 判断は **`isVocabKind()`** 1か所
  (会議で `kind === 'dialogue'` と書いて踏んだのと同じ落とし穴)

#### ② 共有したら、その語がゲストの単語帳に入る

- **`mark_word()` を20回呼ばない。** 20往復になるうえ、あちらは

  すでにあるので、全部入れると記事1本ごとに8語ずつ勝手に溜まる

#### ④ **届いたことを、ゲストの画面に出す**(利用者の指摘)

  **片方だけ変えない**
- **「この教材の語だけ練習する」を置く**(任意・利用者の指定)。

##### 絞るのは「教材の id」ではなく、**語そのもの**

**`material_id` では絞れない。** すでに単語帳にあった語は
`add_material_words()` が触らない(箱を戻さないため)ので、
**前の教材の名前を持ったまま**である。教材の語を id で絞ると、
その語だけが黙って抜け落ちる。

- 渡すのは語の一覧(`only`)。そろえ方は **`normWord` 1か所**を通す
- **絞るのは、読み込んだ直後の1か所**(`onlySet`)。
  そこで落としておけば、出題(`buildSession`)も4択のまちがいも
  札の数え上げも、**下流はいっさい触らずに**その教材の語だけになる。

  「その教材の語を練習する」になっていない

  (「この教材の語だけ 20 語」+「単語帳ぜんぶに戻す」)。

  札の中では狭い画面で折り返して読めなくなる
- **見張り(`useMemo`)には、つないだ文字列を渡す。**
  親から毎回 `[...]` が来ると配列は毎回別のものになり、
  読み直しが止まらない(`voicePool` で踏んだのと同じ落とし穴)
- `npm run test:bar` が**実際に描いて**、3語に絞れているか・
  札が出ているか・戻る道があるかを数える
  (絞りを外して、赤くなることを確かめてある)

#### **0047 を貼るまでは効かない**

- 貼るまで `vocab` で発行すると `materials_kind_check` で止まる
  (会議・スピーチのときと同じ)
- 共有そのものはできる。**語が単語帳に入らないだけ**で、
  知らせにも語数が出ない(`null` を返すので黙る)。

  あちらは `kind` を読んでいない(演習の種類ごとに呼ばれる)

- **0(空欄)は「決めていない」。** 外す道を別に作らない ——
  空にして押せば、ゲストの画面から目標そのものが消える。
  **「決めていない」と「まだ届いていない」は別物**なので、
  0 のときは**行ごと出さない**(`goalPart()` が `null` を返す)
- **責めない・煽らない。** 届いていないときに出すのは「あと ◯」だけで、
  遅れも、できていないことも数えない(「まだ」を赤くしないのと同じ)
- **達成の印は、色と言葉と形の3つで**出す(色だけに頼らない)
- **言葉と算段は `gamify.js`**(`goalPart` / `goalLine`)。
  `goals.js` は Supabase を引き連れていて**素の node で一度も
  走らせられない**ので、判断だけを何にも依存しない形へ出してある
  (`playMark.js` / `mp3Join.js` と同じ考え方)。
  `npm run test:play` が、①決めていなければ出さない ②責めない
  ③**画面が本当に使っているか** ④**ゲストの画面から決められないか**
  を見張る(実際に外して、赤くなることを確かめてある)
- **0042 を貼る前でも壊れない。** 一度断られたら覚えておき、
  そのあとは呼びに行かない(`weeklyGoalSupported()`)。
  目標が出ないだけで、単語帳も Quick Response もこれまでどおり動く
- **表を足したら、消す側にも足す。** `erase_learner()`(0041)を
  0042 で作り直し、`qr_days` と `weekly_goals` を消すようにしてある。
  **中身は 0041 をそのまま写す** —— 返す jsonb のキーは**日本語**で、
  `rls_test.sql` がその名前で数えている(英語のキーを勝手に作らない)

### 続いているのは「日」ではなく「週」で数える

日ごとの連続記録は**1日休んだ瞬間に途切れ、それがやめる理由になる。**
週2回のレッスンに合わせた宿題なので、毎日やる前提が合っていない。
`vocab_days`(1日1行)に残し、`vocab_week()`(SQL)が週で数える。
**数え方を画面に持たない。**

### 単語帳には、手でも入れられる

`WordbookAdd.jsx`(2026-09 利用者の指定「単語帳に手打ちで入力できる
機能をつけてくれ」)。教材の外で出会った語も、その場で入れられる。

- **入れ物は増やさない。** 入り口が違うだけで、入る先はこれまでと同じ
  `word_reviews`。`mark_word()` をそのまま呼ぶので **SQL は要らない**
- **意味は、入れたときに1回だけ引く**(`lookupWord`)。
  単語帳の画面は**控えを読むだけ**で AI に尋ね直さないので、
  引かずに入れると「意味の控えがありません」のまま残る。
  1語あたり約0.1円、控えはスクール全体で共有される。
  **開くたびには引かない**(発音記号・要点フレーズと同じ)
- **引けなくても語は入る。** 意味はあとで教材の中で触れたときに付く
- 空白を含めば `phrase`、含まなければ `word`。**判定は1か所**
- 入るのは **「まだ」**。**入れた語は、その日の復習に出る**(0030)。
  `mark_word()` は「まだ」を翌日に回す決まりだったので、
  **初めて入る語まで翌日**になり、入れた日には1回も出てこなかった
  (2026-09 実機「登録しても反映されません」)。
  **間隔の決まりは変えていない。** 2回目からはこれまでどおり
- **トレーナーも、ゲストの単語帳に手で入れられる**(2026-09 利用者の指定・
  **方針の変更**)。レッスンは画面を共有しながら進めるので、その場で
  出てきた語を入れられないと、紙にメモして入れ直すことになる。
  入る先は**そのゲストの記録**(`mark_word` の `p_learner`・0025)。
  担当していないゲストには SQL 側が書かせない
  (`rls_test.sql` が見張っている)。
  **どちらの単語帳に入るのかは、ボタンの文言に出す**
  (「Airi さんの単語帳に入れる」)。黙っていると自分のに入れたつもりになる
- **「覚えた / まだ」を代わりに付ける道は、いまも作っていない。**
  あれはゲスト本人の申告である。足せるのは「語そのもの」だけ

### 単語帳は `Wordbook.jsx` 1つ。**2つ持たない**

2026-09 利用者の指定。**3度言われて、ようやく1つにした。**

> ゲストモード内のものを教材モード内のものと同じにしてください。

トレーナー用に `LearnerWordbook.jsx` という**別の部品**を持っていた。

**同じ部品に「誰の単語帳か」を渡すだけ**にすれば、片方だけ古くなることが
起こりえない。**似ているものを2つ持たない。そろえるのではなく、1つにする。**

- 読み書きは `readWordbook()`(`src/lib/vocab.js`)**1か所**を通す。
  画面ごとに書き分けると、0027 の `todo` の落とし穴を片方だけ踏む
- **中身をそろえても、囲みが違えば別の画面に見える**(2026-09 実機)。

  ゲストの単語帳は地の上に直に置いていた。**外側まで数える**
- **「覚えかけ」は 0027 を貼るまで使えない**(2026-09 実機)。
  古い `mark_word()` が「状態は known か unknown です」と断り、
  画面には赤い知らせが出るだけだった。
  **一度断られたら、その画面のあいだはボタンごと出さない**
  (`learningSupported()`・`vocab.js` に1つだけ置く)。
  **勝手に「まだ」として記録しない。** 押した言葉と残る記録が
  食い違うほうが困る。知らせ方は役割で変える
  (トレーナーには貼るファイル名まで、ゲストには内側の話を出さない)
- ちがうのは**選んで教材を作れる**(`onMakeMaterial` を渡したときだけ)
  1点だけ。**復習の出題も、トレーナー側で出す。**
  記録は `learnerId` の人のものになる(0025)。レッスンは一緒に進めるので、
  そこで答えたものはゲストの学習そのものである

### 単語帳から、その語で教材を作れる ← ここが循環の要

`Wordbook`(`learnerId` を渡した側)で語を選ぶ → `MaterialForm` の
`initial.mustUse` → 窓口へは**既存の `reviewWords`** として渡す。
**新しい欄を作らない。**

- **同じ「必ず入れる語」でも、演習の種類で言い方を変える。**
  単語・フレーズは「先頭から順にこの語で作る」、文型ドリルは
  「問題文の中で使う」、記事・会話は「本文の中で使う」
- 名指しの語と、自動で拾った語(`reviewPool`)を**二重に出さない。**
  そろえた形(`normWord`)で重複を落とす
- `wordbook_views`(0019)に「見たこと」だけを残す。ゲストの画面に
  **「担当トレーナーが 8/29 にこの単語帳を見ました」**と出る。
  **人が見ていると分かることが、どんなバッジより効く**

**`shortDate()` に時刻付きの値を渡さない。** `viewed_at` をそのまま渡して
`8/NaN` と出した(2026-08)。**日付だけに切ってから渡す。**

**語の意味の先読みは、英文が出る4つの画面すべてに入れる**(2026-08 実機)。

> 単語の意味ですが、やはり初めて調べた時に3-5秒ほどかかるので
> レッスンの時間が無駄になります。

先読み(`prefetchGlosses`)は `LessonView` と `PassagePractice` にしか
入っておらず、**トレーナーの「教材の中身」とゲストの「今週の宿題」には
無かった。** 英文が出る場所は4つある(上の表)。**4つ全部に入れる。**

あわせて先読みそのものも3つ直した。

| 何 | 前 | いま |
|---|---|---|
| 先読みする語の数 | 24語 | **120語**(記事1本を通しでまかなえる) |
| 引き方 | 10語ずつ**順番に** | 10語ずつ**3本同時**(うしろの段落が間に合わない) |
| 先読み中の語に触れたとき | **もう1本呼んでいた** | 走っている問い合わせを待つ(`inFlight`) |

24語では、記事の**後ろのほうの段落がほとんど先読みできていなかった。**
費用は1語あたり約0.1円なので120語で**12円ほど、しかも一度きり**で、
控えはスクール全体で共有される(2人目からは無料)。
**レッスン中に3〜5秒待つほうが高くつく。**

**吹き出しに意味を並べない。** 読んでいる途中に出すものなので、
**いま要るのは1つ。** ほかの意味は畳んでおく(「ほかの意味(N)」)。
生成も1〜3件に絞ってある。**深く調べるのは単語帳の「くわしく」。**
場面が違う(読んでいる最中 / 机に向かっている)。

**出会った文を一緒に控える**(`word_reviews.seen_in`、0018)。
人は文脈ごと覚える。**最初の1文だけを残し、あとから上書きしない。**
上書きすると、覚えかけた手がかりが毎回入れ替わる。

**単語帳は「入った日」と「教材名」で絞れる**(0024・2026-08 利用者の指定)。

- **`updated_at` は使えない。** あれは最後に答えた日で、復習のたびに動く。
  日付で絞る役には立たないので `added_at` を足した(**あとから動かさない**)
- `material_id` の列は 0011 からあったが、**画面から渡していなかった**ので
  ずっと空だった。`markIn()`(`useWordStatuses.js`)で教材が分かる場所に
  1回だけかぶせる。**同じ包み方を6か所に書き写さない**
- 古い語の教材名は**空のまま**(利用者の判断「これからの分だけでよい」)。
  出会った文から推測すると、外れたときに**間違った教材名**が出る
- 絞り込みは**手元で行う**(`WordbookFilter.jsx`)。`review_words()` は
  200件まで返しているので、選ぶたびに聞き直さない
- **カレンダーは、語が入っている日にだけ印を付け、無い日は押せない**
- 部品は**ゲストとトレーナーの単語帳で共通。** 書き写すと片方だけ古くなる

**次に出す日を画面で計算しない。** `mark_word()`(SQL)が決める。
箱(0〜6)が上がるたびに 1 → 2 → 4 → 7 → 14 → 30 日と延び、
分からなかったら 0 まで戻す。**間隔の決まりを2か所に持たない。**
端末の日付や時差で食い違う。数字は `vocab_test.sql` で確かめてある。
**卒業までの回数(25)と、休ませる日数(30)も同じ関数の中にある**(0038)。

句・イディオム・句動詞も**同じ表に入る**。鍵は「そろえた形」なので
`look forward to` はそのまま鍵になる。`kind` で見分けるだけ。
**表も鍵も増やさない。**

要点フレーズ(`material_items.phrases`)は**教材を作る時点で拾う**。
開くたびに AI に拾わせない。費用が毎回かかり、何が出るかも分からない。
`generate-material` の `PHRASE_TYPES` にある演習だけが対象。

意味の吹き出しは `GlossPopover.jsx` 1つ。語(`EnglishText`)と
句(`PhraseChips`)の両方から使う。**同じ見た目を2か所に書き写さない。**

**吹き出しの中は、上下に送れるようにする。**
吹き出しは `position: fixed` なので**画面を送っても付いてくる。**
中身が画面より高いと、はみ出した部分に永久に手が届かなかった
(「文が1番下までくると、外の画面を送ることさえできない」2026-08)。
入る高さを毎回測って上限にし、`.etext-pop-body` の中だけを送らせる。
**「知っていた / 知らなかった」はその外に置く。** 意味がどれだけ長くても、
ボタンは必ず見えている。

**吹き出しは `createPortal` で body の直下に出す。**
紙(`.lesson-sheet`)は `overflow-y: auto` で、CSS の決まりにより
**横方向も切る。** 中に置くと端の語で切れ、紙が横にずれる(2026-08 実機)。
body の直下に出るので `.lesson-sheet .etext-pop` では色が届かない。
`.etext-pop--paper` を付けて当てる。「外側を押したら閉じる」も、
**吹き出しの中は外側ではない**と判定する。

**語をなぞると、まとめて1つの言い回しとして引ける**(`data-widx` +
`elementFromPoint`)。ブラウザの範囲選択は使わない。語には
`user-select: none` が要る(iPhone の長押しメニューを止めるため)。

**2語以上のまとまりは、囲みを1つにする**(`.etext-run`)。
語ごとに色を付けると語間で線が切れ、空白に色を足しても
`<button>` と `<span>` で下端が 7px ずれて継ぎ目が残った(実測)。
色は **1語 = 赤 / 2語以上 = 紫**(2026-08 利用者の指定)。

**吹き出しの中の色は `--pop-bg` / `--pop-fg` / `--pop-dim` / `--pop-faint` /
`--pop-rule` の5つだけで決める。** 紙の上ではこの5つを差し替える。
個別に上書きして回ると必ず取りこぼす(「ボタンだけ黒い」「1つめの意味が
白いまま」を実際に出した)。

**まとまりは、見た目も操作もまとまりとして扱う。** 塊の中のどの語を
押しても塊の意味を引き、カーソルも塊ごと反応する。1語も長さ1の
まとまりとして描く(語に直接色を付けると帯の高さが揃わない)。
**同じ見た目を紙用に別に書かない。** 色は変数で持ち、紙が差し替える。
別に書いたせいで、あとに置いた紙用の指定が勝ち、まとまりの中で
1語だけ反応する不具合になった(2026-08)。

**新しい列を「取り出す欄」に足すと、貼る前は教材が1件も開けなくなる。**
`materials.voice_ids` と `material_items.phrases` を足して、実際に
「教材が見れなくなった」を起こした(2026-08 実機)。PostgREST は
知らない列が1つでもあると**問い合わせ全体を断る**(42703)。
`src/lib/materials.js` の `runTolerant()` が、断られた列だけを外して
読み直す。**足りない列は2つ以上あることがあるので、繰り返す。**
挿入するときも、無いと分かっている列は送らない(送ると挿入ごと失敗する)。

**DB の関数を使うように変えるときは、貼る前でも動く道を残す。**
`setWordStatus()` を `mark_word()` に切り替えたとき、SQL を貼るまで
「押しても色が付かない」状態になった(2026-08 実機)。
関数が無いという断りのときだけ、前の書き方に戻している。
詳しくは仕様書 第5.23節。

### 育った語の例文を、**自動で** Quick Response 帳へ送る(2026-09 利用者の指定)

単語帳と Quick Response は、それまで**つながっていなかった。**
語を覚えても、その語を使った**文をまるごと言う**練習には回らない。

    ① 語を知る          4択・思い出す
    ② 語を文の中で使う   穴埋め(出会った文の、その語を伏せる)
    ③ 語を言える         日本語 → 英語
    ④ 文をまるごと言える  Quick Response      ← ここが切れていた

**材料はもうそろっていた。** 単語帳の行は `seen_in` / `seen_in_ja`
(出会った文とその訳・0018)を持ち、棚の語も `example_en` / `example_ja` が
同じ欄に入っている(`shelfReviews.js`)。
**表も列も SQL も増えない。AI も1回も呼ばない = 0円。**

#### **「箱4」は誤りだった。目印は `learn_streak`**

はじめ「箱4に上がったら送る」と書いたが、**そこへは行けない。**
`review_next()`(0058)は「覚えかけ」の箱を **3 で止める**ので、
箱4以上へ行くのは「覚えた」を押した語だけである。
ほとんどの語は箱3で足踏みし、**一生届かない。**

正しい目印は **`learn_streak`(続けて思い出せた回数)**のほうである。

- **数は `KNOWN_AFTER`(10)。** これはもともと
  **一覧に「覚えた」を出してよいか**を決めている数でもある(`canMarkKnown`)。
  **判断が同じ**(この語はもう身に付いたと言ってよいか)なので、
  **数を2か所に書かない**
- 数の持ち主は **`qrPromote.js`**。`vocab.js` は読み直しているだけである。
  出した理由は**素の node で走らせられるから**で、
  `textNorm.js` へ `normWord` を出したときとまったく同じ作法
- **早すぎると破綻する。** 棚を開いた瞬間に 200 文が入ると、
  Quick Response 帳が一巡できない。
  **遅すぎても届かない。** 卒業(25回)を待つと3か月かかる

#### **`mark_qr()` を通さない。表へ直に入れる**

はじめ `markQr()` を呼んでいた。**2つ、まずいことが起きる。**

| | 何が起きるか |
|---|---|
| ① | **その日の取り組みの数が水増しされる。** `mark_qr()` は「まだ」で呼ぶと `qr_days.answered` を1つ増やす(0042)。ゲストは1問も答えていないのに、**送ったぶんだけ「答えた」ことになる。** 正答率は下がり、続けた記録は膨らむ ——**記録を黙って汚す** |
| ② | **すでに溜まっている文の進み具合が 0 に戻る。** `mark_qr('unknown')` は箱も回数も 0 にする |

どちらも**新しく入れるときには要らない処理**である。
`qr_reviews` は `(learner_id, en_norm)` が一意で、
`status` / `box` / `learn_streak` / `due_on` の既定値が
**ちょうど「まだ・箱0・今日出す」**(0040)なので、
**入れるだけで `mark_qr` と同じ形の行になる。**

- `ignoreDuplicates` を付ければ、**すでに在る行には1文字も触らない**
- `.select('en_norm')` が**実際に入ったぶんだけ**返すので、
  「何文足したか」を数え直さずに済む(**数え方を2通り持たない**)
- **既定値を書き写さない。** 書き写すと 0040 を変えた日に片方だけ古くなる
- 表へ直に書けるのは**自分の行だから**である(`qr_reviews_own_write` / 0040)。
  **RLS は1行も緩めていない**

#### 送らないもの ——**既定は「送らない」側**

- まだ育っていない語(`learn_streak` が 10 に届いていない)
- **出会った文が無い / その訳が無い**語(手で入れた語・基礎単語)。
  **ここで AI に例文を作らせない = 0円**
- 3語に満たない文(Quick Response は文をまるごと言う練習である)
- 出会った文が、その語そのもの(伏せる場所が無く、問にならない)
- **1回に 10 文まで**(棚を入れ直した日に溢れない・止まる条件)
- **ゲスト本人の単語帳のときだけ。** トレーナーが開いたときに送ると、
  **見ただけでゲストの復習が増える**

#### 「もう出さない」で退けた文を、掘り返さない

`dropQr` は行を**消す**ので、データベースでは止められない。
**送った文を端末に控えておく**(`localStorage` の `qrPromoted`)。

- 端末をまたがないので、**別の端末では一度だけ掘り返ることがある。**
  そのときは「もう出さない」をもう一度押せば済む。
  表に持つと列が増えるので、いまはそこまでしない
- 入らなかったぶん(すでに在った文)も控える。
  次に開いたときに、もう一度うかがう必要がない

#### **黙って足さない。画面に1行出す**

言わないと、Quick Response 帳を開いたゲストが
**「覚えのない文が増えている」**と思う。
何文を・なぜ足したのかを、単語帳のその場で言う。

- **送る文が無い日は、この行ごと出ない**(効かない知らせを出さない)
- **色だけに頼らない**(うすい地色 + 同じ色の文字 + 枠線 + 太字)

#### 赤チェックで転んだところ ——**壊し方が違うと、緑のまま**

「`mark_qr()` を通していない」の見張りを試すのに、
`promoteGrownWords` の中の `const { data, error } = await supabase` を
置き換えようとしたが、**その文字列は `markQr()` の本体にも在った**
(`await supabase.rpc('mark_qr', …`)。
先に出てくるほうに当たり、**`markQr` を壊して `promoteGrownWords` は
無傷**だったので、緑のままになった。

**赤くならないのは、壊し方が違うという知らせ**である
(`docs/notes/20-ファイルに持った教材.md` と同じ落とし穴)。
**関数の始まりから探し直す**と、狙いどおり4件が赤くなった。

#### 見張りは、**並びではなく「入っているか」で見る**

`npm run test:play` の「冊が変わったら読み直す」は
`tier, colBook])` と**末尾の並びそのもの**を探していたので、
見張り(`useCallback` の見張り)に1つ足しただけで赤くなった。
**壊れていないものが赤くなると、本当に壊れているものを見落とす。**
`}, [… colBook …])` の形で見るように直した。

### 開いたらすぐ始まる。**トップ画面をなくした**(第5.167節・2026-09)

> quick response と単語帳は、トップ画面をなくしませんか?
> サイドバーや下のタブからクリックしたらすぐに実際のトレーニングの画面に飛び、
> その画面にメニューを足す。

**始めるまで2タップ**だった(サイドバー →「10 語を出す」)。
その1枚目にあった押せるものは **15 個**で、高さは **359px**(390px 実測)。
**設定に用があるのは最初の1回**なのに、毎日いちばん上に居座っていた。

#### 4つの仕事を、行き先ごとに散らした

| 仕事 | これから |
|---|---|
| 冊をえらぶ | **帯の左(`冊名 ▾`)** → 縦1列の本棚 |
| 進み具合(まだ / 練習中 / できた) | **達成具合の専用ページ** |
| 出題の設定(何語・出しかた・絞り込み) | **帯の右(`出しかた`)** |
| ほかの道具(聞き流す・紙に出す) | 同上。**`ReviewScope` の `tools`** |

#### **一度しか走らせない印**が要る(`started`)

「開いた瞬間に始める」をそのまま書くと、
**「とじる」で一覧へ戻った人を、その場で押し戻す。**
行き止まりの反対で、**出口が無くなる。**

`start()` が立てる `started` を見て、**立っていなければ始める**。
冊・段・分野・Unit・中身・型を変えたときは `dropRun()` が倒すので、
**新しい冊の1問目がそのまま出る。**
**1語も無ければ入らない** —— 空の画面(いまの一覧)をそのまま使う。

#### 横に並べる札は、**もう折り返していた**

| | 実測(390px) |
|---|---|
| 単語帳の冊 | **6つ**。札の行は **2行**・高さ **78px** |
| Quick Response の冊 | **3つ**。それでも **2行**(「自分の Quick Response 帳」が長い) |

しかも「3つ + 3つ」のギザギザで**左端がそろわない。**
**1冊1行**にすれば、冊が 6 でも 20 でも**見た目が変わらない。**

- 入れ物は **`SettingsSheet`**(「出しかた」で使っているもの)。
  スマホでは下から、広い画面では吹き出し。**新しい入れ物を作らない**
- **冊の中の区切り(棚・段・Unit・中身・型)は、その冊の行の中**(`sub`)。
  「どの帳面の、どこ」が**1か所で決まる**
- **件数は出していない。** 冊によって数の出どころが違い、
  全部を数えると**読み込みが冊の数だけ増える。**
  `BookShelf` は数が無ければ**その行に数を出さない** ——
  **`0 語` と嘘をつかない**

#### 赤チェックで見つけた「**1つでもあれば緑**」

- 単語帳のとじる口は**2つ**(復習の帯と、終わりの1枚)
- 達成具合の画面も**2つ**(Supabase が設定されているときと、されていないとき)

どちらも `.test()` で「1つでもあるか」を見ていたので、
**片方を消しても緑のまま**だった。**数えるように直した。**

#### 達成具合は、**段ごと読む**

復習の画面は `status: 'todo'`(まだ + 練習中)しか読んでいない。
そのまま真似ると、**「できた」がいつでも 0** になる ——
**0 と「読んでいない」を取り違えない**(CLAUDE.md)。
眺めるページなので、1回だけ多く読んでよい(`status: null`)。

#### 描いて初めて出てきた2つ(達成具合)

**ソースを読むだけでは出てこなかった。** 実際に描かせて気づいた。

- **`tip` が付いていた。** あれは「一度読めば足りる説明」を畳む印
  (第5.166節)であって、**数に付けるものではない。**
  じっくり見るためのページなのに、いちばん見たい「◯週つづけて」が
  **既定で畳まれていた**
- **0040 を貼っていない Supabase では、`loadQrReviews()` が黙って
  空の一覧を返す**(画面を落とさないため)。そのまま数えると
  「まだ 0 / 練習中 0 / できた 0」と出て、**やり切ったように見える。**
  `qrReviewSupported()` を見て、**数えずに「入れ物がまだ無い」と言う**

#### 検証の環境を、自分で汚した

`.env` を一時的に作って達成具合の画面を描いたところ、

#### 見張りが1つ捕まえた ——**消した指定を、引き継ぎ忘れた**

`.wb-books`(横に並べる札)は `margin-bottom` を持っていた。
その札をやめて `.bookpick`(冊名 ▾)にしたとき、**そこを引き継がなかった。**
帯の中では `.focus-top-main` / `.wb-run-head` の `gap` が離してくれるので、
**紙の上に直に置いたときだけ** 0px になる ——
つまり**画面を開いても、帯だけを見ていたら気づかない。**

`npm run test:bar` のすき間の見張りが、390px と 1280px の両方で捕まえた。

    mybook@390px   縦 0px  button.btn.btn--small.bookpick / button.wb-stat
    mybook@1280px  縦 0px  button.btn.btn--small.bookpick / button.wb-stat

直し方は `.card > .bookpick { margin-bottom }`。
**「次に何が来るか」で決めない**(`.a + .b { margin-top }` は、
下に来るものが変わった日にどこにも当たらなくなる・`.claude/rules/common.md`)。
