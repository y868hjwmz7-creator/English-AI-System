### 読み込み中の画面は1つ。**起動画面は `index.html` に置く**

2026-09 利用者の指定。

> アプリのロード中の画面を統一してスタイリッシュに映るようにせよ。
> どんな方法がある？
> 今は田中みなみの画面が一瞬映ったりして微妙だ

#### まず測った。**推測でいじらない**

Chromium で 1.5Mbps・390px にして、起動のあいだ画面に何が出ているかを
50ms ごとに撮った。

| | 何が出ていたか |
|---|---|
| 0 〜 2.0 秒 | **素の白**(CSS すら届いていない) |
| 2.0 〜 6.7 秒 | **地色だけ**の画面 |
| 6.7 秒 | ログインの画面 |

**「読み込み中…」は一度も出ていなかった。** あれは JavaScript が
動き出したあとの文字なので、**いちばん待つあいだには存在しない。**

あわせて、アプリの中の「読み込み中…」を数えると **18 か所・4とおりの
言葉・4とおりの見た目**(`.loading` / `.muted` / `.hint` / 素の `<p>`)で、
**同じ文字が2つの大きさで出ていた。**

#### 起動画面は `index.html` の `#root` の中に、はじめから描いておく

**`<style>` ごと HTML に書く。** そうすれば画像も外部のファイルも待たず、
**0.22 秒で**出る(実測)。React が描き始めると中身が入れ替わる。

- **`Loading.jsx` と、名前も形も文言もそろえる**(`.loading` /
  `.loading-name` / `.loading-bar` / `.loading-note`)。
  **入れ替わった瞬間に画面が1ドットも動かない。**
  **片方を直したら、必ずもう片方も直す**(`theme-color` と同じ決まり)
- **配色の印を、描く前に付ける。** `theme.js` が `data-theme` を付けるのは
  JavaScript が届いたあとなので、これが無いと
  **「明るい」を選んでいる人の端末が暗い設定のとき、一瞬だけ暗い画面**が出る。
  鍵の名前(`english-ai-theme`)は `theme.js` と同じにする
- **動きは `prefers-reduced-motion` で止める。** 止めたときも帯は残す ——
  何かを待っていることは伝わってほしい
- **画面まるごとを待つときは、6つとも `Loading` を使う**
  (`App` / 教材 / ゲスト / 今週の宿題 / 単語帳 / Quick Response)。
  **中身の一部を待つだけの1行(`detailBusy` など)はそのまま** ——
  あれは画面ではない

#### **役割が分かるまで、中身を描かない**(`booting`)

**「一瞬だけ別の画面が映る」の正体はこれである。**

`pages`(左のメニューの一覧)は**役割で中身が変わる。**
プロフィールを読み終えるまで `isTrainer` は偽なので、そのあいだの
`pages` は**ゲストの一覧**(今週の宿題 / 30日講座 / 単語帳 …)になる。
すると「**メニューに無い画面なら先頭へ移す**」見張りが働いて、
**トレーナーで入っても、いったんゲストの画面が出ていた。**
そのあとプロフィールが届いて「教材」へ跳ぶ。

- レッスンは**ゲストと画面を共有しながら**行う。
  見せる気のない画面が一瞬でも出るのは、見た目の問題では済まない
- 判断は **`booting`(`App.jsx`)1か所。**
  `isSupabaseConfigured && !!session && !profileRead`
- **`profileRead` は、引けなかったときにも立てる。**
  立てないでいると、**起動画面から二度と出られない**(行き止まりを作らない)
- **「メニューに無い画面なら先頭へ移す」も、そのあいだは動かさない**

`npm run test:play` が、①起動画面が `index.html` に在るか
②`Loading.jsx` と同じ形か ③配色の印を先に付けているか
④`booting` の3か所 ⑤引けなくても抜け出せるか
⑥6つとも `Loading` を使っているか、を見張る
(実際に4つ壊して、それぞれ赤くなることを確かめてある)。

### 読み込みが終わったら、まず**行き先を並べる**(`AppHome.jsx`)

2026-09 利用者の指定。

> ロードの後いきなり教材が映るのではなく、何か箱を並べて、
> 選択したモードに飛ぶ仕様にしたいです

これまでは、起動画面が消えた瞬間に**いちばん上の画面**
(トレーナーなら「教材」、ゲストなら「今週の宿題」)が出ていた。
ほかにどこへ行けるのかは、**☰ を押すまで分からない。**
下の帯(`AppTabs`)を作ったときとまったく同じ形の不便である
——「入口が1つしか無く、しかも隠れている」。

#### 並べるのは `pages` そのまま。**行き先の一覧を2つ持たない**

名前も絵も、**一覧は `App.jsx` の `pages` 1か所**である
(メニューも上の帯もそこを見ている)。`AppHome` は受け取って箱にするだけで、
**自分では行き先を1つも持たない。**

- **画面を足せば、ホームにも自動で並ぶ**(書き足しに行かなくてよい)
- **役割で並ぶものが変わるのも、そのまま効く** ——
  ゲストに「教材」の箱は出ない(`pages` に入っていない)
- **1行の説明(`desc`)も `pages` が持つ。**
  **呼び名と説明を2か所に分けない** —— 分けると、名前を変えたときに
  説明だけが古いまま残る

#### ホームそのものは、箱にしない

押しても同じ場所に留まるだけである(**効かない操作を見せない**)。
判断は **`HOME_ID`(`AppHome.jsx`)1か所** ——
`App.jsx` は ①`pages` に1行足す ②箱から外す の2か所でこの id を使うので、
**文字列で書くと必ず片方が残る。**

#### 戻る道は ☰。**下の帯には足さない**

`pages` の**いちばん上**にホームを置いてあるので、
左のメニューからいつでも戻れる。

- **`TAB_IDS`(下の帯)は4つのまま。** あちらは利用者が
  「教材、単語帳、Quick Response、スピーチ この四つに」と決めている。
  ホームは「ゲスト」「集計」と同じく **☰ からだけ**行く
- 「メニューに無い画面なら先頭へ移す」の行き先(`ids[0]`)にもなる。
  **どの役割にも必ず在る場所**なので、ここが受け皿として素直である

#### **リンクで来た人だけは、その教材へ**(`?m=…`)

教材のリンクは「この教材を見てください」と名指しで渡されたものである。
ホームに落とすと**渡した教材に着かない。**

- そのために **`askOpenId` を `view` より前に置いた。**
  `useState` の初めの値がこれを見る
- ゲストには「教材」の画面が無いので、そこはホームのまま
  (どのみち見張りが追い出す)

#### アプリの名前は、**柱が出ていないときだけ出す**

箱の上に「English AI System」を小さく置いてある。ただし
**左のメニューが柱として見えている幅では出さない** ——
その頭にまったく同じ名前があり、**同じものが2か所**になる。

- **幅の数字を CSS に書かない。** 柱が出ているかどうかは `App.jsx` が
  `.app-shell.is-wide` / `.is-narrow` で言っているので、
  **その判断にそのまま乗る**(境目を2か所に持たない)
- 字づかいは **`.loading-name` と分け合っている**(`styles.css` の
  選択子を並べる)。**値を書き写さない。** 狭い画面では、
  読み込みが終わってもその字はそこに残り、下に箱が並ぶ

#### 名前も役割も、ここには出さない

誰でログインしているかは、左のメニューの下と、ゲストの箱が言う。
ここへ書き写すと**同じものが2か所**に出る。
この画面の役目は「どこへ行くか」だけにしてある。

#### 狭い画面では**必ず2列**

1列にすると、8つの行き先で画面3枚ぶんになり、
**「並べて選ぶ」という、この画面の役目そのものが無くなる。**

実測(箱の大きさ・横のはみ出しはどの幅にも無い)。

| 幅 | 列 | 箱 |
|---|---|---|
| 1280px | 4 | 241 × 122px |

- **名前は切らない**(「Quick…」では何のボタンか分からない)。
  入らないぶんは折り返す —— 下の行き先の帯と同じ決まり
- **触る端末には「カーソルを載せる」が無い**(CLAUDE.md)。
  押せることが押す前から分かるよう、名前の右に山形(`ChevronIcon`)を置く

### 「貼ったかどうか、覚えていない」を、覚えなくて済むようにする(`SetupStatus`)

2026-09 実機・利用者の問い。

> 前回お願いした2つが、まだでしたら先に。
> ①supabase/apply/pending_matome.sql を貼る ②generate-material を置き直す。
> これをやったかどうか覚えていません。**この現象がなん度も起きています。
> あなたで把握できる方法はないのですか？**

#### まず、正直に線を引く

**こちらからは確かめられない。** この環境から Supabase には届かないので、
リポジトリを何度読んでも分かるのは「**何が要るか**」だけである。
「**何が済んだか**」は Supabase の中にしか無い。

**けれどもアプリからは確かめられる。** 利用者はいつもアプリを開いている。
だから**覚えておくのをやめて、開くたびにアプリに訊かせ、アプリに言わせる。**

#### なぜ、これまで気づけなかったか

知らせる仕組みは**2つとも前からあった。** 足りなかったのは
**「その操作をしなくても分かる」**ことである。

| 何 | いつ出ていたか |
|---|---|
| 表が足りない | その表を使う画面を開いたとき(`speechesSupported()` など) |
| 窓口の版 | **教材を作りに行ったとき**(`noteGenRev`) |

つまり**確かめるには、その操作をするしかなかった。**
しかも教材づくりは**そのまま課金**である。
`speak` には `checkClipGateway()`(ただの `ping`)を足してあったのに、
**`generate-material` には無かった。同じ抜けを二度している。**

#### どちらも 0 円で訊く

| 何 | どう訊くか |
|---|---|
| ① 貼る SQL | **いちばん新しい移行の印**が在るかを読むだけ |
| ② 窓口の版 | `checkGenGateway()`(**読めない中身を送って断らせる**) |

**教材は1本も作らない。音声も1本も作らない。**

##### ②は、窓口に `ping` を足さない

足せば `FN_REV` が進み、**置き直しが要る。**
「置き直したか分からない」を確かめる道が、置き直しを前提にしてしまう。

代わりに、**JSON として読めない中身をわざと送る。** 窓口は

    try { body = await req.json() } catch { return reply({ … }, 400) }

で断る。ここは **Claude を1度も呼ばないいちばん手前**であり、
しかも `reply()` は**どの応答にも版を付ける**ので、断りの中に版が入って返る。
**いま置かれているのがどの版でも効く** —— 版を付ける前のものなら
版が付いてこないので「古い」と読まれる。**それが正しい答えである。**

- **窓口の側で、この早い断りを消さない・順を下げない。**
  Claude を呼んだあとに回すと、**版を訊くだけの問い合わせが課金になる**
- **届かなかったときは「古い」と言わない**(`FunctionsFetchError`)。
  置いてすらいないものに「置き直してください」と言うことになる。
  接続そのものの知らせは `SupabaseStatus` が出す

##### ①の印は「いちばん新しい移行」1つだけ

**`check.sql` の 36 行を、ここに書き写さない。** 写せばこちらも同じように
古びる(CLAUDE.md「移行を足したのに `check.sql` に足し忘れる」)。

`pending_matome.sql` は 0041 以降を**順に**並べたもので、しかも
**Supabase の SQL Editor は失敗した貼り付けをまるごと巻き戻す。**
だから**いちばん新しい移行の印が在れば、その手前も全部入っている。**

- **移行を足したら `NEWEST_MIGRATION` も直す**(`src/lib/setupState.js`)。
  `npm run test:play` が `supabase/migrations/` のいちばん新しいファイルと
  突き合わせており、**直すまで赤いまま**である
  (声の名簿の `KNOWN`・`test:bar` の `WANT` と同じ考え方)
- 印は**表が在るかどうかだけ**を見る。RLS に断られても 0 件で返るので、
  判定は狂わない
- **「そんな表は無い」だけを「まだです」と読む**(42P01 / PGRST205 /
  schema cache)。通信の失敗は `unknown` にして**騒がない**

#### 済んでいれば、1ドットも出さない

`SupabaseStatus` とまったく同じ作法である
(「画面のいちばん上に、読まないものを置かない」)。

- **出るのはトレーナーと管理者だけ**(`canSeeSystemDetail()`・既定は見せない)。
  「SQL を貼ってください」はゲストにできることが何も無い
- **閉じるボタンを置かない。** 済ませれば消えるものを押して消せるようにすると、
  それが**忘れる道**になる —— いま直そうとしているのは、まさにそれである
- **済ませたあと「確かめ直す」を置く**(行き止まりを作らない)。
  押し直しても何も起きないのでは、もう一度読み込むしかなくなる
- **どの行にも「どこで・何を」と、押せる URL まで書く**(共通ルール)。
  `raw.githubusercontent` は**非公開のリポジトリでは開けない**ので使わない

#### 検証は `npm run test:play`。**赤チェックは1つずつ**

①印を古いままにする ②窓口の早い断りを消す ③画面から外す
④版を訊きに行かない ⑤済んでいても出す —— の5つで、
**それぞれ1件だけ**が赤くなることを確かめてある。

**「名前が出てくるか」で見ない**(この回でも踏んだ)。
`// await checkGenGateway(force)` と**打ち消しても文字は残る**ので、
最初の書き方では素通りした。いまは**行の頭から**見る。

**画面に出る文に `**` を混ぜない**(CLAUDE.md)。
`<div>` にそのまま出るので Markdown としては読まれず、
**画面にそのまま見える。** これも描いて実測して気づいた
(場面の説明で一度踏んだのと同じ)。

#### 赤チェックで `git checkout` を使わない(この回で踏んだ)

**まだコミットしていない新しいファイルは、`git checkout` で戻せない。**
それどころか、**同じ回に加えた別のファイルの変更を消してしまう** ——
実際 `git checkout src/App.jsx` で、この回に足した2行を丸ごと失った。
**壊す前に、いじるファイルを別の場所へ写しておく。**

### 入り口の `index.html` は、古いものを使い回させない

中身(JS・CSS)はファイル名に印が付くので、新しくなれば必ず読み直される。
**`index.html` だけは名前が変わらない**ので、端末に残った古いものが
そのまま使われる。実際、スマホに古い版が残っていて、
**新しく足した「接続を確かめる」ボタンが出ていなかった**(2026-08 実機)。

`<meta http-equiv="Cache-Control" content="no-cache, must-revalidate">` を
置いてある。**それでも残ることがある**ので、URL のうしろに印を足す
(別の URL になるので、端末の控えを必ず素通りする)。

#### 確認を頼むときは、**押せる URL を毎回こちらで作る**

2026-09 利用者の指定。

> それをつけた url を毎回生成してください。

**「`?v=8` を付けてください」と書かない。** 付けるのは利用者の手間だし、
付け忘れれば古い版を見ることになる。**完成した URL をそのまま出す。**

    https://y868hjwmz7-creator.github.io/English-AI-System/?v=<コミット番号>

- **印は、そのビルドのコミット番号(短い方・7文字)にする。**
  番号を数えて付けると**付け間違える**うえ、
  **どの版を見ているかが URL から分からない**
- コミット番号なら、**必ず毎回ちがう値になり**、しかも
  「直したはずが直っていない」ときに、**古い版を見ているのか
  本当に直っていないのか**を切り分けられる
- 出すのは**ビルド(GitHub Actions)が終わってから。**
  終わる前に渡すと、押した人は前の版を見る

##### ビルドが終わった印は、**画面に出ている「版」**である

2026-09 実機・利用者の問い。

> ビルドが終わった際の印はあるのですか？

**ある。ただしこちらが1行で伝えていなかった。**

    版: 2026-09-11 15:57 UTC / 6acd5ad

- 出どころは `.github/workflows/deploy-pages.yml` の **`VITE_BUILD_STAMP`**
  (`<日時> UTC / <コミット番号の短い方>`)。**ビルドのときに焼き込まれる**ので、
  **この文字が変わっていれば、新しいビルドが届いている**
- 出る場所は2つ ——**画面のいちばん下(フッター)**と、
  **ログイン画面**(ログインできない人も版を確かめられるように)
- **渡した URL のうしろの番号と、画面の下の番号を見比べてもらう。**
  同じなら新しい版、違えば古い版が端末に残っている
- 「まだ直っていない」と言われたら、**まずここを訊く**
  (CLAUDE.md「古い版を見ているのか、本当に直っていないのか」)

### 通信には、必ず「待ち時間の上限」を置く

**`fetch` は待ち時間の上限を持たない。** Supabase まで届かない状況
(電波が切れかけている・会社のネットワークが塞いでいる)では、
**エラーにならず、ただ返ってこない。**

実際、スマホから「押しても何も起きない・止まる」という報告が出た(2026-08)。
`signIn()` に `try` も上限も無かったので、ボタンが
**「ログインしています…」のまま戻らず、知らせも出なかった。**
**成功と失敗が、同じ見た目で終わってはいけない**のと同じ話である。

- 上限は **`supabase.js` の `withTimeout()` 1か所**に置く(15秒)。
  画面ごとに書くと必ずどこかが抜ける
- **例外を外に出さない。** 投げると呼んだ側の `await` がそこで止まる
- **通信が届いていない失敗は、例外ではなく `error` で返ってくる。**
  Chrome は `Failed to fetch`、**Safari は `Load failed`** と言う。
  見分けないと「つながりましたが断られました」と出て、
  **電波の話なのに設定の話だと思わせる**
- **経過秒数を出す。** 「ログインしています…」だけでは、動いているのか
  固まったのか分からない。5秒を過ぎたら「まだ返事がありません」も出す
- ログイン画面には**「接続を確かめる」**と**版**を出す。
  ログインできない人は、通信が届いていないのか ID が違うのかを
  切り分けられず、**どの版を見ているかも確かめられない**
  (版はこれまでフッター=ログインしたあとにしか無かった)

### 外部の窓口を自動で呼ぶものには、「止まる条件」を持たせる

教材を開いた時点で語の意味を先読みしている(`prefetchGlosses`)。
**Anthropic の残高が切れたとき**、開くたびに10語ずつ呼びに行き、
直らないことのために待たされ続けた(2026-08 実機)。

窓口の応答に `fatal` を付け、残高切れ・鍵ちがいのときは
**その画面のあいだ先読みをやめる。** 触れたときの1語引きは止めない。

断りの英語(`{"type":"error",...}`)をそのまま画面に出さない。
`humanApiError()` で日本語にし、**どこへ行って何をすればよいかまで書く。**

### ゲストには、仕組みの内側を見せない

「Claude の残高が足りません」「鍵が違います」は**ゲストに出さない。**
ゲストにできることは何も無く、スクールの内側の話でしかない。
窓口は `error`(誰に見せてもよい文)と `detail`(原因と直し方)の
**両方**を返し、どちらを出すかは画面側(`src/lib/viewer.js`)が決める。
**役割の判定を窓口と画面の2か所に置かない。** 必ず食い違う。
既定は「見せない」。役割が分からないうちは内側の話を出さない。

### 関数ごとに使うモデルが違う。取り違えない

| 関数 | モデル | なぜ |
|---|---|---|
| `generate-material` | `claude-sonnet-5` | 教材の質が要る |
| `lookup-word` | `claude-sonnet-5` | 質を優先。**遅さの原因は別にあった**(下記) |
| `speak` | Azure Speech(Claude ではない) | 音声合成。無料枠は毎月50万文字 |

`lookup-word` を一度 `claude-haiku-4-5` にしたが、
**利用者の実測で「質には満足だが、速くはなっていない」**(2026-08)。
遅さの正体はモデルではなく**関数の立ち上がり**(SDK の読み込み)だったため、
`claude-sonnet-5` に戻し、代わりに SDK を外して `fetch` で直接呼ぶようにした。
**モデルを速さの調整つまみとして使わない。**

**Haiku 4.5 は `output_config.effort` に対応していない。** 付けると失敗する。
指示のキャッシュも4,096トークン以上でないと載らない(黙って載らないだけ)。
`lookup-word` のモデルを変えるときは、`effort` の指定も一緒に見直すこと。

### Supabase の関数は CPU 2秒で止まる

150秒とは別に、**1回の呼び出しで使える CPU 時間が2秒**しかない。
英文を数値に変換する処理(`gte-small`)は CPU を使うため、まとめて行うと
`CPU Time exceeded` で関数ごと落ちる。**落ちると応答に CORS の印が付かず、
画面には「窓口につながりません」としか出ない**ため、未配置と区別がつかない
(2026-08 実機のログで確定)。

`check-similar` では、1回に変換するのを
**候補12件 + 追いつき5件まで**に制限してある。**この数を勝手に増やさないこと。**
0009 以降に作った教材の英文は作られた時点で変換・保存されるので、
追いつきが要るのは 0009 より前の教材だけである。

### Supabase の関数は150秒で切られる

Edge Function は150秒何も返さないと切断される。Claude の生成は
これを超えることがあるので、**答えが出るまで空白を5秒ごとに送り続ける**
(`generate-material`)。空白は JSON の前に付いても読み飛ばされる。
Anthropic 側も **streaming で受け取る**。`output_config.effort` は
`medium`。既定の `high` は40問で3分近くかかる。


### 「窓口につながりません」は、**未配置とは限らない**(第5.197節)

「200 で正常終了」と記録する。切れたことは呼んだ側にしか分からず、
そこに届くのは「返事を受け取れなかった」の1つだけである。

**この節の上に 2026-08 から書いてあったのに、文言を直していなかった。**
**書き残すだけでは足りない。知らせの側も直す。**

- **見分ける材料は持っていた** —— 開いたときに訊いた窓口の版

- 版を知っているときの文に**「配置」という語を出さない。**
  あの誤診を二度しないための、いちばん短い決まりである

#### Supabase の「エラー 0件」は、生成の失敗を見ていない

`streamed()` が先に 200 を返すので、**生成が失敗しても 200 である**

#### 4XX が出ているのは、**こちらがわざと出している**

`checkGenGateway` は版を訊くために**読めない中身**を送り、

- それでも入れるのは、**押し直すほうが高くつく**から ——
  押し直しは教材を最初の段からぜんぶ作り直す
- **断られた(4XX / 5XX)ものはやり直さない。** 同じ金を二度払うだけ

### 窓口(Edge Function)は、**手で貼らない。GitHub が配る**(第5.233節)
