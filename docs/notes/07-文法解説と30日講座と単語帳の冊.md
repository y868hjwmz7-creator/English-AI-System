### 文法解説は「文ごと」。SVOC と修飾要素を、作るときに1回だけ控える(0051)

2026-09 利用者の指定。

> 文章ごとにSVOCと修飾要素についての解説をしてくれる、文法解説モードが欲しい。

スラッシュリーディング(②)は「**どこで切るか**」までしか教えない。
切ったかたまりが**文の中で何の役をしているか**が見えないと、
長い文になったとたんに読めなくなる。

    The office / bought / a new coffee machine / last week.
       S          V            O                  M

#### **カタマリの訳(0021)と、まったく同じ道に乗せてある**

新しい仕組みを作っていない。**すでに通っている道をなぞる**ことで、
費用の考え方も、ずれたときの断り方も、作り直しの拾い方も1つで済む。

| | カタマリの訳(0021) | **文法解説(0051)** |
|---|---|---|
| 切るのは | 決まり(`chunker.js`) | 決まり(`splitEnSentences`) |
| AI に頼むのは | 訳の文字だけ | **役(S/V/O/C/M)と日本語の説明だけ** |
| 控え | `material_items.chunks` | **`material_items.grammar`** |
| 作るのは | 教材を作るときに1回 | 同じ |
| 前に作った教材 | 使うときに裏で足す | 同じ |
| 数が合わなければ | 出さない | 同じ |

- **一般の動詞は、語のリストでは当てられない**(`run` は名詞にもなる)。
  だから **SVOC だけは決まりで出せない。** ここは AI に頼むしかない
- **文はこちらで切って渡す。** 窓口に切らせると、
  **数が合っているかを確かめる術が無くなる**
- 費用は記事1本で **5〜6円ほど。1回きり。**
  開くたびに作ると、同じ額が**ゲスト500人 × 開いた回数**だけかかる

#### **ずれた解説は、無いより悪い**(落とす条件は4つ)

判断は **`src/lib/grammarNote.js` 1か所。** 画面にも `materials.js` にも書かない。

| 何を見るか | なぜ |
|---|---|
| 段落の英文が変わっていないか | あとから本文を直すと、文と解説の対が狂う |
| **かたまりをつなぐと、元の文に戻るか** | 語が抜けた・増えたときに気づく唯一の手 |
| 役が S / V / O / C / M の5つに入っているか | 知らない役は、画面に出しようがない |
| **控えた文をつなぐと、本文に戻るか** | 文が1つ足りない控えを通すと、**最後の1文だけ解説が無い**教材ができる |

- **1つでも欠けたら、その項目ごと出さない。**
  虫食いの解説は、どの文に解説が付いているのか読む側に分からない
- **空白の入り方の違いだけでは落とさない**(`last week .` と `last week.`)。
  つないだものは**空白を除いて**突き合わせる。並びは保たれるので、
  語が抜けた・増えた・入れ替わったときは、これでも必ず食い違う
- **`splitEnSentences()` で数え直さない。** 略語の決まり
  (`ABBREVIATIONS`)を直すと文の数が変わるので、数え直すと
  **すでに作った解説が丸ごと出なくなる**
  (カタマリの訳で一度踏んだ穴。だから `chunks.parts` を控えている)

#### 出す場所は**集中モード1つ。ボタンは増やさない**

**下の帯はすでに4つで埋まっている**(CLAUDE.md「5つめを足すと狭い画面で
あふれる」)。だから **「訳を見る」のボタンを、押すたびに回るようにした。**

    英語 →(押す)→ 訳 →(押す)→ 文法 →(押す)→ 英語

- **`RepeatUnit`(しない / 文 / 段落 / 全文)とまったく同じ形**である。
  ボタンの文言は**次に何が出るか**を言うので、押す前に分かる
- **無いものは飛ばす**(訳の無い段落・解説の無い教材)。
  どちらも無ければ**ボタンごと出さない**(効かない操作を見せない)
- **`showJa`(真偽値)をやめた。** 見せ方が3つになったので、
  真偽値で持つと必ずどこかで取りこぼす。回し方は **`nextView()` 1か所**
- **並べない。入れ替える**(訳と同じ決まり)。
  並べると箱が2倍になり、**送るものが出て集中モードが壊れる**
- **割った段落では、そのかけらのぶんだけ**(`grammarForPiece`)。
  位置は**空白でない文字の数**で当てる(`wholeAudio.js` と同じ考え方)。
  **当てはまらない文は落とす** —— 画面に無い文の解説を並べない
- **紙(`LessonView`)には出していない。** あちらの練習の行は
  実測で 390px → 342px と、3つでいっぱいである(CLAUDE.md)。
  集中モードは**1段落だけを画面に固定する**画面なので、
  文ごとの解説を置く場所としていちばん素直でもある

#### **色を5つに分けない**(骨組みか、飾りか)

S / V / O / C / M を色で塗り分けるのが世の中では普通だが、**採らなかった。**

- **役の名前そのものが札に出ている。** 色は念押しにしかならない
  (「**色だけに頼らない**」の裏返し)
- 色を1つ足すと `styles.css` の**9か所**に書き足すことになる
  (`:root` / 暗い側2つ / 紙の島 / 紙の暗い戻し2つ / プレイン2つ /
  `.focus` の別名)。**5色なら45行**で、1か所でも抜けると
  暗い配色や紙の上だけで壊れる —— `npm run test:paper` が
  見張っている場所そのものである

代わりに**「骨組み(S/V/O/C)か、飾り(M)か」の2つだけ**を目で分ける。
これは利用者が言った「**SVOC と修飾要素**」そのままの分け方である。

| | 見た目 |
|---|---|
| 骨組み | うすい地色 + 同じ色の文字(**選んでいる印と同じ組み合わせ**) |
| 飾り | **細い枠線だけ。塗りを2つ並べない** |

使うのは `--accent-soft` / `--accent` / `--border` / `--text-*` だけで、
**どれも紙の島にもプレインにも、もとから入っている。**

#### **窓口の置き直しが要る**(`FN_REV` = `2026-09-09`)と、**0051**

- 置き直すまでは、**添削のときとまったく同じ落とし穴**にはまる ——
  古い窓口は `mode: 'grammar'` を知らないので既定の道に落ち、
  「演習の種類が正しくありません」と断る。**そのまま出すと誤診させる**ので、
  `generateGrammar()` が「窓口が古い」と読み替えて知らせる
- **0051 を貼るまで、`grammar` は保存されない。** 画面は `runTolerant()` が
  まだ無い列を外して読み直すので、**教材は普通に作れる。**
  効かなくなるのは文法解説だけである
- **すでに作った教材にも、あとから足せる**(`addGrammar`)。
  「セッションで使う」「印刷」を押したときに、裏で1回だけ走る。
  **1つの教材につきその画面で1回だけ**(止まる条件を持たせる)
- `npm run test:play` が算段(落とす条件・見せ方の回り方・かけらの取り出し)と
  **画面が本当に呼んでいるか**を、`npm run test:bar` が
  **描いて色を測る**(骨組みと飾りが見分けられるか・暗い配色でも読めるか・
  横にはみ出さないか)。実際に落とす条件を1つずつ外して、
  赤くなることを確かめてある

##### 赤チェックの落とし穴 ——「**その1本だけ**が効いているか」を試す

「かたまりをつないで元の文に戻るか」の見張りを外して赤チェックしたのに、
**緑のままだった。** 検証の作り込みが甘く、落とす文から**動詞を抜いて**
いたので、**別の見張り(「動詞が1つも無ければ返さない」)が拾っていた。**

**赤チェックは「その1本を外したら赤くなるか」で見る。**
ほかの見張りにも引っかかる壊し方を選ぶと、**外れていても緑になる。**
いまは**飾り(M)を落として**試している(実際に赤くなることを確かめた)。

### 文法30日集中講座 + 基礎単語(0052)。**ゲスト専用のコース**

2026-09 利用者の指定。

> pre basic と basic に基礎単語習得モードとか文法30日集中講座などが欲しい。
> 日本ではいわゆる中学英語と呼ばれるものだ。**ただ網羅するのではなく**、
> 単語と基礎的な文法の仕組みを**楽しんで身に付けられる**コースにして欲しい。

**2つとも1つの画面にした。** 利用者は「単語と基礎的な文法の仕組みを」と
言っており、**別々に置くと片方だけやって終わる。**

#### 並べ方は「文法書の順」ではなく「**話せる順**」

中学英語の教科書は「be動詞 → 一般動詞 → 三単現 → …」と**文法の都合**で
並ぶ。この講座は**言えるようになる順**に並べた。

    1日目 … 名乗る(I am 〜)
    2日目 … 好きなものを言う(I like 〜)
    4日目 … 相手に訊く(Do you 〜?)

**4日目でやりとりが成立する。** 「網羅するのではなく」という指定は、
ここに効かせてある。30日は3つに割ってあり、
1〜10 いまのことを言う・訊く / 11〜20 時間と場所を足す /
21〜30 言いたいことを長くする。

#### 単語は「基本360語」と「標準1200語」の2段(利用者の指定)

> 超初心者は「厳選360」初心者は「中学英語1200」と2段組で。
> **コンセプトはコミュニケーションのため。**

**呼び名は 2026-09 に改めた**(利用者の指定)。

> 講座の中の単語はそれぞれ基本360語、標準1200語、として
> そもそもが独立して選べる単語帳にしてください

**`id`(`core` / `full`)は変えない。** あれは 0052 の
`check (course in ('core', 'full'))` に入っており、
すでに `course_days` に残っている行の値でもある。**呼び名だけを変える**
(「スピーチ練習」で `pronunciation` を変えなかったのと同じ考え方)。

- **`core: true` の 360 語が「基本360語」。1200 の一部**である。
  **別の一覧を持たない** —— 2つ持つと、片方だけ直したときに食い違う
- **1日 12 語 / 40 語 × 30 日**でぴったり割ってある
  (`npm run test:play` が日ごとに数えている)
- 選び方は**「網羅」ではなく「話せるか」。** 教科書にしか出ない題材語
  (chalk / eraser)は入れず、`sorry` `maybe` `almost` `actually` を入れた
- **`day` は講座の日と同じ番号。** その日の文法で使える語をその日に置く
  (13日目の不規則動詞なら `went` `said` `took`)
- **訳をファイルに書いてある。** 単語帳へ入れるときの意味引きは
  `lookupWord` に任せるが、**講座の画面で読むぶんは0円**である
- **`w` は変えない。** 単語帳の鍵は「そろえた語」(`normWord`)なので、
  書き換えると**すでに覚えた記録とつながらなくなる**

#### **文法の30日は、どちらの段でも同じ**

「超初心者だから文法も半分」にはできない ——
be動詞を知らずに疑問文は作れないので、削ると穴が空く。
**段で変わるのは語の数だけ**である。

#### 新しい練習を作らない

読み上げは `SpeakButton`、語は単語帳(`setWordStatus`)、
例文は Quick Response と同じ「英語 + 訳」の対(`dayPairs`)。
**この講座のためだけの仕組みは1つも作っていない。**
だから講座で入れた語も、ふだんの単語帳とまったく同じように
間隔をあけて出てくる(0015〜0039)。

- **まとめて入れるときは、押す前に語数を出す**(見えない費用は管理できない)。
  1語ずつ順に入れ、**「やめる」でその場で止まる**(止まる条件を持たせる)
- **単語帳へは `WordbookAdd` と同じ道**(`lookupWord` → `setWordStatus`)。
  引かずに入れると、単語帳で「意味の控えがありません」のまま残る

#### つまずいたら、**弱点タグの名前を伝えるだけ**

各日に `tagIds` を持たせてあるが、**ゲストは教材を作れない。**
だから画面には「トレーナーに『◯◯が苦手』と伝えてください」とだけ出す
(**効かない操作を見せない**)。

#### 足りなかった文法タグ4つ(0052)

30日を作るときに、**この4つだけ行き先が無かった** ——
**be動詞 / 動詞の形 / 疑問文 / 三人称単数の -s**。
どれも「まだないもので一般的なもの」(利用者の指定)そのもので、
しかも**つまずく人がいちばん多いところ**である。

**画面(`weaknessTags.js`)と表(`weakness_tags`)の両方に足す。**
片方だけだと、そのタグを付けた教材を発行した瞬間に外部キー違反で止まる
(0050 とまったく同じ落とし穴。`scripts/check-exercise-types.mjs` が見張る)。

**`relative` / `quantifier` は作らなかった** —— すでにある
`relative-pronoun` / `quantity` で足りる。**似たタグを2つ作らない。**

#### 進み具合は `course_days` 1つ(0052)

**ゲスト × 段 × 日で1行**(`vocab_days` / `practice_days` と同じ形)。
「終えた」ことしか持たない —— **点数も時間も持たない。**
講座は測るためのものではなく、順にたどるためのものである。

- **書けるのは本人だけ。** トレーナーが代わりに「終えた」ことにする道は
  作らない(講座はゲストが自分で進めるもの)。読めるのは担当トレーナーと管理者
- **`auth.users` を参照する**ので、`profiles` を消しても道連れにならない。
  だから `erase_learner()` の側で明示的に消す
  (**表を足したら、消す側にも足す**)
- **次にやる日は「終えた数 + 1」で出さない**(`nextDay`)。
  飛ばして進んでもよいので、**終えていないいちばん小さい番号**を返す ——
  3日目だけ飛ばした人を、いつまでも4日目に留めない
- **0052 を貼る前でも壊れない。** 一度断られたら覚えておき、
  そのあとは呼びに行かない(`courseSupported()`)。
  進み具合が残らないだけで、**30日の中身も語も読み上げも動く**

#### **ゲスト専用**(利用者が選んだ)

トレーナーのメニューには出さない。**下の帯(`TAB_IDS`)にも足さない** ——
あちらは利用者が「教材、単語帳、Quick Response、スピーチ この四つ」と

##### **プロフィールと一緒に読む**(ちらつかせない)

##### 印を読むときに、**列の名前を書かない**(この回で踏みかけた)

`SetupStatus` の `checkSqlApplied()` は `select('id')` で表の有無を見ていた。
ところが `learner_features` は **`id` を持たない**(複合キー)ので、
そのまま印にすると断りが「そんな列は無い」(42703)になり、
`noTable()` をすり抜けて **入っていないのに黙る**ことになる。
いまは `select('*')`。`npm run test:play` が見張る。

##### 検証は2つ。**役目が違う**

| 検証 | 何を見るか |
|---|---|
| `npm run test:play` | **判断**(4とおり)・既定・画面が本当に呼んでいるか・貼る SQL がそろっているか |
| `npm run test:bar` | **描いて測る**(講座と基礎単語が、これまでどおり出るか) |
| `rls_test.sql` | 担当トレーナーは決められる / ゲストは決められない / 表に直に書けない / ほかのゲストのものは見えない / まとめて消すと消える |

実際に ①判断をなくす ②画面がベタ書きする ③単語帳に渡さない
④単語帳が見ない ⑤全ゲストに戻す ⑥印を置き去りにする ⑦列の名前を書く
⑧門番を外す ⑨消す行を落とす ⑩ほかのゲストにも見せる、の10で
赤くなることを確かめてある。

### 品詞で絞る。**そろえ方は `posGroups.js` 1か所**

2026-09 利用者の指定。

> そして、講座から単語帳に登録を押せば、単語帳の中の自分の普段の単語に
> 追加される感じで
> そして、全ての単語に対して効くようにして欲しいのが
> 品詞ごとに分ける絞り込み機能です。

**前半は、もうそうなっている。** 講座の「単語帳へ」は
`setWordStatus()` → `mark_word()` → **`word_reviews`** で、
手で入れた語・教材から拾った語と**まったく同じ表**である。
だから間隔をあけた復習(0015〜0039)も箱に応じた出題の形も、
そのまま効く。**別の入れ物は1つも作っていない。**

#### 難しいのは、**品詞の言葉が2通りある**こと

| どこから来た語 | `pos` に入っている文字 |
|---|---|
| 教材・手入力(`lookup-word` が引いた控え) | **日本語1語**(「名詞」「他動詞」…) |
| 基礎単語(`basicWords.js`) | **短い印**(`n` / `v` / `adj` …) |

しかも窓口の指示は「品詞(日本語で1語)」であって**閉じた一覧ではない。**
「句動詞」「助動詞」など、こちらが決めていない言葉も返ってくる。

**画面で `pos === '名詞'` と書くと、基礎単語(`n`)で必ず抜ける**
(`kind === 'dialogue'` と書いて会議で抜けたのと、まったく同じ落とし穴)。
だから**そろえ方は `posGroupOf()`(`src/lib/posGroups.js`)1か所。**
何にも依存しない形にしてあるので、`npm run test:play` が素の node で
1,200 語ぶんを機械的に確かめる。

- **一覧は閉じている**(名詞・動詞・形容詞・副詞・前置詞・接続詞・
  代名詞・冠詞と数・間投詞・熟語)。**並べ替えない** ——
  五十音順ではなく、いつもの並びのほうが探しやすい
- **助動詞は「動詞」へ入れる。** 数が少なく(be / can / will)、
  「動詞だけ」を選んだ人が can を外したいとは考えにくい
- **`その他` を作らない。** 知らない言葉は `''`(分からない)を返し、
  その語は**品詞では絞れない**だけにする。当てずっぽうで「その他」へ
  入れると、そこを選んだ人に名詞と助動詞が混ざって出る
  (`abbrevAt` の「見落としは長い1文になるだけだが、取り違えは
  文をつなげてしまう」と同じ考え方)
- **画面には日本語で出す。** 基礎単語の印は `n` なので、そのまま札に
  出すと「n」と見える。`Wordbook` の読み込み**1か所**で、
  **控えが無いときだけ** `posLabel(posGroupOf(basicPosOf(…)))` を当てる。
  **控えのある語は1文字も書き換えない**(訳とまったく同じ作法・0053)

#### **鍵の一覧を書き写さない**(`FILTER_KEYS`)

`runKeyOf()`(`reviewScope.js`)は「絞り込みが変わったら出題を組み直す」
ための鍵を作るのに、**鍵の名前を書き写していた** ——
だから**レベル(0048)を足したときに、そこだけ数え漏らしていた。**

品詞でも同じことを繰り返さないよう、**一覧そのものを共有した。**
絞る・数える・空にするを **`src/lib/wordbookFilter.js`** へ切り出し
(`homeworkFilter.js` と同じ考え方)、`FILTER_KEYS` を両方から読む。
**呼ぶ側は1行も変わっていない** —— `WordbookFilter.jsx` が
ここから読み直して、これまでどおり出し直している。

#### **生の NUL を、ソースに書かない**(この回で踏んだ)

「教材なし」の合図(`NO_MATERIAL`)と `runKeyOf` の区切りは、
**1バイトの NUL をそのまま**書いてあった。すると
**git がそのファイルを「バイナリ」と見なし、差分も grep も効かなくなる**
(実際、品詞を足すあいだ `WordbookFilter.jsx` の差分が1行も読めなかった)。

`'\u0000'` と書けば**値は同じまま**、ふつうの文字列として読める。
`npm run test:play` が、3つのファイルに生の NUL が入っていないかを見張る
(実際に書き戻して、赤くなることを確かめてある)。

#### 検証は2つ。**役目が違う**

| 検証 | 何を見るか |
|---|---|
| `npm run test:play` | **そろえ方**(2通りの言葉・知らない語・1,200 語が1語残らず入るか・鍵・絞り方・画面が呼んでいるか) |
| `npm run test:bar` | **描いて測る**(行が出るか・選択肢に両方がまとまっているか・**1つしか無いときは出ないか**) |

**「出る」と「出ない」の両方を見る。**「出る」だけだと、
**選べるものが1つしか無いときにも出す形**に壊しても緑のままになる
(効かない操作を見せない)。仮の語には
**日本語(「他動詞」)と短い印(`n`)を混ぜてある** ——
片方だけで測ると、`posGroupOf()` を壊しても気づけない。
しかも「他動詞」は**そのままの言葉では一覧に無い**ので、
動詞へ寄せる仕組みまで通らないと、この行は出ない。

実際に ①「他動詞」を一覧から外す ②`FILTER_KEYS` から `pos` を外す
③絞る1行を外す ④`Wordbook` の当てを外す ⑤`runKeyOf` を書き写す形に戻す
⑥基礎単語の品詞を引かない形にする ⑦生の NUL を書き戻す
⑧1つしか無くても出す形にする、の8つで赤くなることを確かめてある。

  読み直さないと**冊が増えるのは「次に開いたとき」**になる ——
  利用者からは「出したのに出てこない」にしか見えない
- **ゲストの決まりは1文字も緩んでいない。** 足したのは
  `is_trainer()` のときだけ通る道である(`can_set_own_features()`)
- 覚え具合は **`shelf_reviews` に、その人自身の行として残る。**
  `mark_shelf_word()` の門番は「自分か、担当ゲストか」なので、
  **自分のぶんは誰でも書ける** —— ここが締まりすぎると、
  トレーナーは開けても**答えを1つも残せない**

  「自分の単語帳 / 業種べつ」で、**同時には出さない**)
- **`erase_learner()` は棚に触らない。** 棚はスクールの共有物である

##### **RPC と RLS は、同じことを言わせる**(二重に塞ぐ)

0055 からの作法である。0059 が広げたのも**両方**で、
足した半分は **`can_set_own_features()` 1か所**にしてある ——
2か所に `is_trainer()` と書き写すと、片方を直した日に食い違う。

**引数を取らない読むだけの関数**にしてあるので、画面の `SetupStatus` が

**「このゲストの担当ではありません」**と断る。ところが相手は自分で、
**自分の担当かどうかを疑わせても直しようがない。**

##### 見張りは3つ。**役目が違う**

| **ゲストのページ**(この欄) | **画面のいちばん上**(`message` / `error`) |

ゲストのページは縦に長く、単語帳のタブは**下のほう**にある。
だから**成功しても失敗しても、1文字も見えなかった。**
CLAUDE.md に「**失敗の知らせは、その操作をした場所に出す**」と
書いてあり、**`ShelfBuilder` では守っていたのに、こちらで破っていた。**

- **知らせは `ShelfAssign` の中**(`note`)。`toggleFeature` に
  **`quiet` を足して**、上の帯には出さない ——
  **同じものを2か所に出さない**
- **選んだ瞬間に出すと、そう書く**(「えらぶと、すぐ出します…」)。
  黙っていると「**選んだあと、できることがない**」と読める
- **「いま出している単語帳」の見出しを足した。** 札だけだと
  「外す」の字が先に目に入り、**それが出ている印だと読み取れない**
- **「出す」ボタンは置かない。** 決めることは1つしかないので、
  押すものが2つに増えるだけである

###### **描けないものは測れない。** だから部品に切り出した

この欄は `TrainerLearners.jsx` の中に直に書いてあり、あの画面は
**Supabase を引き連れている**ので `npm run test:bar` の骨組みでは
**1ドットも描かれなかった**(`SpeechBoard` → `SpeechPractice` と同じ話)。
**そのあいだ、押した結果がどこにも出ない形が入り込んでいても、
検証は何も言わなかった。**

`ShelfAssign.jsx`(**props で受け取るだけの部品**)に切り出し、
`?screen=shelfassign` で**実際に選んでみる**ところまで測る。

- **「欄がある」だけを見ない** —— 選んでも何も起きない形に戻しても
  緑のままになる。**押して、札が増えるか・結果がこの場に出るか**を数える
- **骨組みは本物と1文字も違えない**(CLAUDE.md)。実際、
  はじめ `useState(['biz'])` と書いて**本物の id(`business`)と
  食い違わせた** —— 札が1枚も出ない状態で測っていたので、
  見出しの検査は**素通りするところだった**(冊数の検査が先に赤くして拾った)

###### 素の `<select>` は、**押せる大きさを割っている**

`input[type='number'], select, textarea` は `padding: 8px 10px` と
`--fs-14` だけなので、**高さは 35px ほどにしかならない。**
CLAUDE.md の「ボタンは 40px を割らない」は `.btn` の話で、
**プルダウンは素のままだと割る。**

- `.shelfbooks-pick > select` は、そのために **`min-height: 40px`** を
  明示していた。**そこと同じ行で値を分け合う**(書き写さない)
- **描かないと分からない。** `npm run test:bar` が3つの幅で測っており、
  実際にこの回、**切り出した直後に3件とも赤くなって拾った**
- **札(`.chip`)も押すもの**なので、36px を割っていないか一緒に数える

###### **こちらでは、書けたかどうかを確かめられない**

この環境から Supabase には届かない。だから
「**RPC が本当に通っていたのか**」は、いまも分かっていない。
直したのは「**理由が見えるようにした**」ことである ——
もし窓口が断っていたなら、次は**その断り文がこの欄に出る。**
**分かっていないことを、分かったように書かない。**

#### 検証は2つ。**役目が違う**

| 検証 | 何を見るか |

| `npm run test:play` | **算段**(冊の数・棚の当て方・名前の作り方・出し分け4とおり・**ゲストに出す2つの道**・画面が本当に呼んでいるか・貼る SQL がそろっているか) |

実際に ①種類を親の棚に落とさない ②ゲストにも全冊出す
