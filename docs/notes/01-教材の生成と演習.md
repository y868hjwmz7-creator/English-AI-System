演習の種類を足す4か所・誤り訂正・ディスカッション・想定される質問・スピーチ練習・添削・被らない教材・空の応答

### Supabase 上で動く関数(Edge Function)4つ

ブラウザに置けないもの(鍵・重い処理)はここにある。配置は利用者が
Supabase の画面から行う。**1関数1ファイル**にしてあるのは、配置の手順を
増やさないため。

| 関数 | 役目 | 鍵 |
|---|---|---|
| `create-user` | アカウント発行 | `service_role`(関数の中だけ) |
| `generate-material` | 教材の下書き生成 | Claude API |
| `check-similar` | 意味が近すぎる英文を弾く | **不要**(`gte-small` が Supabase 内にある) |
| `speak` | 英文の読み上げ音声(MP3)を作って置く | Azure Speech |

同じ英文を二度出さない仕組みは3段(仕様書 第5.16.2節)。
**保証しているのは②と③で、①は誘導にすぎない。**
意味の近さの境目は `SIMILARITY_THRESHOLD`(`src/lib/materials.js`)1か所。
**実測していない初期値なので、外しすぎ・素通りしすぎが出たらここを直す。**

### 教材の種類と、その形

| 種類 | 中身 | 数え方 |
|---|---|---|
| 文型ドリル | 1つの文法を4演習 × 10問 | **問数**(40問。減らさない) |
| リーディング | 記事1本 + 内容理解5 + **ディスカッション5** + 語句8 | **段落数**(6段落 = 250〜350語) |
| ダイアローグ | 会話1本 + 内容理解4 + **ディスカッション5** + 語句6 | **発言数**(14発言) |
| 単語 / フレーズ | 20問 | 問数 |

**音読・オーバーラッピング・シャドーイング・リピーティングは、
演習の種類ではない。** 同じ本文に対する「取り組み方」であり、
ゲストの画面で切り替える(`PassagePractice.jsx`)。
これを演習として分けたために「長文」が16個の短文になった(2026-08)。
**種類を増やすときは「これは読み物か、問題か」を先に決めること。**

記事・会話では**弱点タグは任意**で、問数を弱点で分割しない。
分割すると話がつながらなくなる。探すのはジャンル・場面・見出しで行う。

### 穴埋めはやめた。いまは「誤り訂正」

`error_correction`(2026-09 利用者の指定)。**文型ドリルの2番目**である。

> そもそもこの穴埋めはいらないかもしれない。
> なぜなら、穴埋めは複数の回答が考えられる場合があり、すっきりしないからです。

きっかけは実機でこう出たこと。

    Before kickoff, could you （　　　） me where the away fans usually sit?
    与える語: tell   → tell

`could you` のうしろは原形なので**形を変える必要がなく**、
与える語がそのまま答えになっていた。**空欄の位置そのものが誤っている。**

- **4演習 × 10問 = 40問は変えない**(第5.13.3節)。差し替えただけ
- **誤りは1文に1か所。** 2か所あると、どちらを直すのか決まらない
- `answer` には**直した英文を1文まるごと**入れる。直した語だけにしない
- **`note` は必須。** なぜ間違いかが無いと、直す意味が薄い
- **音声は付けない**(`audioFrom: null`)。誤った文を手本として聞かせられず、
  直した文を読ませると答えが耳から入る。穴埋めのときと同じ扱い
- **`fill_blank` は消さない。** 一覧に残す(旧「長文」と同じ)。
  消すと、**すでに作った教材が開けなくなる**
- 与える語と解答が同じ問は `givesAwayAnswer()` が落とす。
  古い教材を作り直すときのために残してある

### 内容の理解には、設問と解答の訳が付く(0035)

2026-09 利用者の指定。

> 内容理解の設問と解答の訳を見れるようにしてください。音も聞けるように。
> そして解答や設問も単語の意味を調べて単語帳に追加できるようにしてください。

内容の理解は**設問も解答も英語**である。日本語が1つも無いと、
設問の意味が取れない人には**設問そのものが壁**になり、
本文を理解できていたのかどうかを確かめられない。

- 入れ物は `material_items.question_ja` / `answer_ja`(0035)。
  **`prompt_ja` を流用しない。** あれは本文・問題文の訳で、
  Quick Response・スラッシュリーディング・カタマリの訳がその対で動いている。
  **名前の違うものを、同じ欄に入れない**
- **解答はこれまで「ただの文字」だった。** だから語に触れても意味が出ず、
  単語帳にも入れられず、読み上げもできなかった。
  設問のほうは `EnglishText` だったので、**片方だけができていた**
- 出す場所は **`AnswerEn.jsx` 1つ。** 解答が出るのは3か所
  (教材の中身 / レッスン表示 / 今週の宿題)。**書き写さない**
- **設問の訳は伏せない。** 設問は「何を訊かれているか」であって答えではない
  (レッスン表示も、設問の日本語はもともと伏せていない)
- **解答の訳と Listen は、解答を開いたあとにだけ出る。**
  答えが先に耳から入ることはない
- **0035 を貼る前に作った教材には入っていない**(訳が出ないだけ)。
  だから `SPARE_FIELDS` に入れてある。必須にすると、
  窓口を配置し直す前の教材が**1問残らず落ちる**
- ディスカッションの設問には**足していない**(言われた場所だけを直す)。
  必要なら同じやり方で足せる

#### ただし、**解答が日本語の演習では鳴らさない**(`answerLang`)

2026-09 利用者の指定。

> 文型トレーニングなどの解答の和訳に「listen」ボタンは不要なので
> 同じ仕様になっているところは全て削除してください

実機の写真は**英文和訳**だった。

    The manager makes the new staff happy.   [Listen] [解答を隠す]
    → 店長は新しいスタッフを幸せにします。
      [Listen]                               ← これ

**英文和訳の `answer` は、和訳そのもの(日本語)である。**
そこに読み上げを出しても、**日本語を英語の声で読む**だけになる。
`AnswerEn` は `clipVoice` が渡されていれば**必ず**出していたので、
解答が英語か日本語かを一度も見ていなかった。

##### 欄からは当てられない。だから**書く**

| | `fields` | 解答の中身 |
|---|---|---|
| 英文和訳 | `prompt_en` + `answer` | **日本語** |
| 誤り訂正 | `prompt_en` + `answer` + `note` | 英語 |

**同じ形なのに、中身が違う。** `audioFrom` でも当てられない ——
あれは**問題文**の音の話で、誤り訂正は `null` だが
**解答(直した英文)は英語で読める。**

- 一覧は **`answerLang`(`exerciseTypes.js`)**。
  `answer` を持つ演習は `'en'` / `'ja'` のどちらかを必ず書く
- **書き忘れると `npm run test:play` が赤くなる。**
  足すまで赤いままなので、演習を足す人は必ず1回、
  その解答が英語か日本語かを自分の目で決めることになる
  (声の名簿の `KNOWN` と同じ考え方)
- 判断は **`answerHasAudio(typeId)` 1か所。** 使うのは **`AnswerEn` の中だけ**で、
  画面(教材の中身 / レッスン表示 / 今週の宿題)は**種類を渡すだけ。**
  **画面の中で `typeId === 'translate_en_ja'` と書かない**
  (`remakeModeOf()` と同じ考え方)。**既定は「出さない」**
- **内容の理解は消していない。** あちらは 0035 の利用者の指定
  (「音も聞けるように」)そのもので、**解答は英語**である。
  「全て削除」を、**解答が英語のものにまで広げない**

##### 検証は2つ。**役目が違う**

| 検証 | 何を見るか |
|---|---|
| `npm run test:play` | 一覧・書き忘れ・**画面が種類を渡しているか**・種類を見分けていないか |
| `npm run test:bar` | **描いて数える**(解答を開いても Listen が増えないか) |

**「出ない」だけを見ない。** 誤り訂正で**出る側**も数える ——
あちらは問題文に音が無いので、開いて増えた1つが解答のものだと確かめられる。
片方だけだと、**どこにも出さない形に書き換えても緑のまま**になる。

**残っている重なり(直していない)。** 和文英訳は `audioFrom: 'answer'` なので、
**問題文の Listen と解答の Listen が同じ英文を読む。**
解答が英語なので今回の指定には当たらないが、
**同じことをするボタンが2つ**並んでいる。言われた場所だけを直してある。

### ディスカッションには、正解が無い

`discussion`(2026-09 利用者の指定)。記事とダイアローグの**新しいページ**で、
既定は5問、「倍」で10問(`SCALABLE_SECTIONS`)。

> 内容理解５問に追加して、新しいページにディスカッションというものを
> 追加してれ。これも基本は５問、設定により１０問にできるようにしてくれ。

**内容の理解の置き換えではない。足すものである。** あちらは
「本文に何が書いてあったか」を確かめるもので**答えは本文の中にある**が、
こちらは本文をきっかけに**自分の考えを話す**もので**正解が無い。**

- **`answer` の欄そのものを出さない**(`SECTION_FIELDS.discussion`)。
  欄があると、AI は必ず何かを書く。**書けない欄は、最初から作らない**
- 代わりに `note` へ日本語の手がかり(話を広げる観点 + 使える表現)。
  ゲストにも見えてよいので、`hideAnswerFromLearner` は付けない
- **本文が要る**(`needsContext`)。本文が無いと問いが作れないので、
  内容の理解・語句と同じ扱いにする
- **Quick Response には出さない**(`PAIR_FIELDS` に入れない)。
  英語の設問で、対になる日本語が無い
- 声は標準の段(`voiceTierFor`)。まねる手本ではなく、設問である

### 想定される質問は、ディスカッションと**向きが逆**(0045)

`audience_qa`(2026-09 利用者の指定)。**Speech練習だけ**の新しいページで、
既定は5問、「倍」で10問(`SCALABLE_SECTIONS`)。

> 作成したスピーチに対して、聴衆から想定される質問を作る機能を実装して下さい。
> 質問は、他の演習と同じように個数を5個、10個と選べるようにして下さい。

| | 誰が話すか | 何が来るか |
|---|---|---|
| ディスカッション | **自分から**話す | 本文をきっかけにした問い |
| **想定される質問** | **相手から**投げられる | 話し終えたあとの質疑 |

**スピーチで本当に怖いのは原稿ではなく、そのあとの質疑である。**
だから「答えを読む」のではなく「**答えを用意しておく**」演習にした。

- **`answer` を持たない**(ディスカッションとまったく同じ考え方)。
  答えるのは話し手本人で、正解は1つに決まらない。
  **書けない欄は、最初から作らない**
- **`question_ja`(訳)は持つ。** 0035 と同じ理由で、
  日本語が1つも無いと**質問そのものが壁**になる。
  **`prompt_ja` を流用しない**(あれは本文・問題文の訳である)
- **読み上げが付く**(`audioFrom: 'question'`)。
  質疑は**聞き取りから始まる。** 聞けなければ答えようがない
- **本文が要る**(`needsContext`)。本文が無いと質問は作れない
- **窓口には「本文に書いていないこと」も訊かせる**(数字の根拠・費用・期間・
  うまくいかなかったとき・他社との違い)。本文をなぞるだけの質問は、
  内容の理解と同じものになる。**少しきつい質問も1〜2問**入れる
- **出すのは Speech練習だけ。** 記事にも会話にも、話し終えたあとの聴衆はいない

#### `note` が「答えの側」に来る演習は、`noteIsAnswer()` で見分ける

**質問があって解答が無い演習**(ディスカッション・想定される質問)では、
`note` の日本語がそのまま手がかりになる。ところがレッスン表示の
「解答を見る」は **`answer` か `audio_text` があるときしか出していなかった。**
つまり**ディスカッションの手がかりも、どこからも開けなかった**
(0033 から気づかれていなかった)。

- 判断は **`noteIsAnswer(typeId)`(`exerciseTypes.js`)1か所。**
  「`question` を持ち、`answer` を持たない」で決める。
  **`typeId === 'discussion'` と書かない** —— 書くと想定される質問で必ず抜ける
- 文言は**「手がかりを見る / 隠す」**。**「解答」と書かない**
  (正解が無いものに解答は無い)
- **`vocab_note` は入らない。** あちらの `note` は例文と使いどころで、
  答えではない
- `npm run test:play` が、演習の形・4か所の登録・**画面が本当に呼んでいるか**を
  見張る(実際に外して、赤くなることを確かめてある)

### スピーチ練習 — 原稿を出し、添削し、その音で練習する(0054)

2026-09 利用者の指定。

> スピーチ練習を実装しましょう。
> これは、ゲストアカウントのスピーチ内から受け取ったスピーチの原稿を
> AIにより添削し、そしてその文の音声を作成、ゲスト側で練習できる機能です。
> トレーナー側からもゲスト毎にスピーチを登録できます。
> そして、単語帳にはスピーチの単語帳も作ります。

#### **3つめの名前を作らない**

このリポジトリには、**すでに似た名前が2つある**(CLAUDE.md にも
「言葉が近いので、取り違えない」と書いてある)。

| 呼び名 | 何 |
|---|---|
| **スピーチ練習** | 画面(`pages.id = 'pronunciation'`) |
| **Speech練習** | 教材の種類(`materials.kind = 'speech'`) |

利用者が言った「**ゲストアカウントのスピーチ内から**」は前者である。
だから**すでにあるスピーチ練習の画面の中**に置いた。
**単語とフレーズの練習は1つも減らしていない**(一度入れたものを
勝手に減らさない・共通ルール)。見出しだけ「単語とフレーズの音」に改めた。

#### **新しい仕組みを1つも作っていない。足したのは置き場所だけ**

| 何 | どの道を使うか |
|---|---|
| 添削 | `generate-material` の **`mode: 'review_writing'`**(第5.104節) |
| 音声 | `useBodyAudio` → `readAloudSequence` → `speak` |
| 1文ずつ | `SpeakButton`(良い声の段) |
| 単語帳 | `lookupWord` → `setWordStatus` → `word_reviews` |
| 絞り込み | **`App.jsx` の `onlyWords` 1つ**(0047 の `only`) |

**足したのは `speeches`(0054)だけ**である。
`material_progress`(0025)は **`material_id` が not null** なので、
**教材に結び付かないスピーチの原稿は置けなかった。**

#### 添削の上限は 3,000 文字。**窓口はいちばん大きいほうを持つ**

| どこ | 画面の上限 |
|---|---|
| ディスカッションの答え | `MAX_WRITING_CHARS` = 1,500(話して 30〜60 秒) |
| **スピーチの原稿** | **`MAX_SPEECH_CHARS` = 3,000**(話して4分) |

- **窓口は 3,000 まで受け取る。** 小さいほうに合わせると、
  **スピーチの終わりが黙って落ちる**(利用者にも画面にも何も出ない)
- **画面はどちらも「切らずに、断る」。** 勝手に削ると原稿が変わってしまう
- **`FN_REV` を進めた**(`2026-09-10`)ので**窓口の置き直しが要る。**
  置き直すまでは 1,500 文字で切られるので、`NEED_GEN_REV` を見て
  画面が赤く知らせる

#### 走らせるのはトレーナーだけ。**ゲストは「書く」まで**

**判断は `canAskReview()`(`writingReview.js`)1か所。**
`WritingAnswer` とまったく同じものを使う ——
2026-09 の利用者の指定(「ゲストには実行にしてください」)も、
`LEARNER_WRITING_REVIEW` で開く裏の道も、**そのまま効く。**

- **ゲストには、ボタンも調子の欄も出さない**(効かない操作を見せない)
- 代わりに**書いたものがどこへ行くのか**を1行で伝える(**黙って消さない**)
- ゲストが書いた原稿は `speeches` に残るので、
  **トレーナーがそのゲストのページで開けば、そのまま出てくる。**
  受け渡しの仕組みは作らなくてよかった(`material_progress` と同じ話)

#### **直す前の原稿は、読み上げない**

練習の場所は**添削が済んでから**出す(`isReviewed()`)。
まちがった英語を**手本として聞かせる**ことになるからで、
**誤り訂正の英文に音声を付けない**のとまったく同じ考え方である。

#### `RepeatUnit` は使わない。**1文が1つの部だから**

通しの読み上げに渡す `parts` は**添削が返した文そのもの**である
(窓口が**はじめから文ごとに返す**ので、こちらで切り直さない)。
すると `RepeatUnit` の「文」と「段落」が**まったく同じもの**を指す ——
**同じことをするものを2つ見せない**(CLAUDE.md)。
だから `RepeatToggle`(くり返す / 1回)にして、回すのは全文にする。

#### 音声は**1本にまとめる。** 1文ずつの Listen も、その中の区間

2026-09 利用者の指定。**こちらのずれを直したものである。経緯ごと残す。**

出したときは、**1文ずつ別の MP3** を作っていた。ところが本文の音声は
「**1本にまとめる**の仕様に統一しましょう。『段落ごと』は廃止です」と
**すでに指定されている。** スピーチは1人が話しきるので、
**記事の本文とまったく同じ形**である。

| | 通しの Listen | 1文ずつの Listen |
|---|---|---|
| 直す前 | **1本**(`readAloudSequence` がもともとまとめる) | **その文だけの MP3**(継ぎ目が出て、二度課金) |
| いま | 同じ | **同じ1本の、その区間**(0円) |

- 区間を作るのは **`speechWholeSlice()`(`speechPractice.js`)1か所。**
  `wholeSliceOf()`(本文)とまったく同じ考え方で、
  `SpeakButton` の **`whole`** にそのまま渡す
- **番号は `speechLines()` で数える。** 英文の無い文を抜いた並びで、
  **描くのも・鳴らすのも・区間を数えるのも、この1つ**である。
  1つでもずれると**別の文が光り、別の文が鳴る**
- **断るときは `null`。** 1文しか無い・声が決まっていないときは、
  これまでどおり1文ずつ鳴る(**行き止まりを作らない**)
- **`CLIP_REV` は進めない。** すでにある音声は1本も作り直しにならない

#### 添削のレベルは、**そのゲストのもの**(`speechLevelOf()`)

2026-09 利用者の指定。出したときは `level: 'B1'` を**画面に直に書いて**いた。
それでは Pre-Basic の人にも C2 の人にも**同じ難しさの英語**で直してくる。
`profiles.cefr` を持っているのに、使っていなかった。

- 判断は **`speechLevelOf()` 1か所。** 画面で `'B1'` と書かない
- 渡すのは **`App.jsx` → `PronunciationPractice`(自分の `cefr`)**と、
  **`TrainerLearners`(そのゲストの `cefr`)**の2か所
- **まだ判定していない人(null)は B1 に落とす。** ここが唯一の既定である
- 語の意味を引くときも同じレベルで頼む(`EnglishText` / `lookupWord`)

#### 集中モードは足した。**6Steps は足していない**

2026-09 利用者の指定「**今のままに集中モードだけつけて**」。

- **骨組みは `FocusFrame` そのまま**(`FocusReader` / `StepFocus` /

  **スピーチの場面は保存していない**ので、業界と種類だけで絞る
  (絞りすぎて0本になるより、同じ業界のスピーチを避けるほうが役に立つ)
- **0046 を貼る前でも効く。** 筋(`gist`)は 0046 で足す列だが、
  **見出し(`headline`)と話題(`topic`)は 0010 から入っている**
- 費用は**入力側で 300 トークンほど = 1回 0.1円未満**

#### ② 切り口は閉じたリストで持ち、**使っていないものから引く**

`src/data/materialAngles.js`。**`SPEECH_STYLES`(話し方の型)と同じ形**である。

- **記事10個・会話10個。** 記事の切り口(数字で見る・昔と今)は
  会話には使えない(書き手がいない)ので、**本文の種類で分ける**
- **`kind === 'dialogue'` と書かない**(会議で必ず抜ける)。判断は `anglesFor()`
- **スピーチには出さない。** あちらには話し方の型がすでにある
  (**同じことをするものを2つ見せない**)
- **場面ごとの絞り込み(`SCENE_STYLES` にあたるもの)は作れない。**
  場面は 83分野 × 平均21場面で **1,700通り**あり、手で書けない。
  **書けない表は作らない**(あやふやなことを言わない、と同じ)
- **保存する**(`materials.angle`)。保存しないと「まだ使っていないものから」が
  できず、おまかせが同じ切り口を続けて引く。
  **ここが `SPEECH_STYLES` と違う唯一の点**である
- **使った切り口を、入力の欄に書き戻さない。** 書き戻すと
  「作り直す」でその切り口に固定され、**おまかせが効かなくなる**
  (`usedAngle` を別に持つ)
- **足したら `scripts/test-playmark.mjs` の `KNOWN` にも書き足す**
  (声の名簿と同じ考え方。足すまで赤いままなので、必ず1回は自分の目で数える)

#### ③ 量産っぽく読める最大の原因は、**当たり障りのない一般論**である

「近年、〇〇が注目されています」で始まる文章は、業界を変えても場面を変えても
同じ形になる。**具体が入れば、それだけで別の話になる。**
窓口の指示に「書き始める前に、人物・会社・場所・時期・数字を決める」
「一般論で書き出さない」を足した。
**実在の人物・企業の名前は使わせない**(`speechStyles.js` と同じ決まり)。

#### ④ **そもそも新しく作らないのが、いちばん被らない**

作る画面に「この組み合わせの教材は、すでに 7 本あります」と出す。
教材ライブラリの再利用がこの仕組みの前提である(CLAUDE.md 冒頭)。
**数えられなかったら `null` で、行ごと出さない** ——
0 と取り違えると「まだありません」という**嘘の説明**になる。

#### 塞いだ穴 —— **タグの無い記事・会話にも、英文を渡す**

`loadUsedSentencesLike()`。弱点タグが無いときは、
**同じ業界・同じ場面の教材**から英文を集めて①に渡す。
`loadUsedSentences()`(タグから引く)と**中身を書き写さない**
(`sentencesFromMaterials()` が両方の中身)。

#### **窓口の置き直しが要る**(`FN_REV` = `2026-09-06d`)と、**0046**

- 置き直すまで、切り口も避ける話も**黙って捨てられる**(教材はできる)。
  `NEED_GEN_REV` を見て画面が赤く知らせる
- **0046 を貼るまで、`angle` と `gist` は保存されない。**
  `createMaterial` が列を外して送るので、**教材は普通に作れる。**
  効かなくなるのは「まだ使っていない切り口から引く」だけである
- `npm run test:play` が、一覧・引き方・**画面が本当に呼んでいるか**・
  窓口が受け取っているか・**貼る SQL がそろっているか**を見張る
  (実際に切り口を1つ消し、呼び出しを外して、赤くなることを確かめてある)

### 空で返ってきたら、こちらで1回だけやり直す

道具(`emit_section`)は呼ばれているのに `items` が**空の配列**で返ることが
まれにある(`stop_reason: tool_use`)。形は `strict: true` で保証されているが、
**空の配列も「形としては正しい」**ので API は通してしまう。

> もう一度条件も変えずにそのままの状態で作成し直すと次は上手くいったりします。
> 安定させれないものでしょうか?(2026-08 利用者)

**利用者が押し直せば直るのだから、こちらで押し直す。**
費用は増えない(失敗した1回はどのみち課金されている)。

- **2回で止める。** 際限なく試すと、残高切れのときに待たされ続ける
- 2回目には「前回は空だった」と伝える。同じことを繰り返させない
- **断られた(`refusal`)・長すぎて切れた(`max_tokens`)はやり直さない。**
  同じことを頼んでも同じ結果になる

### 出来上がった問は、1問ずつ確かめる。**ただし落としすぎない**

`strict: true` は「その欄があること」までしか保証しない。
**空文字も「形としては正しい」**ので API は通してしまう。実際、
フレーズ20問のうち**1問目が空**(札だけで英文も訳も無い)のまま
「全 20 問」と出ていた(2026-09 実機)。
「中身が0件のまま『成功』を返さない」を、**1問ずつにも当てはめる。**

| 見るもの | どこ |
|---|---|
| **空の問**(必須の欄が空)| `isBlankItem()`(画面)+ 窓口でも落とす |
| **単語 / フレーズの取り違え** | `isWrongShape()`。**語数だけ**を見る |
| 答えが問題文に見えている | `givesAwayAnswer()` |

- **画面の側にも置く。** 窓口だけだと、利用者が配置し直すまで直らない
- **当てられることだけを見る。**「主語が付いている」「三人称単数」は
  語のリストでは当てられない(スラッシュリーディングと同じ)。
  確かなのは語数だけである
- **無くても成り立つ欄は必須にしない**(`SPARE_FIELDS`)。
  `phonetic`(0020 より前)・`answer_alt`・`question_ja` / `answer_ja`(0035)。
  ここを間違えると、**窓口を配置し直す前の教材が1問残らず落ちる**

#### 落とす仕組みには、必ず**安全弁**を付ける

**落とす検査を入れた日に、単語の教材が0問になった**(2026-09 実機)。
窓口にはまだ「単語は1語」と書いていなかったので、
`in light of` のような2語以上が返るのは当たり前で、
それを全部落とすと5回作り直しても1問も残らない。

- **空の問は絶対に落とす。** 中身が無いものは、どうやっても使えない
- **形のちがいは「使えるが望ましくない」だけ。**
  足りなければ**戻す**(`shaped`・`generateSectionUnique`)
- **0問の教材より、形が崩れた教材のほうがましである。**
  落とす仕組みが、教材そのものを作れなくしてはいけない


### 本文から拾う「かたまり」—— 分類と練習(第5.230節・2026-09)

利用者の指定。

> コロケーション、句動詞、イディオム、決まり文句、つなぎ言葉、
> 丁寧な言い回し、言い換え表現などに分類されるものをピックアップし、
> それぞれに練習問題を追加してほしいです。
> …単語単体はここには載せない。あくまで2語以上のチャンクを練習する場とする

- **読むだけのページは、めくられるだけで終わる。**
  「文化の背景」(`culture_note`)を廃止したのも同じ理由である。
  **その場ですることが1つある**と、ページに目的が生まれる
- **分類は7つに固定。** 足せる形にしない —— 増えるほど、どれに入れるか迷う
- **呼び名は `src/data/chunkKinds.js` 1か所。**
  窓口(Deno)はそこを読み込めないので、**画面から一覧を送る**
  (`materialAngles` の切り口と同じ作法)。書き写すと、分類を1つ直した日に
  **利用者へ窓口の置き直しを頼むことになる**
- **データベースにも一覧を書かない。** `check (chunk_kind in (…))` を置くと、
  同じことが SQL の側でも起きる。知らない値が入っても
  **画面は札を出さないだけ**である(当てられなければ黙る)
- **練習は、教材を作るときに一緒に作る。** レッスン中に作らせると、
  その場で待たされ、そのたびに課金される。

- **`practice` は `fields` に入れない。** あれは「作成画面が入力欄を

  (`phrases` / `chunks` / `grammar` と同じ扱い)

  綴りが違うと札が出ず、**効かない操作**になる
- **新しく足した欄は `SPARE_FIELDS` に入れる。** 必須にすると、
  利用者が窓口を置き直すまで**1問残らず落ちて、教材そのものを作れなくなる**
  (0035 の訳とまったく同じ理由)
- **読み上げは かたまり にだけ付ける。** 本文の1文(`source_en`)に付けると、
  本文の側ですでに音になっている英文に**もう一度課金される**
- **見分けは `isChunkSection()` 1か所。** 画面3つ(教材の中身 /
  レッスン表示 / 紙)のどれにも `=== 'vocab_note'` と書かない

  やめたのと同じ理由)。畳むのは `is-closed` / `is-hidden` を付けるだけ

  2つの PDF を作り、**文字を置く命令の数の差**で見る。

- **名前に「語句」と書かない**(2026-09 利用者の指定)。中身は2語以上の

- **本文を持つ教材、どれにも入れる**(記事 / ダイアローグ / 会議 /
  モノローグ・スピーチ)。**外せて、数も選べる**(`SCALABLE_SECTIONS`)。
  見張りは**種類の一覧を書き写さない** ——「本文を持つ種類」を
  `DEFAULT_SECTIONS` から引くので、**種類を足した日に入れ忘れたら赤くなる**

### 「覚えておきたい表現」は、Quick Response の独立した組(第5.235節)
