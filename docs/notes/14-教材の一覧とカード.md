### 教材の中身は `MaterialBody.jsx` 1つ

トレーナーの「教材」と、ゲストの情報の中の「過去の宿題」で**同じものを開く**
(2026-08 利用者の指定「宿題の表示をトレーナーの教材の表示と統一」)。
**同じ見た目を2か所に書き写さない。**

- 宿題の一覧(`loadLearnerAssignments`)は**中身を持っていない**(id と数だけ)。
  開いた教材だけ `loadMaterial()` で読み、**同じ教材を二度読まない**
- 読んでいるあいだは「開いています…」に変える
- 練習の記録を消すボタンは `showReset` を渡したときだけ(トレーナーの教材のみ)

### 教材のカードに、開く・閉じるを置かない

2026-09 利用者の指定。

> わざわざ開いて「印刷・PDFで保存」のボタンを出す必要がない、
> 閉じる・開く機能を排除、そして「この教材をゲストと共有する」ボタンを
> 印刷ボタンの右側へ移してください

開いても出るのは印刷のボタンだけになっていたので、
**開くこと自体が回り道**だった。グレーの囲みは**ただの見出し**に戻す。

```
グレーの囲み(見出し。押せない)
何が何問あるか
[印刷 / PDFで保存] [練習の記録を消す]            ← 手元で扱う操作。1行にまとめる
[この教材をゲストと共有する]                      ← 人に渡す操作。教材の画面だけ
[セッションで使う(大きく表示)]
```

**「練習の記録を消す」は、印刷のとなり**(2026-09 利用者の指定
「練習の記録を消す、を印刷ボタンの右に置いてください」)。
前の2つは**同じ教材を手元で扱う**操作(紙にする / この端末の書きかけを消す)で、
共有だけが**人に渡す**操作である。

**`.btn-row` のままでは「右」にならない。** あれは折り返すので、
狭い画面では縦に積まれる。その1行だけ `.card-tools` にして
**折り返させず、入りきらないときはボタンのほうを縮める**
(`.btn--small` の `flex-shrink: 0` を戻す)。
**縮んでも文言は削らない** — 何のボタンか分からなくなる。
実測: 390px 以上は1行 34px、320px でも横に並ぶ(文字が2行になる)。

- **中身は、紙に出す一瞬だけ描く**(`printId` → `.print-holder`)。
  35件ぶんをいつも描くと、語は1つずつボタンで描いているので画面が重い。
  描かないと**見出しだけの紙**が出る(2026-08 に一度やった)
- `.print-holder` は画面では `display: none`。
  `@media print` が `.print-path` を `display: block !important` に
  戻すので、紙にはちゃんと出る
- **`MaterialBody` にボタンを置かない。** 置くと「開かないと押せないもの」に
  戻る。印刷・共有・記録を消すは**呼ぶ側のカード**にある
- 開閉が無くなったので、**語の先読みと区切りの訳の作り直しは
  「セッションで使う」で拾う**(以前は「開いたとき」だった)

### 押すものが4つ並んだら、**役目で行を分ける**(`IconButton.jsx`)

2026-09 実機・利用者の指摘。

> 印刷/PDF・練習の記録を消す・音声ダウンロード・読み上げ音声を作り直す
> この4つはアイコン化して省スペースしてください。無理やり並べすぎていて
> プロの仕事とは思えません。…今後、トレーナーは通勤中に電車で教材を
> 準備したりするのです。**見やすくコンパクトに、移遷しやすく、を徹底して
> ください。** アイコン化して、触れると説明が出る仕様でよくないですか?

`.card-tools` は **`flex-wrap: nowrap` で、`.btn--small` は縮まない**。
だから入りきらないぶんは**文字が1字ずつ縦に積まれる。** iPhone(390px)では
「印 / 刷 / P / D / F …」という**棒が4本**並び、カード1枚で画面の高さを
丸ごと食っていた。**教材を見比べるための画面が、1件も見比べられない。**

- **絵は `Icons.jsx` に足す**(`EraserIcon` / `DownloadIcon` / `RefreshIcon`)。
  **絵文字を使わない**(端末ごとに形が違う)
- **消しゴムをゴミ箱にしない。** すぐ下に「教材を消す」があり、
  **消える相手がまったく違う**(あちらは教材そのもの、こちらはこの端末に
  残っている書きかけ)。同じ絵にすると取り違える
- **押せる大きさ(40px)は割らない。** `.btn--small`(34px)を下敷きに
  しているので、**`.btn.iconbtn` と2つ重ねて**書く ——
  `.btn--small` はこの行より**あと**に書いてあり、
  `.iconbtn` 1つでは負ける(実測して気づいた)

#### 触る端末には「カーソルを載せる」が無い。**長押しで名前を出す**

`title` だけでは、何のボタンか一生分からない。

- **長押しで「実行」しない。** 2026-08 に、長押しで語の意味を開いて
  3度踏んだ穴がある(送ろうとして指を置いただけで開く)。ここで出るのは
  **消せる案内1つ**なので、間違って出ても害が無い。しかも `EnglishText` と
  まったく同じ作法で、**動いた・画面が送られた時点で取り消す**
- **長押しのあとの指離しは、押したことにしない**(`skip`)。
  名前を読もうとしただけで印刷が始まっては困る
- **カーソルのときは出さない**(`pointerType === 'mouse'` で帰る)。
  あちらには `title` がある。**同じことをするものを2つ見せない**
- **読み上げ機には、いつも名前を渡す**(`aria-label`)

#### **言葉が要る状態では、言葉を出す**

絵だけでは言えないものが3つある。**そのときだけ**横に言葉が出て、
ボタンがその幅に広がる(`text`)。ふだんは絵だけに戻るので、
幅が広がるのは状態のあいだだけである。

| 何 | なぜ絵では言えないか |
|---|---|
| **本当に消す**(2段め) | 元に戻せない。「いま押したら本当に消える」が絵にならない |
| **集めています… 3 / 14** | **進み具合は必ず数で出す。** 絵だけでは止まって見える |
| **作っています… 3 / 14** | 同上(しかもこちらは課金が走っている) |

**「読み上げ音声を作り直す」の「閉じる」だけは言葉にしない。**
押すと**すぐ下に欄が開く**ので、開いていることは目に見えている。
うすい青の印(`iconbtn--on`)だけで足りる。

#### **絵だけでは言えないものがある。だから4つとも絵にはしなかった**(2手め)

2026-09 実機・利用者の指定。**上の直しを、その日のうちに一段進めた。**

> 「音声を作り直す」「学習の記録を消す」を教材を消すの左側に並べて、
> 「印刷 / PDF」と「音声ダウンロード」アイコンを今の位置に並べてください。
> ちなみに、印刷 / PDFマークについては「🖨️」だけでは PDF が出せることが
> わからないので、「印刷 / PDF」として、音声ダウンロードもそのまま
> 「音声ダウンロード」としましょう。
> **もともとスペースの問題だったのでこれで解決です。**

**利用者の言うとおりだった。** プリンタの絵からは「PDF でも出せる」が
読み取れず、下向きの矢印からは「**何を**落とすのか」が分からない。
長押しすれば名前は出るが、**それは知らないと押せない。**

**詰まっていたのは「4つ並んでいた」ことのほうで、絵にすることは
目的ではなかった。** 役目で2つの行に分ければ、2つずつになる。

| 行 | 何 | 見た目 |
|---|---|---|
| `.card-tools`(いまの位置) | 印刷 / PDF ・ 音声ダウンロード | **言葉つき** |
| `.material-foot`(いちばん下) | 読み上げ音声を作り直す ・ 練習の記録を消す ・ **教材を消す** | **絵のまま** |

- **分け方は「どれくらい押すか」ではなく「後戻りが利くか」。**
  下の3つは、作り直し(そのまま課金)・記録を消す・教材を消すで、
  **どれも元に戻らない。** ふだん使う2つから離す理由がそろっている
- **下の2つは絵のまま。**「読み上げ音声を作り直す」は11文字あり、
  「教材を消す」と並べると iPhone では1行に入らない。
  長押しで名前が出る(`IconButton`)
- **`MaterialDelete` は自分の行(`.btn-row.material-danger`)を持ったまま
  中に入る。** 外から包むと、**消せない人のカードに線だけが残る**
  (あの部品は消せない人には何も描かない)。だから中の余白と線は
  `.material-foot` の側で打ち消す
- **説明と知らせは、次の行いっぱいに落とす**(`flex: 1 0 100%`)。
  そのままだとボタンの横に並び、細い柱に押し込まれて読めなくなる
- **作り直しの欄と、記録を消すときの説明も一緒に下げた。**
  **失敗の知らせは、その操作をした場所に出す**(CLAUDE.md)

#### 検証は「1行に収まったか」だけを見ない

**それだけだと、絵を小さくして押せなくしても緑のまま**になる。
`npm run test:bar` は 390 / 375 / 360 / 320px で見る。

①**上の行に言葉が出ているか**(絵だけに戻すと、利用者の指定が消える)
②**下の3つが同じ1行にいて、「教材を消す」が右端か**
③**40px を割っていないか** ④**`aria-label` が渡っているか**
⑤**長押しで名前が出るか** ⑥**ふつうのタップは効くか**
(ここが壊れると**どのボタンも押せなくなる**)
⑦**言葉が要る状態で言葉が出るか** ⑧**「教材をシェア」があるか**。
あわせて **`TrainerMaterials` が本当に同じ形で書いているか**も見る
——検証の入り口(`__screens.jsx`)だけ直しても、利用者の画面は変わらない。

**同じ1行かを、上端で比べない。** 絵のボタンは 40px、「教材を消す」は
34px なので、まん中でそろえてある行では**上端が 3px ずれる**(実測)。
見るのは**まん中**である。

実際に ①長押しを外す ②画面の1つを元のボタンに戻す
③`.material-foot` の並べ方を壊す ④`askOpenId` を渡すのをやめる、の
4つで、赤くなることを確かめてある。

#### **直したのは「教材」の画面だけ**

同じ形の行は `TrainerLearners`(過去の宿題)と `LearnerHomework`
(今週の宿題)にもあるが、**あちらは印刷が1つあるだけ**で、
詰まっていない。**言われた場所だけを直す**(共通ルール)。
4つ並ぶようになったら、そのときここと同じ形にする。

#### **渡す道をボタン1つにまとめ、3つ並べた**(3手め・2026-09 利用者の指定)

> 「教材をシェア」と「教材をゲストと共有」はボタンをひとつにして
> その中でゲストと共有なのか普通の共有なのかを選べるようにしてください。
> 省スペースです。そして、スマホの表示で、「印刷/PDF」「音声ダウンロード」
> 「教材をシェア」を適宜言葉を減らしてアイコンを活かすことで
> ３つ並ぶようにしてください。直感でわかれば良いのです。

**2手めと逆のことを言われている。方針の変更である。経緯ごと残す。**
あのとき言葉を残したのは**2つだったから**で、
3つになれば入る幅が変わる。**数が変われば、答えも変わる。**

| | 上の行 | 人に渡す行 |
|---|---|---|
| 2手め | 印刷 / PDF ・ 音声ダウンロード | この教材をゲストと共有する ・ 教材をシェア |
| **3手め** | **🖨 PDF ・ ⬇ 音声 ・ ⤳ 共有** | **無し**(共有に吸収した) |

##### **絵だけには戻していない。削ったのは添えの部分だけ**

    🖨 PDF   … 絵が「印刷」、字が「PDF も出せる」  ← 2手めの心配はここで消える
    ⬇ 音声   … 絵が「落とす」、字が「何を」
    ⤳ 共有   … 絵が「渡す」、字が「何をするか」

**何のボタンかを言う語は、1つずつ残っている。**
落としたのは「印刷 /」「ダウンロード」「教材を…シェア」という添えだけである。

- **集めているあいだの文言も短くする**(`dlShort`)。
  「集めています… 3 / 14」では3つ並ばない。
  **削るのは動詞だけで、数は1文字も削らない**(進み具合は必ず数で出す)。
  動いていることは、**数が増えることと、押せなくなること**が言う
- **`label()` は残す。** ゲストの「今週の宿題」はボタンが少なく、
  あちらは言葉のまま入る(**押す場所ごとに要る幅が違う**)
- **`ShareIcon` を足した**(点と点をつなぐ形)。`LinkIcon`(鎖)では
  「リンクを渡す」しか言えず、**ゲストに宿題として出す道**を言えない。
  **足す前に、同じ絵がもう無いかを探してある**

##### 中で選ぶ。**ここでは「どちらにしますか」を先に訊く**

`MaterialShare` には**逆の決まりが書いてあった** ——
「2つとも出しておけば、選ぶことがそのまま操作になる」。
あれは**メール / リンクという小さな2つ**の話で、**いまも守っている**
(リンクを選んだ中では、①②が並んで出る)。

**ゲストを選ぶ欄は大きい**(担当25人ぶんのチェックが並ぶ)ので、
両方を開くと箱が画面2枚ぶんになる。利用者が挙げた目的は**省スペース**で、
言葉も「**選べるように**」である。**利用者の言葉が勝つ。**

- 札は **`.chip` / `.chip--on` を使い回す**(ここで新しい配色を作らない)。
  **色だけに頼らない**(うすい地色 + 同じ色の文字 + 枠線 + 太字)
- **既定は「ゲストと共有」。** このアプリの中心は
  「弱点から教材を作り、**指定したゲストに配る**」循環である(冒頭)
- **開くたびに既定へ戻す。** 前に「リンクを渡す」を見ていた人が
  次の教材でもそこから始まると、**ゲストに配る道が隠れて見える**
- **並べない。入れ替える**(訳の出し方と同じ決まり)
- **開け閉めは呼ぶ側(`TrainerMaterials`)が持つ**
  (`open` / `onOpen` / `onClose`)。中に閉じ込めると、
  **共有し終わったときに閉じる合図をもう1本渡す**ことになる
- **「やめる」は箱が持つ。** どちらの道でも同じ場所にある
- 開いている印は **`.btn.share-open.is-on`。`.btn.is-on` と広げない** ——
  `is-on` は読み上げの操作盤(`player-play`)など**あちこちで別の意味**に
  使っており、広げるとそこまで青くなる(**寄せたついでに直さない**)

##### 幅は実測して決めた。**いちばん狭い端末では余白だけを詰める**

| | 3つぶんの幅 | 入る幅(320px) |
|---|---|---|
| ふつう | 221px | 262px |
| 集めている最中 | 232px | 262px |
| **320px + 文字 1.25 倍 + 集めている最中** | **265px** | **262px** ← 3px 足りない |

その1つだけ、**ボタンの中の字が2行に折り返していた**(高さ 34 → 55px)。
360px 以下で**余白だけ**を詰める(12px → 8px・隙間 6px → 4px)。
**言葉も、集めた本数も1文字も削らない。** `.btn--small` の 34px は
そのままなので、押せる大きさは変わらない。

##### **開いた箱は、行の外へ落とす**(撮って初めて気づいた)

いちばん危なかったのはここである。`MaterialShare` は
**ボタンと箱を続けて返す**ので、ボタンを `.card-tools` に置くと
**箱も同じ行の一員**になる。行は `nowrap` だったので箱がそこへ割り込み、
**PDF / 音声 / 共有が縦棒3本に潰れた。**

**高さも「はみ出し」も正常のまま**だったので、
**測っても気づけなかった** —— `SHOT` で撮って初めて分かった。

- `flex-basis: 100%` は**折り返す行でしか効かない。** だから
  `.card-tools` の `nowrap` をやめ、`.share-box` に `flex: 1 0 100%` を置く
- **3つは実測で 320px でも 221〜253px に収まる**ので折り返さない。
  もし入らなくなったら縦に積まれるが、そこは検証が
  「3つが1行か」で赤くする ——**潰れて気づけないより、赤くなるほうがよい**
- 検証にも足した ——**開いたとき、箱がボタンの下にいるか**と、
  **いちばん細いボタンが 50px を割っていないか**
  (実際に戻すと **44px / 34px** で赤くなる)

##### 検証は「1つになったか」だけを見ない

**それだと、片方の道を消しても緑のまま**になる。
`npm run test:bar` は ①ボタンが1つか(**前の2つが残っていないか**)
②開くと2つとも選べるか ③**既定はゲストと共有か**
④切り替えると**中身が本当に入れ替わるか**
⑤3つが1行か(**文字 1.25 倍でも**)⑥集めた本数が消えていないか
⑦**開いても3つの行が崩れていないか**、を見る。

**「あるか」だけでも足りない** —— 共有だけ別の行へ戻しても
「`<MaterialShare>` がある」は満たされるので、
**3つとも同じ `.card-tools` の中にいるか**まで数える。

### 弱点タグは**画面と表の2か所**にある。片方だけに足さない(0050)

2026-09 利用者の指定。

> ついでに苦手タグの文法項目にまだないもので
> 一般的なものがあれば追加してください

文法の見出しは16件しか無く、**受動態・助動詞・動名詞・文型といった、
どの文法書にも見出しがあるものが選べなかった。**15件足した
(文型 / 受動態 / 助動詞 / 動名詞 / 関係副詞 / 代名詞 / 使役・知覚 /
話法 / 否定 / 強調・倒置 / 形容詞と副詞 / 未来の言い方 / there の文 /
命令文・依頼 / 時・条件の節)。

- **既存の16件は1文字も触っていない。** 並びも動かしていない
  (「一度入れたものを勝手に減らさない」— 並べ替えも減らすに当たる)
- **見出し(`category`)は増やしていない。** 言われたのは文法の項目である

#### **`material_tags.tag_id` は表を参照している。だから SQL が要る**

    tag_id text not null references public.weakness_tags(id)

つまり**画面(`weaknessTags.js`)に足しただけでは足りない。**
そのタグを付けて教材を**発行した瞬間に**外部キー違反で止まる。
`npm run lint` も `npm run build` も通る ——
**演習の種類・教材の種類で2度踏んだ穴と、まったく同じ形**である。

- `scripts/check-exercise-types.mjs` が**3つめとして**見張る
  (`npm run test:db` の中)。表のタグ一覧を渡して、
  **画面にあって表に無いもの**を赤くする
- **表のほうが多いぶんには何も言わない。** 使わなくなったタグを
  表から消さない(消すと過去の教材が行方不明になる)ので、
  そちらは正しい状態である

#### この見張りは、**作った日にもとからの抜けを1つ捕まえた**

いちばん最初に赤くなったのは、足した15件ではなく **`all-vowels`
(母音全般)**だった。`all-consonants`(子音全般)は 0001 で入っている
のに、**母音のほうはどの移行にも無い。** 画面には最初からあるので、

#### 「無生物主語」と「名詞構文」を足した(0060・2026-09 利用者の指定)

**貼る先のタグが無かった。**

#### 「丁寧な言い回し」を足した(0061・2026-09 利用者の指定)

  ③「やわらげる・提案する(仕事で効く)」がそのままこの型である。

### 第5.384節 教材の題名が、どれも「レベル」になっていた(2026-10-05)

利用者の指定(写真つき)。

> 同じレベルで「応答問題」をいくつか作ってゲストにアサインすると、
> 一番大きく表示される題名がすべて同じなので、見分けがつかず探しにくい、
> 分かりにくいです。…… 大切な部分です。
> A2＋という題名の２つの教材は違う内容のものです。日付も同じなのでより分かりにくいです。

#### 原因 —— **他に出すものが無かった**

教材名は `日付 / 試験・PART / ジャンル・場面 / 弱点タグ / レベル / 業種` を
つないで作られる(`MaterialForm` の `autoTitle()`)。
**応答問題は、場面も弱点タグも業種も持たない**ので、残るのが `日付 / A2+` だけ。
見出し(`MaterialTitle`)は日付を右上へ逃がすので、
**大きく出るのがレベルだけ**になっていた。

しかも**レベルは、すぐ下の札にもう1つ出ている。**
同じことを2つ見せている状態である。

#### 直し方は3つ重ねた(利用者が「案1 + 案3 + 案4」で指定)

| | 何をするか | 費用 | いまある教材 |
|---|---|---|---|
| **案1** | 中身から組む(正解にする表現の先頭 + ほか N) | **0円** | **効く** |
| **案3** | AI に一言の呼び名を1行返させる | 1本 0.01円未満 | 効かない |
| **案4** | 「教材名」の欄を、畳みの外へ出す | 0円 | — |

#### **どれを名前にするかは `materialName.js` 1か所**

画面の中で `kind === 'response'` や `main === level` と書かない。
**置く場所の数だけ食い違う**(CLAUDE.md「判断は1か所に持つ」)。

| 順 | どこから | いつ |
|---|---|---|
| ① `typed` | トレーナーが書いた名前 | **レベルそのものでなければ** |
| ② `nickname` | AI の呼び名(`headline_ja`) | **本文の無い教材だけ** |
| ③ `content` | 中身(表現の先頭 + ほか N) | **いまある教材にも効く** |
| ④ `kind` | 種類の名前(「応答問題」) | 中身がまだ読めていないとき |

- **どこから来た呼び名かも返す**(`from`)。
  これが無いと、見張りが**①と③を取り違えて緑**になる
- **重なりを数えない。** 応答問題は**1つの表現を2回**正解にする設計なので
  (第5.332節)、そのまま数えると「ほか 19 表現」のように倍で出る
- **並びは `seq`。** Supabase は読んできた順を約束しない

#### **`materialName()` だけ直しても、実機では何も変わらなかった**

トレーナーが見る「過去の宿題」の一覧は、**軽くするために中身を読んでいない**
(数えるための `id` だけ)。読まないままだと、呼び名はいつも「応答問題」になる。

**`material_items ( id )` を `( id, seq, answer )` にした。**
行は1件も増えていない —— もともと引いていたところに短い欄を1つ足しただけで、
本文も訳も読んでいない。`npm run test:name` が、両方を見張る。

#### AI の呼び名は `headline_ja` に入れる(**SQL は1行も要らない**)

本文のある教材では「見出しの訳」、本文の無い教材では「呼び名」。
**どちらも「日本語で見たときの見出し」**で、列はもう在る。
`materialName()` が、**`headline` があるときは呼び名を使わない**ので、
画面で2つが並ぶことはない。

- **最初の演習で1本だけ**受け取る(指導ポイントとまったく同じ理由。
  演習ごとに集めると言い換えが並ぶ)
- 窓口には「**種類の名前・レベル・日付・ゲスト名を書くな**」と頼んである。
  それらを返されたら、いまと何も変わらない

#### 「教材名」の欄は、**前からあった**

「詳しく設定する(任意)」の中に畳まれていて、`placeholder` も
「作ると自動で入ります」だったので、**誰も書かないまま**になっていた。
畳みの外へ出し、「空なら、中身から自動で付きます」に変えた。
**必須にはしない** —— 作業時間がこの仕組みの制約である(第5.6節)。

#### 見張り(`npm run test:name`・新しい検証)

- **「名前が付いた」だけで緑にしない。** いちばん困るのは
  **同じ名前が2つ並ぶこと**なので、**違う中身には違う名前が付く**まで測る
- **「出ない側」** —— トレーナーが書いた名前は、中身があっても上書きしない。
  本文のある教材では、見出しの訳を名前にしない
- **`MaterialTitle` を呼ぶ 9 か所が、ぜんぶ教材を渡しているか。**
  1か所でも渡し忘れると、そこだけ古い名前(レベル)が出る ——
  **画面を開くまで誰にも分からない形**である
- 長さの上限は**書き写さない**(`PHRASE_MAX` から読む)

### 第5.386節 教材の一覧が、新しい 50 件で打ち切られていた(2026-10-05)

利用者の指摘。

> ゲストのページで「この人に教材を作る」で作った教材が、
> 普通の「教材」のページに反映されず、他のゲストに共有できないことです

#### 探し方 —— **作る道を2つとも読んで、同じだと確かめた**

まず「ゲストのページから作ると、何かが違うのではないか」を疑った。
**違わなかった。** 作る画面(`MaterialForm`)は2つの入り口で同じものを使い、
`visibility` は既定の「全トレーナーで共有」、`status` も同じ、
共有しても教材の行は1列も書き換えない。**ここで直すと見当違いになる。**

そこで**利用者に2つだけ聞いた。** 返ってきたのがこれである。

| 聞いたこと | 答え |
|---|---|
| 絞り込みを全部「指定なし」にしても出ないか | **指定なしでも出てこない** |
| 公開範囲はどちらだったか | 見ていない |

**「指定なしでも出ない」のに「過去の宿題では見えている」。**
この2つが同時に起きるなら、**データベースの権限(RLS)ではない** ——
過去の宿題は `assignments` の中に教材をぶら下げて読んでおり、
RLS が隠していれば、そこでも「(消された教材)」になるからである。
**一覧の側が落としている。**

#### 原因 —— `.limit(50)` の決め打ち

    .order('created_at', { ascending: false })
    .limit(50)                              ← ここ

**新しい順の 50 件しか読んでいなかった。** 51 件目から先は、
絞り込みを全部外しても出てこない。**作ったのに消えたように見え、
見つからないから他のゲストにも共有できない。**

- **「黙って絞らない」(CLAUDE.md)の破り方そのもの**である。
  画面には何も出ていなかった
- しかもこの仕組みは**ライブラリ 333 件**を前提に設計されている
  (第5.6.2節)。**大半がいつも見えない**状態だった
- 同じ打ち切りが**アサインする画面**にもあった ——
  「他のゲストに共有できない」は、こちらでも起きる

#### 直し方 —— **1件だけ余分に読む**

全部いちどに読まない。教材1件は本文も設問もぶら下げて読むので、
333 件を一度に読むと何 MB にもなる(開くのが遅くなる)。

**1ページぶん + 1件**を読み、**その1件が返ってきたかどうかで
「まだ先がある」を知る。** 件数を数える問い合わせを増やさない。

- 区切りの算段は `src/lib/pageList.js` 1か所。
  **1ページぶんの件数(`PAGE_SIZE`)も、ここだけ**に書く
- **並びは2段**(`created_at` → `id`)。同じ秒の教材が2本あると、
  ページの切れ目で**同じものが二度出たり、1本飛んだり**する
- 画面には**「◯件まで出しています」+「さらに読み込む」**を置いた。
  文字は**いまの状態だけ**(「余計な説明書きを置かない」)
- ★ **先があるときは「ありません」と言わない。**
  続きに在るかもしれないのに「この条件に合う教材はまだありません」と
  出すと、**要らない教材をもう1本作らせる**(そのぶん課金される)

#### 見張り(`npm run test:play`)

**`materials.js` は Supabase を引き連れていて、手元で一度も走らせられない。**
だから区切りの算段を `pageList.js` へ出した
(CLAUDE.md「測れない場所に置いてあると、見張りが1本も書けない」)。

- **ちょうど1ページぶんなら「まだ先がある」と言わない**(出ない側)。
  ここが `>=` だと、**いつも「さらに読み込む」が出続ける**
- **1件多ければ先がある。その1件は出さない**
- **読む範囲は1ページぶん + 1件**。`- 1` が付いていると、
  最後のページで言い続けるか、1件足りないかのどちらかになる
- **続きは、出した件数の次から**(重ならない・飛ばさない)
- **決め打ちの打ち切りが残っていない** / **並びが id まで決まっている**
- **画面2つが、続きを読みに行ける**(窓口だけ直して画面に書き写していない、
  がこのリポジトリで何度も起きた)
- 変な値(負・0・NaN)や、行が無いときでも落ちない

##### 既にある見張りを1本、**式を書き写していたせいで赤くした**

アサインの画面の「追い越された結果は捨てる」が、
`if (alive) setMats(data ?? [])` を**そのまま書き写して**いた。
`if (!alive) return` に書き換えただけで、**仕組みは1ミリも壊れていないのに
赤くなった**(CLAUDE.md「式も、関数の名前も書き写さない」)。
**性質で見る形に直した** —— 受け取ってから `setMats` を呼ぶまでのあいだに、
生きているかの確かめが入っていること。

### `.select()` の中にコメントを書いて、**すべてのゲストの宿題を消した**(第5.389節)

2026-10-06 実機・利用者の指摘。

> というよりすべてのゲストのすべての宿題が消えているか
> アサインの紐づけがなくなっています

#### 何が起きていたか

第5.384節(教材の呼び名)で、宿題を読む問い合わせに `answer` を足したとき、
**`.select()` に渡す文字列の中に説明を書いた。**

    .select(`
      id, assigned_at, due_on, learner_done_at, admin_checked_at,
      materials (
        …,
        material_tags ( tag_id ),
        /* ★ answer も読む(第5.384節)… */        ← ここ
        material_sections ( id, seq, material_items ( id, seq, answer ) )
      )
    `)

**あれは JavaScript のコメントではない。**
`.select()` に渡すのは**列の名前を並べた1本の文字列**なので、
`/*` も日本語の説明も、**そのまま Supabase へ送られる。**

実際に送られていたのはこれである(supabase-js は空白だけを落とす)。

    …material_tags(tag_id),/*★answerも読む(第5.384節・2026-10-05利用者の…

PostgREST はこれを列の名前として読もうとして断る。
**問い合わせがまるごと失敗し、すべてのゲストの宿題が1件も返らなくなった。**

#### なぜ気づけなかったか

| 仕組み | なぜ助けてくれなかったか |
|---|---|
| `npm run lint` | **JavaScript としては正しい**(ただの文字列である) |
| `npm run build` | 同じ理由で通る |
| `runTolerant()` | **「そんな列は無い」(42703)だけ**を拾う。この断り方は拾わない |
| この環境 | **`supabase.co` へ届かない。** 1度も走らせていない |

**CLAUDE.md「`npm run build` が通っても安心してはいけない」の、4つめの形**である。

#### **メモが書けなくなったのも、同じ1つの原因だった**

> あと、ゲストとセッションしている間のメモも書き込めなくなっていました!
> サイレント退化、本当にやめてほしいです。。。

**別の退化ではない。** 「セッションで使う(大きく表示)」のボタンは、
**過去の宿題の行ごと**に描かれている(`TrainerLearners`)。
宿題が 0 件になると**ボタンが1つも出ない**ので、
そのゲストの教材を開けず、**セッションの記録(メモ)にも入れない**
(`LessonView` の `owner` が決まらない)。

**1つの原因が、2つの困りごとに見えていた。**
`LessonNotes` 自身は 2026-09-28 から1文字も変えていないし、
あちらは失敗をきちんと画面に出している。

#### 見つけ方 —— **送られる文字列を、命令文として読み直す**

「コメントを書いていないか」をソースで探すだけでは**弱い。**
次は別の書き方で壊れる。**列の名前の並びとして正しい形か**を、
1文字ずつ確かめる(`npm run test:play` の ⑮)。

| 見るもの | 何を捕まえるか |
|---|---|
| 使ってよい文字(`[A-Za-z0-9_.*,():!>-"]`)だけか | コメント・日本語・記号の混入 |
| 丸かっこの数が合っているか | 打ち間違い |
| 中身の無い丸かっこが無いか | 消し忘れ |

- **`${…}` の差し込み(`opt()` / `optLast()`)は、先に外してから見る** ——
  あれは走らせたときに列の名前へ化けるので、形の判断には関われない
- **空白の落とし方は supabase-js と同じ**にする(あちらは空白だけを捨てる)
- **見張りの中に、実機を壊した形そのものを1つ置いてある。**
  それが赤くならなければ、見張りが腐っているということである

- **「無ければ素通り」させない**(CLAUDE.md)。
  取り出せた `.select()` の数も出す —— 0 個なら、何も測っていない

**赤チェックは3通り**(どれも、その1本を外したら赤くなるか)。

| 壊したもの | 出た言葉 |
|---|---|
| コメントを戻す | 使えない文字 「/」「★」「も」「読」「む」 |
| 丸かっこを1つ落とす | 丸かっこが閉じていない |
| 見張りの正規表現を壊す | 取り出せた `.select()` は 0 個 |
- **素のクォートの `.select('…')` は相手にしない** ——
  あちらには改行が書けないので、コメントを書く余地がない
- **説明は、必ず文字列の外に書く。** 直したあとはこの形である

#### 壊れていたのは1か所だけだった(数えて確かめた)

入っていない**(確かめた)。
