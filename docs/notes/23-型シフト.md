# 型シフト — 同じ内容を、別の型で言い直す

2026-09 利用者の指定。

> 画期的なトレーニングを作りたいです

そのうえで、どこから作るかを選んでもらった ——
**「型シフトの練習画面から」**、お題は
**「仕事の場面から新しく書く」+「66 型の見本を種にする」**。

---

### 何が新しいのか。**測ってから書いた**

`frameMatch.js`(型を決まりで見分ける道具)を、**採点**に使ったのが新しい。

| 入れた文 | 見分けた型 |
|---|---|
| The price worries me. | — (型なし・素の文) |
| It's the price that worries me. | ○ `It is X that / who ~` |
| What worries me is the price. | ○ `What ~ is …` |
| When it comes to the price, we need to talk. | ○ `When it comes to ~` |

**同じ内容を別の型で言い直した文を、機械が判定できる。**
66 型の見本は **66 / 66** 言い当てる。**AI を呼ばないので 0円。**

- **パタプラ・スピフル**は「**語**を入れ替える」。型を入れ替える練習は無い
- **瞬間英作文**は「和文 → 英文」の**1対1**。同じ内容を3通りで言う練習は無い
- そして何より、**言い換えが正しいかを機械で採点できない**。
  採点できないから、その練習が作れない

### **✕ を付けない。** ここがいちばん大事

`frameMatch` は**迷ったら黙る**(取り違えるくらいなら、見落とすほう)。
だから「見分けられなかった」は「**間違っている**」ではない。

実際 `It is not cost but timing.` は正しい英語だが見分けられない
(`but` のうしろが冠詞の無い裸の名詞のため)。
これを ✕ と出したら、**正しく言えた人に嘘をつくことになる。**

返す答えは4つ。**`unsure` は ✕ ではない。**

| 返り | いつ | 見せ方 |
|---|---|---|
| `ok` | 狙った型で言えている | ○ |
| `other` | **別の型**になっている | 型の名前を出して知らせる(✕ではない) |
| `unsure` | 型として見分けられない | 「たしかめられませんでした」+ お手本 |
| `empty` | 何も言っていない | 何も出さない |

`npm run test:shift` が「**4つの道が全部出るか**」を見る。
片方しか見ないと、**どこにも ○ を出さない形・全部 ○ にする形**に
書き換えても緑のままになる(CLAUDE.md「出ると出ないの両方を見る」)。

### **素の文を見せる。** 和文英訳に戻さないため

日本語だけを出すと「和文英訳」になり、**訳せたかどうか**の練習に戻る。
鍛えたいのは**言い換える力**なので、**言える形(素の文)を先に見せて、
そこから型へ移してもらう。**

`npm run test:shift` は「**素の文が、どの型にも当たらない**」ことも見る。
素の文がすでにその型なら、言い直す練習が成り立たないからである。
(37 本すべてが 66 型のどれでもないことを確かめてある)

### **66 型を、最初の版から1つも落とさない**

37 お題 / **66 問**(答え)で、**66 型すべてに少なくとも1問ある。**
あとから問を増やすときに「型の抜け」から直すのは大変だからである
(**一覧を勝手に減らさない**・`.claude/rules/common.md`)。

`test:shift` は**数を書き写さない。**「型の数 = 覆った型の数」という
**関係**で見る —— お題を1つ足した日に期待値も一緒に動いてしまわないように。

| お題 66 問 | `src/data/frameShift.js`(**ファイル・0円**) |

**Quick Response の問そのもの**だからである。
型シフトの答えを同じところへ入れると、**Quick Response 帳に 66 文が混ざる。**
利用者の指定「最終的には単語帳も Quick Response 帳もすっきり見やすく

畳んだ代わりに、**掛かっている絞り込みは畳んだままでも見せる** ——
**黙って絞らない**(CLAUDE.md)。

**出る形と出ない形の両方**を見る。

### **66 の型を、カテゴリー別のトレーニングにした**(2026-09 利用者の指定)

> これら 66 の型をカテゴリー別に分け、
> それぞれを活用するためのトレーニングを作りたい

**区分けは、ここで作らない。** `sentenceFrames.js` の
**節(3つ)と組(14)**がすでに持っている。別の分け方を作ると、
**分け方が2つ**になり、どちらが本物か分からなくなる。
`src/data/frameTraining.js` が持つのは
**「その組で、何をするか」だけ**である。

#### 14 の組を、8つの「やること」に束ねた

| やること | 組 | 指示 |
|---|---|---|
| モノを主語にする | ①の7組 | モノ・ことを主語にして、言い直す |
| 主語の席に、かたまりを入れる | ② | 主語をひとつのかたまりにして、言い直す |
| 焦点を当てる | ③ 焦点 | 際立たせたいところを前に出して、言い直す |
| 話題を先に置く | ③ 話題 | 何の話かを先に置いて、言い直す |
| 文と文をつなぐ | ③ つなぐ | 2つを1つにつないで、言い直す |
| 1文を後ろへ伸ばす | ③ 伸ばす | うしろに説明を足して、1文に収める |
| やわらげる・提案する | ③ やわらげ | 角が立たない言い方に変える |
| 比べる | ③ 比べる | A と B を比べる形で、言い直す |

- **①の7組は、やることが同じ**(人ではなくモノを主語にする)。
  違うのは動詞の意味あいだけなので、練習の形は1つにした
- **③の6組は、やることがそれぞれ違う。** 焦点は語順を変える練習、
  つなぐは2文を1文にする練習、やわらげるは角を落とす練習で、
  **同じ画面で出しても頭の使い方が別**である

#### 入口を「一覧」にした

はじめは 66 問を1本の列にして「型の組」で絞る形にしていた。
**それだと、何の練習をしているのかが最後まで出てこない。**
いまは**一覧(14 枚のカード)から入る。**
カードには「やること」「その組の型の名前」「問の数」「言えた数」が出る。

- **同じ指示を7回くり返さない。** ①の7枚は指示が同じなので、
  **変わったときだけ**出す。代わりに**その組の型の名前**を出す ——
  組ごとに必ず違うので、これが見分けの手がかりになる
  (**同じことをするものを2つ見せない**・CLAUDE.md)

#### **`what 節` の問が、ちがう組に入り込んでいた**(カードの数で気づいた)

一覧を描いたら、**② が 5 問・③焦点が 6 問**になっていた(本来 6 と 5)。

原因は1つ。組を**読み替え先**(`shiftTargetOf`)から引いていた。
`what 節`(②)は `SAME_SHAPE` で `What ~ is …`(③)として見分けるので、
**③焦点の組に入ってしまう。**

**読み替えは採点のためだけのもの**で、
**どのカテゴリーの練習かとは別**である。組は**書いたほうの型**から引く。

見張りも足した ——
**組ごとの問の数が、その組の型の数と合うか。**
これが、この食い違いを機械で見つける唯一の形である
(問の総数だけ見ていても、どちらの組に入っていても 66 のままで気づけない)。

### **書き込む欄は置かない**(2026-09 実機・利用者の指定)

> 書き込む欄はいらないですね。基本的にタイプするのは面倒なので
> 型シフトトレーニングについては書き込みはなしを共通仕様にしてください

これは**話す練習**である。打たせると、**打つ速さの練習**になってしまう。
**共通仕様**なので、14 のカテゴリーでも名詞句の入れ替えでも同じ。

- 答えるのは**マイクだけ**。「見てもらう」ボタンも要らなくなった
  (話し終わった時点で判定する)
- **聞き取った文は必ず見せる。** 何と聞こえたか分からないと、
  判定に納得できない
- `npm run test:shift` が、この画面に `input` / `textarea` が
  **1つでもあれば赤くする**(`onChange` も見る)

#### マイクが使えない端末を、行き止まりにしない

音声認識に対応していない端末では、**「言えた」を自分で押せる**ようにした。
**打たせないのは同じ**である。あわせて、なぜ機械で確かめられないのかも書く。

**箱ごと出さない。** はじめは「言い直した文」の枠を出したままにしていたが、
マイクが無い端末では一生うまらないうえ、
中の案内が「**マイクを押して**、声に出して言ってください」になっていた ——
**効かない操作を見せない**(CLAUDE.md)の破り方である。描いて気づいた。

### **段1「見分ける」**(2026-09 利用者の指定「どのように量をこなし」)

言い直す練習は1問 **20 秒**かかる。**量をこなす受け皿にならない。**
見分けるだけなら**1問3秒**で、移動中でも押せる。
そして「その型だと気づける」ことは、「その型で言える」ことの**手前**にある。

**素材を1文も書いていない。** すでにある文をそのまま使う ——
66 型の見本・型シフトの答え・名詞句を入れ替えた文。
**答えは機械が知っている**(`frameMatch.js`)ので、正解を書く必要もない。
**素材を足すと、この段の問も自動で増える。**

#### 「約 690 問」は、偏りを数えていなかった

はじめ「素材は約 690 文ある」と書いたが、**数えたら 660 文で、
しかも7つの型に 80 文ずつ偏っていた**(名詞句の入れ替えが、その7つの骨で
作られているため)。そのまま混ぜると**同じ型ばかり出る。**

だから**型ごとに最大3問**にそろえた。いまは **113 問 / 65 型**である。
`npm run test:shift` が「どの型も3問まで」を見張っている ——
上限を外すと赤くなる。

#### まぎらわしい選択肢は「同じ組」から

でたらめな3つを混ぜると、**組さえ分かれば当たる。**
だから同じ組(させる / させない / 要る…)から選ぶ。

**はじめ効いていなかった。** 同じ組・同じ節・全体を1本につないでから
**12 個まとめて混ぜて上から3つ**取っていたので、
同じ組に十分あってもよそから出ていた ——
**113 問中 16 問しか同じ組になっていなかった**(測って気づいた)。
**同じ組を使い切ってから、次の受け皿へ移る**形に直した。

#### 並びは、問の id から決める

毎回 `Math.random()` で混ぜると、**描き直すたびに選択肢が動く**
(押そうとした先が変わる)。問の id から種を作るので、
**同じ問なら必ず同じ並び**になる。

#### **2つの見張りが、互いを吸っていた**

「素材を入れる前に機械で確かめる」と「見分けられない型(`what 節`)を外す」は、
**どちらか片方を外しても、もう片方が拾ってしまう。**
いまの素材はどれも型に当たるので、数え上げの見張りも 0 のまま緑だった。

**赤チェックで赤くならないのは、壊し方が違うという知らせ**(CLAUDE.md)。
**書いてある形そのもの**を数える見張りを足して、
片方を消したら赤くなることを確かめた。
