# 名詞句 —— 単語帳の5冊目と、入れ替えの練習

2026-09 利用者の指定。

> どのビジネスでも使える「名詞句」を厳選し、単語帳に一つのコンテンツとして
> 置き、5文だけでなく、そこを言い換える練習ができるようにしたい。
> 名詞句とは、名詞だけでなく目的語もセットにしたいところです。

---

### 「目的語もセット」を、どう読んだか

**芯の名詞だけでは、文に入らない。**
`decision` を覚えても `the decision to postpone` は出てこない。
だから**うしろに続くところまで、ひとかたまりで覚える。**

    ×  decision                  … 芯だけ。文に入れるとき毎回つまずく
    ○  the decision to postpone  … そのまま主語にも目的語にもなる

**組1〜4(52 件)が、この「うしろに続きを持つ名詞句」**である。
組5・6(28 件)は **2語で1つになっている名詞句**(`a tight deadline` /
`a cost breakdown`)で、**文の中で同じ席に入る**ので入れた。
ご指定と少しずれるので、**要らなければ組ごと外せる形**にしてある。

| 組 | 件数 | 例 |
|---|---|---|
| OF(A の B) | 14 | `the cost of delay` |
| TO DO | 13 | `the ability to adapt` |
| PREP(前置詞が決まっている) | 17 | `a solution to the problem` |
| THAT(中身が文) | 8 | `the fact that we are behind` |
| ADJ + N | 18 | `a tight deadline` |
| N + N | 10 | `a cost breakdown` |

### 新しい仕組みを1つも作っていない

| 何 | どの道を使うか |
|---|---|
| 80 件 | `src/data/nounPhrases.js`(**ファイル・0円**) |
| 覚え具合 | **`word_reviews`** —— 自分の単語帳と同じ表 |
| 出題・4択・絞り込み・聞き流し・紙 | `Wordbook.jsx` そのまま |

**表も列も RPC も SQL も1行も増えていない。**
コロケーション(`collocationWords.js`)と**1文字も違わない形**にしてある。
`Wordbook.jsx` に足したのは「冊を1つ」と「読む道を1本」だけである。

**冊は後ろへ足す。並べ替えない**(docs/notes/22 の決まり)——
前へ割り込ませると、ゲストが覚えた置き場所が全部ずれる。
`npm run test:play` が、`'col'` より後ろに `'np'` があることを見ている。

### 「そこを言い換える練習」= 骨を固定して、肉だけ変える

66 の型は**骨**で、名詞句は**肉**である。

    When it comes to 〔 the cost of delay 〕, we need to be careful.
    When it comes to 〔 a lack of information 〕, we need to be careful.
    When it comes to 〔 a tight deadline 〕, we need to be careful.

例文を5つ読むのと違い、**80 通りを自分の口から出す**ことになる。
「型シフト」の一覧に **④ 名詞句を入れ替える** として1枚足した(**556 問**)。

#### 骨は「どんな名詞句でも入る」ものだけ

`There is ___.` のような骨は、冠詞で当たり外れが出る
(`There is a problem with the data.` は自然だが
`There is the root cause.` はおかしい)。
**`a` でも `the` でも自然に入る骨だけ**を7つ選んだ。

#### 出せない組み合わせは、はじめから出さない

7 × 80 = 560 通りのうち、**4通りだけ機械で確かめられない。**

- `the fact that we are behind` を入れると、**別の型(`the fact that`)に見える**
- `short notice` は冠詞が無いので、`It is X that` の決まりが弾く

**確かめられないものを出して「ちがう型です」と言わない** ——
正しく言えた人に嘘をつくことになる(型シフトの根っこの決まり)。
だから `swapQuestions()` が**機械で確かめてから出す。**
一覧を手で書いていないので、**名詞句を足したときも自動で付いてくる。**

**落とした数も見張る。** 決まりを1つ変えて大半が落ちても、
「出した問が全部 ○ になる」だけでは**緑のまま**である(0問でも緑)。
`npm run test:shift` は「落ちたのは全体の5%未満か」も見る。

#### 判定をもう1つ増やした —— `nophrase`

骨が合っていても、**入れるはずの名詞句が入っていなければ**
その練習をしたことにならない。

    言った  When it comes to money, we need to be careful.
    →  型は合っています。名詞句が入っていません
       この練習で入れるのは「the cost of delay」です。

**✕ にしない。** 骨は言えているのだから、あと1つである。
判定は `ok` / `other` / `unsure` / `empty` / **`nophrase`** の5つになった。

#### 英語を見せない。型の名前も重ねない

- **入れる名詞句の英語は画面に出さない。** 出すと写すだけになる ——
  意味はお題の日本語の中に出ている(思い出せなければ「お手本を見る」)
- **入れ替えの練習では、型の名前を出さない。**
  骨(`When it comes to ___, …`)にその型がそのまま書いてあるので、
  **同じことを2つ見せる**ことになる(CLAUDE.md)

### 例文には、その語句がそのまま出てくること

`npm run test:play` がいちばん効かせている見張りである。
出てこない例文だと、**文脈ごと覚える**という単語帳の前提がくずれる(0018)。

**大文字小文字は見ない。** 文頭に来ると `A lack of …` になるためで、
はじめ区別して数えたときは **24 件が偽の赤**になった。
本当に食い違っていたのは3件(`a reason to wait` / `a project plan` /
`a risk assessment` が、例文では `no` や `The` で始まっていた)。
