# 名詞句・副詞句・コロケーション —— 単語帳の冊と、入れ替えの練習

2026-09 利用者の指定。

> どのビジネスでも使える「名詞句」を厳選し、単語帳に一つのコンテンツとして
> 置き、5文だけでなく、そこを言い換える練習ができるようにしたい。
> 名詞句とは、名詞だけでなく目的語もセットにしたいところです。

---

### 「目的語もセット」を、どう読んだか

**芯の名詞だけでは、文に入らない。**
`decision` を覚えても `the decision to postpone` は出てこない。
だから**うしろに続くところまで、ひとかたまりで覚える。**

    ×  decision                  … 芯だけ。文に入れるとき毎回つまずく
    ○  the decision to postpone  … そのまま主語にも目的語にもなる

**組1〜4(52 件)が、この「うしろに続きを持つ名詞句」**である。
組5・6(28 件)は **2語で1つになっている名詞句**(`a tight deadline` /
`a cost breakdown`)で、**文の中で同じ席に入る**ので入れた。
ご指定と少しずれるので、**要らなければ組ごと外せる形**にしてある。

| 組 | 件数 | 例 |
|---|---|---|
| OF(A の B) | 14 | `the cost of delay` |
| TO DO | 13 | `the ability to adapt` |
| PREP(前置詞が決まっている) | 17 | `a solution to the problem` |
| THAT(中身が文) | 8 | `the fact that we are behind` |
| ADJ + N | 18 | `a tight deadline` |
| N + N | 10 | `a cost breakdown` |

### 新しい仕組みを1つも作っていない

| 何 | どの道を使うか |
|---|---|
| 80 件 | `src/data/nounPhrases.js`(**ファイル・0円**) |
| 覚え具合 | **`word_reviews`** —— 自分の単語帳と同じ表 |
| 出題・4択・絞り込み・聞き流し・紙 | `Wordbook.jsx` そのまま |

**表も列も RPC も SQL も1行も増えていない。**
コロケーション(`collocationWords.js`)と**1文字も違わない形**にしてある。
`Wordbook.jsx` に足したのは「冊を1つ」と「読む道を1本」だけである。

**冊は後ろへ足す。並べ替えない**(docs/notes/22 の決まり)——
前へ割り込ませると、ゲストが覚えた置き場所が全部ずれる。
`npm run test:play` が、`'col'` より後ろに `'np'` があることを見ている。

### 「そこを言い換える練習」= 骨を固定して、肉だけ変える

66 の型は**骨**で、名詞句は**肉**である。

    When it comes to 〔 the cost of delay 〕, we need to be careful.
    When it comes to 〔 a lack of information 〕, we need to be careful.
    When it comes to 〔 a tight deadline 〕, we need to be careful.

例文を5つ読むのと違い、**80 通りを自分の口から出す**ことになる。
「型シフト」の一覧に **④ 名詞句を入れ替える** として1枚足した(**556 問**)。

#### 骨は「どんな名詞句でも入る」ものだけ

`There is ___.` のような骨は、冠詞で当たり外れが出る
(`There is a problem with the data.` は自然だが
`There is the root cause.` はおかしい)。
**`a` でも `the` でも自然に入る骨だけ**を7つ選んだ。

#### 出せない組み合わせは、はじめから出さない

7 × 80 = 560 通りのうち、**4通りだけ機械で確かめられない。**

- `the fact that we are behind` を入れると、**別の型(`the fact that`)に見える**
- `short notice` は冠詞が無いので、`It is X that` の決まりが弾く

**確かめられないものを出して「ちがう型です」と言わない** ——
正しく言えた人に嘘をつくことになる(型シフトの根っこの決まり)。
だから `swapQuestions()` が**機械で確かめてから出す。**
一覧を手で書いていないので、**名詞句を足したときも自動で付いてくる。**

**落とした数も見張る。** 決まりを1つ変えて大半が落ちても、
「出した問が全部 ○ になる」だけでは**緑のまま**である(0問でも緑)。
`npm run test:shift` は「落ちたのは全体の5%未満か」も見る。

#### 判定をもう1つ増やした —— `nophrase`

骨が合っていても、**入れるはずの名詞句が入っていなければ**
その練習をしたことにならない。

    言った  When it comes to money, we need to be careful.
    →  型は合っています。名詞句が入っていません
       この練習で入れるのは「the cost of delay」です。

**✕ にしない。** 骨は言えているのだから、あと1つである。
判定は `ok` / `other` / `unsure` / `empty` / **`nophrase`** の5つになった。

#### 英語を見せない。型の名前も重ねない

- **入れる名詞句の英語は画面に出さない。** 出すと写すだけになる ——
  意味はお題の日本語の中に出ている(思い出せなければ「お手本を見る」)
- **入れ替えの練習では、型の名前を出さない。**
  骨(`When it comes to ___, …`)にその型がそのまま書いてあるので、
  **同じことを2つ見せる**ことになる(CLAUDE.md)

### **66 型ぜんぶに骨を用意した**(2026-09 利用者の指摘)

> 和らげと名詞句以外にも沢山型があったはずです。
> 私が全てを思い出せないだけで、などなど、と言う書き方をしましたが、
> 全てを網羅してください

**そのとおりだった。** 骨は7本しかなく、**66 型の1割しか数をこなせなかった。**
いまは `sentenceFrames.js` の **66 型すべてに骨が1本ずつある**。
`npm run test:shift` が「66 型ぜんぶに骨があるか」を見張る ——
型を足して骨を足し忘れたら赤くなる。

#### 席の種類(`slot`)で、入る肉が決まる

66 の型は、**空いている席の種類が違う。**

| `slot` | 入るもの | 出どころ | 骨 |
|---|---|---|---|
| `subj` | 無生物の主語 | `swapParts.js` | 31 |
| `vp` | 動詞のかたまり(原形) | `swapParts.js`(24) | 9 |
| `ving` | 動詞のかたまり(~ing) | 同上 | 2 |
| `np` | 名詞句 | `nounPhrases.js`(80) | 12 |
| `clause` | 短い文 | `swapParts.js`(16) | 5 |
| `own` | **その骨だけの肉** | 骨のとなりに書く | 7 |

**部品を1つ足すと、その席を持つ骨すべてに効く。**
手で書いたのは骨 66 本 + 部品 136 件 = **202 行**で、
**1,640 問**ができた(**1行あたり 8.1 問**)。

#### **主語の総当たりは、意味のおかしい文を大量に出す**

はじめ無生物主語を1つの一覧にして総当たりにしたら、こうなった。

    ○ This tool helps us meet the deadline.
    × The price helps us meet the deadline.       ← 値段が助けてくれる?
    × Poor planning helps us meet the deadline.   ← 準備不足のおかげで?
    × Bad weather allows you to work from home.

数えると、`___ allows you to …` に自然に入るのは **20 のうち 7 つ**だけだった。
**機械は型しか見ないので、この種のおかしさは捕まらない**
(`Poor planning helps us …` は型としては正しい)。

だから主語を**4つの性格**に分け、**骨のほうがどれを呼ぶかを言う**
(`pick: 'good' | 'bad' | 'info' | 'task'`)。

| 性格 | 中身 | 呼ぶ骨 |
|---|---|---|
| `good` | 後押しするもの(この道具・新しい仕組み) | させる・可能にする・良い結果 |
| `bad` | 妨げるもの(準備不足・その遅れ) | させない・悪い結果・困らせる |
| `info` | 知らせるもの(そのデータ・彼の一言) | 示す・説明する・思い出させる |
| `task` | 仕事・案件(この案件・その段取り) | 要る・かかる・含む |

見張りは**書いてある形そのもの**を数える ——
総当たりに戻しても型だけ見る見張りは緑のままだからである。

#### どれも単数にそろえた

`___ requires patience.` のような**現在形の骨**があるので、
複数の主語を混ぜると `Rising costs requires …` になる。
**一覧の側で単数にそろえる**(骨ごとに書き分けない)。
`test:shift` が「主語がどれも単数か」を見ている。

#### 薄かった骨を2本、自前の肉にした

- **名詞化(動詞→名詞)**: 名詞句 80 件を総当たりしても **12 件しか当たらない。**
  この型が言っているのは「**動詞を名詞にする**」であって名詞句一般ではない ——
  自前の肉 13 件に差し替えた
- **同格**: `our goal, ___` に冠詞の無い肉(`fewer complaints`)を入れると
  見分けられない。冠詞つきにそろえた

いまは **1,655 通りのうち 1,640 問**(99.1%)。いちばん少ない骨でも 8 問ある。

#### 骨は2段でえらぶ

66 本を1列に並べると札の壁になるので、
**まず組(14)をえらび、その中の骨をえらぶ。**
札には**その骨で何問出るか**も添える(**黙って絞らない**)。

### **3つの冊をまとめて厚くした**(2026-09 利用者の指定)

> ■ビジネスで使用する名詞句100
> ■ビジネスで使用する副詞句50
> ■ビジネスで使用するコロケーション50

| 冊 | 前 | 後 |
|---|---|---|
| **名詞句** | 80 | **100**(6組のまま、後ろへ足した) |
| **副詞句** | 無し | **50**(新しい冊・7組) |
| **コロケーション** | 50(基本動詞5つ) | **100**(ビジネスの5動詞を足した) |

#### コロケーションは、冊を増やさず同じ冊に足した

利用者の指定「同じ冊に足して 100 件に」。
**冊が増えると、ゲストは置き場所を覚え直すことになる**(docs/notes/22 の決まり)。

足したのは **MEET / REACH / RAISE / SET / HANDLE** の5動詞 × 10。
もとの MAKE / TAKE / GIVE / HAVE / DO は**1件も動かしていない。**

`npm run test:play` は **数を書き写さず**、
「**組の数 × 10 = 件数**」という関係で見る ——
組を足した日に、期待値も一緒に動いてしまわないように。

#### 副詞句は、名詞句と1文字も違わない形にした

`adverbPhrases.js` の行の形は `nounPhraseRows()` と同じなので、
`Wordbook.jsx` から下は**1文字も書き分けていない。**
足したのは「冊を1つ」と「読む道を1本」だけである。

**名詞句・コロケーションと何が違うか**を、ファイルの頭に書いた ——
名詞句は**文の席に入るもの**、コロケーションは**動詞と目的語の組**、
副詞句は**文にそえるもの**(いつ・どのくらい・どんな立場で)。

```
We will send it.                            … 骨だけ
We will send it 〔 by the end of the day 〕. … いつ
〔 To be honest 〕, we will send it tomorrow.  … どんな立場で
```

#### 冊は後ろへ足す。並べ替えない

札は **自分の単語帳 / 業種べつ / 基礎単語 / コロケーション / 名詞句 / 副詞句** の6つ。
`test:play` が「`np` より後ろに `adv` があるか」を見ている。

### 例文には、その語句がそのまま出てくること

`npm run test:play` がいちばん効かせている見張りである。
出てこない例文だと、**文脈ごと覚える**という単語帳の前提がくずれる(0018)。

**大文字小文字は見ない。** 文頭に来ると `A lack of …` になるためで、
はじめ区別して数えたときは **24 件が偽の赤**になった。
本当に食い違っていたのは3件(`a reason to wait` / `a project plan` /
`a risk assessment` が、例文では `no` や `The` で始まっていた)。

### ビジネス必須チャンク集 —— 3冊を1冊の中の3段にした(第5.199節)

2026-09 利用者の指定「今の3冊をこの中へまとめる」。

    冊  ビジネス必須チャンク集
    段  名詞句 / 副詞句 / コロケーション
    組  ◯◯まとめ + OF / TO DO / … / 前置詞句 / -ING / 5WH + SV

**`14 の型` とまったく同じ形**(冊 → 中身 → 型)。判断は
`src/lib/chunkBook.js` 1か所で、**Supabase を引き連れていない**ので
素の node で数えられる。画面は `ChunkParts`(props だけの部品)。

- **「まとめ」はどの段にも必ず置く**(利用者の指定「全てに共通とします」)。
  名前は段から作る(`${段}まとめ`)。**書き写さない**
- **段を替えたら、組は「まとめ」に戻す** —— 組の id は段ごとに違うので、
  残すとその段に無い組が選ばれたままになる(0件の画面・行き止まり)
- **行に欄を足していない。** 行はもともと `material_title` に組の名前を
  持っており、その名前を作るのは `chunkPool()` が呼ぶのと同じ関数である。
  欄を足すと `review_words()` と形が変わり、画面が書き分けを持つ
- **覚え具合は1語も動かない**(鍵は語句そのもの)

#### 足した組

| 組 | どこに | 件数 |
|---|---|---|
| **前置詞句** | 副詞句の中(利用者の指定「副詞句の中の前置詞句」) | 16 |
| **-ING** | 名詞句の中 | 10 |
| **5WH + SV** | 名詞句の中 | 10 |

**いまある 50 件の副詞句は動かしていない。** `by the end of the day` も
前置詞句だが、はたらきの組に入っているものはそのまま ——
動かすと、ゲストが覚えた置き場所がずれる(docs/notes/22 の決まり)。

#### 紙は、行ではなく**題**が足りなかった

紙は「いま画面に出ている一覧」から作るので、**絞りはもともと効いていた。**
足りなかったのは題で、`単語帳` / `Quick Response 帳` としか出ず、
**何を絞って刷ったのかが紙に残らなかった。**
題は**画面の題とまったく同じもの**を使う(2か所で組み立てない)。
