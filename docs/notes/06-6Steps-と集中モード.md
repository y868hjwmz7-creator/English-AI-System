### ③ オーバーラッピングは「2〜3語うしろから追いかける」

**「同時に重ねて読む」ではない**(2026-08 利用者の指定)。

> オーバーラッピングは音と同時に喋るではなく、音から2〜3単語遅れて、
> 耳に入り聞いて確認してから真似るのが正しいやり方です。

同時に声を出すと、自分の声でお手本が聞こえなくなる。
少し遅れて追いかけるから、耳で確かめてからまねられる。
⑤ シャドーイングとの違いは、**本文を見るか隠すか**だけである。

### 6Steps は「同じ本文への取り組み方」。演習として分けない

`src/lib/sixSteps.js` に6つの定義がある。①ディクテーション ②スラッシュリーディング
③オーバーラッピング ④意味音読 ⑤シャドーイング ⑥リピーティング。

**別々の教材ではない。** 分けたために「長文」が16個の短文になった
失敗がすでに一度ある。切り替えは `PassagePractice.jsx` の中に置く。

- **単位が2通りある。** ①②④⑥ は**1文ずつ**、③⑤ は**本文まるごと**。
  1文ずつのステップは `sentencesOf()` で段落・発言をほどく
  (切り方は読み上げと同じ `splitSentences()`。**2か所に持たない**)
- **⑤ シャドーイングは本文を隠す。** ③との違いはそこだけである。
  隠しても**行の場所は残す**(消すと段落がいくつあるか分からなくなる)
- 日本語は**段落ぶんしか無い。** 文ごとの訳は付けられないので、
  段落の訳に「段落の訳」と札を付けて出す。**無いものをあるように見せない**
- ステップを足したら `SIX_STEPS` に足す。**画面に書き足さない**

### 練習の行は「6Steps → Quick Response → 集中モード」。**どの画面でも同じ**

2026-09 利用者の指定。

> トップの画面でのボタンの並びを左から「6Steps」「Quick Response」
> 「集中モード」にして、ディクテーション画面でもスラッシュリーディング
> 画面でも同じにしてください。
> そして、スラッシュリーディングやディクテーション、その他のトレーニングの
> タブの左の 6Steps の文字を削除してください

- **並びを変えない。** 6Steps を開いても、閉じても、同じ3つが同じ順で出る。
  **場所が動くボタンは、探すことになる**
- **集中モードは、6Steps の最中も同じ行に出す。** そのときは
  **いまの取り組み方**の集中モード(1文ずつ / 1発言ずつ)に入る。
  開いているかどうかは**レッスン表示の側が持ち**、
  `PassagePractice` に渡す(`focus` / `onFocusChange`)。
  **中にも同じボタンを置かない** — 1つの画面に同じものが2つ出る
- **プルダウンの左の「6Steps」は出さない。** 上のボタンの行に「6Steps」が
  あり、押して開いた先なので、ここでもう一度名乗る必要がない。
  **読み上げのための名前(`aria-label`)は残す**

### 単位の言葉は、教材の形から決める(段落 / 発言)

2026-09 実機・利用者の指定。

> これは、会話だから「段落ごと」ではなく「発話ごと」で分けてほしいです。
> 会議も同じく。記事だと段落ごとです。

記事は**段落**、会話・会議は**発言**で数えるのは、もともとの決まり
(`countUnit()`)。ところが ② スラッシュリーディングの「単位」だけ
**「段落ごと」と決め打ち**にしていたので、会話でも「段落ごと」と出ていた。

- `slashUnitsFor(isDialogue)`(`sixSteps.js`)1か所で決める
- **会議も本文の演習は `dialogue`** なので、これ1つで両方に効く

| 教材 | 選択肢 |
|---|---|
| 記事 | 段落ごと / 文章全体 |
| 会話・会議 | **発言ごと / 会話全体** |

- **残っていた2か所も直した**(2026-09 利用者の指定「『発言』にしましょう」)。
  「段落の訳」の札(`slash-ja-label`・3か所)と、
  ③⑤ の「段落で区切らない」。
  **言葉は `bodyUnitWord(isDialogue)`(`sixSteps.js`)1か所で決める。**
  出す場所は4つあるので、書き写すと必ずどこかが「段落」のまま残る
  (実際、`slashUnitsFor()` で選択肢だけ直したときに残っていた)

### 集中モードでも、鳴っている段落をそのまま開く(2026-09 利用者の指定)

> 集中モードでも再生中の文章がハイライトされるようにして下さい。
> 何もしなければ次の段落、または発言などに進むようにして下さい。

**6Steps の集中モードだけが、そうなっていなかった。**
実際に描かせて測ると、こうなっていた(③ オーバーラッピング・会話2発言)。

| | 上の帯 | 光っている発言 | 光っている文 |
|---|---|---|---|
| 鳴らした直後 | 1 / 2 発言 | 1 | あり |
| **音が2発言目へ移ったあと** | **1 / 2 発言のまま** | **0** | **無し** |

理由は単純で、**集中モードは1つだけを描く**(`section.items.slice(at, at + 1)`)
のに、**鳴らすのは本文ぜんぶ**だからである。音が次の発言へ移った時点で、
その発言は**画面に出ていない。** 色を付ける相手がいないので
ハイライトも消え、画面は1つめのまま止まって見えていた。

- **`FocusReader`(読んで調べる集中モード)は、もともとこうしている**
  (`goRef` で鳴っている段落へ移る)。**役目が同じなら、動きもそろえる**
- 直したのは `playAll()` の `onIndex` 1か所。
  **段落 / 発言を1つずつ出しているときだけ**動かす
  (`byItem = focus && current.unit === 'passage'`)。
  ①②④⑥ は単位が違うので、通しの番号をそのまま当てると別のものを開く
- **番号は `section.items` から数え直す。** 鳴らす側の並び(`playable`)は
  **英文の無い項目を落としてある**ので、そのまま渡すと別の段落を開く
- **紙(`LessonView`)は1文字も変えていない**(あちらは全部を描いている)
- `npm run test:play` が見張る(実際に外して、赤くなることを確かめてある)

### 6Steps にも集中モードがある。**取り組み方ごとに1つずつ**(`StepFocus.jsx`)

2026-09 利用者の指定。

> 6steps全てに集中モードを作ってください。今は形式的にはボタンがあっても、
> 押すとトップの単語チェックのページの集中モードに飛ばされてしまいます。
> ディクテーションやスラッシュリーディングでこれをできるようにしてください

`PassagePractice` の中の「集中モード」は、押すと `FocusReader`
(**本文を読んで語を調べる**画面)を開いていた。書き取りの途中でも、
区切りを入れる途中でも、**同じ「語を調べる画面」に飛ばされる。**
いま取り組んでいることが、そこには無い。

- **骨組みは `.focus` をそのまま使う**(`FocusReader` と同じもの)。
  足すのは「上の帯の右に 6Steps のプルダウンを置く」1点だけ
- **中身は作らない。** ふだんの画面(`PassagePractice`)の中身を
  **そのまま渡す。** 書き写すと片方だけ古くなる(単語帳で踏んだ失敗)
- **1つだけ渡す。** 部品(`StepDictation` / `SlashReading` / `StepSentence`)は
  一覧を受け取る作りなので、**長さ1の一覧**を渡すだけで1つずつになる。
  描き方を変えていないので、見た目も操作もふだんと同じ

  | 取り組み方 | 単位 | 何を渡すか |
  |---|---|---|
  | ① ディクテーション | 文 | `groupSentences()` の1かたまりに入っている文 |
  | ② スラッシュリーディング | 段落 / 発言 / 文章 | `slashBlocks` の1つ |
  | ③⑤ 本文まるごと | 段落 / 発言 | `section.items` の1つ |
  | ④⑥ 1文ずつ | 文 | `sentences` の1つ |

- **数え方を2通り持たない。** ①は `StepDictation` と同じ `groupSentences()` を
  通してから数える(難易度を変えると数が変わる)
- **取り組み方・単位・難易度を変えたら、先頭へ戻す。** 個数が変わるので、
  前の番号をそのまま使うと別の場所に飛ぶ
- **6Steps はこの画面の中で切り替えられる。** いちいち出て、選び直して、
  また入る…では続かない
- **プルダウンは縮める。** `<select>` は**いちばん長い選択肢**の幅になるので
  (「② スラッシュリーディング」)、iPhone(390px)で 20px はみ出し、
  **画面が横に送れる状態**になっていた(実測 410 > 390)。
  `min-width: 0` で縮め、入らないぶんは「…」で切る。
  **番号(①〜⑥)は必ず見える**ので、どれを選んでいるかは分かる
- **レッスン表示では、ボタンは上の行にある1つだけ**(2026-09 利用者の指定で
  並びをそろえた)。6Steps を開いていなければ**本文を読んで語を調べる**
  集中モード、開いていれば**いまの取り組み方**の集中モードに入る。
  **役目は違うが、押す場所は1つ**である
- **紙の幅を引き継ぐ**(`focusWidth`)。120% で読んでいた人が、
  入った瞬間に 100% に戻っては落ち着かない。
  数字は `FocusReader` と同じ `.focus--w*`(**2か所に持たない**)
- **1枚のカードにする**(単語帳の集中モードと同じ考え方)。
  地の上に面(`--surface-1`)を置くと、
  どこからどこまでが「いま向き合うもの」かが分かる。
  1つしか出さないので**下の区切り線は引かない**(続きがあるように見える)。
  カードにする前は「1文しか無いのに画面いっぱいへ散らばって」見えていた
  (2026-09 実機「UIとデザインが崩れています」)
- **幅は、もとの紙と同じ。`margin: 0 auto` を必ず残す**(2026-09 利用者の指定)。

  > 画面幅を広げると、コンテンツがどんどん左に寄ってしまうのを改善して
  > ください。これは全ての集中モードで統一にしてください。
  > 元々の幅に合わせてください。

  一度 `min(100%, 48rem)` で頭打ちにしたが、**紙より細くなる。**
  上限は `.focus--w*`(紙の幅)だけが決める。
  **実測: 1430px でも 2200px でも、左右の余白が同じ**(199 / 584)
- **中は「濃く、色でメリハリ」**(2026-09 実機
  「全体的にコンテンツの文字などが薄すぎて少し見づらいです」)。
  1つだけに向き合う場所なので、紙の一覧より一段はっきりさせる。
  話す人は**紙と同じように色で分け**(`--voice-a` / `--voice-b`)、
  番号は**うすい青の丸**(`--accent-bg` + `--accent`)、
  「速さ」などの見出しはうすい灰色をやめる。
  **色はすべて変数から取る**(プレインを選べば、そのまま灰色になる)
- **番号は、どのページでも出す**(2026-09 利用者の指定
  「どのページでも段落番号とか全て入れてください」)。
  ②スラッシュリーディングと③⑤の本文にも足した。
  **`startNo` を外から渡す** — 集中モードでは1つしか渡さないので、
  そのままだと何番目でも「1」になる
- 集中モードでは、**見出し・やり方・6Steps の欄・音声認識の断り書きは出さない。**
  何度も読むものではないので、向き合っている場所をそのぶん狭めない。
  **速さ・本文を出す(⑤)は残す** — その取り組み方の最中に要る操作である

### 集中モードは「黒い地の上に、白い紙」。**普通の画面と同じ形**

2026-09 利用者の指定。**2手かかっている。経緯ごと残す。**

> 濃さについては、普通の画面と同じように、左右の空白部分は黒にしてください。

集中モード(`FocusReader` / `StepFocus`)は**レッスン表示の紙の中**から
呼ばれる。紙は `--surface-*` などを差し替えて**明るい配色の島**にしてある
ので(`.lesson-sheet`)、そのまま描くと、**画面ぜんぶを覆うこの画面まで
紙の白**になっていた。暗い配色を選んでいても、左右の余白が真っ白になる。

はじめは `createPortal` で body の直下に出しただけにした。地は黒くなったが、
**中身まで暗くなった。** これは言われたことではなかった。

> 集中モード、全てを黒にしてほしかった訳ではないです。
> 6Step モードではない普通のモード時は、真ん中に紙があり、
> コンテンツは基本白ベース、幅により余る左右のスペースが黒。
> このようにして欲しいのです。

**「普通の画面と同じ」とは、地が黒いことではなく、
黒い地の上に白い紙が1枚あることだった。**

- **`createPortal` で body の直下に出す**(地はアプリの配色に戻る)。
  吹き出し(`.etext-pop`)を紙の外に出しているのと同じ理由である。
  こうすると**どこから入っても集中モードは同じ見た目**になる
- **中身は `.focus-paper` に載せる。** 紙の変数の島(`.lesson-sheet` の
  `--paper` / `--ink` / `--surface-*` …)を**選択子で分け合う。**
  `.lesson-sheet, .focus-paper { … }` と書けば、色は1か所のままである。
  **書き写すと、片方だけ古くなる**
- **置き方は分ける。** 送る箱なのは `.lesson-sheet` だけで、
  集中モードは外側(`.focus-body`)が送る
- **紙にしか無い色は、アプリ側にも置く。** 番号の丸(`--accent-bg`)と
  話す人(`--voice-a` / `--voice-b`)は `.lesson-sheet` の中にしか
  無かった。`.num-badge` のように**紙の外でも使う部品**があるので、
  **`styles.css` の3か所すべてに書く**(`:root` / media / `[data-theme]`)。
  プレインの側にも足す
- **`var(--qa-line, var(--border))` のように控えを書いてある変数は、
  そのままでよい。** 紙の外でも成り立つように作ってある
- **「紙の上か」を見ている場所も、一緒に数える。** 語の意味の吹き出しは
  `anchorEl.closest('.lesson-sheet')` で明るい色に切り替えていたので、
  紙の外へ出した瞬間に**白い紙の上へ暗い吹き出しが載る**ようになった。
  `.focus-paper` も同じ扱いにする(`GlossPopover`)。
  **紙を増やしたら、「紙かどうか」を尋ねている場所を探すこと**
- **白い紙があると、中央にあることが目で分かる**(2026-09 実機
  「集中モードを押すとコンテンツが左に寄っていて、中央に配置されません」)。
  実測では**前から中央にあった**(1440px で左右 204px ずつ)。
  ところが**黒い地の上に文字だけが載っていた**ので、
  短い1文では左に寄っているようにしか見えなかった。
  **「中央かどうか」は、囲みが無いと見えない**

### 紙の周囲は、配色によらず黒。**暗い配色では紙も黒**(2026-09 利用者の指定)

> 配色が「暗い」「明るい」どちらが選択されているかにかかわらず、
> 紙の周囲は黒で統一でお願いします。
> つまり、配色が「暗い」の時は紙も黒です。

**上の節(「黒い地の上に、白い紙」)を、利用者の指定で一段進めたもの。**
以前は地が `var(--surface-0)` だったので、**明るい配色では周囲まで明るい灰色**
だった。「黒い地の上に紙が1枚」という形は、配色によらず同じであってほしい。

| 配色 | 地 | 紙 |
|---|---|---|
| 明るい | **黒** | 白(これまでどおり) |
| 暗い | **黒** | **暗い**(カードと同じ色) |

- 地は **`.focus--sheet`** に**決め打ち**(`.lesson-bar` と同じ作法)。
  `FocusFrame` が付けるので、**紙のある集中モードだけ**に効く。
  **単語帳の集中モード(`.wbfocus`)には効かせない** — あちらには紙が無く、
  言われたのは「紙の周囲」の話である
- **レッスン表示の紙(`.lesson-sheet`)は1ドットも変えていない。**
  あちらは画面共有用で、「暗い配色を選んでいても紙は白のまま」という
  **別の決まり**がある(共有先で見やすいことが優先)
- **紙を完全な黒にはしない**(地 `#0c0c0b` に対しカード `#1c1c1a`)。
  段差が無いと**紙がどこからどこまでか見えなくなる**
  (「白い紙があると、中央にあることが目で分かる」の裏返し)

#### 暗くする方法 — **色の値を書き写さない**

紙は `--surface-0` などアプリと**同じ名前**を差し替えた島である。
暗い配色で戻そうとして `--surface-0: var(--surface-0)` と書くと、
**自分を参照する輪**になって黙って効かなくなる。

だから**紙の外(`.focus`)でアプリの色を別名(`--app-…`)に控え、**
`.focus-paper` はそこから取る。**暗い側の色を1つも書き写していない**ので、
配色を直せば集中モードの紙も一緒に直る。

- 島に変数を足したら、**暗いときの戻し(2か所)にも足す。**
  `:root[data-theme="dark"]` と `@media (prefers-color-scheme: dark)` の両方
- **`npm run test:paper` が見張っている。** 抜け・食い違い・値の書き写し・
  別名の取り違え・地が黒いかを、機械的に確かめる

#### 紙にかかる指定で、**色を決め打ちしない**

**この検証で実際に3つ見つけた**(2026-09)。

| どこ | 何が起きていたか |
|---|---|
| `.lesson-sheet .btn, .focus-paper .btn` | `background: #fff`。**白い錠剤が黒い紙に載る** |
| `.focus-paper select / input / textarea` | 同上 |
| `.qr--paper` の5色 | `--qr-dim: #55554e`。**黒い紙に黒い「英語を見る」** |

どれも「紙は暗い配色でも白のまま」だった頃の名残である。
**`var(--btn-bg)` / `var(--ink-soft)` のように紙の変数から取れば、
レッスン表示の紙(島の値=明るい)と集中モードの紙(配色に従う)の
両方が1つの指定で正しくなる。**

**語の意味の吹き出しも同じ**(`GlossPopover`)。
`.focus-paper` の上では **`etext-pop--paper` を付けない** —
何も足さなければアプリの配色に従い、紙とそろう。
**レッスン表示の紙の上では、これまでどおり明るい色に決め打ちする。**

### 集中モードは「いま取り組んでいること」を1つずつ出す。**別の練習へ移さない**

2026-09 実機・利用者の指摘。**同じ取り違えを2度した。**

> Quick Response で集中モードを押すと違うトレーニングになってしまいます。

6Steps でまったく同じことを言われている(「押すとトップの単語チェックの
ページの集中モードに飛ばされてしまいます」)。あのときは 6Steps だけを直し、
**Quick Response を数え忘れていた。**

**集中モードは「取り組み方」ではない。** いま開いているものを
**1つずつ画面に固定する見せ方**である。だから
**練習を開いているあいだは、その練習の集中モードに入る。**

| いま開いているもの | 集中モードで出るもの |
|---|---|
| 何も開いていない | 本文を読んで語を調べる(`FocusReader`) |
| 6Steps | いまの取り組み方を1つずつ(`StepFocus`) |
| Quick Response | **その1問**(`QuickResponse` の `focus`) |

- **開いているかどうかは、ボタンのある `LessonView` が持つ。**

- **「3 / 6 段落」を上と下の2か所に出さない。** 下の帯が出すので、
  上の帯からは外した(帯の中の進み具合の線を消したのと同じ話)

##### 幅の境目で決めない。**入るまで詰める**(`useFitRow`・2026-09 利用者の指定)

> レスポンシブに幅に収まるように

はじめは**決め打ちの境目**(560 / 480 / 400 / 370px)で言葉を落としていた。
ところが**境目のあいだが、いちばん危ない** —— 実測すると
**375px(iPhone SE)だけ余りが 8px** しか残っていなかった
(360px 以下でしか詰めていなかったため)。

しかも**幅だけでは決まらないものが3つある。**

| 何 | なぜ幅では分からないか |
|---|---|
| 端末の「表示を大きく」 | 同じ 390px でも文字が 1.25 倍になる |
| 端末ごとの字形 | iPhone の Safari と Chromium で幅が違う |
| **中身そのもの** | 最後の段落だけ「次 ▶」が**「まとめ」**に変わる |

だから**幅から当てるのをやめた。**
`useFitRow`(`src/lib/fitRow.js`)が**実際にあふれているかを測り、
入るまで印を1つずつ足す。** CSS は「その印で何を削るか」だけを持つ。

| 印 | 何を削るか | なぜその順か |
|---|---|---|
| `is-fit1` | `Listen` の言葉 | speaker の絵だけで通じる |
| `is-fit2` | 「訳**を見る**」 | 「訳」だけでも、何のボタンかは分かる |
| `is-fit3` | 余白・三角の幅 | **押せる大きさ(28px)は割らない** |

**数(3 / 6 段落)と、くり返しの単位(しない / 文 / 段落 / 全文)は
1文字も削らない。** そこが読めないと、何をしているのか分からない。

- **見張るのは親のほう。** 自分を見張ると、印が余白を変える → 幅が変わる →
  測り直す → 印を外す、と**行ったり来たり**になる
- **描き直すたびに測る**(見張りに何も渡さない)。中身が変わると、
  幅が同じでも入るかどうかが変わる
- **3つで止める。** それでも入らないならあふれたままにする ——
  **言葉を削り続けて、何のボタンか分からなくするほうが悪い**
- **`.focus-mid` は折り返させない**(`nowrap`)。ただし折り返さない箱は
  **足りなくなると外へあふれて隠れる**ので、検証では高さだけでなく
  `scrollWidth` も見る
- **これは「実測でしか見つからない」を、検証だけでなく
  動いている画面の側にも当てはめたもの**である

- **「用意しています…」は、スマホでは出さない**(2026-09 利用者の指定で
  「どんなに狭くても消さない」から改めた。下の節)
- **`.focus-mid` は折り返させない**(`nowrap`)。折り返しは「重なるよりまし」
  として入れたものだが、入るようになったのだから要らない。
  ただし**折り返さない箱は、足りなくなると外へあふれて隠れる**ので、
  検証では高さだけでなく `scrollWidth` も見る
- **段が変わる幅のあいだが、いちばん危ない。** はじめ 360px 以下でだけ
  詰めていたので、**375px(iPhone SE)だけ余りが 8px** になっていた。
  **いまは幅で決めていない**(上記)
- **最後の段落を必ず測る。** そこだけ「次 ▶」が**「まとめ」という言葉の
  ボタン**に変わる。ふだんの段落だけを測っていたので、
  **320px で 13px あふれているのに気づけなかった**(実測して見つけた)
- **`npm run test:bar` が見張っている。** 560 / 430 / **402 / 393 / 390 /
  384 / 375 / 368 / 360 / 344** / 320px と、**帯の文字を 1.25 倍にした端末**で、
  **最後の段落まで送りながら**高さとあふれを見る。
  **境目でない幅を混ぜてある** —— 幅で決めていないことを、そこで確かめる。
  実際に `useFitRow` を外して、**16件が赤くなる**ことを確かめてある。
  **上の帯も一緒に見る** —— 最後の段落では、そちらに「まとめ」が増える
- **`StepFocus`(6Steps の集中モード)には効かせていない。**
  あちらは `.focus-mid` が空で、詰める理由がない(言われた場所だけを直す)

### 6つは、そのまま並べる(第5.239節)

2026-09-22 利用者の指定。

> 6steps として6つ作ると煩雑だと思うんです。もう少しスタイリッシュかつ
> シンプル、分かりやすく出来ないでしょうか?

**プルダウンは、開くまで6つが見えない。** 順にやるものなのに、
「いま何番目か」「あといくつか」が画面に出ていなかった。
**6つを並べれば、それ自体が道しるべ**になる(`StepBar.jsx`)。

- **並びは `SIX_STEPS` のまま。** ここで減らさない・並べ替えない
- **色だけに頼らない** —— 地色 + 枠線 + 太字 + `aria-current="step"`
- **狭い画面では番号だけ。** 名前は `aria-label` と `title` に残るので、
  **読み上げからは消えない**(見た目だけが減る)
- **`.chip` は 30px ほどしかない。** 指で押せる高さ(36px)を足す

### 「やり方」は畳んだ側が既定。ねらいの1行はいつも出す

開いたままだと、スマホでは**画面の 1/4 を手順が占めていた**(実測)。

- **`<details>` は使わない**(共通ルール)——
  畳んでも中身が場所を取り続け、札の中に別のボタンを置くと
  **押すたびに畳みが動く**。状態を1つ持ち、閉じているあいだは描かない
- **ねらいの1行は、畳んでいても出す。** 何のための練習かが消えると、
  「やり方」を開くまで分からなくなる(行き止まり)
- **名前と「やり方」は同じ行に。** 名前・ねらい・ボタンの3つを1行に
  入れると、狭い画面で**ボタンだけが次の行へ落ちて、ひとりぼっちの行**になる

### 行の道具が2段に折り返していたのは、13px 足りなかったから

| | |
|---|---|
| `Listen / くり返し / 速さ / 解答を見る` に要る幅 | **331px** |
| 390px の画面で使える幅 | **318px** |

- 「この端末では、声で確かめる練習は使えません。」 → **いまの状態**なので残した。

`.env` を触らずとも、骨組み(`src/__screens.jsx`)を Playwright で開けば

### 判断は `SIX_STEPS` の表1枚に持つ(第5.239節)

6つでアプリがやることは**8つとも同じ**である ——
聞く / くり返す / 速さ / 英語を出す・隠す / 日本語を出す・隠す /
声で言って確かめる / 途中を覚える / 集中モード。
**本当に違うのは3つだけ**だった。

| 列 | 何を決めるか |
|---|---|
| `view` | どの練習の形か(`dictation` / `slash` / `sentence` / `passage`) |
| `barRate` | 帯に「速さ」を置くか(**① だけ false**) |
| `speak` | 声で確かめる仕組みがあるか(**② だけ false**) |

**画面から `step === '…'` が5か所とも消えた。**
この節には前から「ステップを足したら `SIX_STEPS` に足す。**画面に書き足さない**」
と書いてあったのに、**守られていなかった。**
7番目を足すときは、表に1行足すだけでよい。

- 集中モードで何を数えるかは **`focusListOf()`**、
  その言葉(文 / 段落 / 発言 / 文章)は **`focusUnitWord()`**
- **素の node で走る形に切り出してある**(`npm run test:play` が数えられる)

#### 行の見出しと、声で確かめるボタンは1つの部品に

| 部品 | 何をまとめたか |
|---|---|
| `PracticeRow.jsx` | 番号 → 話す人 → 右に道具。**3か所が同じ形を書き写していた** |
| `SpeakCheckButton.jsx` | 声で確かめるボタン。**4か所**にあった |

- **押す前の文言は、取り組み方ごとのまま**(①「まねて言う」/
  ④⑥「英語で言う」/ ③⑤「話して確かめる」)。
  ①は解答をまねる、④⑥は自分で言う —— **意味が違うものを、同じ名前にしない**
- **聞いている最中の文言だけ**を1つにした(`LISTENING_LABEL`)。
  ここが場所ごとに違うと、同じ操作が別のものに見える
- **`SoundPractice` は手をつけていない。** あれは音の練習で、6Steps ではない

#### 寄せるときは、写真をバイトで突き合わせる

**画面は1ドットも変えない**のが約束なので、
骨組みを Playwright で撮って **`cmp` で突き合わせた。**
「たぶん変わっていない」では、変わっていたときに気づけない。

#### 【不具合・報告のみ】② で「文章全体」を選んでも「段落」と出る

画面にあった判断を `focusUnitWord()` へ移すときに気づいた。

```js
slashUnit === 'all' ? '文章' : ...   // ← 'all' はどこにも無い値
```

② の単位の id は `para` / `whole` の2つ(`SLASH_UNITS`)。
**`'all'` はどこからも渡らないので、「文章」には一度もならない。**

**寄せたついでに直さない**(CLAUDE.md)。見た目が変わるので、
利用者に報告してから直す。**そのまま持ってきてある。**

#### 見張りで、また同じところを踏んだ

「話し終わったら押す」が**1か所にしか無いか**を数えたが、
**`SpeakCheckButton.jsx` の説明文の中にも同じ言葉が書いてあった。**
定数を書き換えても1件のままで、**赤チェックで初めて出た。**

**「名前が出てくるか」では見ない。コメントを落としてから数える。**
