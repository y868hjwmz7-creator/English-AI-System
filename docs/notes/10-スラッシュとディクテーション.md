# スラッシュとディクテーション

**[CLAUDE.md](../../CLAUDE.md) の「構成」から切り出したもの。決まりの重さは1つも変わっていない。**

区切りの決まり・カタマリの訳・書き取り・発音記号・test:bar

見出しで探す: `grep -n '^### ' docs/notes/*.md`　言葉で探す: `grep -rn 'さがす言葉' docs/notes/`

---
### やり方の説明は、1行に1つ

`SIX_STEPS` の `how` は**配列**。1つの段落に流すと、改行も区切りも無い棒に
なって読めない(指導ポイントで一度学んだこと)。`<details>` で畳み、開閉を覚える。

**見た目は指導ポイント(`.teaching-note`)にそろえてある**(2026-08 利用者の指定)。
題は「やり方」、色は 6Steps の緑(`--accent`)のまま。

- **ちがうのは「中身が手順」だという1点。** 指導ポイントは並びに意味の無い
  箇条書きなので丸い点、こちらは**番号の丸**にしてある
- `aim`(何ができるようになるか)は**「ねらい」の札**にして中身のいちばん上へ。
  題が「やり方」になったので、見出しには置けない。
  **札は塗りつぶさない**(2026-08「塗りつぶしが濃すぎます」)。
  まわりがうすい面なので、細い枠と文字だけで足りる
- **CSS の値は書き写してある。** 指導ポイントは「指示があるまで変えない」と
  決まっているので、規則を共有するとこちらを直したついでにあちらが動く。
  **あえて分けてある。** 直すときは片方だけを直してよい

### スラッシュリーディングの区切りは、決まりで出す。AI に頼まない

利用者が挙げた決まりは、**どれも閉じた語のリストで判定できる**
(`src/lib/chunker.js`)。前置詞も助動詞も数が決まっている。
1文ごとに課金する理由がない。**決まりで書けるものを AI に頼まない。**

- **まちがいは、その場に吹き出しで出す。** 下にまとめて並べていたので、
  どの区切りの話なのか分からなかった(2026-08 の指摘)。
  短い一言(`short`)を赤い吹き出しでスラッシュの横に出し、
  詳しい言い方(`text`)は `title` に持たせる
- **指摘は、次の操作で片づく。** 読んだあと自分で消して回らせない。
  ①隣の正しいところを押す ②吹き出しを押す ③よそを押す — **3つとも**
  で、まちがいのスラッシュごと消える。
  **ただし、いま押したものは残す。** 消すと吹き出しが出た瞬間に消える
- **やり方の説明を、本文の上に置かない**(2026-09 利用者の指定
  「青くハイライトした文言は不必要です。消してください」)。
  同じことは上の「やり方」(`SIX_STEPS` の `how`)に畳んで置いてある。
  **同じ説明を2か所に置かない。** 読むものが増えると本文が下へ押し出される
- **模範の区切りは出さない。比べさせない**(2026-08 利用者の判断)。
  > そもそもが区切り方を比べる自体が難しいです。視覚からパッと入って
  > 来ません。比べる気も起こりません。そして、区切り方は、ルールとして
  > 決めたこと以外、正解はないからです。

  以前は模範を出して見比べさせ、合っている数・模範には無い数・あと何か所、
  まで数えていた。**これは採点である。** 区切り方に正解は無いので、
  案と違うだけのものを並べると**決まりに反している1本が埋もれる。**
  言うのは「**決まりに反している**」ことだけ。それ以外は何も言わない
- **画面は3段**(利用者が書いた設計そのまま)。
  ① 自分で区切る → 決まりに反するものだけ 💬 が出る
  ② 「この区切りで訳を出す」を押す
  ③ **自分の区切りが入った英文**と、それに対応する訳が一緒に出る。
  出したあとは、上の英文(訳なし)が**練習用**、下の対が**確認用**
- **②は「段落ごと」と「まとめて」の両方から押せる**(2026-08 利用者の指定)。
  > これは段落ごとでも全体を一度にでもどちらでもできるようにして欲しいです。

  段落の数だけボタンを押させない。上の帯に**「すべての区切りで訳を出す」**を
  置く(2段落以上あるときだけ)。1つずつ確かめる道も残す。
  **単位(段落ごと / 文章全体)を切り替える話とは別物。** あちらは
  区切りを入れる単位、こちらは訳を出す操作である
- **「通しで見る」は、いつでも押せる**(2026-09 利用者の指摘)。

  > 段落ごとに分けた英文と訳は、すべてつながって見れる場所が欲しいです。

  はじめは**全段落の訳を出したあとだけ**出していた(虫食いの一枚を
  見せないため)。ところが**そこへ行き着く道が見えなかった。**
  いまは**押したときに、こちらで全段落の訳を出してから切り替える。**
  虫食いにならず、しかも1回で着く。
- **全部の段落が終わったら「通しで見る」**(2026-08 利用者の指定)。
  > 全ての段落が終わった後には、各段落の区切った文と訳を全て繋いである
  > ものを用意してあげて参照できるようにしたいな。
  > ボタンを押せば切り替わるような仕組みが良い

  段落ごとの箱を外し、**自分の区切りと訳だけをつないだ1枚**にする。
  - **終わる前は出さない。** 押しても虫食いになるだけ
    (「効かないボタンを出さない」)。終わったかどうかは
    「全段落の訳を出したか」で見る
  - **通しでは語を押せなくしておく。** 参照するためのものなので、
    区切りを触れると練習用と見分けが付かなくなる
  - **段落の切れ目は残す**(点線)。消すとどこからどこまでが1段落か
    分からなくなる(⑤ シャドーイングで本文を隠すときと同じ考え方)
  - 対の描画は `MinePairs` 1か所。**段落の箱と通しで書き写さない**
- **NG の判定は `slashProblem()` 1か所。** 模範を作る `add()` も同じものを
  通す。2か所に書くと**模範が自分の決まりを破る**(`test:chunk` が落ちる)。
  NG は「**うしろの語にかかる語で、カタマリを終えない**」の言い換えである。

  | 何 | 言い方 |
  |---|---|
  | 前置詞のあと(前置詞と冠詞のあいだを含む) | `of` の前で区切る |
  | 冠詞のあと | `the` は名詞と離さない |
  | 所有格(`'s`)のあと | 次の名詞と離さない |
  | 助動詞のまとまりの途中(`have to` / `will` など) | `have to` は切らない |
  | **句動詞の途中**(`Get / up at 6am.`) | `Get up` は切らない |
  | **形容詞・分詞とうしろの名詞のあいだ** | `new` は名詞と離さない |
  | 接続詞・関係詞のあと(`and` `which` `because` …) | 次のまとまりの先頭に置く |

- **注意に使う語のリストは、模範を作るリストと別にしてある**(2026-08 実機)。
  取り違えようのある語を前置詞・冠詞と決めつけて、**誤判定を2つ出した。**

  | 出した誤判定 | 本当は |
  |---|---|
  | `Apps like this / let …` に「this は名詞と離さない」 | `this` は**代名詞** |
  | `pull in / more than …` に「in の前で区切る」 | `in` は**句動詞の副詞** |

  だから注意する側(`SURE_PREPS` / `SURE_DETERMINERS` / `SURE_MODALS` /
  `HEAD_WORDS`)には、**ほかの品詞にならない語だけ**を入れる。
  `in` `on` `up` `over` `by` `about`(句動詞の副詞)、`like`(動詞)、
  `this` `that` `some`(代名詞)、`his` `her`(目的語)、
  `have` `do` `is`(本動詞)、`while`(名詞)は**入れない。**
  見逃しても害は小さいが、**間違った注意は何も言われないより困る。**
- **句動詞は「動詞 + 副詞」の対で持つ**(`PHRASAL_PAIRS`・2026-08 利用者の指定)。
  > Get up at 6am. だとしたら、Get up / at 6am です。この場合の up は
  > 前置詞ではなく、副詞であり、get とセットとして考えるべきです。

  **動詞のリスト × 副詞のリストで掛け合わせない。** 同じ語が
  句動詞の副詞にも前置詞にもなる(`pull in` / `run in the park`、
  `get up` / `go up the stairs`)。掛け合わせると**正しい区切りを咎める。**
  対そのものを並べれば取り違えない。**ここは模範の側にも効かせてある**
  (`Get / up` という不自然なカタマリを作らないため)
- **形容詞は「述語かどうか」で見分ける**(2026-08 利用者の指定)。
  > 形容詞と名詞の間に区切りを入れても注意されません。ただ、
  > I am happy / because … みたいに後ろが名詞ではない場合は OK であるべきです。

  咎めないのは3つのどれかに当てはまるとき。
  ①つなぎの動詞が2語前までにある(`is happy /` `feels very safe /`)
  ②うしろが機能語(前置詞・接続詞・助動詞・`than` `as` `to`)
  ③文の切れ目・読点のあと。
  `clean` `open` `light` `right` `hard` `fast` `late` `high` は
  **動詞・名詞・副詞にもなる**ので `ADJECTIVES` に入れない
- **うしろから修飾する分詞は、切っても切らなくてもよい**(利用者の指定)。
  > I saw some people / dancing in the park. でも OK だし、
  > I saw / some people dancing in the park. でも OK です。

  だから分詞を見るのは**冠詞や形容詞のうしろに立つとき**だけにする
  (`a broken / window` は咎め、`some people / dancing` は咎めない)。
  不規則な分詞(`broken` `written` `lost`)は形からは分からないので並べてある
- **前置詞を取る動詞は `PHRASAL_PAIRS` に入れない**(`work on` `look after`
  `stand by` `go over`)。あれは前置詞句なので `work / on the report` と
  切ってよい。入れると正しい区切りを咎める
- **数字や記号が混じった語を、語のリストに当てない**(`bare()`)。
  `6am` が `am`(be動詞)に化けて、`at / 6am` という**自分の決まりに
  反する区切りを模範が作っていた**(2026-08 実測)。`5,000` も同じ
- **模範を作る側(`idealSlashes` の `add()`)は、広いリストのままにする。**
  狭めると模範の区切りが**増え**、教材に控えたカタマリごとの訳(0021)と
  数が合わなくなって、**訳が丸ごと出なくなる。**
  注意より常に厳しくしておけば、模範が決まりを破ることはない
  (`npm run test:chunk` の1本目が見張っている)

- **文の切れ目(`.` `?` `!`)と読点のあとは、いつでも正しい**(利用者の指定)。
  > 「以前」という意味の副詞として before が使用され、文の最後に置かれ、
  > ピリオドが続き、そのピリオドとその後の文の始まりの間に区切りを
  > 置くことは何ら問題はありません。

  `before` `after` `since` `over` は前置詞にも副詞にもなる。
  **どちらかは語のリストでは当てられない。** けれども文が終わっていれば
  前置詞ではありえない(前置詞ならうしろに名詞が要る)ので、
  記号だけで確実に分かる。**咎めない。**
  同じ理由で、`once` `when` `so` などの**副詞にもなる語は
  `HEAD_WORDS` に入れない**(あやふやなことを言わない)
- **1つも反していなければ、褒める**(2026-08 利用者の指定)。
  > 違反している区切りはありません、ではなくて、結果的に違反の数がゼロなら
  > fantastic! などポジティブな声かけに、変えましょう

  「◯◯はありません」は**無いことの報告**であって、褒め言葉ではない。
  声かけは**段落ごとに決める**(`praiseFor()`)。押すたびに入れ替わると、
  目が言葉のほうへ行って気が散る
- **理由の一覧は出さない**(長い文で12行並び、「見づらいだけ」と言われた。
  理由は1本ずつ `title` に持たせる)
- **押すのは「語」。語と語のあいだではない。**
  あいだに押せる帯を置いたら「最初から全部にスラッシュが入っているように
  見える」「壊滅的に使いづらい」と言われた(2026-08)。
  語なら大きくて指で狙え、押すまで**素の英文のまま**である
- **空白は囲みの外に置く。** `white-space: nowrap` の中に入れると
  改行できる場所が無くなり、長い文が画面からはみ出す(実測)
- 前置詞・接続詞・助動詞のまとまり・冠詞のリストを触ったら、
  **必ず `npm run test:chunk` を通す**(模範が自分の決まりに違反していないか、
  NG に注意が出るか、文末の副詞を誤って咎めていないかを見る)
- **上級ほど区切りが減る**(利用者の指定)。強さだけで決めると初級と中級が
  ほとんど同じになったので、**カタマリの最小語数**でも絞っている
- **「動詞の前で切る」は、当てられるぶんだけ入れてある。**
  一般の動詞は語のリストでは当てられない(`run` は名詞にも動詞にもなる)。
  **あやふやなことを言わない。**「たぶん違う」は、何も言われないより困る。
  ただし**助動詞と be動詞は数が決まっていて、しかも必ず動詞**なので、
  その前では切る(強さ1。**初級でしか出ない**)。
  `How long / is the ride?` — 利用者の紙の教材と同じ形になる
- **「動詞のあとで切る」は、控えの側にだけ入れてある**(2026-08 利用者の指定)。

  > 動詞の後も初心者には区切ってもらいたいポイントです。

  `The office bought / a new coffee machine` `the trend has / a darker side`。
  **注意する側(`slashProblem`)には足していない。** 控えは切れ目が増えるだけで
  害が小さいが、注意は取り違えるとそのまま**間違った注意**になる。
  **動詞を数え上げない**(2026-09 利用者の指定で改めた)。

  > 動詞の目的語を動詞とは分けて考えるのが初心者です。
  > どうにかしてあらゆる他動詞について一括でこのルールを変えれないですか?

  はじめは `COMMON_VERBS` という一覧に載っている動詞のあとだけ切っていたが、
  **載っていない他動詞では切れなかった。** 一般の動詞は語のリストでは
  当てられないので、数え上げるかぎり穴は残る。
  いまは `objectHere()` が**名詞のかたまりの始まり**の側から見る。
  前の語が冠詞・形容詞・所有格・前置詞・接続詞・副詞のどれでもなければ、
  そこが動詞と目的語の切れ目である(**一覧は消した**)。
  取り違えを避ける条件は4つ。
  ①前が冠詞・形容詞・所有格・前置詞なら**名詞**である(`the plan` `a new place`)
  ②**前の語が名詞のかたまりの中身**なら動詞ではない
  (`We need the plan / a week` の `plan`。形容詞をまたいで冠詞まで戻って見る)
  ③句動詞の副詞が続くときは `add()` が断る(`talking / up a stock` を防ぐ)
  ④うしろが**名詞のはじまり**のときだけ切る。冠詞・代名詞・数に加えて、
  **`anything` のような不定代名詞**も名詞のはじまりとして数える
  (2026-09 実機。`Before you buy / anything fancy,` が切れていなかった)。
  **`-ing` で終わるだけの語**(`anything` `morning`)を分詞と間違えないよう、
  `NOT_PARTICIPLES` で除いてある。
  **`have` `do` は本動詞にもなる**ので `insideAux()` を緩めてある
  (うしろが名詞のはじまりなら助動詞ではない)。ただし**文頭の
  `Do the students …?` は疑問文の助動詞**なので、そこでは切らない。
  **冠詞の付かない目的語(`waste money`)は、いまも切れない。**
  名詞のはじまりの印が無く、当てようがないためである
- **単位は「段落ごと」か「文章全体」。** 1文ずつでは細かすぎる
  (2026-08 の指摘)。`blocksOf()` で切り替える
- **自分の区切りに合わせた訳は、控えを組み替えて作る**(`chunkPairsAtMarks()`)。
  訳を分けられるのは**控えの境目(初級の区切り)だけ**なので、
  そこと重なった区切りで分ける。重ならない区切りは**英語には出し、
  訳はそのカタマリぶんをまとめて置く。**
  **押すたびに AI に訳し直させない。** 無料で、待ち時間も無い
- **カタマリごとの訳は、教材に控える**(`material_items.chunks`・0021)。
  切る場所は決まりで分かるが、**そのカタマリを日本語で何と言うか**は
  決まりでは書けない。だから**そこだけ**を AI に頼み、
  作るときに1回だけ作って控える(仕様書 第5.29.3節)。

      どれくらいの長さですか / 乗っているのは
      How long              / is the ride?

  - **1つのカタマリに訳がいくつも入ったときは、行を分ける**(2026-09 実機)。
    自分の区切りが控えの境目と重ならないと、その区切りは**英語にだけ出て、
    訳はそのカタマリぶんがまとまって**置かれる(下の決まり)。
    ところが**つないで1本の文字列にしていた**ので、

        今日時間を作ってくれて話しておきたかったスケジュールについてそして料金について

    と、**日本語として読めない棒**になっていた(利用者の写真)。
    `chunkPairsAtMarks()` がつなぐ前の姿(`jaParts`)も返し、画面が
    **行を分けて**出す。**区切り記号は足さない**(訳の側にスラッシュは
    出さない・2026-08 の指定)。行が分かれているだけで、別の意味だと分かる
  - **並びは「英語が上・訳が下」。訳はそのカタマリの真ん中に置く**
    (2026-08 利用者の指定)。訳の側にスラッシュは出さない
    (区切りは上の英語が示している)
  - **囲みも線も置かない**(2026-08 利用者の指定。帯 → 線 と2度直して、
    どちらも「ダサい」と言われた)。**字づかいだけで層を分ける。**
    大きさ 0.72 倍・落ち着いたセージ(`--chunk-fg`)・わずかな字間・
    行間を広く。どのカタマリの訳かは**真下にあること**で分かる(近接の原理)
  - **狭い画面(860px 以下)では、訳を左寄せにする**(2026-08 利用者の指定)。
    > このように毎回改行するのであれば日本語は左寄せでお願いします。

    まん中に置くのは、カタマリが**横に並んでいる**ときの話である。
    スマホでは1カタマリで1行を使い切るので、まん中だと訳が広い行に浮き、
    **上の英語のどこに対応するのか分からなくなる。**
    **判断は幅だけ**(`useWide()` と同じ 860px)。文字数から当て推量しない
  - **カタマリの訳だけを出す形は、どの画面幅でも作らない**
    (2026-08 利用者の判断。一度作って取り下げた)。
    > 訳と自分の区切りが一致しなければ意味がないし、スマホでは
    > スクロールして訳を見ても同時に英文が見えないからです
    > pcでは訳だけ表示するメリットはありそうですが、それでも自分の
    > 区切り方と模範解答の、区切り方が異なることも多いので、
    > それでは意味をなしません

    **これは狭さの話ではない。** カタマリの訳が持っている情報は
    「この日本語は、**英語のどこからどこまで**に当たるか」であって、
    訳の文言そのものではない。**英語が隣に無いと、その情報が消える。**
    しかも自分の区切りは模範と違っていることが多いので、
    訳だけを並べても自分の切り方には重ねられない。
    だから **PC でも訳だけにはしない。** 英語と訳は必ず対で出す。

    出し入れは「カタマリの訳を出す」(訳を全部消す)と
    「解答を出す / 隠す」(箱ごと閉じる)で足りる。
    **同じことをする操作を3つ置かない**
  - **「区切りの訳を作る」ボタンは置かない**(2026-08 利用者の指定)。
    > 教材を作った時点で区切りの訳がバックグラウンドで生成される
    > デザインの方が良いです。

    作るときに `MaterialForm` が一緒に作る。足りない教材は、さがす画面で
    **開いたときに裏で1回だけ**作る(`needsChunkJa`)。
    **止まる条件を持たせる**(1教材につきその画面で1回。失敗しても繰り返さない)
  - **前の名詞を説明する語句は、名詞と1つの単位で訳させる**
    (2026-09 利用者の指定)。

    > the boy running in the park の訳が「男の子は走っている / が…」
    > 本来は、「走っている男の子」であるべきです

    英語は名詞のうしろから説明するが、日本語は**前から**説明する。
    別々のカタマリで訳させると「男の子は」「走っている」となり、
    つなぐと**述語のように**読める。`baseChunks()` が
    `postModifier()` の切れ目だけを落として1つにまとめる。
    **英語の区切り(スラッシュ)は変えていない。** 変えたのは訳の単位だけ
  - **並べているもの(`and` / `or`)の前で切る**(2026-09 利用者の指定)。

    > A pair of shoes / and a water bottle を /靴一足と水筒/ と
    > なってしまいます。靴一足 / と水筒一本 となるように

    強さ1(初級だけ)。`but` `because` のような「ここから意味が変わる」
    切れ目とは違い、並べているだけである。
    **`and` のあとで切るのは、これまでどおり咎める**
  - **訳をつなぐときは、同じことを二度書かない**(`joinJa`)。
    窓口が隣のカタマリの意味まで書くことがあり、
    「無視するのは難しい無視するのは」と出ていた(2026-09 実機)。
    **窓口の指示を直しても、すでに作った訳は直らない。** 出すときにも見る
  - **中身の空いたカタマリがあれば、作り直す**(`needsChunkJa` ④・2026-09 実機)。
    窓口の指示を直しても、**すでに作った訳は直らない**(訳は教材に控えてある)。
    ところが「主語のカタマリに全部書いてしまう」形の訳には、
    **必ず空のカタマリが残る**(書く分が無くなるため)。
    **英語があるのに訳が空、というのはどんな場合でも正しくない**ので、
    これを見つけたら作り直す。窓口を配置し直したあとなら、
    次にその教材を使ったときに**ひとりでに直る**
  - **足りなかった段落は、こちらでもう一度頼む**(`generateChunkJa`)。
    窓口は「カタマリの数が合った段落だけ」を返し、合わなかった数を
    `skipped` で知らせていたが、**画面がそれを見ていなかった。**
    6段落のうち何段落かだけ訳が入り、残りは
    「訳を出す(段落まるごと)」に落ちていた(2026-09 実機)。
    **2回で止める。** 頼み直すのは足りない段落だけなので、
    うまくいく回の費用は変わらない
  - **主語だけ・目的語だけのカタマリは、その分だけを訳させる**
    (2026-09 利用者の指定)。日本語は「主語 → 目的語 → 動詞」の順なので、
    主語のカタマリに動詞と目的語の意味まで書いてしまう。
    書いてしまうと**次のカタマリの訳が空になり**、どの英語がどの日本語に
    当たるのか分からなくなる(実機で
    「小さなクラウド障害が先週大きな問題を引き起こした」が
    主語のカタマリに丸ごと入っていた)
  - **控えは、いまの決まりより粗ければ作り直す**(`needsChunkJa` ③)。
    控えが粗いと、ゲストがそこで切っても訳を分けられず、
    2つぶんの訳がまとまって出て**右へずれて見える**(2026-08 実機)。
    粗いままでも**訳は出る**ので、作り直しは見た目をそろえるためである
  - **控えの単位は、細かいほどよい。** 訳を分けられるのは控えの境目だけなので、
    細かいほど「どこで切っても訳が真下に来る」。前置詞・接続詞に加えて、
    次も切れ目にしてある(強さ1)。**足りない型に気づいたら、ここに足す。**

    | 型 | 例 |
    |---|---|
    | 副詞(`-ly` と、よく出る形) | `… a week / suddenly started` |
    | 主語の代名詞 | `Last spring / she noticed` |
    | **前置詞 + 代名詞のあと** | `Apps like this / let a trader` |
    | **句動詞のあと** | `Some streams pull in / more than …` |
    | **前の名詞を説明する分詞** | `Phone scams / targeting elderly people` / `The money / raised by the fund` |
    | **比べる `than` の前** | `it feels safer / than reading a textbook.` |
    | **動詞のあと** | `The office bought / a new coffee machine` |
    | **文末の時・場所の副詞句の前**(2026-09) | `for making time / today.` / `a table / backstage.` |

    **文末の「いつ・どこで」は、切り離す**(2026-09 利用者の指定
    「前からの訳において、初心者がやるように細かく分けるとまだ
    対応しきれていない部分があります」)。
    `today` `tonight` `tomorrow morning` `next month` `backstage` は、
    直前の名詞句とは別の情報なのに、くっついたまま1つのカタマリに
    なっていた。だから訳も「来月のイベントの前に」と1本になり、
    **「いつ」がどの英語に当たるのかが見えなかった。**
    `TAIL_ADVERBS` / `TIME_HEADS` / `TIME_NOUNS`(閉じたリスト)で見分ける。
    **前が前置詞・冠詞・接続詞のときと、そこで文が終わるときは切らない**
    (`before / next month` のような、ありえない切り方になる)。

    #### 目的語をはさむ句動詞は、**まとめて1つ**にする(2026-09)

    `set that up` `write that down` `working this out` を
    `set / that up` と切っていた。`up` `down` `out` を前置詞と
    取り違えているためで、**「動詞 + 目的語 + 副詞」で1つの意味**である。
    `splitPhrasalAt()` / `insideSplitPhrasal()` が、
    **その副詞でカタマリが終わるか、うしろが前置詞・接続詞のとき**だけ
    分離した句動詞と見なす(`run in the park` を巻き込まないため)。

    **注意する側(`slashProblem()`)には足していない。**
    控えは切れ目が減るだけで害が小さいが、注意は取り違えるとそのまま
    **間違った注意**になる(`PHRASAL_PAIRS` と同じ考え方)。

    #### 数詞と `one` は割らない(2026-09)

    - `Ninety / thousand` … `NUMBER_WORDS` に `eleven`〜`nineteen` /
      `forty` / `sixty`〜`ninety` が**抜けていた。** 数どうしは切らない
    - `to this / one` … `one` `ones` は**代名詞**なので、
      指示語のうしろで切ると訳が「4つ」のように化ける。
      冠詞・指示語のうしろの `one` では切らない
    - `since / you mentioned` … `since` は接続詞にもなる。
      うしろが主語の代名詞なら、そこは**節の始まり**であって前置詞句ではない
    - `and we'd / like your set` … `like` は**動詞にもなる**(`verbBefore()`)。
      主語の代名詞・助動詞・短縮形のうしろでは前置詞として扱わない
    - `Got / it,` … 節を閉じる**裸の目的語の代名詞**の前では切らない

    **分詞は `-ing` だけではない**(2026-08 利用者の指定)。

    > 前の名詞を説明する分詞も初心者は分けて考えます。

    `-ed` と不規則な分詞も同じように切る(`postModifier()`)。
    ただし**前の名詞の説明ではないとき**は切らない。
    助動詞のうしろ(`was raised` `has been caught`)、
    冠詞・形容詞のうしろ(`a broken window`)、
    前置詞のうしろ(`by reading books`)、副詞のうしろ(`quietly selling`)。

    ただし切らないものが2つある。
    **`more than` `less than`** は数量のひとかたまり(`more / than` にしない)。
    **うしろに `-ing` を取る動詞**(`stop` `start` `keep` `enjoy` …)は、
    そのあいだで切らない。`She stopped / guessing` と切ると、訳が
    「彼女はやめた」「推測すること」に割れて意味をなさない。
    活用は語幹に戻して当てる(`stopped` → `stop`。
    **`ped` を `p` に置き換えると `stopp` になる。** 子音の重なりで戻す)

    `like this` は**前の名詞にかかる2語のかたまり**なので、
    `Apps / like this` と切ると「アプリが」「このようなものは」に割れる
    (2026-08 実機)。**前置詞の前ではなく、代名詞のうしろで切る**
  - **控えには「カタマリの英語」も一緒に残す**(`chunks.parts`・2026-08)。
    切れ目を**表示のたびに計算し直していた**ので、区切りの決まりを直すと
    数が変わり、**すでに作った訳が丸ごと出なくなった**(実機)。
    控えたときの切れ目そのものを残せば、あとで決まりを変えてもずれない
  - **「作り直しが要るか」は `chunkPairsOf()` で見る。`storedChunks()` の
    有無で見ない。** あれは英文が同じかしか見ないので、数がずれた教材まで
    「もう作ってある」と判定し、**訳が出ないのに作り直せない**行き止まりになる
  - **数が合わないときは、黙って英語だけを出さない。**
    「作り直してください」とどこで押すかまで書く
  - **控えるのは初級の区切りぶんだけ。** 中級・上級の区切りは初級の
    **一部**なので、隣どうしをつないで作る(`src/lib/chunkJa.js`)。
    3レベルぶん作らせると費用も3倍になる。
    **この「一部である」前提そのものを `npm run test:chunk` が見張っている**
  - **数が合わなければ出さない。** 英文を直した教材・決まりを直したあとでは
    数が変わる。**ずれた対は、無いより悪い**(`sentencePair.js` と同じ)
  - 窓口は増やさない。`generate-material` に `mode: 'chunk_ja'` を足してある。
    **切り終わったカタマリを渡す。** 区切りの決まりを窓口に持たせない
  - すでにある教材には、さがす画面の**「区切りの訳を作る」**で後から足せる
- **文の切れ目(`.` `?` `!`)でも切る。** 切らないと段落の中で文がつながる
  (`the ride? Can you tell me` が1カタマリになっていた)。
  文の切り方は読み上げ・QR と同じ `splitEnSentences()`。**2か所に持たない**

### ディクテーションの操作は、文ごとに持つ

2026-09 利用者の指定。

> ディクテーションのデフォルト画面で、stopボタンがあるのですが、これは
> 必要ありませんので消してください。そしてその横の再生スピード調整タブも、
> 削除しする代わりに各文につけてください。また、同じく各文にリピート再生と
> 一度の再生を切り替えるボタンも。

書き取りは**1文ずつ**の練習である。鳴らすのは各文の Listen なので、
**帯の Stop は、押しても何も鳴っていない**ことがほとんどだった
(Listen は鳴っているあいだ Stop に変わる)。速さも「どの文も同じ」になる。

- **Stop は、どの取り組み方でも帯に置かない**(2026-09 利用者の指定
  「STOPボタンが必要ないです。すべてのページで同じにしてください」)。
  **鳴らすボタンがそのまま Stop に変わる**(各文の Listen も
  「Listen (全体)」も同じ作法)。止める場所を探させない
- **通しで鳴らしているあいだは、その段落の Listen も Stop になる**
  (2026-09 利用者の指定)。

  > そもそも全体を再生を押した後は、再生中の段落の listen ボタンは
  > Stop ボタンになっているべきです

  **鳴らすボタンがそのまま Stop に変わる**のがこのアプリの作法だが、
  通しの読み上げは `SpeakButton` の**外側**で鳴らしているので、
  その段落が鳴っていることをボタンが知らなかった。
  目はいま光っている段落にあるのに、そこには「Listen」と書いてあり、
  押すと**二重に鳴り出す。** 押したら通しごと止める。
  - **見た目(`speakingId`)と、押したときの判定(`speakingRef`)を
    そろえる。** 片方だけ動かすと「Stop と書いてあるのに止まらない」になる
- **通しで鳴らしているかは、専用の状態で持つ**(`playingAll`)。
  「いま読んでいる文」の印(`speakingId`)は最初の合図が来るまで空なので、
  それだけで見ていると**押しても Stop に変わらない時間**ができる
- **速さは、①ディクテーションでは出さない**(文ごとに置いてある)。
  ③⑤(本文まるごと)には残す
- **帯が空になったら、場所も取らない**(`.passage-tools:empty`)。
  空のまま置くと、上下の余白だけが残る
- 文ごとに **Listen / くり返す・1回 / 速さ / 解答を見る** を置く
- **速さを変えるのは、その文だけ。** 開いたときの速さ(`rateId`)を
  一緒に動かすと「1つ変えたら全部変わった」ように見える(実測)。
  ただし**最後に選んだ速さは覚える**(次に開いたときの初めの速さ)
- **くり返しは覚えない。** 鳴りっぱなしになる指定なので、
  次に開いたときは必ず1回に戻す
- くり返しは `SpeakButton` の `repeat`。**止まる条件を持たせる**
  (0.3秒に満たずに終わったら失敗とみなしてやめる。
  画面から消えるときも止める。**放っておくと鳴り続ける**)

### 短すぎるものは、次とまとめる

### 画面から何かが「知らない間に消える」のを防ぐ(`npm run test:bar`)

2026-09 利用者の指定。

> 新しく何かを実装すると何か古いものが知らない間になくなることを
> 防ぐようにできませんか?

**帯に並ぶものは増え続ける**(閉じる・ページ送り・解答・表示・書き込む・
メモ・読み上げの操作盤・速さ・文字・幅・印刷…)。1つ足すたびに場所の
取り合いになり、**折り返しや条件のかけ違いで、古いものが黙って消える。**
`npm run lint` にも `npm run build` にも引っかからず、
**その画面を、その条件で開くまで分からない。**

だから**実際に描かせて、並んでいるものを数える。**
耳の代わりに `test:audio`、目の代わりに `test:paper` を置いたのと同じ。

- 見るのは**3つの立場 × 2つの幅**(パソコン / スマホ)。
  狭い画面では「表示」に畳まれるので、**開いてから数える**
- **帯が1行に収まっているか**も一緒に見る(1440 / 1280 / 390 / 320px)
- 期待する一覧は `scripts/test-bar.mjs` の **`WANT` 1か所**。
  **わざと外したら、ここを直すまで赤いまま。**
  足したときも同じで、**必ず1回は自分の目で確かめることになる**

#### **ソースを読むだけの検証にしない**

メモのボタンは**ソースには書いてある**が、`learnerId` と役割の2つが
そろわないと描かれない。ソースを読むだけなら「ある」と答えてしまう。
**見えているかどうかは、描かせないと分からない。**

書き足すための入り口は `src/__screens.jsx`(**利用者の画面には出ない。**
`index.html` はこれを読み込まない)。条件は URL で渡す。

#### 実際に、この検証が2つ捕まえた

- **「表示」はパソコンでは出ない**(畳まないので札も要らない)。
  こちらが「いつもある」と思い込んで書いた一覧が、その場で赤くなった
- わざとメモを外したら、**パソコン・スマホの両方で赤くなる**ことを確かめた


### 本動詞を、前の名詞とまとめない(第5.240節)

2026-09-23 実機・利用者の指摘。

> 区切っているのにまとめて訳にされているところがまだまだ散見されます。
> 英文法に則り…区切りの訳を**最小限の細かい単位**でされた時と
> 安定して区切れるよう改善してください。

`baseChunks()` は「前の名詞を説明する分詞」を名詞とまとめるが、
`postModifier()` が**形だけ**を見ていたので**本動詞まで巻き込んでいた。**
**6つの文で実測したところ、本動詞も修飾語も1つも区別できていなかった。**

#### 切り分けは「うしろにもう1つ動詞があるか」1つだけ

```
The boy / running in the park / just said hello to me.    → 説明(said がある)
The money / raised by the fund / was not enough.           → 説明(was がある)
… our customers / signed a contract within the first month.  → 本動詞(何も無い)
```

| 関数 | 何を返すか |
|---|---|
| `participleAfterNoun()` | 形だけを見る(ここまでは同じ) |
| `postModifier()` | **うしろに動詞がある** → 訳を名詞とまとめる |
| `mainVerbHere()` | **うしろに動詞が無い** → **その前で区切る** |

**同じ見分けを2か所に書かない。**

#### 動詞の一覧は作らない。**見落としに害が無い側へ倒す**

2026-09 に `COMMON_VERBS` を消した覚え書きがある
(「載っていない他動詞では切れなかった」)。今回は**逆向き**である ——
見つからなければ「本動詞」と見なして**まとめない**ので、
訳が細かくなるだけで、利用者の指定に近づく。

だから `SURE_PAST` には**動詞にしかならない語だけ**を入れる。
`saw`(のこぎり)`rose`(ばら)`left`(左)`led`(LED)`put` `cut` `set`
`cost` `read` `hit` は**入れない** —— 取り違えると本動詞をまとめてしまう。

**`objectHere()` を使い回す案は、試して外した。**
`Our sales team reached / the target early / this year.` の `early` が
動詞に見えて、「うしろに動詞がある」と読んでしまう。

#### 主語と述語のあいだで区切る

助動詞のある述語(`we / are losing …`)はすでに切れていたが、
**過去形1語でできている述語**だけが、どの決まりにも当たらなかった。
だからゲストがそこに印を入れても、**控えに切れ目が無くて訳が割れない。**
画面には `/` が出ているのに訳は1つのまま —— これが写真の出どころである。

#### `too much time` を割らない

`too` は `-ly` で終わらないので `isAdverb()` では拾えず、
冠詞でもないので `DETERMINERS` にも入っていなかった。
**すでにある `DEGREE_WORDS`** を `objectHere()` でも見るようにした。

### 文法タグごとに、区切り方を確かめる(第5.241節)

2026-09-23 利用者の指定。

> 間違えている区切りをその度に送るのは時間がかかり過ぎます。
> **中学英文法の文法タグ**がありますよね。それらの文法を鑑みれば
> 区切り方のルールをさらに精度上げることができるはずです。

`weaknessTags.js` の `category: 'grammar'` は**37 件**ある。
これは**区切りの決まりが面倒を見るべき文法の一覧**そのものである。

`src/data/grammarSlash.js` に、**タグ1つにつき例文を1つ**置いた。

```js
{ tag: 'there-is', en: 'There are two options on the table.',
  keep: ['There are'],   // この中では切らない
  cut:  ['on'] }         // この語の前では切る
```

#### 見つかった本当の間違いは2つ

| | |
|---|---|
| `There / are two options` | `there` は**場所取りの語**で主語ではない。切ると「そこに」「2つある」となり日本語にならない |
| `She writes very / clearly` | `very clearly` は1つの副詞のかたまり(`too much time` と同じ話) |

**残り7件は、アプリがわざと切っていた場所**だった ——
主語と動詞を切る / 動詞と目的語を切る / 前置詞 + 名詞 / 比べる相手の前。
**期待のほうを直し、「なぜわざと切るのか」を例文に書き添えた。**
書いておかないと、次に読んだ人が「直し忘れ」と読んでまた触る。

#### タグを足したら、例文も足さないと赤くなる

例文の側は `weaknessTags.js` から数える。**一覧を2か所に書かない。**

#### `keep` だけでは、見張りにならない

はじめ `cut` を書いた例文は **16 / 37** しか無かった。
`keep` だけだと「**どこにも切らない**」形に書き換えても全部緑になる。
「**切る場所も見ている例文が、半分以上ある**」という行を足したら、
その1行が最初に赤くなり、36 / 37 まで書き足すことになった。

#### これで「都度お知らせ」が要らなくなったわけではない

**37 件は文法の「名前」の一覧であって、英文のすべてではない。**
例文1つで当たるのは、その文法の**いちばん素直な形**だけである。
崩れた英文が出たら、**そのまま例文に足す** —— 一度足せば二度と戻らない。

### ボタンが全部白かったのは、紙が色をつぶしていたから(第5.242節)

1. **`.lesson-sheet .btn` が、どのボタンも紙の白にそろえていた。**

#### 描いたものから期待値を作らない(第5.242節・赤チェックで判明)

「② の英文が1回だけ」を、はじめ
**`.slash-body` の字を `wordsOf()` で数えた数 = `.slash-w` の数**で見ていた。
**英文を2回描くと、両方とも倍になる。** 比は 1:1 のままなので、
わざと2回描いても**緑のまま**だった。

**外に持ち出せる期待値が無いときは、中だけで成り立つ性質で見る。**

- 押せる語は、**どれか1つのカタマリの中**にいる
- **同じ4語のつながりが、二度出てこない** ——
  英文を2回描けば、どの4語も必ず二度出る。
  ふつうの英文で同じ4語が並ぶことは、まず無い

**壊し方を2通り試す。** カタマリの外に描く形と、中に描く形では、
当たる行が違う(前者は両方、後者は4語の行だけ)。
1通りだけだと、片方の行が働いていなくても気づけない。
