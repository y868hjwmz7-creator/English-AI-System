# パタプラ風の「言う練習」(Quick Response)

**[CLAUDE.md](../../CLAUDE.md) の「構成」から切り出したもの。決まりの重さは1つも変わっていない。**

耳で聞いて、間の中で声に出す。チャンクで積む。型を固定して入れ替える

見出しで探す: `grep -n '^### ' docs/notes/*.md`　言葉で探す: `grep -rn 'さがす言葉' docs/notes/`

### パタプラのようにする(2026-09 利用者の指定)

> あなた、英語学習用アプリの「パタプラ」や「スピフル」を知っていますか?
> quick response を、特に「パタプラのようにしたいです。」

**知らなかったので、調べた。** 公式ページ(`patapura.com`・App Store・
プログリット)は**この環境から通信が遮断されていて開けず**、
検索結果の要約までしか読めていない。**実際に使ってはいない。**

分かった範囲で、パタプラ(パタプライングリッシュ)の芯は4つだった。

| | |
|---|---|
| ① | **テキストを見ない。** 耳で聞いて、**間(ポーズ)の中で声に出す** |
| ② | **チャンク**(2〜8語の意味のかたまり)単位で口に出す |
| ③ | **型を固定して、中身だけ入れ替える**(`I'd like to ___`) |
| ④ | **Type A(かたまりのリピート)→ Type B(文のリピート)**の段 |

**スピフル**(プログリット)は軸が違う ——
AI の即時フィードバックと **WPM**(1分あたり発話語数)の測定、独り言英会話。
**パタプラ=口を作る / スピフル=測って直す。** 今回はパタプラのほうである。

利用者の指定は「**全て切り替えて使えるようにしたい**」。

#### **新しい画面を作らない。聞き流しに載せる**

聞き流し(`WordRadio`)は
「**音声が自動で進み、間を選べて、やめるまで回りつづける**」——
パタプラに要るものが、もうぜんぶ在った。
足りないのは**どの順で鳴らすか**だけなので、
`radioSteps()`(`wordRadio.js`)に読み方を足しただけである。

- **単語帳は1ドットも変えていない。** 言われたのは Quick Response である。
  語は文ではないのでチャンクに割れない(**言われた場所だけを直す**)
- 入口の名前を **「言う練習・聞き流し」**に変えた。
  「聞き流す」とだけ書いておくと、**探している人が一生たどり着かない**
  (「覚えかけ」と書いて中身が「まだ」だったのと、同じ間違い)

| 読み方 | 並び |
|---|---|
| **英語だけ、くり返し**(これまで) | 英語 → くり返しの間 → 英語 |
| **言う練習(間 → 答え)** | **言う番** → 英語 → 間 → 英語 |
| **チャンクで積む** | かたまり → 言う番 → …(くり返し)… → **1文まるごと** → 言う番 → 1文 |
| **慣れるまでチャンク、慣れたら1文** | 箱0 なら「チャンクで積む」、箱1以上なら「言う練習」 |

#### **「言う番」から始める。答えを先に鳴らさない**

答えを先に鳴らしてから間を置くと、**ただのリピートになる。**
パタプラの芯は「**思い出して、自分で言う**」ほうである。

同じ理由で、**言う練習では英文を画面に出さない。**
出ていたら、間の中で「言う」のではなく「読む」ことになる。
1つめの音が鳴った瞬間に開き、次の問へ移ったら閉じる。

- 隠しているあいだは**同じ場所・同じ高さ**に1行を置く。
  別の場所に出すと、**答えが鳴った瞬間に行が入れ替わって画面が跳ねる**
- **日本語は、いつも出ている。** これが出題そのものである
  (読み上げるのは英語だけ —— 2026-09 利用者の指定)
- 判断は **`hidesAnswer()` 1か所。** 画面で `mode === 'say'` と書かない

#### かたまりの割り方は、**スラッシュリーディング1か所**

**新しい割り方を作らない。** ここで別に書くと、
**同じ文が画面とここで違う場所で切れる。**

段は **「中級」**。実測するとこうだった。

    初級 … you / please let / us know    … 1〜2語。**細かすぎる**
    中級 … 8 / 3 / 4 / 5 語              … **ちょうど合う**
    上級 … 11 / 9 語                     … **長すぎる**

##### **1語のかたまりは、となりへ寄せる**(実測して直した)

区切りをそのまま使ったら、**400 かたまりのうち 52(13%)が1語**だった
(`you` `can.` など)。**1語では言い直す単位にならない。**

寄せたあと、実データ 756 文(Native Flow 690 + 型の例文 66)で

| | |
|---|---|
| 割れた文 | 153 文 |
| かたまり | 318 |
| **1語のかたまり** | **0** |
| 8語以下 | **99.1%** |
| **足すともとの文に戻らない文** | **0** |

- **区切り方そのものは触っていない。** あちらは**読むため**の区切りで、
  ここは**言うため**の単位である。寄せるのはここだけにしておけば、
  画面のスラッシュは1本も動かない
- **割れない短い文は、かたまりにしない**(同じ音が3回続く)。
  Native Flow の多くは1〜8語なので、そのまま「1文まるごと」に落ちる

##### 検証は「約束できることだけ」を見る

はじめ「かたまりはどれも **2〜8語**」と書いたが、**上は約束できない** ——
区切りはスラッシュリーディングが決めており、長い節は長いままである
(実データの最長は 12 語)。

**下は約束できる**(1語は寄せてある)ので、見るのは

- **1語のかたまりを作らない**
- **足すともとの文に戻る**(1語も落としていない)
- **ほとんど(9割超)が8語以下** …… **割合で見る。**
  ぴったりの数を書き写すと、文を足した日に期待値も一緒に動く

#### 「言う番」は、**どれも「考える間」**

はじめ、かたまりのあとに「語と語のあいだ」
(選んだ秒 × 250/1400 = 既定 **268ms**)を置いていた。
**4〜8語のかたまりを言い直すには、短すぎた。**

間は**1つしか選ばせていない**(「3つとも選ばせると、どれを触れば
よいのか分からなくなる」)。だから**言う番はその1つ**にそろえる。

#### Type A → Type B は、**箱が決めている**

- **箱0**(まだ一度も言えていない / 間違えた直後)→ **かたまりから積む**
- **箱1以上**(一度は言えた)→ **1文まるごと**

**新しい数を決めていない。** 箱そのものが、その判断をすでに持っている
(`KNOWN_AFTER` を足したときと同じ考え方で、**数を2か所に書かない**)。

#### 型を固定して入れ替える = **並べ方を1つ足すだけ**

パターンプラクティスの芯は「**型は固定したまま、中身だけ入れ替える**」。
`I'd like to ___` を続けて何本も言うから、**型のほうが手に残る。**
混ぜてしまうと1本ごとに型を探し直すことになり、それは練習にならない。

**新しい仕組みを作っていない。** どの文がどの型かは
`frameMatch.js`(2026-09)がもう言えるので、
**並べ方に「型でまとめる」を1つ足しただけ**である。

- 型を言い当てられなかった文は**後ろにまとめる。落とさない**
  (**黙って消さない**)。前に混ぜると、型の並びが途切れる
- 並べ方(`QR_ORDERS` / `orderQrPairs`)は **`qrOrder.js` へ出した。**
  `qrReviews.js` は Supabase を引き連れていて**素の node で走らせられない**
  のに、並べ方は純粋な算段だからである。
  **呼ぶ側は1行も変わっていない**(`textNorm.js` と同じ作法)

#### 読み方を足した日に見つかった、**古い落とし穴**

`radioModeOf()` の落とし先が **`modes[modes.length - 1]`(いちばん最後)**
だった。読み方が**1つしか無かったころは先頭と末尾が同じ**なので、
どちらで書いても同じだった。

4つに増やした瞬間、**端末に残った古い値(`enja` / `jaen`)が
「慣れるまでチャンク」に落ちる**ようになっていた。
`npm run test:play` の「端末に残っている `enja` / `jaen` は `en` に落ちる」が
**その場で赤くした。** 落とし先は `DEFAULT_RADIO_MODE` 1か所に直した。

**しかも同じ間違いが2か所にあった。** `loadRadioMode()` にも
`modes[modes.length - 1].id` と書いてあり、こちらが本命だった ——
**端末に `jaen` が残っている人が、聞き流しのつもりで開くと
「慣れるまでチャンク」の言う練習が始まる。**
`npm run test:bar` の「読んでいる文と画面がずれている」が見つけた
(画面にかたまりが出ていた)。**落とし先は `radioModeOf()` 1か所**に寄せた。

**一覧が1つしか無いうちは、先頭と末尾の区別が付かない** ——
足す日まで、間違いが間違いに見えない。
**そして、同じ書き方は必ず2か所にある。**

#### **描き替えを1手待ってから鳴らす**

`setLine()` のすぐあとに鳴らすと、**音が先、文字があと**になる。
実測で「`Could you walk me through…` を読んでいるのに、
画面は1つ前のかたまり」だった(`npm run test:bar` が見つけた)。
React はその場では描き替えないので、**`setAt()` で踏んだのと
まったく同じ落とし穴**である。

**`requestAnimationFrame` は使わない** ——
別のタブへ移ると止まるので、そこで練習ごと固まる。

#### 「3つめを足さない」という決まりは、**利用者が解いた**

`wordRadio.js` には「**3つめを足さない**(`writingTones.js` の4つと同じ決まり)」
と書いてある。これは**こちらの思いつきで増やさない**ための決まりで、
**利用者がここを名指しで変えたので、そのぶんだけ解けている。**
思いつきで足したものは、いまも1つも無い。

同じ理由で、`npm run test:play` の
「読み方(Quick Response)… 英語だけの1つ」も開いた。
代わりに見るのは **「いちばん上が、これまでの『英語だけ』のままか」** ——
**既定が動くと、毎日使っている人の耳が黙って変わる。**

#### まだ入れていないもの(日本語の音声)

パタプラは**音声の中に日本語が入る**。ここは**まだ英語だけ**である。

2026-09 に利用者が「日本語入りはいらないですね!こえの質が悪すぎます!」と
外したのは**端末の声**のほうで(`docs/notes/` の聞き流しの節)、
**窓口で作る日本語は別物**である。調べた範囲では、

- 読み上げの窓口は `eleven_v3` を使っており、**日本語も扱える**
- **Azure の鍵はもう持っている**(`npm run audio`)。
  F0 は**月 50 万文字までニューラル音声が無料**
- Native Flow 690件の訳は **7,911文字**、コロケーションが 844文字。
  **合わせて 8,755文字 = 無料枠の 1.8%**

**声そのものは聴いていない**(この環境から窓口へ通信できない)。
入れるなら、`npm run audio` と同じく**先に MP3 を作って配る**形にする ——
実行時に窓口を1回も呼ばないので、**永久に0円**である。
