### ゲストの見出しは「左が誰か・右がどのくらいか」

2026-09 利用者の指定。

> 青でハイライトした部分を右に寄せて下さい。
> そして空いたスペースには、ゲストが選んだアイコンを入れれるとよいです。

| 左(`.learner-who`) | 右(`.learner-side`) |
|---|---|
| アイコン・名前・状態 | タブ・TOEIC / VERSANT / レベル |

スコアは名前の真下(左)にあったが、右へ寄せてタブの下にそろえた。
**アイコンは名前の行とスコアの行にまたがる高さ**なので、左右が同じ背丈になり、
行が余らない。**狭い画面(640px 以下)では右寄せをやめる。**
右に寄せるのは「横に並んでいる」ときの話である(カタマリの訳と同じ)。

#### 開いているあいだも、箱の左上に名前を出す(2026-09 実機・**方針の変更**)

> 一番上のVERSANTのスコアなどが表示されているボックス内の左上、
> 元々ゲストの名前があったところにも名前を入れて下さい。
> ぽっかり空いていてデザインが微妙です。

**一度は外していた。** 上に貼り付く箱(`LearnerBar`)が名前も札も出すので、
**同じものが2つ**になるという理由である。ところが実機では
**この箱の左上がまるごと空き、右のスコアだけが浮いて見えた。**

**役目が違うので、2つあってよい。**

| どこ | 何のためにあるか |
|---|---|
| 貼り付く箱(`LearnerBar`) | **画面の上端。** 送っても消えない道しるべ |
| この箱の左上 | **紙面のいちばん上。**「この数字は誰のものか」の見出し |

- **札(受講中)は足さない。** 言われたのは名前だけで、
  札は貼り付く箱の右端に出ている(**言われた場所だけを直す**)
- **押せなくする**(`<span className="learner-name is-open">`)。
  ここは名前でいちばん大きい字(20px 太字)なので、
  `<button>` に戻すと**画面共有中に触れただけで一覧へ飛ぶ**
  (2026-09 実機で直したところ)。閉じる道は「← 一覧」と
  下の「閉じる」の2つ残る
- **見た目(大きさ・太さ・色)は一覧の名前と同じ。**
  同じ人の名前が場所で違う顔になっては落ち着かない

### ゲストの一覧は「名前から探す」で絞れる

2026-09 利用者の指定「担当しているゲスト内に『名前から探す』を入れて下さい」。

いま担当は22人、伸ばしたあとは**1人あたり25人**になる(CLAUDE.md 冒頭)。
名前で引けないと、目当ての人を見つけるのに一覧を送ることになる。

- **形は「教材をさがす」とそろえる**(`card finder` + `finder-head`)。
  欄そのものは **`SearchBar` を使い回す。同じ見た目を書き写さない**
- **件数(◯ 件)は渡さない。** ゲストは「人」で数える。
  すぐ下の1行が、絞ったあとの人数まで受け持つ
- **黙って絞らない**(CLAUDE.md)。当てはまる人が0人のときは
  **「『◯◯』に当てはまるゲストがいません。」**と言う ——
  「まだ担当がいない」のか「絞り込みで消えた」のかが分からないと、
  行き止まりになる
- **開いているゲストは、絞り込みに関係なく開いたまま**
  (引くのは `openId` の側)。名前が当てはまらなくなった瞬間に
  画面から消えては困る
- **覚えない。** 探すのはその場の操作であって、設定ではない
- **`TrainerLearners` は Supabase を引き連れている**ので、骨組み
  (`__screens.jsx`)には描けない。`npm run test:bar` が**書いてある形**で
  見張る。ただし「名前が出てくるか」ではなく、**使っている形**
  (`: shown).map(`)で見る —— 欄だけ置いて絞っていなくても、
  **画面は普通に出るので気づけない**

### ゲストの一覧は「名前 → スコア → 最後 → 押すもの」

2026-09 利用者の指定「このゲストのボックス内の情報と見え方を
プロの仕事で整理してください」。

```
名前(20px 太字)            TOEIC  VERSANT  レベル   ← 上の行:左が誰か・右がどのくらいか
受講中
● 2日前 最後      [取り組みを見る] [この人を開く]   ← 下の行:左が中身・右が押すもの
```

- **アイコンは、画面のどこにも出さない**(利用者の指定
  「アイコンはいらない」)。ゲストの一覧から消したあと、
  **左メニューの自分の欄に残っていて2度言わせた。**
  「いらない」は**画面ぜんぶの話**である。1か所消して終わりにしない。
  入れ物(`profiles.avatar`・0029)と `Avatar.jsx` は残してあるので戻せる
- **囲みの中に、囲みを重ねない。** カードの中に札の箱、その隣にボタンの箱…と
  入れ子が続くと、線ばかりが目に入る。
  最後に取り組んだ日は**点と文字だけ**。上下は**細い線1本**で分ける
- **押すものは1本の行にまとめる。** 以前は取り組みが右、開くが左と
  離れた2行に散っていた
- **名前はカードでいちばん大きい**(20px)。17px ではスコアの数字(16px)と
  変わらず、どこを見ればよいか分からなかった。
  青い下線はやめ、**見出しの顔**にする(開く道はボタンにもある)
- **広い画面では、スコアの幅を決める**(300px)。中身なりにしていたので
  点数の桁でカードごとに左端がずれ、一覧がぎざぎざに見えた
  (実測 x=1013 / 1044 / 1080)
- **狭い画面では、押すものが横いっぱいを分け合う**

### 数を並べただけでは、何も伝わらない

2026-09 実機。

> 日数とか取り組みの表示がたくさんある割にパッと見て何もわからないです。
> それなら「取り組みをみる」とか、何かいい名前のボタンを押してより
> わかりやすい吹き出しなどで表示される方が良いです

取り組みの札を5つ並べていた(最後 / 2週間 / 回数 / 時間 / 種類)。
スマホでは**3行を食う**うえ、「2週間」が何の2週間なのか分からない。
**数が多いほど、どれも読まれない。**

- **いつも見えるのは1つだけ**にする(ここでは「最後はいつか」)
- 残りは**「取り組みを見る」**を押したときに、吹き出しで出す
- 吹き出しには場所があるので、**言葉で説明した名前**を使う
  (`practiceStats` の `items[].full`。札用の短い `label` と別に持つ)
- **リマインドも吹き出しの中へ。** 取り組みを見て決めることだから

**もう一度押したら閉じる。** 押したボタンの上は「外側」ではない。
そこで閉じてしまうと、そのあとボタンの `onClick` が
「閉じているから開く」と判断して**開き直し、消えなくなる**(2026-09 実機)。
`Popover` は `anchorEl` の中を押したときは閉じない。

**吹き出しは `Popover.jsx` を使う。** 出す場所の決め方(下 → 上 →
押し上げる)と閉じ方(外側・Esc)は**どの吹き出しでも同じ**である。
カレンダー(`CalendarPopover`)も同じものを使っている。

**押したものと出てくるものが結び付かなかった**(2026-09 実機

一覧には「**この人を開く**」だけを置き、
中で何を見るかは開いてからプルダウンで選ぶ。

### 見出しの中で、押すものを右上の隅に置かない

2026-09 利用者の指定「プルダウンの機能が右にあるのも使いにくい」。

**右上の隅は、いちばん指が届きにくい。** しかもスコアの真上にあったので、
押すたびに数字の列をまたいでいた。
**押すものは、見出しの下に1行取って左端から始める**(`.learner-tabrow`)。
狭い画面では横いっぱいにする。

**スコアは右のままでよい。** あれは読むもので、押すものではない。
「右へ寄せる」(2026-09 の指定)は、**読むものについての話**である。

### アイコンは「選んだ印」だけを残す。絵も写真も持たない

`profiles.avatar`(0029)+ `src/data/avatars.js` + `Avatar.jsx`。

- **選ぶのは本人だけ。** 置き場所は**左のメニューの下、自分の名前の隣**の
  1か所(`AvatarPicker`)。トレーナーの画面では**出すだけ**で、
  人のアイコンは変えられない
- **写真は上げさせない。** 置き場所(Storage)が要るうえ、
  **顔写真は個人情報**である。選ぶだけなら、その心配がない
- **選んでいない人も、空の丸にしない。** 名前の頭文字を出す
  (`initialOf`)。空だと、選び忘れなのかまだ読めていないのかが分からない。
  丸の色は**名前から決める**ので、同じ人はいつも同じ色になる
  (色をこちらで持たない。表も列も増やさない)
- **絵文字を使うのは、ここだけの例外。** ふだん絵文字を使わないのは
  「隣の文字と大きさがそろわない」ためだが、アイコンは丸の中に1つ置く
  だけで、そろえる相手がいない
- **印そのものを保存する**(id と絵の対応表を持たない)。
  表を書き換えたときに、すでに選んだ人の絵が変わってしまう
- `role` は**これまでどおり誰にも書き換えさせない。** 0029 が開けるのは
  `avatar` の1列だけで、0001 の考え方は変えていない
  (`rls_test.sql` が「他人のアイコンは変えられない」を見張っている)

### ゲストの記録は、まとめて消せる(0041)。**管理者だけ**

2026-09 の安全性レビューで見つかった穴。

> 退会したときに、まとめて消す手順がありません。
> 「消してほしい」と言われたときに応えられない状態です。

**画面から順に消させない。** 表をまたいで15か所以上あるので、途中で失敗すると
「どこまで消えたのか」が誰にも分からなくなる。**SQL の関数1つ**
(`erase_learner()`)にまとめ、**まるごと成功するか、まるごと失敗するか**にする。

- **できるのは管理者(`is_owner()`)だけ。** トレーナーにはできない
  (担当ゲストを持つ人が1人でも消せると、事故が大きすぎる)。
  **判定は関数の中。画面に持たせない**
- **ゲスト以外は消せない。** 相手の `role` を確かめる
  (トレーナーをまちがって消さないための歯止め)
- **消さないもの。** 教材そのもの(スクールの共有物)と、
  語の意味の控え(`word_glosses` は英単語の辞書であって、その人の記録ではない)
- **`auth.users` は消さない。** 消すには `service_role` が要る。
  **鍵を扱わないという決まりを、この機能のために曲げない。**
  プロフィールが消えるのでアプリは使えなくなるが、ログインの行そのものは
  Supabase の画面から消してもらう(画面がそう伝える)
- **`profiles` を消すと `on delete cascade` で多くが道連れになる**が、
  `vocab_days` / `practice_days` / `wordbook_views` / `reminders` は
  **`auth.users` を参照している**ので道連れにならない。**明示的に消す**
- **何件消したかを返す**(表ごと)。画面はそのまま出す
  (成功と失敗を、同じ見た目で終わらせない)
- 画面は**名前を打ち込ませる。** 2段(「本当に消す」)だけでは、
  並んだカードの取り違えを防げない
- **表を足したら、ここにも足す。** 英語の日記のような入れ物を作ったら、
  消す側にも1行足す。`rls_test.sql` が「消しすぎていないか」も見張っている

### 教材は消せる。**トレーナーだけ**(0044)

2026-09 利用者の指定。

> また、ゲストに作った教材を消す方法を作って下さい。
> 全ての場面にて「教材を消す」の機能を追加したいです。
> トレーナーだけの機能です。ゲストには消せません

| 誰 | 消せるか | どこで決まっているか |
|---|---|---|
| 作った本人(トレーナー) | ○ | **0001 のまま。1文字も変えていない** |
| 管理者(`owner`) | ○ | **0044**(どの教材でも) |
| ほかのトレーナー | × | どのポリシーにも当たらない |
| ゲスト | × | 同上 |

- **判断は `canDeleteMaterial()`(`src/lib/materialDelete.js`)1か所。**
  画面の中に書くと、置く場所の数だけ食い違う(`remakeModeOf()` と同じ考え方)。
  **何にも依存しない形**にしてあるので `npm run test:play` が見張れる
- **守っているのは RLS のほう。** 画面が間違えても
  `deleteMaterial()` が**返った行数**を見て断る
  (RLS は「消せない」を error ではなく**0件**で返す)
- **消せない人には、ボタンごと出さない**(選ばせてから断らない)
- **部品は `MaterialDelete.jsx` 1つ。** 置くのは**2か所**
  (トレーナーの「教材」/ ゲストのカードの「過去の宿題」)。
  **ゲストの「今週の宿題」には置かない** —— あれはゲストの画面である
- **2段で押させる**(「教材を消す」→「本当に消す」)。元には戻せない
- **押したときに、共有している人数を数える**(`materialShareCount`)。
  教材は既定で全トレーナーの共有物なので、消すと**配った先の宿題からも
  黙って消える。** 数を出さないと、何が起きるのか押す前に分からない。
  **数えられなかったら `null`** —— 0 と取り違えると
  「まだ誰にも共有していません」と**嘘の説明**になる
- **表を1つずつ消して回らない。** `materials` を参照している表は
  どれも `on delete cascade`(語と文は `set null`)なので、1回の delete で
  そろって消える。途中で失敗すると「どこまで消えたのか」が分からなくなる
  (`erase_learner()` と同じ考え方)
- **単語帳と Quick Response の復習は消えない。** あちらは「その語・その文」の
  記録であって、教材の持ち物ではない
- **`created_by` を取ってこないと、ボタンが出ない。**
  過去の宿題の問い合わせ(`loadLearnerAssignments`)には入っていなかったので
  足した。**画面もライブラリも lint を通るので、開くまで分からない**
- **`rls_test.sql` が見張っている。** ゲスト・別のトレーナーには消せないこと、
  作った本人と管理者には消せること、中身と宿題が道連れになること、
  ほかの教材が減っていないこと。**トレーナー1は退職済みなので、
  この節のためだけに現役のトレーナー3を足してある**
- **なぜ管理者にも足したか。** 教材は共有物なので、作った人が退会すると
  **誰にも消せない教材が残る**(0041 で見つけたのと同じ穴)。
  **トレーナーには足さない** —— 人の教材を消せると事故が大きい

### ゲストのファイルは、非公開の置き場に入れる(0031)

`learner_files`(表)+ `learner-files`(Storage・**非公開**)+
`src/lib/learnerFiles.js` + `LearnerFiles.jsx`。

- **見えるのは本人と、いま担当しているトレーナー(と管理者)だけ。**
  判定は 0001 の `teaches()`。**新しい判定を作らない**
- **中身**(バイト列)は置き場、**何があるか**(名前・大きさ・置いた人・
  メモ)は表。置き場だけでは「誰のものか」を SQL で絞れない
- **道は必ず `<ゲストの id>/…` で始める。** 表の側にも置き場の側にも
  同じ決まりを書く。**片方だけでは守れない**
- **URL は押した瞬間に作る**(5分だけ有効)。一覧に持たせると、
  画面を開いたままにしているうちに期限が切れる
- **書き換えのポリシーは作らない。** 直したいときは消して入れ直す
- **中身 → 控え の順**に入れる。控えの書き込みに失敗したら、
  **置いた中身を消す。** どちらかだけが残るのがいちばん困る
- **読み上げ音声(`tts`)は公開、こちらは非公開。取り違えない**
- 第 3.2 節の「**録音音声は端末から出さない**」は変えていない。
  ここに入るのは利用者が自分で選んで置いたファイルだけである

### ゲスト名の箱は、画面の上に貼り付ける(`LearnerBar.jsx`)

2026-09 利用者の指定。

> また、ゲストを一人選んでそのページの中にいるときは、
> 常に画面上部にゲスト名ボックスが固定されているようにしたいです。

ゲストのページは縦に長い(見出し → 切り替え → 宿題の一覧 →…)。
下へ送ると**誰のページを開いているのかが画面から消える。**
レッスンは画面を共有しながら行うので、
**取り違えたまま気づかない**のがいちばん怖い。

#### **`.app-stick` の中に入れる。`top` に帯の高さを書かない**

上に貼り付く帯を別々に `top: 0` で置いたら、送ったときに
**2つとも上端 0 へ来て重なり、☰ が押せなくなった**(`.jobbar` の節)。
だから貼り付く役は **`.app-stick` 1つ**が持っている。
ゲスト名の箱も**その中に入れる** —— そうすれば
**`top` に帯の高さを書かずに済む**(あの値は端末の切り欠き
`env(safe-area-inset-top)` で変わるので、決め打ちにするとずれる)。

- ところが `.app-stick` を描いているのは `App.jsx` で、
  開いているゲストを知っているのは `TrainerLearners.jsx` である。
  **だから控え(`lastLearner.js`)に見張らせる**(`generateJob.js` と同じ形)
- **`.learnerbar` は自分で貼り付かない。** 書き戻すと、また同じことが起きる
- **ゲストの画面にいるときだけ出す**(`view === 'learners'`)。
  控えは「教材」へ移っても残るが、**そこはそのゲストのページではない**

#### 名前も一緒に控える。**取りに行かせない**

id だけでは箱に何も書けない。`TrainerLearners` はもう名前を持っているので、
そのまま渡す(`rememberLearner(id, { name, status })`)。

- **同じ中身なら知らせない。** 描き直しが止まらなくなる
  (`voicePool` で踏んだのと同じ落とし穴)
- **状態の対応表は `src/data/learnerStatus.js` 1か所へ出した。**
  箱でも同じ札を出すので、**2か所に持たない**

#### 同じものを2か所に出さない

| 何 | どうしたか |
|---|---|
| 「← ゲストの一覧に戻る」 | **箱へ移した。** もとの場所は中身と一緒に送られて消える |
| 状態の札(受講中) | **開いているあいだ、カードの側に出さない。** 箱がいつも出している |

### セッションの記録は、宿題の一覧より**上**に置く(第5.219節)

#### Quick Response には、語で入る道が無い

`QrReview` は「冊」と「Unit」で選ぶ作りで、**語の一覧を受け取る口が無い**
(お題が**文**なので、語から引く索引そのものが無い)。
足すなら索引が要る。**要るかどうかは、単語帳のほうを使ってもらってから決める。**
