# 読み上げ用の英文(Text Normalization)

**画面に出ている英文と、声にするときの英文は別である。**
ここは、その書き換え(`src/lib/speakText.js` / `speakNum.js` /
`src/data/speakDict.js`)にまつわる決まりを置く。

---

### 画面の英文は、1文字も変えない(第5.205節・2026-09 利用者の指定)

> 画面表示用の英語(Written Form)と、TTS に渡す自然な読み上げ用英語
> (Spoken Form)が異なる表記を正しく変換する。
> **単純な文字置換ではなく、文脈を判定してから**適切な spoken form へ変換する。

```
DISPLAY TEXT  →  speakText()  →  SPOKEN TEXT  →  TTS  →  AUDIO
   画面           書き換え         窓口へ渡す      音声
```

**画面用の文字列そのものは書き換えない。**
`speakText()` が返すのは**別の文字列**である。

- **窓口へ渡すところ1か所**で通す(`audioClips.js` の `ttsBody()`)。
  ①本文まるごと ②1つずつ ③端末の声、**3つの道すべてがここを通る**
- **鍵(置き場所)も、読み上げ用の英文で取る。**
  画面の英文で取ると、**読み方の決まりを直しても古い音が鳴り続ける**
  (鍵が、音を決めているものを覆っていない状態)
- **数字も略語も無い文は、書き換えが起きないので指紋も同じ = 0円。**
  作り直しになるのは「いま読み方が間違っている文」だけである

---

### 語の色は、**画面の英文の位置**で動かす

`$25` は画面で3文字、声では 19 文字(`twenty-five dollars`)である。
**どちらの位置で数えているかを、取り違えない。**

| 何を | どちらの英文で |
|---|---|
| 置き場所・窓口へ渡す | **読み上げ用**(`spoken`) |
| 語の色・◀▶ の飛び先 | **画面**(`onScreen`) |
| 端末の声の合図(`boundary`) | 読み上げ用で返ってくる → **`displayAtOf()` で画面へ戻す** |

`playClip()` の中で `shown` という名前を使おうとして、
**すでに「いま入れてある音量」で使われていた**(CLAUDE.md
「違うものに、同じ名前を付けない」)。`onScreen` にした。

---

### 当てはめる順は、**長くて特殊なものから**

小数や整数を先に処理すると、**URL も版番号も IP アドレスも壊れる。**

```
192.168.1.1 を one hundred ninety-two point … と読んではいけない
v2.4.1      を小数として扱ってはいけない
03/04/2026  を分数として扱ってはいけない
$25.50      をただの小数として扱ってはいけない
```

`MATCHERS` の並びがその順である。**入れ替えない。**

---

### 分からないものは、変えない

`The Dr. was late.` のように**前も後ろも手がかりが無い**ときは、
**画面の文字のまま TTS へ渡す。** 当てずっぽうで意味を変えると
取り返しがつかない(CLAUDE.md「分かっていないことを、分かったように書かない」)。

### ここで実際に転んだもの(2026-09)

**どれも、本物の教材 996 本をまるごと通して初めて出てきた。**
仕様書の例だけを見ていたら、1つも見つからなかった。

#### ① 文字の並びの中の `-` が「範囲」になっていた

```js
/([+-−])(\d+)/     // ← `+`(U+002B)から `−`(U+2212)まで。数字がまるごと入る
```

`$63` の `6` が**符号として食われ**、`$minus three` と読んでいた。
`[+\-−]` と書く。**文字の並びの中の `-` は、必ずエスケープする。**

#### ② うしろの任意のかたまりの前に `\s?` を置くと、空白だけが食われる

```js
/([$])(\d+)\s?([KMBT])?/   // `$63 for` → `$63 ` まで当たる
```

当たったうしろが字だと歯止めに引っかかり、**当てはめごと捨てられる。**
**1か所で削る**(`speakText()` の中で、うしろの空白を返す)。
当てはめる人を1つずつ直して回ると、足した日にまた同じことが起きる。

#### ③ `I` をローマ数字と読んでいた

`Because I'm hungry.` → **`Because the First'm hungry.`**
`I` は英語でいちばん多い語である。**2文字以上のときだけ**数として読む。
`MIX` `MID` `DID` のような**英語の語**も外す。

#### ④ `in`(前置詞)を inches と読んでいた

`Dial 911 in case of emergency.` → **`nine hundred eleven inches case`**
英語の語と同じ字の単位は、**うしろが句読点か、長さを言う語のときだけ**
単位として読む(`6 in.` / `6 in tall`)。

#### ⑤ 国の TLD は、ふつうの英単語と同じ字である

`inanimate.it` / `the meeting.In fact`(空白を打ち忘れた文)が
「ドメイン」になっていた。**`https://` / `www.` / `/道` が付いていないときは、
よく見る TLD だけ**(`com` `org` …)。国の TLD は、その前が
よく見る TLD のときだけ(`example.co.jp`)。

#### ⑥ カンマを、数の一部として食っていた

`\d[\d,]*` は `15,` の読点まで食う。**画面から読点が消える**ので、
`\d+(?:,\d{3})*` と書く(**3桁ずつのときだけ、カンマは数の一部**)。

### 名簿は `src/data/speakDict.js` 1か所

読み方(単位・通貨・敬称・略語・記号・月・曜日・ギリシャ文字)は
**すべてここ**が持つ。`speakText.js` に書き写さない。
`npm run test:speak` が「書き写していないこと」まで見る。

**`wordTiming.js` の `ABBREVIATIONS` とは役目が違う。**
あちらは「その `.` は文の終わりか」を見分けるための一覧で、
**読み方を持っていない**(だから `etc.` `no.` をわざと外してある)。**混ぜない。**

### 文の終わりの点を、食べたままにしない(2026-09 実機)

```
画面  … the arrival time is 4:50 P.M. For the 10:20 departure …
読み  … the arrival time is four fifty P M  For the ten twenty departure …
                                          ↑ 点が消えていた
```

`P.M.` の点は、**文の終わりの点を兼ねている。**
食べたままにすると、向こうは**息継ぎ無しで次の文へ続けて読む。**

**「その点は文を終わらせているか」は、すでに1か所が知っている** ——
`wordTiming.js` の `splitSentences()` である。**ここで判じ直さない。**
`Mr. Smith` の点は文を終わらせていないので、戻さない。

### 大文字1文字は、席の記号であって単位ではない(2026-09 実機)

```
画面  I can give you seats 12 A, B, and C.
読み  I can give you seats twelve amperes, B, and C.   ← 直す前
```

ふつうの英語で、数のうしろの大文字1文字は**席や部屋の記号**である。
`domain` が理科・医療・IT・学術のときだけ単位として読む。
**迷ったら単位にしない**(CLAUDE.md「既定は『できない』側」)。

### 会社名の読みを指定する(第5.266節)

2026-09-26 利用者の指定。

> UMITO のような会社の名前をしてして記事やダイアローグを作ろうとすると、
> 英語の読みが「ゆーえむあいてぃーおー」と言われてしまいます。
> これを何とかできませんか?
> 他のケースでもうまく対応できるよう汎用性のある解決策を考えてください。
> 例えば「細かい指定」内に読み方も含めればOKなど、、、

#### これは**間違いではない**。だから決まりでは直せない

読み上げは、**知らない大文字の並びを1文字ずつ読む**(`U M I T O`)。
`IBM` も `ATM` もそう読むべきなので、**既定はこれで正しい。**

「母音があれば語として読む」のような決まりを入れると、
**`USA` が「ウサ」になる。** `NASA` と `USA` を字面だけで見分ける
決まりは無い —— だから CLAUDE.md の
「**迷ったら文字ずつ**」(`speakDict.js`)は正しい。

**名前ごとに教えてもらうしかない。**

#### 教える場所は「細かい指定」の中(利用者の指定)

    UMITO=ウミト
    UMITO=ウミト、KDDI=ケーディーディーアイ
    唐揚げ工場の話。UMITO=ウミト / Sakura＝さくら
    UMITO=oo-mee-toh          ← 英語のつづりで書いてもよい

- **新しい欄も、新しい列も作っていない。** 細かい指定は
  `materials.topic` にもう保存している
- 拾うのは **`名前=よみ` の形だけ。** ふつうの日本語の文に `X=Y` は
  まず出てこないので、**細かい指定の中身を取り違えない**
- **1文字の名前は拾わない**(`a=あ` で本文の `a` が総取り替えになる)
- 全角の `＝` も受ける —— 日本語入力ではそちらになる

#### **かな → 英語風のつづり**(ローマ字にしない)

    ウ → oo   ミ → mee   ト → toh      →   Oo-mee-toh

素のローマ字(`Umito`)にしないのは、英語の読み上げが
`u` を「ユー」、`i` を「アイ」と読みがちで、**「ユーマイト」**に
なってしまうからである。辞書が発音を示すときの書き方(respelling)と
同じ考え方にする。表は `src/data/kanaSpell.js`(147 通り)。

- **促音(ッ)は次の子音を重ねる**(サッポロ → Sap-poh-roh)
- **拗音を割らない**(キャ を キ + ャ にしない。長いほうから引く)
- **読めない字が1つでも混ざったら `null` を返して黙る。**
  いちばん危ないのは「**半分だけ読める**」形で、
  `ウミ人` を `Oo-mee` にすると**直したつもりで別の音**になる
  (赤チェックで、ここが素通りした)
- **空白を作らない(ハイフンでつなぐ)。**
  語の数が変わると、**語ごとの色(読み上げ中のハイライト)がずれる**

> **この節には誤りがあった。** 下の第5.269節で直した ——
> 「読み上げが1文字ずつ読む」と書いたが、**1文字ずつに開いていたのは
> こちらのコード(`speakText()`)だった。**
> だから細かい指定に書いても、根っこはそのままだった。
> **消していない** —— どう間違えたかが残っていないと、同じ道をもう一度通る。

#### **画面の英文は1文字も変えない**(第5.205節と同じ決まり)

書き換えるのは「お手本音声にする英文」(`material_items.audio_text`)だけ。
この欄は **0007 からある**(「空なら prompt_en を使う」)。

読み上げにする英文を決めるのは **`audioTextOf()` 1か所**にそろえた ——
これまで画面3つ(`LessonView` / `MaterialBody` / `LearnerHomework`)が
`it[type.audioFrom]` を**書き写して**いたので、
そこだけ素通りするところだった。

- **リスニングには当てない。** あちらは `audioFrom` がその欄そのもので、
  しかも答え合わせで**その文字がそのまま画面に出る**
- **これまでの教材は1文字も変わらない** —— 窓口が `audio_text` を返すのは
  リスニングだけなので、ほかの演習では空のままである
  (= 指紋が変わらない = **作り直しにならない・0円**)
- 置き換えが1つも起きなければ、**欄ごと作らない**(`sayAsText()` が空を返す)

#### まだできていないこと(**報告のみ**)

- **語ごとの色が、その語から先で少しずれる。** 読み上げ中のハイライトは
  読み上げた英文の位置で数えているので、`UMITO`(5文字)を
  `Oo-mee-toh`(10文字)に替えると、そのぶん後ろがずれる。
  **音は正しい。** ずれるのは色だけである
- **すでに発行した教材には当たらない。** 焼き込むのは発行のときなので、
  あとから読み方を足したら、その教材は作り直しになる
- **単語帳 / Quick Response の聞き流しには当たらない**(教材ではないので
  細かい指定が無い)

### 1文字ずつに開いていたのは、こちらのコードだった(第5.269節)

2026-09-26 実機・利用者の指摘。

> UMITOの読み方が全く直っていません。細かい指定で読み方を
> 指定するべきなのですか?

#### **動かして確かめたら、5秒で分かった**

    speakText('We visited UMITO last week.')
      → "We visited U M I T O last week."

**読み上げに渡す前に、こちらが開いていた。**
第5.266節で「読み上げが1文字ずつ読む」と書いたのは**誤り**である。

しかも同じ節で「**MP3 の道は `speakText()` を通っていない**」とも書いたが、
これも誤りだった —— `ttsBody()` が `spokenForm()` を呼び、
その中身は `speakText()` である。**読まずに書いていた。**

**CLAUDE.md「推測でいじらない。まず測る」を、こちらが破っていた。**
1行動かせば分かることを、1日置いてから確かめた。

#### 直し方 —— **名簿を1つ持たせて、いちばん先に見る**

`speakDict.js` に `SAY_AS_BOOK` を置き、`speakText()` の
**当てはめる人のいちばん先**に `mSayAs` を入れた。

    SAY_AS_BOOK = { UMITO: 'Oo-mee-toh' }

- **いちばん先でなければならない。** あとに回すと `mInitialism` が
  大文字の並びとして拾い、**文字ずつに開いてしまう**(それがこの不具合)
- **点は入れない**(`[A-Za-z][A-Za-z0-9&'-]*`)。文の終わりの `UMITO.` でも
  名前だけを拾い、ピリオドは文の終わりとして残る
- **「細かい指定」に書かなくても効く。** しかも **`speakText()` は
  読み上げの直前に通る**ので、**すでに発行した教材にも効く**
- **読み方は、利用者に訊いてから足す。** `UMITO` は「ウミト」と教わった
  (推測で辞書に入れない)

#### **効いていない1行を、自分で足していた**

`mSayAs` に「うしろが字なら当てない」を書いたが、**赤チェックで
一度も赤くならなかった。** 調べると、当てはめる人を回す側が

    if (hit && isWordCh(src[i + hit.len])) hit = null

を**全員にまとめて**掛けていた。**判断は1か所**にある。
書いた1行は効いていなかったので外した(**効かない指定を残さない**)。

**赤チェックで「赤くならない」は、見張りが甘いという意味とは限らない** ——
**そこがもう守られている**という知らせのこともある(CLAUDE.md)。

#### 発行の直後の「支度」が、書き換え前の英文で作っていた

第5.266節で足した「細かい指定の読み方を `audio_text` へ焼き込む」は、
**発行の直後の支度には届いていなかった** ——
`startPrepare()` に渡していたのが**画面が持っている元の演習**だったため。

支度で作った音と、あとで探す場所の**指紋が食い違い、
同じ文に二度課金される。** `createMaterial()` が組み直した演習を返し、
それをそのまま渡すようにした(**数え方を2通り持たない**)。

#### 名簿と「細かい指定」の使い分け

| | どこに書くか | いつ効くか |
|---|---|---|
| **会社名など、毎回出るもの** | `SAY_AS_BOOK`(名簿) | **すぐ・既存の教材にも** |
| その教材だけの一度きりの名前 | 細かい指定(`UMITO=ウミト`) | 発行のとき焼き込む |

**名簿に足すと、その名前を含む英文の音声は1回だけ作り直しになる**
(指紋が変わるため)。**いま読み方が間違っている文だけ**なので、
これは払ってよい費用である(`audioClips.js` の同じ決まり)。
