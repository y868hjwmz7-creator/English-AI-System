### 誘導を出す先は、**集中モードのボタンと同じ行き先**にする(第5.212節)

2026-09 実機。文型ドリルで語を長押ししても、案内が出なかった
(iPhone の「コピー / Google で検索」だけが出ていた)。

案内は `onNeedFocus`(行き先)があるときだけ出る決まりで、
そこを**本文のときだけ**渡していた。
**第5.208節で本文の無い教材にも集中モードができた**のに、
こちらを合わせていなかった。

- **行き先を決める関数を1つ置く**(`focusFor(sec, i)`)。
  英文が出るのは1枚のカードの中だけで3つある
  (**本文 / 設問 / 解答**)。どれにも同じ関数を渡す ——
  画面のあちこちで `isPassageSection(…) ? … : …` と書かない
- **右下の「集中モード」ボタンと、まったく同じ行き先**にする。
  ボタンで入るところと、案内で入るところが違っては困る
- **長押しした問から開く。** いつも1問めから開くと、
  30問のドリルで20問めを長押ししてから20回送ることになる
- **設問(`it.question`)には、はじめから1つも渡していなかった。**
  足す場所を数えるときは、**その画面に英文が出る場所を全部数える**
- 見張りは「出る」だけを見ない。**どの問から開いたか**まで見る ——
  いつも1問めに壊しても、出るだけなら緑になる

### 開く手段を、環境の判定1つに賭けない

語の意味の吹き出しを「カーソルが使える端末ならカーソル、そうでなければ長押し」で
出し分けたところ、`(hover: hover) and (pointer: fine)` が false になる端末で
**何をしても開かなくなった**(2026-08)。

**どの操作で来たかは `pointerType` で見る。** 環境の当て推量に賭けない。
語の意味は **パソコン=クリック / 触る端末=タップ(指を離したときに開く)**。
カーソルを置いただけでは開かない。

**長押し(450ms)はやめた**(2026-08 実機・3度目の指摘)。

> タッチで使用するデバイスだと相変わらずスクロールしようと
> タッチすると単語の意味が出てしまいます。

長押しは**押しているあいだに開く。** 指を置いて少し迷ってから画面を送ると、
**送り始める前に 450ms が過ぎて開く。** 動いたら取り消す見張りを足しても、
**動く前に開いてしまうので間に合わない。**
時間で判定するかぎり、この穴は塞げない。

**「指を離したときに決める」。** 画面を送るときの指は**必ず動く**ので、
「動かずに離れた」ことがそのままタップの証拠になる。
押している長さは見ない(迷って長く触れても、動かなければタップ)。

**ダブルタップにはしない**(利用者が案として挙げたが採らなかった)。
iOS では拡大の操作とぶつかり、**2語以上をなぞって調べる道**とも
両立しにくい。1回叩くだけで開くほうが、調べる回数の多い読解では速い。

**送りを止めるための1回は、タップとみなさない。**
画面が流れているときに叩くのは「止めたい」であって「調べたい」ではない。
`lastScrollAt`(書類ぜんぶに1つだけ置く)を見て、
**直前 400ms 以内に画面が動いていたら開かない。**

タップのあとには `click` が続けて起きる。**この1回を捨てないと、
開いた直後に閉じる。**

### なぞっているあいだは、画面を動かさない

**最初の一動きで決め、決めたら最後まで貫く**(2026-08 利用者の指定)。

> 2語以上を選択しようと横に移動や、下の行にドラッグしようとすると、
> スクロールが始まってしまい上手く出来ません。

- 語の上で指を置いたら `'undecided'`。**最初の 10px は画面を動かさない**
  (`preventDefault`)。判断を保留するため
- 10px を超えたら、**横が縦より大きければ `'drag'`、そうでなければ `'scroll'`**
- **`'drag'` のあいだは縦横とも動かさない。** そうしないと
  「横に動かしてから下の行へ」ができない
- 見張りは **`{ passive: false }` で自分で付ける。**
  React の `onTouchMove` は passive なので `preventDefault()` が効かない
- **あとから止めることはできない。** iOS はいったん画面送りを始めると
  `touchmove` を取り消せなくなる。だから最初の一動きで決める

**タップの判定は「動いたら・画面が送られたら、やめる」。**
iOS は画面が動き始めると、その要素へ pointer の知らせを送らなくなるので、
語に来る `pointermove` / `pointercancel` だけでは気づけない
(2026-08 実機「スクロールしようとすると単語の意味が出て来てしまいます」)。
縦に送るとき指は**同じ語の上に留まる**ので、語が変わったかでも足りない。
**書類ぜんぶに2つ見張りを置く。**

- 指が **10px** より動いたか(`pointermove` / `touchmove`)
- **画面が動いたか**(`scroll`。**伝わらないので capture で拾う。**
  紙は `overflow-y: auto` の要素なので、window だけでは届かない)

画面が動いたあとの指離しは、**なぞりと見なさない。**
`touch-action: pan-y` は**使えない**(インラインの箱には効かない)。

### 触る端末では、押した手応えを返す

**指は画面を隠す。** マウスと違い、押した場所が見えない
(2026-08 利用者の要望)。`src/lib/haptics.js` 1か所に置き、
`installTapFeedback()` を **App で1回だけ**呼ぶ。画面ごとに書くと必ず抜ける。

| 端末 | 手 |
|---|---|
| Android | `navigator.vibrate`(タップ 8ms / 長押し 18ms) |
| iPhone / iPad | `vibrate` は**無い。** Safari 17.4 以降の switch 付きチェックボックスを1つ隠し持ち、切り替えて振らせる |
| それ以外 | 何もしない。**押した印(CSS)だけが残る** |

- **音も鳴らす**(2026-09 利用者の指定。「鳴らさない」から改めた)。

  > ボタンなどを押したときは音が鳴るように、そして正解したらピンポン
  > となるようにしてほしいです。体で感じれる仕様です
  > ぶるっとしたり、おとがなったり、そういうのを実装してください

  **ふるえと音は、同じところから出す**(`tapFeedback()`)。
  別々に書くと、片方だけ鳴るボタンが必ずできる。
  音は `src/lib/sfx.js` が**その場で短い波を作る。**
  ファイルを持たない(読み込み待ちも容量も増えない)。

  | 合図 | いつ |
  |---|---|
  | `tap` | 押した。**いちばん短く、いちばん小さく**(何度も鳴る) |
  | `correct` | 言えた・覚えた。**ピンポン**(低い → 高い) |
  | `miss` | まだ。**責めない。** 低く1つだけ |
  | `done` | 裏の仕事が終わった。3つ上がる |

  - **`AudioContext` は1つだけ作り、二度と閉じない**(`speech.js` と同じ作法)。
    最初に画面へ触れた瞬間に起こす(iOS は触っていないところで
    始めた音を鳴らさない)
  - **切れるようにしてある**(左のメニューの下)。レッスン中に邪魔なとき用。
    もとの「鳴らさない」は、それが理由だった
  - 答え合わせの合図(`answerFeedback`)も**触って押したときだけ。**
    マウスの人には色と文字がすでに見えている
- **語は長押しが効いた瞬間だけ。** 触れた瞬間に振ると「押せた」と誤解させる。
  押しているあいだは `.etext-word.is-holding` で目にも見せる
- **画面を送ったときは返さない。** 指を置いた場所がボタンでも、
  そこから送り始めたなら押していない。`pointerdown` で返すと送るたびに
  振れるので、**指を離したときに、押しっぱなしだった場合だけ**返す
- **当てにしすぎない。** 効かない端末では静かに何もしない

あわせて、**開いたものを離れた瞬間に閉じない。** 中のボタンを押せなくなる。
閉じるのは ✕ / 外側を押す / Esc / 同じものをもう一度押したときだけ。

### トレーニングのやりかけは、覚えておく

`src/lib/progress.js` 1か所(2026-08 利用者の指定)。

> 各種トレーニングをやり途中で他のページに行ってから戻ると
> 途中まで区切ったスラッシュリーディングや書き途中だった
> ディクテーションが消えてしまいます。

- 鍵は **`eas.prog.<教材id>.<演習id>.<何の途中か>`。**
  教材の id を頭に置いてあるので、**教材ごとにまとめて消せる**
- `useProgress()` は `useState` と同じ形。**鍵が変わったら読み直す**
  (読み直しは**レンダーの中**で行う。`useEffect` だと1回ぶん古い値を
  新しい鍵で書いてしまう)
- 覚えるのは ①書きかけ ②区切り ③開いた行 ④どのステップか
  ⑤ Quick Response の何問目か。**トレーナー側・ゲスト側で同じ**
- **控えていた場所が範囲の外になっていることがある**(教材を直したあと)。
  そのまま使うと問が空になるので、必ず中に収める

**途中経過は、ゲストとトレーナーで分かち合う**(0025・2026-08 利用者の指定)。

> スラッシュリーディングの区切りやディクテーションで書き込んだことや、
> 取り組んだ回数なども同じ扱いとしてゲスト側に共有され保存される。

- 置き場所は **端末(localStorage)+ `material_progress`(0025)の両方。**
  端末の控えを先に出すので待たされないし、Supabase が無くても動く
- `useProgress(key, initial, learnerId)` の**3つめを渡したときだけ**
  サーバーにも置く。渡さなければ、これまでどおり端末の中だけ
- **あとから書いたほうが上書きしてよい**(利用者の指定)。
  > レッスン中にトレーナーが書いたものが、ゲストの書きかけを
  > 消してよいですか → 大丈夫です。添削できるからその方が良いです。

  だから「どちらが新しいか」を争わせない。読むときはサーバーを採り、
  書くときは 1.2 秒だまってからそのまま上書きする
- **読み終わる前に送らない。** 端末の控えでサーバーを消してしまう

**教材ごとのリセットは、トレーナーの「教材の中身」に置く**(利用者の指定)。
押し間違いを防ぐため2段(1回目で「本当に消す」に変わる)。

**消えるのは localStorage の途中経過だけ。** 単語帳(`word_reviews`)・
宿題・取り組みの記録は Supabase にあるので触れようがない。
**消せるものと消せないものを、置き場所で分けてある。**

### 画面に何かを足したら、トレーナー側とゲスト側の両方を数える

語の意味を出す仕組みを**ゲストの画面にしか入れず**、利用者(トレーナー)からは
「動いていない」ようにしか見えなかった(2026-08)。英文が出る場所は4つある。

| 画面 | 部品 |
|---|---|
| ゲスト「今週の宿題」 | `LearnerHomework.jsx` |
| ゲスト「本文の練習」 | `PassagePractice.jsx` |
| トレーナー「レッスンで使う(大きく表示)」 | `LessonView.jsx` |
| トレーナー「教材の中身」 | `TrainerMaterials.jsx` |

**4つ全部を確かめる。** 利用者はふだんトレーナーとして使っている。

### 語のそろえ方は3か所にある。ずらさない

`norm_word()` は **SQL(0011)・Edge Function(lookup-word)・画面(`src/lib/vocab.js`)**
の3か所に同じ規則で書いてある。**ずれると意味の控えを引き当てられず、
同じ語に何度も課金される。** `don't` と `well-known` は1語。
**原形には戻さない**(戻すには辞書が要り、間違えると別の語の意味が出る)。

語の意味の控え(`word_glosses`)に**書き込めるのは Edge Function だけ**。
画面からは読むだけ。

**「知っていた / 知らなかった」は、どの画面で押したかで持ち主が変わる**
(0025・2026-08 利用者の指定)。

| どこで押したか | 誰の記録になるか |
|---|---|
| ゲスト自身の「今週の宿題」 | そのゲスト |
| トレーナーの**ゲストのカードの中**(過去の宿題・レッスン表示) | **そのゲスト** |
| トレーナーの「教材」画面 | **トレーナー自身**(利用者の確認) |

> セッションで一緒に取り組んでいるので学習時間に入ります

レッスンは一緒に進めるので、そこで付けた語も、書いた区切りも、
取り組んだ時間も**ゲストの学習そのもの**である。

- **表の RLS は緩めない。** `mark_word()` / `log_practice()` を
  `security definer` にして、**関数の中だけ**で `teaches()` を確かめる。
  窓口を1つに絞るほうが、表そのものを開けるより穴が小さい
- 誰の記録にするかは `markIn(mark, materialId, forLearner)` で1回かぶせる。
  **画面ごとに書き写さない**
- ゲストのカードの中では、**映す記録もそのゲストのもの**にする
  (`useWordStatuses(openId)`)。押した色と、実際に残る先をそろえる
- `rls_test.sql` が「担当していないゲストには書けない」を見張っている。
  **この検証を外さない**

処理は `src/lib/useWordStatuses.js` に1つだけ置く。画面ごとに書き写さない。

**単語帳の「今日の復習」は、意味を隠してから出す。**
記憶は**思い出そうとしたときに**強くなる。読み返した回数ではない。
**答えを見る前に必ず1回考える。** 一覧の形(語と意味が同時に並ぶ)は、
見返す用のタブにだけ残してある。決まりは4つ(2026-08 利用者の指定)。

- **「覚えた / まだ」は最初から押せる。** 分かっているものを開かせない。
  **答えの2つは、となりどうしに置く**(2026-08 の指定で改めた)。
  「意味を見る」は答えではないので**1段上**。3つを1列に並べると、
  狭い画面で [まだ][意味を見る] / [覚えた] と折り返し、
  **答えの2つが上下に分かれていた**(実機)
- **毎回順番を混ぜる。** 並び順で覚えると、意味を思い出さずに答えられる
- **出会った文を、訳なしで先に出す**(`seen_in`)。文の音も聴ける。
  「意味を見る」で語の意味と**文の意味**(`seen_in_ja`)が出る
- **日本語 → 英語の向きも要る。** 読んで分かる力と、話すときに出てくる力は
  別物である。この向きのときは、**出会った文の中の答えを伏せる。**
  ただし**語そのものの音は聴ける**(2026-09 利用者の指定・**方針の変更**)。
  もとは「鳴らせば答えが聞こえてしまう」ので伏せていたが、この向きは
  **口に出して言う**練習なので、自分で言ってから**耳で答え合わせをする**
  ほうが素直である(Quick Response で同じ判断をしている)


### 「英語を見る」をやめて、**問題の箱ぜんぶ**をタップで切り替える(第5.262節)

2026-09-26 利用者の指定。

> 単語帳や quick response の「英語を見る」ボタンは廃止。
> 日本語の表示されているあたりをタップすれば英語に切り替わるように
> してください。タップできる範囲は広めにとってください。

#### どこまでを押せる範囲にするか(訊いて決めた)

**問題の箱ぜんぶ。** 番号も、話す人の名前も、日本語の行も、その上下の余白も。
**狙う場所を探させない** —— 指で使う端末では、
小さいボタンを狙わせること自体が手間である。

#### どの出し方に付けるか(訊いて決めた)

| 出し方 | タップ | なぜ |
|---|---|---|
| 日本語 → 英語 | ○ | 言われたもの |
| 思い出す | ○ | 向きが逆(英語 → 意味)だが、動きは同じ |
| 穴埋め | ○ | 伏せた語が出る |
| **4択** | **×** | 選択肢を押して答える形。**切り替える余地がそもそも無い** |

**判断は `canTapReveal()` 1か所**(画面で `form === 'ja2en'` と書かない)。

#### 伏せているときと、出したあとで、作りを変える

- **伏せているあいだは、本物の `<button>`。**
  中に押せるものが1つも無いので、そのまま押せるものにできる ——
  **キーボードでも読み上げでも、ふつうに押せる。**
  `div` に `role="button"` を付けて回るより確かである
- **出したあとは素の入れ物。** 答えの側には**語ごとの `<button>`**
  (`EnglishText`)が並ぶ。箱ごとボタンにすると
  **押せるものの中に押せるものが入る** ——
  正しくない作りだし、**語を押したつもりが問題に戻る。**
  だから**押された場所を見て**、押せるものを踏んでいたら切り替えない

**単語帳は4つとも中に押せるものが無い**(4択だけ `SpeakButton` が入るが、
そこには印を付けない)ので、`role="button"` + `onKeyDown` で足りる。

#### 言葉は消していない

ボタンの**文字**を消しただけで、「英語を見る / 意味を見る / 答えを見る」は
**読み上げの名前(`aria-label`)に移した**(`revealLabel()` 1か所)。
**黙って消さない**(CLAUDE.md)。

#### 見張りを6本、書き直すことになった

**新しい決まりに合わなくなった見張りは、放置すると黙る。**

| どこ | 何を見ていたか |
|---|---|
| `test:play` | 「冊名 ▾ は帯にある」(`top={bookPick}` の形) |
| `test:play` | 「ソートは長さの違う3本線」 |
| `test:bar` ×4 | **ボタンの文字「英語を見る」を探して押していた** |
| `test:shift` | 「ボタンに『答えを見る』と書いてある」 |

**`test:bar` の1か所は、文字で探していたので、廃止した日にそこが黙る
ところだった。** 押す先を `.qr-body--tap` / `.wordcard-face--tap` に変え、
名前は**箱の `aria-label`** で見るようにした。
