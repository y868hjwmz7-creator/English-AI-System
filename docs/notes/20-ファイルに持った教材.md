### 渡された PDF は、**ファイルに持つ**(2026-09 利用者の指定)

> これらを教材として独立させて登録せよ。
> Native flow は Quick Response 教材、コロケーション基本動詞は単語帳だ。

|  | 中身 | どこへ |
|---|---|---|
| **Native Flow Vol.1** | **690 フレーズ**(Unit 1〜6) | Quick Response 帳の**冊** |
| **コロケーション基本動詞** | **50 件**(MAKE / TAKE / GIVE / HAVE / DO × 10) | 単語帳の**4冊目** |

#### **新しい仕組みを1つも作っていない**

| 何 | どの道を使うか |
|---|---|
| 中身 | `src/data/nativeFlow.js` / `src/data/collocations.js`(**0円**) |
| 覚え具合 | `qr_reviews`(0040)/ `word_reviews` |
| 溜める | `markQr()` → `mark_qr` / `setWordStatus()` → `mark_word` |
| 出題・4択・絞り込み・聞き流し・紙 | `QrReview.jsx` / `Wordbook.jsx` **そのまま** |

**表も列も RPC も増えていない。** 基礎単語(`basicWords.js` + `basicReviews.js`)と
**まったく同じ形**である —— あちらも訳をファイルに持っているので、
単語帳へ入れるときに窓口を1回も呼ばない。

- **`materials` にしない。** 教材にすると SQL も発行の手順も要るうえ、
  **AI が作ったものではない**ので作り直しの道も意味を持たない
- **「まず入れる」という段を作らない。** 0053 で一度その形にして、
  **入れるまで1問も練習できなかった。** 冊そのものにすれば、
  **開いた瞬間から練習できる**(答えた問にだけ行ができる)

#### 行の形をそろえる。**画面は1文字も書き分けない**

`nativeFlowRows()` は **`qr_items()`(0048)が返すのと1つ残らず同じ欄**、
`collocationRows()` は **`review_words()` と同じ欄**を返す。
だから出題も絞り込みも聞き流しも紙も、**そのまま効く**
(`basicRows()` / `shelfReviews.js` とまったく同じ考え方)。

**行の無い問は「まだ・箱0・今日出す」。** 待たせる理由がない。

#### **Unit の切り替えを作らない。`material_title` に入れる**

Quick Response の復習には、もともと**「教材の名前で絞る」**がある
(`WordbookFilter` の `showMaterial`)。あれが見ているのは
**`material_title` だけ**で、`material_id` は使っていない。

    material_title: 'Native Flow Unit 1 1〜2単語の表現'

だから **Unit の絞り込みを1つも作らずに済む** ——
棚が `material_industry` / `material_scene` / `material_level` を
使い回したのと、まったく同じ話である。

- 頭に「Native Flow」を付けてあるので、**自分の Quick Response 帳の
  教材名と並んでも、どちらの冊の問か、ひと目で分かる**
- コロケーションも同じ(`コロケーション MAKE(何かを生み出す・作る系)`)。
  ただし**単語帳では `showMaterial={false}`** なので、絞り込みには出ない ——
  **害が無く、紙や将来の絞り込みで使える**ので入れてある

#### **原本のとおりに持つ。直したのは合字だけ**

- 合字(PDF の組版で fi / fl が1文字になっているもの)は、そのままだと
  `normEn` でも読み上げでも**別の語になる。** 2文字に直す
- 引用符・三点リーダ・度記号は**原文のまま**(英語としてそれが正しい)
- **原本では通し番号 480 が2回使われている**(抜けは無い)。
  **こちらで振り直さない** —— 鍵は `normEn(en)` であって、番号ではない
- **同じ英文が3組ある**(`Tidy up the room.` など)。
  鍵は英文なので `mark_qr` が1つにまとめる。**それでよい**

#### **`base` を意味の欄に混ぜない**(答えが漏れる)

コロケーションの `nuance`(判断する)は、たいてい `base`(decide)の
訳そのものである。混ぜると

    make a decision → 「判断する(フォーマル) ≒ decide」

となり、**4択の選択肢に英語が出て、`decision` と `decide` で答えが見えてしまう**
(「答えを出しておいて、答えさせない」)。
**データには持つが、行の意味には出さない。**

#### **0062 が要る**(`qr_items()` の上限が 500 だった)

`qr_items()` は **SQL の本文で 500 に切っていた**(0048)。

    limit greatest(1, least(coalesce(p_limit, 200), 500));

Native Flow だけで 690 問あるので、**後ろの 190 問は覚え具合が付かず、
何度答えても「まだ」に見える。** 単語帳が 200 で切られていたのと
まったく同じ壊れ方である(0056)。

- 上限の出どころは **`public.qr_limit()` 1か所**(0062)。
  中身は `wordbook_limit()`(0056)を返すだけ —— **数字を2か所に書かない**
- **印のためだけの関数ではない。** 語(単語帳)と文(Quick Response)では
  溜まる数が違うので、**別の値にしたくなる日が来る**
- **貼る前でも壊れない。** 500 問までは覚え具合が付き、その先は
  「まだ」として出るだけである(練習はできる)
- **表も列も作らない移行**なので、`SetupStatus` の印は
  **`qr_limit()` が在るかどうか**で見る(0056 とまったく同じ作法)

#### `qr_items()` を通す。**`qr_reviews` を直に読まない**

`qr_reviews` の RLS は **`learner_id = auth.uid()` だけ**(0040)。
表を直に読むと、**トレーナーがゲストのページから開いたときに0問**になる。
`qr_items()` は `security definer` で「本人 / 担当トレーナー / 管理者」を
見てくれる —— **画面で役割を判定しない。**

**棚と基礎単語が表を直に読んでいるのは、あちらの RLS が
担当トレーナーにも開いているからである。事情が違う。**

#### そろえ方(`normWord` / `normEn`)を `textNorm.js` へ出した

`normWord()` は `vocab.js`、`normEn()` は `materials.js` にあったが、
**どちらも Supabase を引き連れている**ので**素の node で一度も
走らせられない**(`playMark.js` / `mp3Join.js` と同じ話)。

ファイルに持った教材を覚え具合と突き合わせる算段は
`npm run test:play` が確かめたいので、**`src/lib/textNorm.js` へ出した。**

- **読む側は1行も変わっていない** —— `vocab.js` も `materials.js` も
  ここから読み直して、そのまま出し直している
  (`MATERIAL_KINDS` を `materialKinds.js` へ移したときと同じ作法)
- **同じ規則を2か所に書かない**(データの側にも書き写さない)

#### 検証(`npm run test:play`)

見るのは7つ ——①数が減っていないか ②原本のとおりか
③行の形が表から来る行と同じか ④絞り込みが効く形か
⑤答えが漏れていないか ⑥**画面が本当に呼んでいるか** ⑦貼る SQL がそろっているか。

**「例文の中に、その動詞が出てくるか」は見ない。**
`make a decision` の例文は `made`、`do damage` の例文は `did` で、
**活用は語のリストでは追えない**(**当てられることだけを見る**)。
見るのは**名詞のほう**で、あちらは活用しないので 50 件とも当たる。

実際に ①単語帳がコロケーションを読まない ②QR 帳の冊から Native Flow を落とす
③Native Flow を1件減らす ④意味の欄に `base` を混ぜる
⑤Unit を `material_title` に入れない ⑥合字を1つ戻す
⑦まとめた1つに 0062 を足し忘れる、の7つで
**それぞれ狙ったものだけ**が赤くなることを確かめてある。

##### 赤チェックの落とし穴 —— **赤くならないのは、壊し方が違うという知らせ**

⑥で `You're fired.` を置換しようとしたが、**当たらなかった。**
あの英文のアポストロフィは右シングル引用符なので、
データファイルでは**シングルクォートで書かれている**(ダブルクォートになるのは
ASCII のアポストロフィを含む行だけ)。置換が0件のまま「赤くならなかった」と
読んでいたら、**合字の見張りが効いていないと誤診するところだった。**

##### 出力に NUL が混じるので、`grep -a` を使う

`npm run test:play` は `runKeyOf()` の区切り(NUL 文字)を出力に含むので、
**`grep` が「binary file matches」と言って中身を見せない。**
赤チェックでは **`grep -a`** で読む。

#### 出す場所は、呼ぶ側が決める(`showCol` / `showNf`)

**既定は「出さない」。** トレーナーがゲストの単語帳や
Quick Response 帳を開く画面には、**冊の切り替えがもともと1つも無い**
(棚も基礎単語も渡していない)。そこを**1ドットも変えない**ためである ——
0053 で基礎単語を3冊目にしたときと、まったく同じ判断である。

| どこ | 出るか |
|---|---|
| **自分の単語帳 / Quick Response 帳**(`App.jsx`) | **出る**(`showCol` / `showNf` を渡す) |
| ゲストのページから開く画面(`TrainerLearners`) | **出さない**(渡さない) |

- **誰に出すかを絞る指定は、まだ受けていない。** 50 件も 690 問も
  ファイルに書いてあるので、棚のように「出された冊だけ」に絞る理由がいまは無い。
  絞りたくなったら `learnerFeatures.js` に1つ足すだけである(`shelf:` と同じ形)
- **既定を `true` にしない。** そうすると
  `TrainerLearners` と骨組みの両方に `false` を書くことになり、
  **書き忘れた場所が、黙って変わる**

##### 冊を足したら、**数を見ている検証も直す**

`npm run test:bar` は「冊の札が**ちょうど3つ**か」「札が3つのときだけ
35 冊を数える」という形で書いてあった。4冊目を足すと、

- **「冊の切り替えが出ていない」**(札の並びが一致しない)
- **「35冊そろっていない」**(`札.length === 3` が成り立たず、数えに入らない)

の2つが赤くなる。**これは正しい赤**である ——
**足すまで赤いままなので、必ず1回は自分の目で数えることになる**
(声の名簿の `KNOWN`・`test:bar` の `WANT` と同じ考え方)。

#### **前の決まりを、こちらから取り消した**

この文書には、すぐ上にこう書いてある。

> #### **Unit の切り替えを作らない。`material_title` に入れる**

**その判断は、利用者の指定で覆った。** 消さずに残す ——
なぜ作らなかったのか、なぜ作ることにしたのかが両方残っていないと、
次に同じところで迷う。

- **「教材の名前で絞る」は、そのまま残してある。** 絞り込みの中にあるので、
  Unit を選ばずに通しで回しながら**あとから絞る**道は消えていない
- **冊を6つに割らない。** 札の行が「自分の帳 + 6」になって、
  何を選ぶ場所なのか分からなくなる。**冊は2つのまま、中で Unit を選ぶ**
  (業種べつの単語帳とまったく同じ形・`ShelfBooks`)
- **「ぜんぶ」を残す。** 棚は 35 冊あるので「1冊選ぶ」しかないが、
  こちらは6つで、しかも**いままで 690 問を通しで回せていた。**
  選べるものを黙って減らさない(**勝手に狭めない**)

#### 配布は、**棚(`shelf:`)とまったく同じ入れ物**

`learner_features`(0055)に **`nf:<Unit の番号>`** で入る。

| | |
|---|---|
| 新しい表 | **要らない** |
| 新しい窓口(RPC) | **要らない**(`set_learner_feature()` そのまま) |
| 新しい RLS | **要らない**(門番は `teaches()` / `is_owner()`) |
| **貼る SQL** | **1行も増えていない** |

`learner_features.feature` に check を置いていないのは、
**まさにこのため**である(0055 の comment)。
`erase_learner()` もすでに消しているので、消す側に足す必要もない。

- **名前の作り方は `nfFeature()` 1か所。** 画面で `'nf:' + id` と書かない
- **`check.sql` に足す行も無い**(表も関数も増えていないので、見るものが無い)

#### **棚とはわざと違う。トレーナーには既定で出す**

棚は 2026-09 の指定で**トレーナーも「出された冊だけ」**になった。
**ここはそうしない** —— 利用者の指定がはっきり分かれている。

    指定したゲストだけに届くように、
    **トレーナーにはデフォルトで表示される**ように

だから形は **`showsBasics()` のほう**(ゲストだけ絞る)に合わせてある。

- **似ているからと、あちらに寄せない**(CLAUDE.md「寄せたついでに直さない」)
- `npm run test:play` が、**棚が役割を見ないままであること**も見張っている
  —— 片方を直したついでにもう片方を動かすと、そこで赤くなる
- **役割が分からないうちは出さない**(読み込みの途中・引けなかったとき)

| | 出る Unit |
|---|---|
| トレーナー・管理者(自分の Quick Response 帳) | **6つとも** |
| ゲスト | **出された Unit だけ**(1つも無ければ、冊ごと出ない) |
| ゲストのページから開く画面(`TrainerLearners`) | **出さない**(渡していない。1ドットも変えていない) |

#### **出せなくなった Unit は、黙って落ちる**

トレーナーが指定を外したあとも、端末には「前に開いていた Unit」が
残っている(`NF_UNIT_KEY`)。そのまま使うと
**見えていないはずの問が出題に混ざる。**
出してよい一覧に無ければ「ぜんぶ」に落とす
(棚の `pickedShelves` とまったく同じ落とし穴)。

なお「ぜんぶ」も**出してよい Unit の中のぜんぶ**である ——
`loadNativeFlowQr()` には、選んでいなければ `nfUnitsFor()` の一覧を渡す。

#### 部品は2つとも「props で受け取るだけ」

- `NativeFlowUnits`(ゲスト側・どの Unit を練習するか)
- `NativeFlowAssign`(トレーナー側・誰に出すか)

**自分では何も読み込まない。** `TrainerLearners.jsx` は Supabase を
引き連れているので、あそこに直に書くと**骨組みでは1ドットも描かれない。**
**描けないものは測れない** —— 実際それで「押しても何も起きない」が
実機で指摘されるまで残った(`ShelfAssign` の経緯)。

`?screen=nfunits` / `?screen=nfassign` で描いて測ってある
(390px / 1280px とも、はみ出しなし・札は 36px 以上・
札どうしが接していない・プルダウンは 40px)。

- **札を6つ並べる。プルダウンにしない。** `ShelfAssign` がプルダウンなのは
  **35 冊あるから**である。6つなら**いま出ているものが一目で分かる札**の
  ほうがよい。**決まりを形だけ真似ると、かえって見えなくなる**
- 大きさの決まりは **`.shelfassign` / `.shelfbooks-pick` と同じ行で分け合う。**
  別に書くと、36px / 40px を変えた日に片方だけ古くなる

#### 検証で転んだところ —— **測り方が違うと、壊れていなくても赤くなる**

「置き場所は Quick Response のタブか」を
`indexOf('NativeFlowAssign')` で見ていたが、**いちばん上の `import` に
当たって必ず手前になる**ので、正しく置いてあっても赤かった。
**`<NativeFlowAssign` (置いてある場所)で見る。**

同じ根で、「冊が変わったら読み直す」は `[learnerId, book]` という
**並びそのもの**を探していた。見張りに `unit` を足したとたん赤くなる。
**並びではなく「入っているか」で見る**(`colBook` のときと同じ直し方)。

#### **ユニット毎にも、丸ごとにも出せる**(2026-09 利用者の指定)

> トレーナーアカウントのゲストページで、
> ユニット毎、または丸ごとアサイン出来るようにしてください

1つずつ押すと**6回**かかる。ふだんは「この人には Native Flow をぜんぶ渡す」で
足りるので、そこを1回で済ませる。

- **`toggleFeature()` を6回呼ばない。** あれは**押すたびに `features` を見て
  向きを決める**うえ、`featureBusy` が立っているあいだは何もしない。
  続けて呼ぶと、**2回目以降は素通りするか、古い `features` を見て逆向きに倒す。**
  丸ごとは「どちらにそろえるか」が先に決まっているので、
  **向きを渡して、まとめて1回だけ書き戻す**(`setNfAll`)
- **すでにその向きの Unit には、窓口を呼ばない。**
  6つとも呼ぶと、変えていない Unit まで書き直すことになる
- **途中で断られても、黙って落ちない。** そこまでに通ったぶんを
  `features` に残し、**いくつ済んだか**を数えてその場に出す
- **数えながら進む。** はじめ、あとから引き算で「何件済んだか」を出す式を
  書いたが、**読んでも正しさを確かめられない式**になった。
  `done += 1` に直した(**分かっていないことを、分かったように書かない**)
- 「ぜんぶ」の問数は **`units` から数えて出す。** 書き写すと、
  Vol.2 で Unit を増やした日に嘘になる
- **「ぜんぶ外す」は、出しているときだけ出す**(効かない操作を見せない)

**トレーナーがゲストのページから開く Quick Response 帳そのものは、
まだ1ドットも変えていない**(Native Flow の冊は出していない)。
ゲストのページで言われたのは**割り当て**なので、そこだけを足した。
