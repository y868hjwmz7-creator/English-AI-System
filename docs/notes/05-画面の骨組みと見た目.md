### うしろを送れなくする鍵は、**数える**(`scrollLock.js`)

2026-09 実機・利用者の指摘。

> スクロールを始めるとサイドバーのハンバーガーが触れなくなる

**端末を尋ねたら、iPhone・iPad・パソコンの3つとも**だった。
つまり端末の癖ではない。

#### まず測った。**推測でいじらない**

Chromium で骨組みを描き、600px 送って ☰ を `elementFromPoint` で叩く。

| | 帯の上端 | ☰ は押せるか |
|---|---|---|
| ふつう | **8px**(貼り付く) | **押せる** |
| `body` に `overflow: hidden` が残ったとき | **−592px** | **押せない** |

**再現した。** 1280 / 900 / 768 / 390px の4つとも同じ。
`overflow: hidden` は箱を「送れる箱」に変えるので、
**`position: sticky` が効かなくなる**(この CLAUDE.md に書いてある)。
帯ごと画面の外へ流れ出るので、送るほど ☰ が遠ざかる。

#### では、なぜ `hidden` が残るのか —— **4か所が勝手にやっていた**

画面ぜんぶを覆うものが4つある(かぶせて開くメニュー `AppNav` /
レッスン表示 `LessonView` / 集中モード `FocusFrame` /
単語帳の集中モード `Wordbook`)。**どれも同じ3行を書き写していた。**

    const before = document.body.style.overflow
    document.body.style.overflow = 'hidden'
    return () => { document.body.style.overflow = before }

**入れ子になると壊れる。**

| | 何が起きるか |
|---|---|
| 単語帳の復習を開く | 控え = `''` → `hidden` |
| ☰ でメニューを開く | 控え = **`hidden`** → `hidden` |
| メニューから別の画面へ移る | 単語帳が `''` に戻し、そのあとメニューが **`hidden` を書き戻す** |

**`body` が `hidden` のまま取り残される。** しかもこれは
「ページからページへ移る」という**ふつうの操作**で起きる。

#### 直し方 —— **控えを1つにして、数える**

- **最初の1枚が掛けたときだけ控え、最後の1枚が外れたときだけ戻す**
- **外す順は問わない。** 逆順でも、二度外しても、同じところへ戻る
- **画面ごとに `body` を触らない。** `lockScroll()` だけを呼ぶ
- 何にも依存しない形にしてある(`playMark.js` と同じ考え方)ので、
  **素の node で確かめられる**

#### 見張りは2つ。**役目が違う**

| 検証 | 何を見るか |
|---|---|
| `npm run test:play` | **取り残しが起きうるコードの形**(入れ子・逆順・二度外し・4か所が自前で `body` を触っていないか) |
| `npm run test:bar` | **貼り付きそのもの**(送っても ☰ が押せるか)。あわせて**`hidden` が残ると押せなくなること**も測る |

**`test:bar` だけでは足りない。** あちらは実際の入れ子の順を作れないので、
4か所を元の形に戻しても**緑のまま**である(実際に確かめた)。
**コードの形は `test:play` が捕まえる**(戻すと4件赤くなる)。

**`test:bar` の側で「押せる」だけを見ない。** 貼り付きが外れても
気づけないので、**壊れ方(`hidden` を残すと押せなくなる)も一緒に測る。**

### 「この教材は AI が作っています」は、**教材の中に1行**(`AiNote.jsx`)

2026-09 実機・利用者の問い。

> また、音声や教材を「AIで作成してます」という注意書きはいらないのか？

#### 要る。ただし「法律で必須だから」ではない

- **法律**: このアプリはスクールの既存ゲストだけが使う**非公開**のもので、
  日本に「AI 生成物であることを表示せよ」という一般的な義務は、
  こちらが確かめた範囲では無い。EU の AI 法には透明性の義務があるが、
  EU の利用者がいなければ対象外である
- **各社の利用規約**(Anthropic / ElevenLabs)に表示の求めがあるかは、
  **この環境から規約を読めないので確かめていない。**
  **「無いから要らない」とは書かない**(あやふやなことを言わない)
- **本当の理由は、ゲストの受け取り方が変わること。** 英文も訳も音声も
  AI が作っている。それを知らないゲストは、変な英文に出会ったときに
  **「これが正しい英語なんだ」と受け取ってしまう。**
  AI が作っていると分かっていれば「トレーナーに訊いてみよう」になる。
  声も同じで、**実在の人物の声だと誤解されない**意味がある

#### 出し方(利用者が選んだ)

**教材の中に1行だけ。** 画面のいちばん上に居座る帯は、
**まさに同じ回で外したところ**である(下の節)。**同じものを作り直さない。**

- **読むもののそばに置く。** 変な英文に出会ったその場で分かる
- **静かに置く**(12px・うすい色・上に細い線1本)。
  添え物なので、本文より先に目が行ってはいけない
- **紙にも刷る。** 刷った用紙もゲストの手に渡る(`no-print` にしない)
- **何をすればよいかまで書く。**「AI が作っています」だけでは、
  読んだ人にできることが無い ——「おかしいと思ったところは、
  トレーナーに知らせてください」まで書く
- **文言は `AiNote.jsx` 1か所。** 出す場所は2つある
  (レッスン表示の紙 / 教材の中身)ので、**書き写すと片方だけ古くなる**
- **色は変数から取る**(`--ink-faint` / `--rule` に控え付き)。
  紙は配色の島なので、値を直に書くと**暗い側で黒い紙に黒い文字**になる

##### 色の決め打ちは、**描いても見つからない**

`npm run test:bar` は紙の地色との差を測るが、
**明るい紙の上では黒く決め打ちしても「読める」ので通ってしまう**
(実際に `#1c1c1a` に戻して、緑のままだった)。
だから**書いてある形**でも見る(`.ai-note` の `color` /
`border-top-color` が `var(` を含むか)。**片方だけでは足りない。**

### 「サンプルデータに戻す」は消した。**押す意味が無く、しかも嘘だった**

2026-09 実機・利用者の指摘。

> ゲストのIDとパスワードでログインすると危険そうなものがあるぞ。
> 1番下の、「サンプルデータに戻す」というやつです

#### まず、何が起きるのかを読んだ。**危険ではなかった**

押すと `resetState()` が `localStorage` の **`english-ai-system:v1`
1つだけ**を書き換えていた。中身は `learners` / `studyLogs` /
`pronunciationAttempts` の3つで、**どれもどの画面からも読まれていない。**
Supabase(教材・宿題・単語帳)にも、`eas.prog.*`(書きかけ・区切り)にも
届かない。**つまり、押しても実際には何も起きなかった。**

**「危険ではなかった」で終えない。** 出ていた確認の文が問題だった。

    保存されているデータをすべて消して、サンプルデータに戻します。

**これは嘘である。** 単語帳も宿題も消えない。読んだゲストは
**自分の記録が消えると思う。** しかも**ゲストの画面にも出ていた** ——
試作版の後始末であって、日々の操作ではない。

#### 道具ごと消した

**値を偽にするだけにしない。** 残すと、次に見た人が「まだ使うのかも
しれない」と読む(`withSkip` を消したときと同じ作法)。

- ボタンと `handleReset` を外した
- `state` / `loadState` / `saveState` / `resetState` の配線も外した
  (**どの画面からも読まれていなかった。** 読み込んで保存するだけの
  入れ物が、描き替えのたびに走っていた)
- **`src/lib/store.js` と `src/data/seed.js` は削除した。**
  ほかから使われていない(`createId` も `seed.js` 専用だった)
- **版(`VITE_BUILD_STAMP`)はフッターに残す。**
  どの版を見ているかを確かめる唯一の手がかりである
- `!state` を読み込み中の合図に使っていたので、`!authChecked` だけにした

`npm run test:bar` が、骨組みの4つの幅で
**「サンプルデータに戻す」が無い・フッター(版)は在る**を数える。
実際にボタンだけ戻して、4件が赤くなることを確かめてある。

| 何 | どうしたか |

| 試作版の断り書き | **丸ごと外した** |

  「SQL Editor で 0001 を実行してください」は**仕組みの内側の話**で、

### 行き先は、**画面の下の帯**に出す(`AppTabs.jsx`)

2026-09 実機・利用者の指定。

> ゲストとしてログインするとメニューにたどり着く方法が
> 1番上までスクロールしてハンバーガーを押すしかないのが
> かなり不便かつ分かりにくいです。改善してください

#### まず測った。**言われたとおりの不具合は、無かった**

上の帯(`.app-topbar`)は `position: sticky` である。実測すると
**390px で 900px 送っても、上端 8px のまま・☰ は押せた**
(送れる箱は1つも無く、`body` にも `overflow` は残っていない)。
つまり「**一番上まで戻らないと押せない**」形にはなっていない。

**それでも利用者の言うことは正しかった。** 本当の問題は別で、
**入口が1つしか無く、しかも隠れていること**である。ゲストの行き先は
4つ(今週の宿題 / 単語帳 / Quick Response / スピーチ練習)しかないのに、
**その全部が絵1つの裏**にある。どこへ行けるのかは、押すまで分からない。

**「その症状は再現しない」で終えない。** 症状の言い方が外れていても、
**不便であること自体は本当**である。測った結果は伝えたうえで、
何が不便なのかを取り出して直す。

#### 置き場所は画面の下。**読み上げの操作盤と同じ判断**

利用者自身が `.player-dock` で選んでいる ——「いっそのこと画面の下部に
黒帯にした中に固定にした方がスタイリッシュな気がします」。
スマホでいちばん親指が届くのは下端で、しかも**送っても消えない。**

- **狭い画面だけ**(768px 未満 = メニューがかぶせて開く幅)。
  それ以上では柱が出ているので、**同じことをするものが2つ**になる。
  判断は **`showTabs = !navPush && tabs.length > 0`(`App.jsx`)1か所**
- **トレーナーにも出す**(下の節)。**4つに絞る**
- **☰ は残す。** 下の帯は行き先を出すだけで、配色・音などの
  一度決める設定は、これまでどおり ☰ の中にある
- **`.app` の外に置く。** 中に入れると本文と一緒に送られて消える ——
  それではこの帯の役目そのものが無くなる
- **`z-index` は 40。** メニューをかぶせたとき(膜 50 / メニュー 60)と
  レッスン表示(`.lesson` は 100)・集中モード(120)には**必ず隠れる**
- **本文の下に余白を足す**(`.app-shell.has-tabs .app`)。
  足さないと、いちばん下の行が帯に隠れて読めない
- **いまいる画面の印は、色だけに頼らない**(CLAUDE.md)。
  うすい地色 + 同じ色の文字 + 太字 + 上の細い帯の4つ
- **名前は切らない。**「Quick…」では何のボタンか分からない
  (Quick Response の札で一度学んだこと)。入らないぶんは**2行に折り返す**

実測: 430 / 390 / 375 / 360px は **帯 57px・4つとも1行**、
320px だけ「Quick Response」が2行になって **63px**。
どの幅でも切れず、横のはみ出しも無く、押せる大きさ(56px)を割らない。

#### **トレーナーにも出す。ただし4つに絞る**(2026-09 利用者の指定)

> トレーナーのアカウントでも、ゲストと同じようにスマホやパッドで見る時には
> 下段のメニューを表示するようにしてください。教材、単語帳、Quick Response、
> スピーチ この四つにしてください。ゲストも同じです。
> 「発音を練習」を「スピーチ練習」にしてください

**「トレーナーは行き先が6つあり1行に収まらない」と書いたのが、
出さない理由だった。** ところが利用者は**どの4つを出すか**まで指定した。
数が問題なのだから、**出す数を決めればよい。**

| 誰 | 下の帯に出る4つ |
|---|---|
| ゲスト | **今週の宿題** / 単語帳 / Quick Response / スピーチ練習 |
| トレーナー・管理者 | **教材** / 単語帳 / Quick Response / スピーチ練習 |

- **「出す行き先は `pages` そのまま」は、もう成り立たない。**
  一覧は **`TAB_IDS`(`App.jsx`)1か所**が持ち、**名前と絵は `pages` から引く**
  (`pages.find(...)`)。**呼び名や絵を2か所に持たない**という決まりは、
  そのまま守れている
- **引けなかったものは落とす**(`.filter(Boolean)`)。
  ゲストに「教材」は無いので、書き間違えても**空の札は出ない**
- **トレーナーの「ゲスト」と「集計」は、帯に出ない。**
  その2つを開いているあいだは**どの札にも印が点かない**が、
  ☰ からはこれまでどおり行ける(**行き止まりを作らない**)

  **これは利用者が確かめたうえで決めたことである**(2026-09)。

  > 「ゲスト」はサイドバーにだけ出るようにします

  **帯に足し直さない。** 「トレーナーにも下の帯を出す」という指定を、
  「全部の行き先を出す」と読み替えない —— 数が多くて入らないことが
  そもそもの理由だった。**集計も同じ扱いのまま**(言われたのはゲストだが、
  4つに絞るという決まりから外れる理由がない)
- **ゲストの4つは1つも変わっていない**(呼び名だけ)

##### 「発音を練習」→「**スピーチ練習**」は、呼び名だけ

- **`id`(`pronunciation`)は変えない。** 覚えている画面(`eas.*`)も、
  取り組みの記録(`practice_days.kind`)もこの id で残っている。
  変えると**過去の記録が別物になる**
- 直した場所は3つ ——`App.jsx` の `pages` /
  `PronunciationPractice.jsx` の見出し / `practice.js` の `PRACTICE_KINDS`。
  **`PRACTICE_KINDS` の鍵は `pronunciation` のまま**(0022 の行がそれで残っている)
- **教材の種類「Speech練習」(`kind = 'speech'`)とは別物である。**
  あちらは自分の原稿を貼って練習する**教材**、こちらは
  マイクに向かって話す**画面**。**言葉が近いので、取り違えない**

#### 検証は「出る」と「出ない」の両方を見る

**「出る」だけを見ると、広い画面にも出すように書き換えて緑のまま**になる。
`npm run test:bar` は

1. **ゲストとトレーナーの両方**で、390 / 375 / 360 / 320px に
   4つとも出て、名前が切れず、押すと移るか
2. **広い画面には1つも出ないか**(768 / 900 / 1280px)
3. `App.jsx` が `!navPush && tabs.length > 0` で出しているか・
   **`pages` ではなく `tabs`(4つ)を渡しているか**・
   `TAB_IDS` の中身と「スピーチ練習」の呼び名

実際に ①条件を `isLearner && !navPush` に戻す ②`pages` をそのまま渡す
③呼び名を「発音練習」に戻す、の3つで赤くなることを確かめてある。

##### 「画面の中にあるか」で貼り付きを見ない

**最初の検証は、貼り付きをやめても緑のままだった。**
送った先ではたまたま画面の中に入るためである
(「無ければ素通りする検証を書かない」と同じ弱さ)。
いまは**送る前と送ったあとの両方で、帯の下端が画面の下端に重なるか**を見る。
貼り付いていなければ、送る前は 1200px 下にいるので必ず外れる
(実測 下端 1257 / 窓 844 で赤くなる)。

#### 帯を足したら、**そこに浮いているものを数える**(2026-09 実機)

> トレーナーの教材画面で、下部のタブに「教材をつくる」が
> 被ってしまっています。少し上に移動させて被らないようにしてください。
> タブから少しだけマージンは取ってください

さがす画面の「**＋ 教材を作る**」(`.finder-float`)が、帯の下にもぐっていた。

**どちらも `position: fixed` で、帯のほうがあとに描かれる。**
だから重なっても `npm run lint` にも `npm run build` にも引っかからず、
**狭い画面でその画面を開くまで分からない。**

- **`.app-shell.has-tabs` で見る。幅の境目で決めない** ——
  帯が出るのは「狭い画面 **かつ** 行き先がある」ときで、
  幅だけでは決まらない(`showTabs = !navPush && tabs.length > 0`)
- **帯の高さは実測する**(`?screen=tabs`)。**57px、320px では 63px**
  (「Quick Response」が2行になる)+ 端末の切り欠き。
  そこへ **12px** 足す —— 利用者の言う「少しだけマージン」である
- **`.sheet-floats.is-above-dock` とまったく同じ考え方。**
  下に貼り付く帯を足したら、**その上に浮くものを1つずつ数える**

##### 「重なっていない」だけを見ない

それだけだと、**画面のはるか上へ逃がしても緑**になる。
すき間が **8〜24px に収まっているか**まで見る。

あわせて**「持ち上げが `.has-tabs` に絞られているか」**も見るのだが、
**「その指定が在るか」で見てはいけない** —— 持ち上げを素の
`.finder-float` へ移しても、狭い画面ぶんの指定が残っているかぎり
**緑のままになる**(実際にそうなった)。
いまは**素の `.finder-float` が置いている `bottom` の値**を1つずつ読み、
帯の高さぶん浮いていないことを確かめる(実測 16px / 10px)。

実際に ①逃がす指定を外す(4件赤)②200px まで上げる(4件赤)

### 上に貼り付く帯は、**1つの箱にまとめる**(`.app-stick`)

2026-09 実機・利用者の指摘。**「☰ が消える」の正体である。**

> いや、上部バーは消えていなかったのですが、このバックグラウンドロード中の

> これを処理を止めて閉じるとずっとステイしているのが確認できました。

**利用者の切り分けがそのとおりだった。** こちらは「☰ が消える」を
何日も再現できずにいたが、**上の帯は1px も動いていなかった。**

#### まず測った。**推測でいじらない**

`?screen=sticky`(骨組みをそのまま描く)で 600px 送って測る。

| | 上の帯 | 支度の帯 | ☰ は押せるか |
|---|---|---|---|
| 送る前 | 0〜61px | **61〜120px**(下に並ぶ) | **押せる** |
| **送った後** | **0〜61px のまま** | **0〜59px**(上に重なる) | **押せない** |

1280 / 900 / 768 / 390px の4つとも同じ。出どころは1行で、
**`.app-topbar` と `.jobbar` が、どちらも
`position: sticky; top: 0; z-index: 30`** だったことである。
送る前は縦に並ぶので気づけず、**送ると2つとも上端 0 へ来て、
あとに書いてある支度の帯が上の帯をまるごと覆う。**

#### **`top` に帯の高さを書いて逃げない**

いちばん素直に見えるのは `.jobbar { top: 61px }` だが、**採れない。**
あの値は 56px + 端末の切り欠き(`env(safe-area-inset-top)`)で変わるので、
決め打ちにすると端末ごとにずれる(**「幅の境目で決めない」と同じ考え方**)。

**貼り付く役を `.app-stick` 1つに持たせる。** 帯2つをその中に入れれば、
**測る値が1つも要らない。** 支度の帯が出ていないときは、
中身が上の帯1つになるだけである。

- **`.jobbar` は自分で貼り付かない。** 書き戻すと、また同じことが起きる
- 「別々に `fixed` で置かない」(`.sheet-floats`)と**まったく同じ話**である

#### 見張りは2つ。**片方だけでは足りない**(実際に確かめた)

| 壊し方 | 何が赤くなるか |
|---|---|
| `.jobbar` に `top: 0` を書き戻す | **形の見張りだけ**(包んであるので重ならない) |
| 包み(`.app-stick`)を外す | **描いて測るほう4件**(☰ が押せない) |

**「送る前」だけを見ない。** そこでは縦に並ぶので、
**壊れたままでも緑になる。** 送ったあとに
`elementFromPoint` で ☰ を叩いて確かめる。

#### 上の帯は白。影は**箱がまとめて出す**。絵は `pages` から引く

| **影** | **`.app-stick`**(`.app-topbar` ではない) |

  **すぐ下の帯に隠れて見えない。** 箱ごと落とせば、

| 1380px | 操作盤が帯に入るか(**実測して決めた値**) |
| 600 / 560 / 480 / 400 / 360 / 320px | 狭くなるにつれて1つずつ詰める |

**まとめると、測って決めた振る舞いが壊れる。**
字の段のときと同じで、**数えてから書くこと。**

### 字・角・間は「段(トークン)」で持つ。px を直に書かない

2026-09、利用者の指定「UI/UX の完成度を一段上げたい」を受けて、
**まず実測した。** 推測で直さないためである。

| 何 | 実測 |
|---|---|
| `font-size` の px 直書き | **22種・284か所** |
| `border-radius` | 16種・153か所 |
| `gap` | 28種・238か所 |
| 折り返しの幅 | CSS に14個 + JS に3個(`useWide` 860 / 1024 / 1380) |

**同じ役目のものが 12px だったり 12.5px だったり 13px だったりしていた。**
画面ごとに書き足してきた結果で、**どこが正しいのかコードからは決められない。**

- 段は **`styles.css` のいちばん上の `:root` 1か所。**
  `--fs-*`(字)/ `--r-*`(角)/ `--sp-*`(間)。
  **前からある `--radius` と `--gap` は、段を指すようにしてある**
  (呼ぶ側は1行も変わっていない)
- **段を寄せるときは、その1行だけを書き換える。**

      --fs-12h: var(--fs-12);   ← 12.5px を 12px に寄せる

  284か所を探して回らなくてよいし、**気に入らなければその1行を戻すだけ**で元に戻る
- **名前は「いまの値」にしてある**(`--fs-12h` = 12.5px だった段)。
  寄せたあとも名前は残す —— 消すと 31 か所を書き換えることになり、
  **元がどこだったか分からなくなる**

#### 寄せてはいけない段が3つある

**見た目の好みで決まっていない段は、段の数に数えない。**

| 段 | なぜ動かせないか |
|---|---|
| **`--fs-16`** | **入力欄。** 860px 以下でこれを割ると **iOS が画面を勝手に拡大する** |
| `--fs-19` / `--fs-23` | **紙の文字「大」「特大」。** 16 / 19 / 23 の3段は利用者が選ぶ |

**「15段 → 7段」と書いたのは言い過ぎだった。** 実際に1つずつ見ると、
上の3つと、アイコンの大きさ(16 / 20 / 28)は**決まりで値が決まっている。**
寄せられたのは**半端な段(.5)5つと、1〜3か所しかない段4つ**で、
22 → 17 になった。**数えてから書くこと。**

#### 撮り比べで「1ドットも変わっていない」を確かめる

置き換えだけの回(第1週)は、**見た目が変わらないことが成功条件**である。
6画面 × 3幅(1440 / 768 / 390)× 明暗 = **36枚**を置き換えの前後で撮り、
**バイト単位で同じ**であることを確かめた(36 / 36)。
撮る道具は `scratchpad/shots.mjs`(リポジトリには入れていない)。

##### **縦しか測っていなかった。横に並ぶ組は一度も見ていなかった**

2026-09 実機・利用者の指摘。

> 「聞き流す」と「印刷・PDF」ボタンの間に隙間がありません。
> これは PC での表示ですが、**すべてのデバイスでこれが起こらないように

`.wb-listen` は **`margin-top: 10px` だけ**だった。上下は空くが、
**横に並ぶ2つのあいだには何も無い。** どちらも `btn--quiet`(灰色)なので、
2つが**1つの灰色の塊**に見えていた。

**横に並ぶ組を、まるごと読み飛ばしていた。** だから接していても緑だった。

- **「徹底する」とは、測るものを増やすことである。**

  **「並んでいるから」では外さない** —— それをやると何も守らなくなる
- **重なっているもの(-1.5px より深い)は数えない。**
  別々に置いた物ではなく、上に載せた飾りのことが多い
- 直し方は**決まりどおり** —— **`gap` で離す**(`.wb-tools`)。

- **単語帳と Quick Response の両方を直した。** 同じ `.wb-listen` を

### どの画面にも効く決まりは、まとめて書く

`styles.css` の「どの画面にも効く決まり」の節に置く。
部品ごとに書いて回ると、新しい部品で必ず抜ける。

- **横には揺らさない**(2026-09 実機・利用者の指定)。

  > スマホやパッドでスクロールすると、横方向にゆらゆらと画面がズレる

  横にはみ出す中身は**その場で直すのが本筋**である(この回の原因は
  紙に敷いた板が自分の幅を測っていたことと、練習の入口が3つになって
  1行に収まらなくなったこと。どちらも実測して直した)。
  そのうえで `html, body { overscroll-behavior-x: none }` を置き、
  **端まで来たときの跳ね返りと、親へ送りが伝わるのを止める。**
  中身を切り落とさないので、横に送れる箱(タブ・表)はこれまでどおり送れる。

  **横のはみ出しは、実測でしか見つからない。** 見つけ方は
  「その箱の `scrollWidth > clientWidth` か」と
  「中の箱の右端が、外の箱の内側の右端より右にあるか」の2つ

  **それでも揺れた**(2026-09 実機・利用者の指摘・2手め)。

  > スマホで教材ページやその他のページを表示しスクロールする際に
  > 左右にブレるので、これも固定されて動かないようにしてください。
  > ただし、スマホやパッドを横向きにした時はその幅にレスポンシブに適合するように

  **こちらの Chromium では再現しなかった**(390 / 375 / 320 / 844px の
  どこでも、画面より右へ出る箱は1つも無い)。iPhone だけで起きるので、
  **原因を突き止める道がこちらに無い。** だから
  **`html, body { overflow-x: clip }` でページそのものを横に送れなくした。**

  - **`hidden` にしない。** あれは箱を「送れる箱」に変えるので、
    **`position: sticky` が効かなくなる**(`JobBar` が貼り付かなくなる)。
    `clip` は送れる箱を作らない(実測で確かめてある)
  - **幅は画面の幅のまま。** 横向きにすればその幅に広がる
    (実測: 390 / 844 / 1180 / 320px とも、本文の幅 = 窓の幅)
  - **`position: fixed` のものは切られない**(浮きボタン・語の吹き出し)。
    あちらの寄る先は画面であって、この箱ではない
  - **横に送れる箱(タブ・表・紙)は、自分の中でこれまでどおり送れる**
  - **教材の中(`.lesson-sheet`)には触っていない**(利用者の指定)
  - `npm run test:bar` が、**わざと画面より広い箱を差し込んで**
    横に送れないことを確かめる。`hidden` に変えると赤くなる
- **選んでいる印を、べた塗りにしない。**「黒と濃い水色の塗りつぶしがダサい」
  (2026-08)。**うすい地色(`--accent-soft`)+ 同じ色の文字 + 枠線 + 太字**の
  4つで示す。色だけに頼らないので、プレインでも見分けられる
- **合っている=緑(`--ok`)/ まちがい=赤(`--ng`)。** ただし
  **地色と線(取り消し線・波線)も必ず併せる。** 緑と赤は見分けにくい人がいる
- **`:focus-visible` で輪を出す。** `:focus` だとマウスで押しただけでも出る
- **ボタンは 40px を割らない**(`.btn`)。小さくするものは `btn--small` で明示する
- **押し分けが要るボタンは3段で持つ。** 塗りつぶしを増やさない

  | 何 | 見た目 | 例 |
  |---|---|---|
  | 進む・正解 | `btn--primary`(青の塗りつぶし) | 覚えた / 言えた |
  | もう片方の答え | `btn--quiet`(**灰色の塗りつぶし**。`--border`) | まだ / 知らなかった |
  | 答えではない操作 | `btn--ghost`(枠線だけ) | 意味を見る / 英語を見る |

  **ボタンの色は専用の変数で持つ**(`--btn-bg` / `--quiet-bg` / `--on-accent`)。
  `--surface-0`(ページの地色)を使っていたので、暗い配色では**カードより
  暗くなり、黒い穴のように見えた**(2026-08「黒背景に黒ボタンは殺風景」)。
  **ボタンはカードより少しだけ明るく。** 青の塗りつぶしの文字も、
  暗い配色では白ではなく濃い色にする(うすい水色に白は薄い)

  **「まだ」を赤くしない**(2026-08「赤がいらないです」)。
  知らないことは失敗ではなく、語そのものに付く赤い線がその役目を担っている。
  `btn--ghost` を塗りつぶさないのは、暗い配色で**黒い箱に見える**ため
- **860px 以下では入力欄を 16px にする。** それ未満だと iOS が勝手に拡大する
- **札(chip)を `white-space: nowrap` にしない。** 弱点の名前は
  「間の取り方 + つなぎ言葉 + 決まり文句」のように長く、**札1つが
  囲みからはみ出す**(2026-09 実機・Safari)。`max-width: 100%` と
  `white-space: normal` にすれば ` + ` のところで折り返る。
  短い札(C1・食べ歩き)は、もともと1行なので見た目は変わらない
- **余白は「重なっているものをまとめて」見る。** 画面の余白(16px)→
  カード(20px)→ 見出しの囲み(12px)で**左右 48px ずつ**、
  iPhone(390px)では**画面の約1/4が余白**になっていた
  (2026-09 実機「文字が画面端から隙間が多すぎ」)。
  560px 以下では3つとも詰めて 32px にしてある。
  **1か所だけ詰めても効かない**
- **AI が付ける文字列(教材名・英語の見出し)には `overflow-wrap: break-word`。**
  長い1語が来ても囲みから出さない
- **実機で「文字が大きい」と言われたら、まず computed の px を測る。**
  こちらの指定と食い違うなら、**原因は端末側にある。**
  `-webkit-text-size-adjust: 100%` はすでに置いてあるので、
  疑うのは端末の「表示を大きく」の設定と、Safari のページズーム
  (サイトごとに残る。アドレスバー左の「ぁあ」で確かめられる)。

  **実際にそうだった**(2026-08)。写真では 12.8px の見出しが 16px 相当に
  見えており、こちらの指定より約 1.25 倍だった。
  利用者の端末が「表示が大きくなる設定」で、**アプリ側は正しかった。**
  一度は小さくして入れてしまい、そのあと戻した。

  **測らずに小さくして回らない。** 全部の画面が小さくなり、
  設定を戻した人には今度は小さすぎる
- **`prefers-reduced-motion` を尊重する。** 滑る動きが苦手な人がいる
- 影は `--shadow-1` / `--shadow-2`。**色と同じく変数で持ち、3か所すべてに置く**

### 説明の文は、既定では出さない(`tips.js` / `.tip`)

2026-09 利用者の指定。

> 目指すのは説明がない、直感的なUIです。ここでは

#### まず数えた。**`field-hint` は2つの別物に使われていた**

実測すると `.field-hint` が 81 か所・`.card-hint` が 46 か所・`.hint` が 27 か所。
ところが中身を1つずつ読むと、**まったく別のものが同じ札を着ていた。**

| | 例 |
|---|---|
| **説明**(こう操作してください・こうなっています) | 「場面によって丁寧さと言い回しが変わります」 |
| **知らせ**(いま何が起きているか) | 「調べています…」「この条件に当てはまる宿題はありません」 |
| **中身**(教材やデータそのもの) | `{sec.instruction}` / `{it.note}` / `{m.instruction_ja}` |

**だから「`.field-hint` をまとめて消す」はできない。**
やれば**誤り訂正の解説も、演習のやり方も、曲名も消える。**
消してよいのは**説明だけ**である。

#### 消していない。**`tip` の印を付けて畳んである**

判断は **`src/lib/tips.js` 1か所**(`eas.tips`・**既定は「出さない」**)。
畳む決まりは **styles.css の1行だけ**。

    :root:not([data-tips="on"]) .tip { display: none !important; }

- **`!important` を付ける。** `.generate-box .field-hint { display: block }`
  のように**部品の側で `display` を書いてある**ところがあり、
  そちらと**同じ強さ**(0,2,0)なので、書いてある場所しだいで勝ち負けが変わる。
  ここは唯一のつまみなので、必ず勝たせる
- **出すときは何も書かない。** この決まりが当たらなくなるだけで、
  部品それぞれの `display` がそのまま効く(`revert` と書くと、
  上の `display: block` まで巻き戻してしまう)
- **画面の中で `data-tips` と書かない。** 置く場所の数だけ食い違う
  (`remakeModeOf()` / `canAskReview()` と同じ)。画面がするのは
  **`tip` の印を付けることだけ**である
- 切り替えは**左のメニューの下**(配色・色づかい・音と同じ場所)。
  **一度決める設定だからである**

#### 「カーソルを当てたら」ではなく「その場に出る」にした

このアプリは iPhone で使われる。**触る端末には「カーソルを載せる」が無い**
(CLAUDE.md)。吹き出しにすると、**いちばん読みたい人が読めない。**
利用者の言葉は「**くらいの扱いでOK**」なので、
**それより届きやすい形**にしてある(同じことをするものを2つ作らない)。

#### **畳まなかったもの5つ。どれも先に書いてある決まりである**

| 何 | なぜ残すか |
|---|---|
| **費用**(「AI を 10 回呼ぶので、およそ ◯円」) | 見えない費用は管理できない |
| **取り消せない操作の断り**(教材を消す・まとめて消す・記録を消す) | 押す前に知らないと戻せない |
| **失敗・読み込み中・0件の知らせ** | 成功と失敗を同じ見た目で終わらせない |
| **書いたものがどこへ行くか**(添削・スピーチの原稿) | 黙って消さない |
| **教材やデータの中身** | 説明ではない。消すと教材が欠ける |

**「畳んだか」だけを見る検証を書かない** —— それだと、
**知らせまで畳んでも緑のまま**になる。`npm run test:play` は
上の5つを**文言で名指しして**、印が付いていないことを数える。

#### 文を畳んだら、**その場所は形で言う**

利用者が名指しした
「上の『学ぶ分野をえらぶ』で、練習したい分野にチェックを入れてください。」は、
**1分野も選んでいないときの案内**だった(行き止まりを作らない)。
畳むだけでは、何をすればよいか分からない画面が残る。

だから**「学ぶ分野をえらぶ」を、1冊も選んでいないあいだ青くした**
(`ShelfBooks`)。**押すところが1つしか無いのだから、そこが青ければ迷わない。**
**説明を省くとは、文を消すことではなく、形に置き換えることである。**

##### **青くした日に、その字が読めなくなっていた**(2026-09 実機)

> 業種別単語帳のボタンが真っ青です

**文字も絵も無い、ただの青い板**になっていた。原因は1行である。

    .btn--primary   { color: var(--on-accent) }   /* 1173 行目 */
    …
    .wb-add-open    { color: var(--accent) }      /* 5584 行目 */

**重さが同じ**(0,1,0)で**あとに書いてある**ほうが勝つので、
**青い地に青い字**になる。絵は `currentColor` なので**一緒に消える。**

- 直しは **`:not(.btn--primary)` を付けるだけ。**
  札の地色で同じことをしたときの **`:not(.chip--on)` とまったく同じ**である
- **`.btn--primary` の側を重くしない。** あれは全部のボタンに効く
- **ほかにも同じぶつかりが無いかを数えた。** `btn--primary` と一緒に
  書かれている札を全部拾い、**そのあとに `color` を書いている単独の決まり**を
  探した —— **当たったのはここ1つだけ**だった

###### 「青いか」ではなく、**読めるか**を測る

`npm run test:bar` は **`className` に `btn--primary` が入っているか**しか
見ていなかったので、**この不具合のあいだ、ずっと緑だった。**
**「名前が出てくるか」で見ない、の色の版**である。

いまは**描いて、字と地の差を測る**(明るい側と暗い側の両方)。
実測 **明 6.5 / 暗 6.3**、ぶつかっていたときは **1.0** である。
実際に `:not()` を外して、**そこだけ**赤くなることを確かめてある。

#### 検証は2つ。**役目が違う**

| 検証 | 何を見るか |
|---|---|
| `npm run test:play` | **算段**(既定 off・戻す道・判断が1か所・畳む決まりが1行・**畳まなかった5つ**) |
| `npm run test:bar` | **描いて数える**(既定で 0 個・オンにすると出る・えらぶボタンが青く、**その字が読める**) |

実際に ①既定を `on` に戻す ②畳む決まりから `!important` を外す
③画面が `data-tips` を直に書く ④費用の行に `tip` を付ける
⑤えらぶボタンを青くするのをやめる、の5つで

#### 名指しされた3つ(2026-09 実機「こういうの、いらないです」)

**同じことを2か所に出さない。**

**ただし、畳むには行を分けるしかなかった。** あの段落には
**先取りの断り**(「正解しても次に出る日は動きません」)が同居していた。

③教材のカードの `tip` を外す ④復習の説明を片方だけ畳む、の4つで

### 画面まわりの決まり

- **「面の段差」で情報を分ける。明るい側も暗い側も同じ考え方にする。**
  地(`--surface-0`)→ カード(`--surface-1`)→ その中の面(`--surface-2`)に
  **目に見える差**を付ける。枠線と影も一段強くして、カードの輪郭を出す。

  | | 地 | カード | 中の面 | 枠線 |
  |---|---|---|---|---|
  | 明るい | `#eaecef` | `#ffffff` | `#f0f2f4` | `#d5d9de` |
  | 暗い | `#0c0c0b` | `#1c1c1a` | `#2b2b28` | `#46463f` |

  以前は明るい側が `#f7f6f3` → `#fcfcfb`(差 5)、暗い側が
  `#131312` → `#1a1a19`(差 7)で、**どこがカードか分からなかった**
  (2026-08「全体的に見にくい」)。
  **片方だけ直さない。** 同じ見づらさは両方の配色で起きる
- **明るい側の地色に、茶み(暖色)を入れない。**
  段差を付けたとき暖かいベージュ寄りにしたところ、
  **「この茶色の背景が好きになれません」**(2026-08 実機)。
  段の深さはそのままに、**灰色**へ寄せた(`#eceae4` → `#eaecef`、
  `#eeece6` → `#f0f2f4`)。
  **同じ色を使っているところは、まとめて直す。**
  紙(`.lesson-sheet`)の `--paper` / `--rule` / `--qa-bg` / `--qa-line` /
  `--qa-answer` / `--quiet-bg` と、吹き出しの `--pop-rule` が同じ系統だった。
  1か所だけ直すと、そこだけ色味が違って残る
- **配色は3通り**(自動 / 明るい / 暗い)。`src/lib/theme.js` が
  `<html>` の `data-theme` を切り替える。色の変数を足すときは
  **`styles.css` の3か所すべてに書く。**
  `:root` / `@media (prefers-color-scheme: dark)` / `:root[data-theme="dark"]`。
  **1か所でも抜けると、そこを選んだときだけ色が食い違う。**
  実際、暗い側を media にだけ2回書き、`[data-theme="dark"]` に書き忘れて
  吹き出しの帯が明るいまま残った(2026-08)。**確認は明るい・暗いの両方で行う**
- **色を使うかどうかは選べる**(カラー / プレイン)。`src/lib/palette.js` が
  `<html>` の `data-palette` を切り替える。プレインは
  `:root[data-palette="plain"]` で**変数だけを差し替えて**色を消している。
  したがって**色は必ず変数で持つこと。** 値を直接書くと、プレインを
  選んだときだけその色が残る(紙の中だけは例外。常に白なので直接書く)。
  **ボタンやタブの青は消さない。** あれは「押せる」という合図である
- **読み上げ中の色は「文」単位。** フルストップからフルストップまでを
  まとめて光らせる(2026-08 利用者の指定)。語ごとに動かしていたが、
  合図(`boundary`)を出さない端末では見積もりに頼るしかなく、
  **1語ずれると目に見えて気持ちが悪い。** 文の単位なら、多少ずれても
  「いまこの文を読んでいる」は正しいままである。
  **精度を上げるより、外れても困らない見せ方を選ぶ。**
  文の切り方は `splitSentences()`(`src/lib/wordTiming.js`)1か所
  - **色は文ぜんぶを囲む箱1つ**(`.etext-sent`)に付ける。語や空白に
    別々に付けると帯が階段状になる。`<button>` は `display: inline` を
    指定しても効かず、Chromium では `inline-block` になるためである
    (実測で語の箱 31.6px / 空白の箱 21.0px)。`.etext-run` と同じ考え方
  - 箱は**ただのインライン**にする。`display` を変えると折り返し方が変わる
  - 位置の元になる合図は2段。① ブラウザの `boundary` があればそれに従う
    ② **来ない端末では時間から見積もる**(`attachWordTracking`)。
    利用者の会社PC(Windows / Chrome)の英語の声は3つとも Google の
    「通信を使う声」で、**3つとも合図を出さない**(mic-test.html で 0 回を実測)。
    MP3 なら `audio.duration` で長さが分かるので、そのぶん正確になる
- **狭い画面では、めったに触らない操作をしまう。** レッスン表示の操作欄が
  スマホで4段になり、**画面の4割**を占めていた(2026-08 実機)。
  いつも要るのは「閉じる・ページ送り・解答」の3つだけ。
  速さ・配色・文字の大きさ・印刷は「表示」の札に畳む(860px 以下)。
  **パソコンでは畳まない。** 札も出さない
  - **端末の種類を当て推量しない。** UA も `pointer` も見ず、
    **見えている幅だけ**で決める。横向きにすれば広い扱いになるのも素直
  - **いつも要る操作は、1つの囲みにまとめて折り返させない**
    (`.lesson-bar-main` に `flex-wrap: nowrap`)。帯ぜんぶを折り返させて
    いたので、iPhone(390px)で「表示」だけが2段目に落ち、
    **帯の高さが2倍**になっていた(2026-08 実機)。紙がそのぶん狭くなる。
    詰め方は**言葉を短く → 余白を詰める → 絵だけにする**の順で、
    320px でも1行に収まることを実測してある
  - **一度決める設定は覚える。** 文字の大きさを覚えていなかったので、
    開くたびに操作欄を触ることになっていた(それ自体が原因の一つ)
  - Esc は**開いているものから閉じる。** いきなり画面ごと閉じない
- **レッスンで使う表示**(`LessonView.jsx`)は画面共有用。
  **暗い配色を選んでいても紙は白のまま。** 共有先で見やすいことが優先。
  したがって**紙の中の文字色は決め打ちにする。** `var(--text-primary)` の
  ままだと、暗い配色のとき白い文字が白い紙に載って消える(2026-08 実機)。
  **文字色だけではない。** `<select>`・入力欄・札・ボタンも同じで、
  端末の色のままだと白い紙に黒い箱が乗る(2026-08 実機)。
  **部品ごとに打ち消して回らない。** `.lesson-sheet` で
  `--surface-*` / `--border` / `--text-*` / `--btn-bg` ごと差し替え、
  **紙の中を「明るい配色の島」にしてある。**
  そうすれば、紙の中に何を置いても自動的に明るい側の色になる。
  **色の変数を足したら、紙にも足す。** 名前が1つ違うだけで暗い色が残る
  (`--speak-bg` は紙にあったが、6Steps が使うのは `--speaking-bg` で、
  シャドーイング中の段落が**真っ黒**になっていた・2026-08 実機)。
  確かめ方は「暗い側にあって紙に無い変数」を洗い出すこと
- **色の帯と文字のあいだを詰めない**(2026-09 実機・利用者の指摘
  「段落の左側のライン、スマホだと少し文字に近すぎます」)。
  帯そのものが 5px あるので、行の左余白が 8px だと**文字まで 3px** しかない。
  **14px にして、線の内側に 9px 空ける。**
  **再生していない行も同じだけ空ける**(下記)ので、行は1px も動かない
- **色が付くときだけ余白を足さない。行が横に動く**(2026-09 実機・利用者の指摘)。

  > 普通のモードで再生されている時と通常時で数px横に表示がズレる

  狭い画面の紙で、**読み上げ中の行にだけ `padding-left` を足していた**
  (色の帯が番号の丸にかぶらないように)。そのぶん行が右へ動いていた
  (実測 6px)。**はじめからその余白で置く。**
  同じ注意は `.passage-part` の側にコメントで書いてあったのに、
  こちらで破っていた。**片方に書いた注意は、もう片方でも確かめる**
- **内側に敷いた帯は、角を丸めると両端が細る**(2026-09 利用者の指定
  「この左側の色の線は真っ直ぐにして欲しいです」)。
  `border-radius` は `box-shadow: inset` にも効く。
  左だけ角を落とさない(`border-radius: 0 6px 6px 0`)。
  **文字が太くなるのは構わない**(利用者の判断)
- **会話は、番号と話す人の名前で1行を使う。** 本文は次の行から左端にそろえる
  (`.lesson-speaker + .lesson-en { clear: left }`)。スマホでは番号を
  `float: left` で浮かせているが、丸は話す人の行より**数 px だけ背が高い。**
  そのはみ出しに1行目が回り込み、**発言ごとに1行目だけ字下げ**されていた
  (2026-08 実機)。記事は話す人がいないので、これまでどおり番号の横から
- **一覧は「押せる」ことが見て分かる形にする。** 宿題が下の小さなボタンで
  しか開けず、ただの一覧に見えていた(2026-08)。行そのものを押せるようにし、
  ▸ / ▾ の印を出す

### 指導ポイントの見た目は、指示があるまで変えない

### `npm run test:bar` を途中で止めたら、**開発サーバーを片づける**(2026-09)

`test:bar` は **5198 番の口**に開発サーバーを立てて、そこへブラウザをつなぐ
(`strictPort` なので、ふさがっていたら立ち上がらない)。

**途中で止めると、このサーバーだけが残る。** そのまま次の検証を走らせると、
新しいサーバーは立てられず、**古いほうにつながってしまう。**
実際にそうなったときの見え方はこうだった。

- 検証は動いているように見える(赤が出る)
- けれど中身は `?screen=shift` ではなく、**ログイン画面**だった
  (`本文: English AI System / ログインID …`)
- 出た赤は「型の欄そのものが描かれていない」—— **直したはずのものが
  描かれていないのではなく、別の画面を見ていた**

**「何も変わらない」は、届いていないという意味である**(CLAUDE.md)の
いちばん地味な形である。直す前に、**いま何を見ているか**を確かめる。

    fuser -k 5198/tcp     ← 残ったサーバーを片づける
    ps aux | grep '[v]ite'  ← ほかに残っていないか見る

**`pkill -f "vite"` で止めない**(実行中のシェルごと落ちる・CLAUDE.md)。

#### 赤チェックは、**リポジトリの複製の中**で壊す

`test:bar` は 20 分ほどかかる。本体を壊したまま待つと、そのあいだ
**作業ツリーが汚れたまま**になり、途中で環境が捨てられたら壊れたものが残る。

    git archive HEAD | tar -x -C <複製先>
    ln -s <本体>/node_modules <複製先>/node_modules

こうして**複製の側だけを壊す。** 本体はコミット済みのまま動かさない。
**節を1つだけ抜き出した短い版**を作れば、20分が 30秒になる

### 絵は、いちばん小さい大きさで見分けられるか(第5.189節)

### 「いちばん下」は、あとから足したもので変わる(第5.189節)

「設定」は第5.163節の指定で**サイドバーのいちばん下**に置いた。

**「設定」が真ん中に挟まって**いた。

### 「画面いっぱいに広げる」指定は、長さの分からない中身に効かせない(第5.193節)

2026-09 実機・利用者の指摘。

> 終わった後のリストの背景の色が途中から切り替わっています。
> これが、背景が黒の時は時の色と重なって読めなくなります。

`flex: 1 1 auto; min-height: 0` は「**1問ぶんを画面いっぱいに見せる**」
ための指定である。ところが**終わりの一覧は長さが分からない。**
広げたままだと箱の高さは画面ぶんで止まり、
**はみ出した中身は地の色の上に乗る。**

- **明るい配色では気づきにくい**(白 → 薄灰)。
  **暗い配色で初めて牙をむく** —— 同じ色の字がそのまま重なる
- **中身の長さが分からないものは、中身なりに伸ばす**
- 単語帳は `:not(.wordcard--result)` で**すでに外してあった。**
  **片方にだけ入れたから割れた** —— 同じ直し方を、同じ理由で

### 長い一覧の下のボタンは、画面に貼り付ける(第5.193節)

> 下までスクロールしないと「続ける」ボタンがクリックできません。

終わったあとにいちばんしたいことが、**一覧の下に埋もれていた。**

- **並びは変えない。** 点数 → 一覧 → ボタンのまま、
  **画面の下に貼り付ける**(`position: sticky; bottom: 0`)
- **地の色を必ず敷く。** 敷かないと下を流れる文字が透ける
- **浮いているので、すき間の見張りは数えない**(共通ルール)

### `test:bar` を途中で止めると、次の回が古いサーバーを測る(2026-09)

`npm run test:bar` は**自分用の vite を2つ**立てる
(`vite.bar.config.js` / `vite.shell.config.js`)。どちらも `strictPort` なので、
**前の回のものが居座ると、新しい回はポートを取れない。**
そのまま古いサーバーの画面を測るので、**直していない場所が赤くなる。**

実際に2回踏んだ。

| 出たもの | 本当の原因 |
|---|---|
| 22 行目で `.lesson-bar` が `null` で落ちる | 26 分前の vite が居座っていた |
| `書く欄` `文法解説の指定` が 5 本赤くなる | 同上(触っていない画面) |

- **赤が出たら、まず `ps -eo pid,cmd \| grep "[v]ite --config"`**
- 居たら `kill <pid>`。`vite.*.config.js` と `__bar.html` `__shell.html` も消す
- **`fuser -k 5173/tcp` では消えない** —— あれは `npm run dev` のポートで、
  `test:bar` が使うのは別の番号である
