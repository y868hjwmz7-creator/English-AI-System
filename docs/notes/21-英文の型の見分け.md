### 型を「決まり」で見分ける(2026-09 利用者の指定)

> 型の見分け、使い分けは必ず実現したいトレーニングです

`sentenceFrames.js` の 66 型は、それまで**巻末に刷るだけ**だった。
眺めるだけでは「この文はどの型か」が身に付かない。
**手元の英文が 66 型のどれなのかを言えれば**、単語帳も Quick Response も
**型べつに練習できる。**

| どこ | 何が変わったか |
|---|---|
| `src/lib/frameMatch.js`(新) | 65 本の規則で、英文 → 型を1つ返す。**当てられなければ `null`** |
| `src/lib/wordbookFilter.js` | `FILTER_KEYS` に `frame` を足し、`frameOf(row)` を置いた |
| `src/components/WordbookFilter.jsx` | **型**のプルダウン(①②③の見出しつき) |
| `src/components/QrCard.jsx` | 答えを開いたとき、下に**型の札**(`showFrame` を渡された画面だけ) |
| `scripts/test-frame.mjs`(新) | `npm run test:frame` |

#### **AI には尋ねない。0円で見分ける**

単語帳の語も Quick Response の問も**千を超える。**
1文ごとに尋ねると、そのたびに課金になる(「見えない費用は管理できない」)。
スラッシュリーディングの区切り(`chunker.js`)とまったく同じで、
**閉じたリストと記号だけ**で見分ける。

- 690 本の初回で **26ms**、控えを引いた 10 周で **1ms**(実測)。
  「CPU 2秒」(`04-起動と窓口と通信.md`)には遠い
- 控えは英文を鍵にした `Map` 1つ。**答えは英文だけで決まる**ので、
  控えと食い違うことがない

#### **当てられないものは黙る。取り違えるくらいなら、見落とす**

`SURE_PREPS` や `abbrevAt` とまったく同じ考え方である。
型を言い当てられなかった文は「型なし」で、**絞り込みの選択肢にも出ない。**
**当てずっぽうで型を付けると、練習そのものが嘘になる。**

見落としているものを、こちらで分かっているぶんだけ書き残す。

- **文の中に埋まっている関係詞**(`The report that we sent yesterday arrived.`)。
  拾おうとすると `that` を含む文がぜんぶ関係詞になる
- **`-ure` `-al` `-th` で終わる名詞化**(`refusal` `growth`)。
  `temperature` `total` `month` に**元の動詞が無い**ので、まとめて外した
- **`keeps costs low`** のような、**副詞にもなる形容詞**(下記)

#### 型の名前は `sentenceFrames.js` が唯一の出どころ。**書き写さない**

規則は型の `form` の文字列を**そのまま鍵に使う。**
食い違ったら `frameRuleAudit()` が知らせ、`npm run test:frame` が毎回まわす。

- **型を足して規則を足し忘れると、赤くなる。**
  `check.sql` と移行の関係とまったく同じ作法である ——
  足すまで赤いままなので、**必ず1回は自分の目で数えることになる**
- 見分けないと決めた型は `SAME_SHAPE` に**理由つきで**書く。
  黙って落とさない。いまは `what 節`(②)1つだけで、
  **`What ~ is …`(③)と語の並びが1文字も違わない**ためである

#### 語の一覧は `chunker.js` から読む。**2か所に書かない**

`PREPOSITIONS` / `DETERMINERS` / `OBJECT_PRONOUNS` / `SUBJECT_PRONOUNS` /
`NUMBER_WORDS` / `INDEFINITE_PRONOUNS` / `PLAIN_ADVERBS` / `TAIL_ADVERBS` /
`isAdjective` / `isParticiple` に **`export` を足しただけ**で、中身は1語も
変えていない(`npm run test:chunk` が緑のままであることで確かめてある)。

**別に持っているものが3つある。役目が違うからである。**

| ここだけの一覧 | なぜ `chunker.js` に足さないか |
|---|---|
| `TIME_SPAN` | あちらの `TIME_NOUNS` は**「いつ」**の一覧(`next month`)で、`hour` も `minute` も入っていない。足すと**スラッシュの落ちる場所が変わる**(言われていない場所を直すことになる) |
| `PERSON_OBJ` | あちらの `OBJECT_PRONOUNS` には `this` `that` `it` も入っている。ここで要るのは**人**だけ |
| `IT_ADJ` | `make it ___ (for 人) to do` は**席が固まっている**ので、`hard` のように副詞にもなる語を入れても取り違えない |

#### **並び順が意味を持つ。狭いものを先に置く**

上から順に当たったもの勝ちである。

    S leads 人 to do     より先に見る、ではなく **より先に置く**
    S leads to 名詞      ← あと

`S requires 人 to do` → `S requires 名詞`、
`It is X that / who ~`(③)→ `形式主語 it`(②)、
`The reason ~ is that …`(③)→ `the way / the reason`(②)も同じ。

#### **目的語の切れ目は、いちばん手前だけを見る**

`It makes me feel good about myself.` を**奥まで探しに行かせる**と、
目的語を `me feel` と取って `good` に行き着き、
**`S makes 人 形容詞` になっていた。** 正しくは `makes me feel` である。

**目的語は動詞のすぐうしろから始まる**のだから、
**成り立つ切れ目のうち、いちばん手前が答え**である。
奥を許すと、**必ずどこかで形容詞に行き着く。**

あわせて、**こういう終わり方をする目的語は無い**と決めてある。

- **冠詞で終わる** …… `made a decision` の `a` を目的語と見なすと、
  `decision` が原形の動詞に見える
- **形容詞で終わる** …… `made a good fortune` の `good` で切ると、
  `fortune` が原形の動詞に見える
- ただし **`her` は残す。** あれは**冠詞でもあり、人の目的語でもある**
  (`inspired her to learn`)。冠詞だからと外すと、この型が丸ごと落ちた

#### **副詞にもなる語を、形容詞の一覧に入れない**

`He left the office early.` が `S leaves 人 形容詞` になっていた(実データ)。
`early` `late` `fast` `hard` `high` `low` `free` `even` は
**形容詞にも副詞にもなる。** `chunker.js` の形容詞の一覧が
これらを入れていないのは**正しい判断**で、ここでも同じにする。

その代わり **`keeps costs low` を取り逃がす。**
取り違えるより、見落とすほうを選ぶ。

同じ根で、**`-ly` で終わらない副詞**も外している
(`make a decision soon` の `soon` を原形の動詞と見なしていた)。
一覧は `chunker.js` の `PLAIN_ADVERBS` / `TAIL_ADVERBS` から読む。

#### **名詞のかたまりかどうかは、「文の終わりの記号」で割る**

③「1文を後ろへ伸ばす」の4つ(関係詞・現在分詞・過去分詞・同格)は、
型そのものが**名詞のかたまり**である(`the report sent yesterday`)。

    The door opened slowly.      ← ふつうの文
    the report sent yesterday    ← 名詞のかたまり

**語の並びは1文字も違わない**(`the` + 名詞 + 過去分詞 + 副詞)。
**語では割れない。** 割れる目印は1つしかない ——
**書いた人が文として閉じたかどうか**である。
教材の英文にも Quick Response の問にも、必ず終わりの記号が付いている。

**この見張りを外すと、`The email sent this morning.` が過去分詞になる**
(赤チェックで確かめてある)。

#### 検証(`npm run test:frame`)—— **「出る」と「出ない」の両方を見る**

見るのは7つ。

| | 何を |
|---|---|
| ① | 型の一覧と規則が食い違っていないか(足し忘れ・書き間違い・重複) |
| ② | **66 の例文が、それぞれ自分の型に当たるか** |
| ③ | **型が付いてはいけない文に、付かないか**(18 本) |
| ④ | **例文ではない文**でも当たるか(15 本)—— 丸暗記の規則になっていないか |
| ⑤ | 実データ 740 本で、**やみくもに付けていないか**(2割未満・5種類以上) |
| ⑥ | 絞り込みが効く形か(鍵・空・数え上げ・組み直し・`en` と `seen_in` の両方) |
| ⑦ | **画面が本当に呼んでいるか**(コメントを落としてから、使っている形で数える) |

- **片方だけでは何も守らない。**「出る」だけを見ていると
  **全部に型を付ける形**でも緑、「出ない」だけを見ていると
  **どこにも型を付けない形**でも緑になる。実際に両方に書き換えて、
  **それぞれ別の行が赤くなる**ことを確かめてある
- **いちばん危ない形を、検証の中に必ず置く** ——
  空の文字列・空白だけ・1語・疑問文・**終わりの記号が有るだけの名詞のかたまり**
- **例文を書き写さない。** ④は同じ型を**別の語**で書いたものである。
  例文だけに当たる規則(丸暗記)になっていたら、ここで赤くなる
- 赤チェックは8本。①規則を1本外す ②いつも最初の型を返す
  ③いつも型なしを返す ④終わりの記号の見張りを外す
  ⑤絞り込みの鍵から `frame` を外す ⑥型のプルダウンを画面から落とす
  ⑦復習の画面で型を出すのをやめる ⑧答えと型のあいだの `gap` を消す。
  **8本とも、狙ったものだけが赤くなる**ことを確かめてある

#### 出す場所は、呼ぶ側が決める(`showFrame`)

**既定は出さない。**

| どこ | 型の札が出るか |
|---|---|
| **Quick Response の復習**(`QrReview`) | **出る**(`showFrame` を渡す) |
| 教材の中の Quick Response(`QuickResponse`) | **出さない** |

教材の中のものは**集中モードにも紙にも出る**ので、
渡すと**言われていない場所が変わる**(`showCol` / `showNf` と同じ判断)。
教材の中でも出したくなったら、`showFrame` を1つ渡すだけである。

- 札は**答えを開いたときだけ**出る。自分で言ってから英語を開いたとき、
  そこに型の名前があれば「いまのは `S allows 人 to do` だったのか」と結びつく
- **色だけに頼らない** —— うすい地色 + 同じ色の文字 + 枠線 + 太字
- 答えと札のあいだは **`gap` で離す**(子に `margin` を付けて回らない)。
  `.qr-answer` を `flex` にするとき **`align-items` は既定(stretch)のまま** ——
  `center` を入れると英文の行が中身なりの幅に縮んで、左端がぎざぎざになる

#### 絞り込みは、**`FILTER_KEYS` に1語足しただけ**

`frame` を足すと、**空にするのも・札の数も・出題の組み直し(`runKeyOf`)も
ひとりでに付いてくる** —— レベルを足したときに `runKeyOf` だけ数え漏らした
のを直してあるからである(`19-記録と集計.md`)。

- 見るのは **Quick Response の問は `en`、単語帳の語は出会った文 `seen_in`**。
  **どちらか在るほうを見る**ので、画面ごとに書き分けていない
- **型が1つしか見つからなければ、欄ごと出さない。**
  Native Flow のような短い言い回しばかりの冊では、そもそも出ない ——
  **効かない操作を見せない**
- 選択肢は **`FRAME_FORMS` の順のまま**(①無生物主語 → ②主語の席 → ③それ以外)。
  五十音順にすると、**巻末の一覧や PDF と見比べられなくなる**
