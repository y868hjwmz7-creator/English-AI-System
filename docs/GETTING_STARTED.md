# はじめての方へ — 用語と、リポジトリの中身の説明

Claude Code / GitHub を使い始めたばかりの方向けに、
「この言葉は何を指すのか」「このファイルは何のためにあるのか」をまとめました。
開発の経験がなくても読めるように書いています。

---

## 1. 出てくる言葉

| 言葉 | かんたんな説明 |
|---|---|
| **リポジトリ** | プロジェクトのファイル一式を入れておく箱。GitHub 上にあります |
| **コミット** | 「ここまでの変更を1つのまとまりとして記録する」操作。セーブポイント |
| **ブランチ** | 作業用の枝分かれ。本流(`main`)を壊さずに作業するために使います |
| **プッシュ** | 手元の記録を GitHub に送ること |
| **プルリクエスト (PR)** | 「この枝の変更を本流に取り込んでいいですか」という提案。相談・確認の場 |
| **npm** | 部品(ライブラリ)を集めてくる道具。Node.js に付いてきます |
| **ライブラリ** | 他の人が作った部品。自分で全部書かずに済みます |
| **ビルド** | 書いたコードを、ブラウザが読める形に組み立てること |
| **デプロイ** | 組み立てたものを、実際に使える場所に置くこと |
| **React** | 画面を組み立てるためのライブラリ。このアプリで使っています |
| **Vite** | 開発用のサーバーとビルドの道具。「ヴィート」と読みます |
| **Supabase** | データの保管庫とログイン機能をまとめて提供してくれるサービス |

---

## 2. リポジトリに何を入れて、何を入れないか

**入れるもの:** 自分で書いたコード、設定ファイル、ドキュメント

**入れないもの:**

| 入れないもの | 理由 |
|---|---|
| `node_modules/` | ライブラリの実体。何万ファイルもあり、`npm install` でいつでも復元できる |
| `dist/` | ビルド結果。コードから作り直せる |
| `.env` | パスワードやAPIキーを書くファイル。**GitHubに載ると誰でも見られる** |

これらは `.gitignore` というファイルに書いておくと、自動的に除外されます。

> **鍵の扱いだけは特に注意してください。**
> APIキーやパスワードを間違ってコミットすると、削除しても履歴に残ります。
> そのため、値は `.env`(Gitに入らない)に書き、
> 見本だけを `.env.example`(Gitに入る、中身は空)として置く決まりになっています。

## 3. このリポジトリのファイルの役割

### 設定ファイル(触る機会は少ないです)

| ファイル | 役割 |
|---|---|
| `package.json` | 使うライブラリの一覧と、`npm run ○○` コマンドの定義 |
| `package-lock.json` | ライブラリの正確なバージョンの記録。自動生成なので手で編集しない |
| `vite.config.js` | ビルドの設定 |
| `index.html` | アプリの入れ物。中身は React が描画します |
| `.gitignore` | Gitに入れないファイルの指定 |
| `.env.example` | 設定値の見本 |

### ドキュメント

| ファイル | 役割 |
|---|---|
| `README.md` | リポジトリを開いた人が最初に読むページ |
| `docs/PROJECT_SPEC.md` | 何を作るのかを決めた仕様書 |
| `docs/GETTING_STARTED.md` | このファイル |

### アプリ本体(`src/`)

```
src/
├── main.jsx        アプリの入口。ここから始まります
├── App.jsx         全体の枠。画面の切り替え、データの読み込み
├── styles.css      見た目。色やレイアウトはここで決まります
│
├── components/     画面を組み立てる部品
│   ├── EnglishStudyLog.jsx   学習者の画面(記録フォーム・発音練習・グラフ・履歴)
│   ├── AdminDashboard.jsx    管理者の画面(学習者一覧・集計グラフ)
│   └── charts/               グラフの部品(縦棒・横棒)
│
├── lib/            画面ではなく「処理」をまとめた場所
│   ├── store.js          データの保存と読み出し
│   ├── speech.js         読み上げと録音
│   ├── pronunciation.js  発音の採点
│   └── format.js         日付や時間の表示を整える
│
└── data/           固定のデータ
    ├── categories.js       学習カテゴリの定義
    ├── practicePhrases.js  発音練習の例文
    └── seed.js             最初に入っているサンプルデータ
```

**なぜ `components/` と `lib/` を分けているか**

「画面の見た目」と「裏側の処理」を分けておくと、片方を変えてももう片方に影響しません。

たとえば発音の採点を本物に差し替えるとき、`lib/pronunciation.js` だけを直せば済み、
`components/EnglishStudyLog.jsx`(画面)は一切触らなくて済みます。
同じように、データの保存先を Supabase に変えるときは `lib/store.js` だけを直します。

## 4. Claude Code に頼むときのコツ

うまく伝わりやすい頼み方の例です。

- **場所を示す** — 「`src/lib/store.js` の保存先を Supabase に変えてください」
- **仕様書を参照させる** — 「`docs/PROJECT_SPEC.md` の第5.1章の案1で実装してください」
- **確認方法まで頼む** — 「実装したあと、画面を開いて動くか確かめてください」
- **分からない言葉はその場で聞く** — 「RLSって何ですか。この場合どういう意味になりますか」

判断に迷うことは、勝手に決めずに聞いてもらって構いません。
「どちらがいいか分からないので、選択肢と、あなたのおすすめを教えてください」と伝えると、
比較して提案が返ってきます。

## 5. 困ったときは

| 症状 | 対処 |
|---|---|
| 会社PCとiPhoneで記録が違う | 端末ごとに別々に保存されるためです。Supabaseをつなぐと解決します |
| iPhoneで録音ボタンが反応しない | 公開URL(`https://`)で開いてください。1ファイル版ではマイクが使えません |
| 1ファイル版で録音ボタンが押せない | ブラウザの決まりで `file://` ではマイクが使えません。README の方法2をお使いください |
| データが消えた | ブラウザの履歴・サイトデータを消すと一緒に消えます。今の試作版の仕様です |
| 別のパソコンで開いたら記録がない | データはブラウザの中にあるため引き継がれません。Supabase をつなぐと解決します |
| グラフが空っぽ | 「サンプルデータに戻す」を押すと、デモ用のデータが入ります |
