# もうひとつのプロジェクトにも同じ仕様を置く

`CLAUDE.md` は **リポジトリごと**のファイルです。
このリポジトリに置いても、もうひとつのプロジェクトには効きません。
同じ仕様にするには、向こうにも置く必要があります。

## 仕組みの全体像

Claude Code がセッション開始時に自動で読むファイルは、置き場所で効く範囲が変わります。

| 置き場所 | 効く範囲 | このプロジェクトでの使い方 |
|---|---|---|
| `~/.claude/CLAUDE.md` | **そのパソコンの全プロジェクト** | 自宅の Mac でだけ有効。**クラウドのセッションには残らない** |
| `./.claude/rules/*.md` | そのリポジトリ | **共通ルールをここに置く**(下記) |
| `./CLAUDE.md` | そのリポジトリ | **そのプロジェクト固有のこと**だけ書く |

> **クラウドのセッションでは `~/.claude/` は消えます。**
> このチャットは使い捨ての作業場所で動いているため、
> ホームディレクトリに置いたものは次回には残りません。
> **確実に残るのはリポジトリの中だけ**なので、両方のリポジトリに置きます。

## 手順

### 1. 共通ルールをそのままコピーする

このリポジトリの [`../.claude/rules/common.md`](../.claude/rules/common.md) を、
**もうひとつのリポジトリの同じ場所**(`.claude/rules/common.md`)に、
中身を変えずにコピーします。

言語・事実の扱い・検証の作法・記録の残し方・鍵の扱い・Git の決まりが入っています。
**プロジェクトに依存しない内容だけ**にしてあるので、そのまま使えます。

> 片方を直したら、もう片方にも同じ変更を入れてください。
> リポジトリが分かれている以上、自動では同期されません。

### 2. そのプロジェクト用の `CLAUDE.md` を書く

共通ルールに書いていないこと——**そのプロジェクト固有のこと**だけを書きます。
下は骨組みです。`〈 〉` の中を埋めてください。

```markdown
# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**全プロジェクト共通のルールは `.claude/rules/common.md` にある。**
このファイルには、このプロジェクト固有のことだけを書く。

作業ブランチ: `〈ブランチ名〉`

## コマンド

| 目的 | コマンド |
|---|---|
| 開発サーバー | 〈 〉 |
| ビルド | 〈 〉 |
| テスト | 〈 〉 |

## このアプリが解く問題

〈何のための道具か。中心にある価値は何か。1〜2段落〉

## 設計を縛っている最大の制約

〈費用、時間、人数、端末など。判断が割れたときの決め手になるもの〉

## 構成

〈使っている技術と、データがどこに置かれるか〉

## この環境の制約

〈できないこと。到達できない通信先、使えない道具など〉

## 踏んだ落とし穴(繰り返さないこと)

〈実際に失敗したことだけを書く。想像で書かない〉
```

**空欄のまま置かないでください。** 書くことが無い節は消します。
中身の無い見出しは、次のセッションの判断を助けません。

### 3. 200行を超えないようにする

`CLAUDE.md` は毎回のセッションで読み込まれます。長いほど守られにくくなります。
目安は **200行以内**。増えてきたら、
特定のファイルを触るときだけ読む形(`.claude/rules/` の `paths:` 指定)に分けます。

## 何を書き、何を書かないか

| 書く | 書かない |
|---|---|
| **実際に踏んだ失敗**とその避け方 | 一般的な作法(「テストを書く」など) |
| なぜその判断をしたか | コードを読めば分かること(ファイル一覧など) |
| コードから読み取れない制約 | 想像で書いた「気をつけること」 |
| 毎回守ってほしい決まりごと | 一度きりの手順(これは skill にする) |

**目安は「同じ説明を2回した瞬間に書き足す」**です。

## 私(Claude)に書かせる場合

もうひとつのリポジトリをこのセッションから読めるようにすれば、
中身を読んだうえで `CLAUDE.md` を書けます。
ただし**別のリポジトリを読み込む操作には許可が要ります**ので、
その旨をチャットで伝えてください。

読めない状態で書くと、**中身を知らないまま推測で書くこと**になります。
それは次のセッションを助けるどころか誤らせるので、行いません。
