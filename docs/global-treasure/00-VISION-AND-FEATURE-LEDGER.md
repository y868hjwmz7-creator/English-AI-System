# 00. ビジョンと完成形機能台帳

## 1. プロダクトビジョン

> **日本で安い。世界では、欲しい。**

写真を撮るだけで、そのモノが**世界のどこで最も価値を持つか**を見つけ、
最適な価格で売り、梱包し、発送するところまで支援するアプリ。

日本での価格だけを基準にしない。同じ商品でも、日本では余っていて、
米国では高く、ドイツでは品薄で、UAE やサウジアラビアではさらに高いことがある。
GLOBAL TREASURE はその差を発見する。

### 誰のためか

**Phase 1 は日本にいる日本人。** 「日本国内でしか売らない版」という意味ではない。
**国内販売と海外販売の両方を、専門知識なしでできるようにする**という意味である。

海外販売に興味はあるが、英語・送料・関税・梱包・海外購入者とのやり取りが
面倒で怖い、という心理的障壁を極限まで下げる。
ユーザーを越境ECの専門家に育てるのではなく、**専門知識を持たないまま世界に売れる**ようにする。

### 究極の体験（PRODUCT NORTH STAR）

> 英語が苦手でも、海外発送をしたことがなくても、商品を撮るだけで世界へ売れる。

## 2. プロダクト原則

体験の中心は常に 📸 **SCAN** である。

```
撮る → 商品を特定 → 状態を確認 → 市場価値を分析
   → BUY / HOLD / SELL / PASS → 出品 → 梱包 → 発送 → 売却完了
```

- アプリの複雑さをユーザーに見せない。計算は裏側、表には判断だけを出す。
- 専門家向け管理画面にしない。ホームは大きな 3 ボタンとカメラ。
- 数字を見せるときは、必ず**根拠と Confidence** をセットで見せる。

### 3つのメインモード

| モード | 場面 | ユーザーの問い | 出す答え |
|---|---|---|---|
| ① NEW BUY | 新品を買う前 | 「これ、本当はいくらなのか？」 | TRUE COST（購入価格 − 推定将来売却価格） |
| ② MY STUFF | 持っている物 | 「今いくらの価値があるか？」 | 現在価値・Value Retention・SELL / HOLD |
| ③ HUNT | 中古店・フリマ | 「これを買ったら儲かるか？」 | REAL NET PROFIT・BUY / RISKY / PASS |

3つは別機能ではない。**同じ VALUE ENGINE の入力と出し方の違い**である（[07](07-VALUE-ENGINE.md)）。

## 3. 絶対に避けること（設計上の禁止事項）

この 10 項目は、機能追加や納期の都合で覆してはならない。
各項目に対して、**どの設計で機械的に防ぐか**を対応させている。

| # | 禁止事項 | 防ぐ仕組み | 詳細 |
|---|---|---|---|
| N-1 | AI が架空の中古価格を生成する | LLM に数値の出力経路を与えない。価格は VALUE ENGINE のみが返す | [05](05-AI-PIPELINE.md) §2 |
| N-2 | AI が写真から傷を消す | AUTO STUDIO は生成系処理を使わない。決定的画像処理のみ + 加工ログ保存 | [05](05-AI-PIPELINE.md) §6 |
| N-3 | AI が未確認の動作状態を書く | FACT LEDGER にない主張は検証器が機械的に棄却 | [05](05-AI-PIPELINE.md) §7 |
| N-4 | Marketplace を無断スクレイピングする | データ取得元を Provider に限定。取得元ごとに許諾状態を記録 | [06](06-INTEGRATIONS.md) §2 |
| N-5 | 規約違反の自動出品 | API 未許諾の Marketplace は SELL PACK 生成までで打ち止め | [06](06-INTEGRATIONS.md) §4 |
| N-6 | 古い税・関税情報を固定使用する | 税率・規制はコード埋め込み禁止。バージョン付き参照データ + 有効期限 | [06](06-INTEGRATIONS.md) §7 |
| N-7 | 送料を推測する | 送料は ShippingProvider の見積のみ。未取得時は「未取得」と表示 | [06](06-INTEGRATIONS.md) §5 |
| N-8 | 送れない商品を「発送可能」と断定する | EXPORT CHECK 未通過の商品は発送導線をブロック | [09](09-LEGAL-CHECKLIST.md) §3 |
| N-9 | 価格予測に根拠・Confidence を付けない | VALUE RESULT の型に basis と confidence を必須フィールドとして持たせる | [07](07-VALUE-ENGINE.md) §9 |
| N-10 | 数字だけ見せて算出根拠を隠す | すべての金額に内訳を展開できる UI を必須とする | [02](02-SCREENS.md) §5 |

## 5. コピー候補（ブランド言語）

実装時の文言トーンの基準として保持する。

- 日本で安い。世界では、欲しい。
- その値段、日本だけかもしれない。
- 撮るだけで、世界中の価値がわかる。
- 値札を見るな。残る価値を見ろ。
- 円安を、売る力に。
- Scan anything. Find where it's worth the most.

## 6. 最初のカテゴリ

「何でも世界で査定できる」を最初から目指さない。
**商品特定がしやすく、価格比較データが取れるカテゴリ**に絞る。

| 候補 | 特定のしやすさ | 海外需要 | 越境の障害 |
|---|---|---|---|
| カメラ・レンズ | 高（型番刻印・シリアル） | 非常に高い（日本製中古の世界的人気） | リチウム電池（本体別売なら回避可） |
| オーディオ・ヘッドホン | 高 | 高い | 電圧（据置機）、電池 |
| ゲーム機・ソフト | 非常に高（JAN） | 高い | リージョン、電圧、内蔵電池 |
| Apple / PC | 非常に高（型番・シリアル） | 高い | 電池が必ず内蔵、アクティベーションロック |
| DJ機材 | 高 | 高い | 大型・重量、電圧 |

**MVP の推奨は「カメラ・レンズ」1 カテゴリからの開始。**
理由: 型番の特定が最も確実で、状態が価格に直結し、海外需要が明確で、
かつ**本体のみなら電池規制を回避しやすい**（[09](09-LEGAL-CHECKLIST.md) §3）。

`要確認`: 最終決定は、各カテゴリの市場データを実際に API から取得できるかを
検証してから行う（[10](10-BACKLOG.md) EPIC-0 のスパイク）。
